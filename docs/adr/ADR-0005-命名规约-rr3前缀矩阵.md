# ADR-0005：命名规约 —— rr3 前缀矩阵

- **状态**：已接受
- **日期**：2026-09-28
- **关联**：[naming.md](../naming.md)（速查表）· [architecture.md](../architecture.md)

## 背景

用户决策：**RockRobot3 整个项目的所有函数前缀都使用 "rr3"**。需要把该决策转译为跨语言（Rust/Python/C）可执行的精确规则——Rust 有模块系统，函数逐个加前缀在 crate 内部非惯用且可读性代价大；C/Python 无命名空间，前缀是刚需。

## 决策

### 1. 决策精神的精确表述

> 全项目任意代码中出现的**跨边界全局符号**（跨模块调用、事件、配置、进程名）都能一眼识别归属为 rock3。

### 2. 命名矩阵（完整表见 [naming.md](../naming.md)）

| 层级 | 规则 | 示例 |
|---|---|---|
| 模块目录/crate/进程/bin | `rr3-<域>` | `rr3-sense` |
| 基座基础设施 crate | `rr-<设施名>`（无 3，区分基座 vs 模块） | `rr-ipc` |
| Rust 跨 crate 导出自由函数 | `rr3_<域>_<动作>` | `rr3_ipc_publish()` |
| Rust 导出类型 / trait | `Rr3` 前缀 | `Rr3Envelope`、`trait Rr3AudioInput` |
| Rust crate 内部私有函数 / trait 方法 | 不加前缀 | `fn parse_vad_frame()` |
| Python 包/模块 / 包级函数 | `rr3_<域>` / `rr3_<域>_<动作>` | `rr3_brain`、`rr3_brain_submit_text()` |
| 事件/RPC 主题 | `rr3-<模块>/<域>/<事件>`（= manifest.name 前缀） | `rr3-sense/audio/vad_start` |
| 环境变量/配置键 | `RR3_` | `RR3_LOG_LEVEL` |
| systemd / D-Bus | `rr3-<域>.service` / `cn.rockrobot.rr3.<域>` | — |

### 3. Rust 边界规则（本 ADR 核心裁定）

- **加前缀**：跨 crate 导出的自由函数、导出类型、trait 名——消费方调用时可见归属
- **不加前缀**：crate 内部私有函数、trait 方法（命名空间已由模块路径限定）
- 理由：`rr3_xxx` 逐方法前缀在 Rust 中制造 `rr3_sense::rr3_audio::rr3_parse` 式冗余；边界规则已满足"任意跨边界符号可识别归属"
- 兜底：后续在 tools/ 增加规约 lint 脚本做 CI 检查

### 4. 连带修正

事件主题从早期草案的 `sense/audio/vad_start` 统一改为 `rr3-sense/audio/vad_start`：主题前缀 = manifest.name，与新决策自洽，校验规则不变。

## 备选方案否决理由

- **全函数（含私有）加 rr3_**：Rust 可读性代价大，且私有符号不构成跨边界识别问题
- **基座也用 rr3- 前缀**：基座 crate（rr-ipc 等）被所有模块依赖但不属于业务域，用 `rr-` 区分"基座 vs 模块"，减少视觉噪音

## 后果

- 正面：跨语言命名一致，grep `rr3` 即可锁定全部项目资产；四合一校验（目录=crate=进程=IPC前缀）由 rrd 启动时强制
- 负面：Rust 导出 API 比惯例多一层前缀（可接受，属项目级约定）
