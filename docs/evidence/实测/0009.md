# N43-4 W5/T3 部分验收（Pi 板）

- 板：Pi 4B（aarch64，Raspberry Pi OS/Debian 13 trixie）当板；Mac 宿主经 FT232
  `/dev/cu.usbserial-A50285BI`，1.5M。Pi 宿主栈 `rrd` inactive，板程序从源码区外
  构建目录启动。
- 接线：OLED SSD1315 0x3C；SG90 pan=pin32/GPIO12、tilt=pin33/GPIO13，V+ 走独立
  UBEC 5V，GND 与 Pi 共地；ADS1115 之实物模块已判定不跟随，rail 挂起。

## 1 U3（帧面 canonical）

`frame_probe.py` 以 `RR3_PROBE_BOARD=pi` 注入 Pi 四键真值
（`i2c_sda=2`、`i2c_scl=3`、`uart2_tx=14`、`uart2_rx=15`）：

- 九条帧面调用全部 PASS（舵机读/写/越界、非法轴、表情写/非法、未知主题）；
  `payload_crc32`、`id` 回带、`dst` 全对。
- `rr3.set_bindings` PASS，`{"applied": true, "mismatch": 0}`；其余六键接受但不参与
  Pi 对账。
- Pi INFO 无 `selfheal_skip`（经典自愈字段），探针记 **SKIP**，不冒充通过。
- 两轮独立抓取 **10/10**，`U3_FRAME_DIGEST` 逐字相同：

```text
5432ac1f7f27acda7633cec9e95dba1b52be9cd45a74e044a593408df1741c9a
```

口径：digest 只含平台中立的 `rr3.call` 回包 canonical JSON；`set_bindings` 的
`mismatch` 是板级真值差，不纳入跨板 digest。行面 `u3_capture.py` 的 HELP/SCAN
能力文案与 Pi 不同，不作本档 U3 口径。

### 1.1 classic 板对拍（2026-11-06）

FT232 转接 classic UART2（GPIO18/19，1.5M），同一 `frame_probe.py` 走 classic
十键绑定（`RR3_PROBE_BOARD` 不设）：

- 首轮 9/10，`表情写 happy` 回 `previous="happy"`（Pi 为 `"idle"`）；逐条
  `U3_CALL` 摘要把差异定位到该命令，**digest 不等（4497a84a…）**。
- 根因：classic 行面 `FACE` 只改渲染态、未记账 `ctl.prev_expr`，帧面随后读到的
  `previous` 是过期值；Pi 行面有记账。属实现缺陷，不是平台差异。
- 修复 `tools/esp32-periph-base/src/commands.rs` 行面 `FACE` 补记账，esp32 门禁
  与 `check.sh` 全绿，`espflash` 烧录后复测。
- 复测两轮 **10/10**，逐条 `U3_CALL` 与 Pi 全同，`U3_FRAME_DIGEST` **逐字相等**：

```text
classic  5432ac1f7f27acda7633cec9e95dba1b52be9cd45a74e044a593408df1741c9a
Pi       5432ac1f7f27acda7633cec9e95dba1b52be9cd45a74e044a593408df1741c9a
```

### 1.2 S3 板对拍（2026-11-06）

- 烧录口为 S3 数据线 `/dev/cu.usbserial-1420`（CH340，esp32s3 v0.2、16MB flash、
  MAC `7c:e8:b1:ab:1e:f4`）；`espflash flash --chip esp32s3` 烧录 14:02 产物，
  启动日志 `app version 495763c`、`compile time Nov 6 2026 14:00:34`。
- 烧录前旧固件首测 10/10 但 digest `d80e9d73…`，唯一差异 `表情写 happy` 的
  `previous="none"`（与 classic 首轮同根因：行面 FACE 未记账）。
- 烧录后两轮 **10/10**，`set_bindings` `mismatch=0`，注入后 `selfheal_skip`
  增量 0；逐条 `U3_CALL` 与 classic/Pi 全同，digest 逐字相等：

```text
classic  5432ac1f7f27acda7633cec9e95dba1b52be9cd45a74e044a593408df1741c9a
Pi       5432ac1f7f27acda7633cec9e95dba1b52be9cd45a74e044a593408df1741c9a
S3       5432ac1f7f27acda7633cec9e95dba1b52be9cd45a74e044a593408df1741c9a
```

舵机现场接入（pan=GPIO4 / tilt=GPIO5）：小角度点动轴向正确（先水平后垂直）；
全行程 `PAN 60/120`、`TILT 80/100`、`SERVO 90 90` 全部 `OK`，最终
`INFO pan=90 tilt=90`，`job_drop=0 reply_drop=0`，堆余量稳定；冷启动回
开机姿态 60/93 后再回中。现场确认全行程无卡顿。

30min 长跑（S3 补充稳定性，不替代 Pi 台架的 N43-4 判据）：1800s、181 次
`INFO`、0 错、0 复位；`max_job_drop=0`、`max_reply_drop=0`、
`min_free=8,487,352B`；周期 PAN/TILT 与 FACE 无失败，末态
`pan=90 tilt=90`。

## 2 U5（共享机制）

`tools/periph-mech/tests/u5.rs` 锁定三平台共用字节：

- 舵机 `angle→duty` 全表：pan 60–120、tilt 80–100，`DUTY_MIN=410`/`MAX=2048`；
- OLED 页 0 字节流：`rr3_page_cmd(0)` + `rr3_frame_pages([0xAA;8])[0]`；
- 轨压分档表：`RailJudge(4600, 4400)` 自 6000mV 降至 0mV，逐拍档位/边沿。

```text
U5_DIGEST 7a8b983a76eefc38   （FNV-1a 64，test u5_shared_mechanism_digest）
```

Pi 侧实测 PWM 对账：`pwm0/pwm1` period **20ms**，90° duty **1.500244ms**
（`rr3_deg_to_duty(90)=1229` → `pwm_ticks_to_ns=1500244`），enable=1。U5 为共享
机制 digest；classic/S3 同 crate，换板不改机制。

## 3 舵机与 OLED

- 全行程 `PAN 60/120`、`TILT 80/100` 均 `OK`；回中 `PAN 90/TILT 90`；水平/垂直

## 4 rail（挂起）

- 实物 ADS1115 模块（黑/绿端子版）I2C 0x48 通信正常，但芯片端不跟随分压中点：
  DMM 轨 5.25V、中点 2.62V；`RAIL` 重复读数 **4544/4560/4595mV**（对应 AIN0
  1.69–1.71V），误差远超 ≤50mV；2.78:1 标定亦漂移。已拒绝该模块，代码恢复 2:1，
  待直入型模块到货后补 `RAIL≈5240mV`。
- 无 ADS 时 `INFO` 显式 `rail=absent`、`RAIL` 回 `ERR ADS1115 未装配`，不冒领。
