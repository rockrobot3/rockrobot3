# N44 Pi4 独立 host-only 实机验收

- 板：Pi 4B（aarch64，hostname `spharx`，`192.168.0.194`），Raspberry Pi OS；
  装机 rrd 0.0.1（2026-10-31 构建），模块目录 `/usr/lib/rockrobot3/modules`。
- 装配：`profiles/pi4b-host.toml`＋`hardware/pi4b-host/wiring.toml` 铺到
  `/usr/lib/rockrobot3/{profiles,hardware/pi4b-host}/`，profile sha256
  `56984f3b36bdf7fa0434e5399b551f1787a2cb03ac3c136bad5098939ab2998d`。
- 起法：`sudo env RR3_DATA_DIR=/var/lib/rockrobot3 RR3_HAL_BACKEND=linux rrd
  --socket /var/run/rock3-ipc.sock --contracts /usr/lib/rockrobot3/contracts
  --profile /usr/lib/rockrobot3/profiles/pi4b-host.toml`（cloud.env 同 systemd
  drop-in 源入环境）。

## 1 启动与模块

```text
rrd: 装配单已加载: /usr/lib/rockrobot3/profiles/pi4b-host.toml
rrd: spawn rr3-connect pid=1229 ...
rrd: spawn rr3-interact pid=1230 ...
rrd: spawn rr3-brain pid=1231 ...
rrd: rr3-interact → running
rrd: rr3-connect → running
rrd: rr3-brain → running
```

`rr3-ctl status`：

```text
NAME          TASK  PHASE
rr3-connect   2     running
rr3-interact  3     running
rr3-brain     4     running
denied_publish = 0
```

`rr3-ctl health` 三模块心跳均在窗内（HB 2000/1000/2000ms，SINCE_BEAT≈0.9s）。

## 2 本机末梢

- 显示面：`[rr3-interact] 显示面就绪: backend=linux 8x8`；`/dev/spidev0.0` 在位
  （MAX7219，SPI0 CE0）。
- 播放面：`[rr3-interact] 播放面就绪: backend=linux rate=16000 ch=1`；
  `aplay -l` 见 `card 3: Device [USB Audio Device]`。采集面只有
  `card 2: sndrpigooglevoi`（voiceHAT），无 USB 采集，故本档不启用
  `audio.capture/vad`，与 `pi4b-host.toml` 的八格三模块一致。
- 面板：`面板就绪: http://127.0.0.1:8080（28端点）`。

## 3 链路后端

`RR3_HAL_BACKEND=linux` 时：

```text
[rr3-connect] 链路面就绪: linux up=true ssid=Some(WXYYBG) rssi=Some(-65)
[rr3-connect] 配网面就绪: linux 无在册凭据（出厂 ap）
[rr3-connect] 蓝牙面: phase=off（骨架，真后端板上后置）
```

不设 `RR3_HAL_BACKEND` 时 `rr3-connect` 落 `sim`（`ssid=rock-sim`）；这是
部署环境变量选择，不是 profile 数据缺陷。真链路起法须带 `RR3_HAL_BACKEND=linux`。

### 3.1 systemd 默认切换（2026-11-06）

- 备份装机 drop-in：`profile.conf` → `profile.conf.bak-n44`；新 drop-in 的
  `ExecStart` 指向 `/usr/lib/rockrobot3/profiles/pi4b-host.toml`，并显式
  `Environment=RR3_HAL_BACKEND=linux`（cloud.env/secrets 同源保留）。
- `systemctl enable --now rrd`：`active` / `enabled`；三模块
  `rr3-connect/rr3-brain/rr3-interact` 全 `running`、`denied_publish=0`；
  `链路面就绪: linux up=true ssid=WXYYBG rssi=Some(-66)`。
- `systemd show rrd -p Environment` 确认 `RR3_HAL_BACKEND=linux` 已注入。

## 4 面板动作（MAX7219／USB 声卡）

```text
POST /api/face {"expression":"happy"}
{"ok":true,"result":{"expression":"happy","previous":"idle"}}

POST /api/beep
{"ok":true,"result":{"played_ms":200}}   （重复两次均 200ms）
```

两条均走 `rr3-interact` 进程内显示/播放路径。**现场确认：USB 声卡正常出声**
（两次 200ms 蜂鸣均听到）；**MAX7219 尚未接到 Pi**，`显示面就绪: backend=linux
8x8` 只证明 spidev 打开与模块路径就绪，**不能算物理显示通过**，待接线后复验。

systemd 实例下复测：`/api/beep` 仍 `{"ok":true,"result":{"played_ms":200}}`，
`/api/face happy` 仍 `{"ok":true,...}`（写入 spidev，无物理屏可目视）。

`POST /api/selftest`（面板自检）：

- `speaker` pass、`face` pass；
- `wiring/signal:J0` 两项 `n-a`（供电/地导体豁免），`wiring/net:J0:rail5v` pass，
  `wiring/rated:J0` pass，`wiring/pin:ui.face.spi` `n-a`（接线档未收敛该 pin）；
- `contracts/contract:*` 五条 pass（四册 sha 对齐＋真值集 7 成员齐全）；
- 唯一红腿 `relay`：`没有在册模块 exposes 主题 rr3-act/relay/set`（N44 不启用
  `rr3-act`，属 host-only 不适用项；共享 selftest config 仍期望 `relay=pass`），
  故整体 `verdict=fail`。

口径：N44 的验收目标腿是 face/speaker，两条均 pass；relay 红是共享配置对
host-only 能力面未判 `n-a`，不是装配档装载失败。后续可按 enabled_slots/能力面
在 selftest 里把缺模块腿判 `n-a`（代码面），或给 host-only 单独的 interact
配置覆写；本批不改共享 config，避免把 classic 的 relay 腿一起降级。

## 5 结论与余项

- N44 host-only 装配档在 Pi 实机可装载、三模块 running、真 WiFi 链路与
  播放面就绪；`/api/beep` 现场确认有声；`/api/face` 模块路径成功；
  selftest 的 face/speaker 两条目标腿 pass。systemd 默认已切 N44 并 `enable`。
- **MAX7219 未接线**：`ui.face` 在 profile 里声明 present，但物理屏不在位；
  当前只证 spidev/模块路径，显示面物理验收待接屏后复测。若长期不接屏，应把
  `ui.face` 从 profile/`[slots].present` 移除；但 `rr3-interact` 的显示探活是
  fail-closed，需同批裁定。
- selftest `relay` 腿在 host-only 下应判 `n-a`（共享 config 仍期望 pass，待
  代码面按能力面判或 host-only 配置覆写）；本批不改共享 config，避免把 classic
  的 relay 腿一起降级。
- 余项：MAX7219 物理显示；N43-4 的 Pi 30min 长跑（需把 FT232 从 S3 移回 Pi）；
  rail 等直入 ADS。
