# N44 Pi4 独立 host-only 实机验收

- 板：Pi 4B（aarch64，hostname `spharx`，`192.168.0.194`），Raspberry Pi OS；
  装机 rrd 0.0.1（2026-10-31 构建），模块目录 `/usr/lib/rockrobot3/modules`。
- 装配：`profiles/pi4b-host.toml`＋`hardware/pi4b-host/wiring.toml` 铺到
  `/usr/lib/rockrobot3/{profiles,hardware/pi4b-host}/`，profile sha256
  `56984f3b36bdf7fa0434e5399b551f1787a2cb03ac3c136bad5098939ab2998d`。
- 起法：`sudo env RR3_DATA_DIR=/var/lib/rockrobot3 RR3_HAL_BACKEND=linux rrd
  --socket /var/run/rock3-ipc.sock --contracts /usr/lib/rockrobot3/contracts
  --profile /usr/lib/rockrobot3/profiles/pi4b-host.toml`（cloud.env 同 systemd
  drop-in 源入环境）。

## 3 链路后端

`RR3_HAL_BACKEND=linux` 时：

```text
[rr3-connect] 链路面就绪: linux up=true ssid=Some(WXYYBG) rssi=Some(-65)
[rr3-connect] 配网面就绪: linux 无在册凭据（出厂 ap）
[rr3-connect] 蓝牙面: phase=off（骨架，真后端板上后置）
```

不设 `RR3_HAL_BACKEND` 时 `rr3-connect` 落 `sim`（`ssid=rock-sim`）；这是
部署环境变量选择，不是 profile 数据缺陷。真链路起法须带 `RR3_HAL_BACKEND=linux`。

## 4 面板动作（MAX7219／USB 声卡）

```text
POST /api/face {"expression":"happy"}
{"ok":true,"result":{"expression":"happy","previous":"idle"}}

POST /api/beep
{"ok":true,"result":{"played_ms":200}}   （重复两次均 200ms）
```

两条均走 `rr3-interact` 进程内显示/播放路径。**现场确认：USB 声卡正常出声**
（两次 200ms 蜂鸣均听到）；**MAX7219 已接线并现场确认**：8×16 两片级联各显示
一张 happy 脸（两眼＋笑嘴），与代码 `RR3_MAX7219_CHIPS=2` 的双片同值包一致。
首次 `CS` 接到了非 CE0 脚，改正到 **pin 24 / GPIO8 / CE0** 后点亮；裸 spidev
happy 原始帧与面板 `/api/face` 两条路径均能画出该表情。

systemd 实例下复测：`/api/beep` 仍 `{"ok":true,"result":{"played_ms":200}}`，
`/api/face happy` 仍 `{"ok":true,...}`，物理 MAX7219 已确认显示 happy 脸。

`POST /api/selftest`（面板自检）：

- `speaker` pass、`face` pass；
- `wiring/signal:J0` 两项 `n-a`（供电/地导体豁免），`wiring/net:J0:rail5v` pass，
  `wiring/rated:J0` pass，`wiring/pin:ui.face.spi` `n-a`（接线档未收敛该 pin）；
- `contracts/contract:*` 五条 pass（四册 sha 对齐＋真值集 7 成员齐全）；
- `relay` 腿按能力面判：`rr3.ctl.status` 模块表无 `rr3-act` → `n-a`，不向总线
  发无人接的 on/off；reason=`rr3-act 未启用（host-only 能力面 n-a）`。共享
  selftest config 仍保留 `relay=pass` 默认，classic 的 relay 腿不受影响。
- 因此整体 `verdict=pass`：speaker/face pass，wiring 组零 fail（signal/pin 为
  n-a），contracts 组零 fail。

口径：relay 的 n-a 不是“跳过验收”，而是能力面判定——host-only 没启用
`rr3-act`，该腿本就不适用；`rr3-act` 在册但 relay 调用失败仍如实 fail。
实现：`server.rs` selftest 先查 `rr3.ctl.status`，仅当 `rr3-act` 缺席或
`expect.relay=n-a` 时记 n-a，并对该腿局部覆盖期望；共享 config 不改。

Pi 实测（2026-11-06）：当前源码在 `/home/pi/rr3-interact-src` 以
`cargo build --release --features alsa` 构建 aarch64；装机二进制备份
`rr3-interact.bak-n44selftest`；重启 rrd 后三模块 running、`denied_publish=0`，
`POST /api/selftest` → `verdict=pass`（relay n-a，speaker/face pass，
wiring/contracts 零 fail）。

## 6 voiceHAT 采集裁定（不纳入 host-only）

- 采集设备：`card 2: sndrpigooglevoi`（Google voiceHAT），`arecord -l` 里唯一
  的 capture 设备；USB 声卡 card 3 只有 playback，无采集。
- 实测：`arecord -D plughw:2,0 -f S16_LE -r 16000 -c 2 -d 3` 成功，48000 帧，
  **RMS=0.0、peak=0**；`amixer -c 2 scontrols/contents` 为空，无采集增益/静音
  控件可调。
- 裁定：**不纳入 N44 host-only**。当前是“有采集设备、无有效麦克风信号”，
  不能冒充“本机可听”；N44 保持 MAX7219 + USB 回放。若后续要做 Pi 独立听觉，
  先接有效麦克风/USB 采集，另立 `pi4b-host-audio.toml`（`audio.capture` +
  `audio.vad` + `rr3-sense`），不在 N44 里静默扩模块。
- 口径：不是判定 voiceHAT 硬件损坏，而是当前信号链无可用输入且无混音器可调；
  待麦克风/信号链补齐后复测。

  21:56:29–22:26:30，1800s。
