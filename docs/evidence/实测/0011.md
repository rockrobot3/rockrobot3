# W6 Pi 宿主 × S3 板冒烟（2026-11-07）

- 宿主：Pi 4B（`192.168.0.194`，aarch64），`rrd` 仍跑 N44 host-only（不占 UART0）；
  探针从 Pi 本机 `/dev/ttyAMA0` 发起，Mac 只经 SSH 访问 Pi。
- 板：ESP32-S3 N16R8，`esp32-periph-base`（当前刷录版），S3 自身 USB 供电。
- 接线：Pi pin 8（GPIO14/TX）→ S3 GPIO42（RX）、Pi pin 10（GPIO15/RX）→
  S3 GPIO41（TX）、GND↔GND；FT232 已从 Pi UART0 拔除；S3 的 OLED（GPIO8/9）
  与双轴（GPIO4/5）保持原线束。

## 1 链路与 U3

`INFO` 首次应答即通（1.5M）。`frame_probe.py` 以 `RR3_PROBE_BOARD=s3` 从 Pi
跑两轮：

```text
通过 10/10
U3_FRAME_DIGEST 5432ac1f7f27acda7633cec9e95dba1b52be9cd45a74e044a593408df1741c9a
```

`rr3.set_bindings` 注入 S3 十键真值：`{"applied": true, "mismatch": 0}`；
注入后 `selfheal_skip` 增量为 0。digest 与 classic/Pi/S3 三端基线逐字相等，
证明“宿主换板为 Pi”不改变帧面语义。

## 2 OLED 与双轴

行面从 Pi 发：

```text
SERVO 90 90            => OK pan=90 tilt=90
PAN 60                 => OK pan=60
PAN 120                => OK pan=120
TILT 80                => OK tilt=80
TILT 100               => OK tilt=100
SERVO 90 90            => OK pan=90 tilt=90
OLED S3 W6 PI HOST     => OK oled "S3 W6 PI HOST"
```

S3 OLED 文本与双轴全行程命令面通过；现场确认 S3 OLED 显示
`S3 W6 PI HOST`，双轴 60/120 与 80/100 全行程正常（S3 端点本身已在 0009 验证）。

## 3 rail（不判定，登记假 OK）

```text
RAIL                   => OK rail sample queued
RAIL rail=6256mV raw=4095
INFO ... rail=6256mV raw=4095 rail_tier=ok ...
```

S3 的 ADC 输入 GPIO1 未接 5V 分压，读数 `raw=4095` 是悬空饱和，`6256mV`
不是真实轨压；`rail_tier=ok` 是**假 OK**，本档 rail **不判定**。要得到有效
W6 轨压，需把 S3 5V 经 **10k → GPIO1 → 10k → GND**（2:1）后复测，预期
`RAIL≈5000mV`；并给 S3 固件加饱和/悬空保护（`raw=0/4095` 报 absent/invalid，
不报 ok）。用户已确认将断电接分压，rail 与固件保护同批复测；Pi 的 ADS rail 另案。

## 4 MAX7219 与组合档

- 本次 W6 是**探针冒烟**：Pi 只当 UART 宿主，不经过 `pi4b-host-esp32s3.toml`
  的 rrd 五模块组合档；MAX7219 不参与，接在 Pi 上无影响。
- 若后续跑 `pi4b-host-esp32s3.toml` 全 host 栈，该档 `ui.face` 仍绑
  `rr3-interact`、`[[pin]]` 仍是 Pi `spidev0.0`，那时 MAX7219 必须接。
- 全 rrd 五模块组合档（含 `rr3-act`/`rr3-sense` 与板侧 UART 单消费者约束）
  本轮未跑；W6 只按计划做冒烟。
