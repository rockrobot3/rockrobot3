# Pi 宿主 × ESP32 classic 真件会话（2026-11-16）

## 1 现场与拓扑

- 宿主 Pi 4B（Debian 13 trixie 内核 6.12），`rrd` 以 systemd 单元起，
  装配单 `pi4b-host-esp32-classic.toml`（组合形态：Pi 宿主 + ESP32 classic 板端）。
- 板端 ESP32 classic 4MB 经 Pi `pin8/pin10`（GPIO14/15）三线连 `/dev/ttyAMA0`（1.5M）。
- Pi 本地末梢：MAX7219 双片级联（`/dev/spidev0.0`）、USB 声卡
  `card 3: Device [USB Audio Device] 0d8c:0012`。

## 2 启动面

开场时 `rr3-interact` 处于 `failed`（其余四模块 running）。根因不是代码缺陷，而是
装配单 `[hardware].alsa_device = "plughw:CARD=Device"` 指向的 USB 声卡当时**未接入**
（`aplay -l` 只有 HDMI×2 与 voiceHAT）——模块 fail-closed 打开播放面失败后退出，
连续 5 次达上限被 rrd 停止重启并降级。per-unit 日志逐字给出原因：

```text
rr3-interact 退出: 打开播放面(linux)失败: HAL 参数非法: alsa 打开设备
"plughw:CARD=Device" 失败: ALSA function 'snd_pcm_open' failed with error
'No such device (19)'
```

声卡接入后重启单元，五模块全 running：

```text
NAME          TASK  PHASE
rr3-connect   2     running
rr3-act       3     running
rr3-sense     4     running
rr3-interact  5     running
rr3-brain     6     running
denied_publish = 0
```

`vcgencmd get_throttled` = `0x0`（无降压/温度限频）。

## 3 面板面（interact）

| 动作 | 结果 |
|---|---|
| `POST /api/selftest` | `verdict=pass`；speaker/relay/face 三腿 pass，wiring 与 contracts 全 pass |
| `POST /api/beep` | `{"ok":true,"result":{"played_ms":200}}` |
| `POST /api/face` happy → blink → idle | 三次 `ok=true`，`previous` 依次 idle/happy/blink |
| `POST /api/face` talk | 被 `non_pointable=["talk"]` 策略拒绝（400 语义），符合设计 |

启动自述：`播放面就绪: backend=linux rate=16000 ch=1`、`显示面就绪: backend=linux 8x8`、
`面板就绪: http://127.0.0.1:8080（28端点）`。

## 4 声卡电平（敞口 #24）

USB 声卡热插入后 `amixer -c Device scontents` 仍为 `14 [38%] [-23.00dB]`——批N38 件一
的 `ExecStartPre` **从未铺到板上**（`/lib/systemd/system/rrd.service` 仍是 10-31 版本）。
按仓内真值补铺后重启单元：

```text
ExecStartPre=-/usr/bin/amixer -c Device sset PCM 100%
→ Front Left/Right: Playback 37 [100%] [0.00dB] [on]
```

机制成立。`sudo reboot` 后复验：`up 1 min` 时电平仍 `100%`（`0.00dB`）、五模块全
running、`denied_publish=0`、`throttled=0x0`——跨重启保持成立。余量：运行中热插拔
声卡不会重跑 `ExecStartPre`，电平回落需重启单元或手工置位。

## 5 部署面漂移门（敞口 #25）

门由 7 件 config 扩为 16 件（模块 config 7 + 装配单 8 + systemd unit 1；unit 口径忽略
`ExecStart=`，因 rr3-pack 出包按 `--profile` 改写该行）。扩面后真板当场抓到两件：

```text
DRIFT profiles/esp32s3-mini.toml       （UART2 41/42 真板订正注释只进仓，板上仍旧 17/18）
DRIFT base/os/distro/units/rrd.service （批N38 注释未铺板）
比对 16 件：漂移/缺件 2 件
```

按仓内真值铺板后 `比对 16 件：漂移/缺件 0 件`。两件均为注释漂移、零行为差异，
但正是"仓内改了、板上没跟"的活证据。工具 self-test 六例覆盖正反两侧。

## 6 ESP32 链路面

本次 boot 内的板面流与动作链（sense 日志原文）：

```text
音频源就绪: backend=esp32 rate=16000 ch=2 frame_ms=20
rr-hal-esp32-audio: 板面流就绪（实测 rate=16000 ch=2 s16le）
反射环: 判停后下发 pan=65°
rr-hal-esp32-audio: 板面命令回执就绪（id=1 ok；后续成功回执不逐条打印）
反射环: 点头蓄势 tilt=90°
反射环: 点头示意 tilt=98°
```

`rr3-act` 侧：`执行面就绪: servo=remote(rr3-sense) led=placeholder relay=placeholder`
——舵机桥由 sense 独占是设计（单 UART、flock 单消费者），`act.led`/`act.relay` 在
装配单 `[slots].present` 中如实申报不在位，故 placeholder 回 Unsupported 属正确行为。

拆帧面：本次 boot 内 3 次 `载荷 CRC32 不符`（每次 `已弃 11161B 重扫`，整帧丢弃），
音频流未中断（`pcm_frames` 持续增长、VAD/ASR 正常出轮）。量级归敞口 #16 继续取证。

## 8 长跑（1800s）与云侧分支

`rr3-ctl counters` 前后两次差值（时长 1800s）：

| 键 | 增量 | 判读 |
|---|---|---|
| `rr3-sense pcm_frames` | +89,292 | 期望 90,000（20ms/帧），到位 99.21% |
| `rr3-sense pcm_empty_frames` | 0 | 零空帧，音频流无断流 |
| `rr3-sense reflex_pan_cmds` / `reflex_tilt_cmds` | +8 / +16 | 8 轮听声定位→点头 |
| `rr3-brain asr_ok` / `asr_fail` | +6 / +2 | 云 ASR 有活动 |
| `rr3-brain rounds_audible` / `rounds_replied` | 0 | 无完整对话轮 |
| `rrd boots` / 模块崩溃 | 0 / 0 | 全程零重启 |

板面链路窗统计（sense 自述，10min 窗）：

```text
桥链统计（10min 窗）: 本窗帧=+4685 坏=+1 重连=+0 | 累计帧=23420 坏=8 重连=0
```

即坏帧率 0.02%/窗、累计 0.034%，零重连——与首节 3 次 CRC32 拆帧失败同源但量级很小。

对话轮为 0 的根因在云侧，不是链路：brain 日志反复给出

```text
ASR 第 1/2 次失败（云端不可达 https://api.siliconflow.cn/v1/audio/transcriptions:
Network Error: Error encountered in the status line: timed out reading response），500ms 后重试
轮次 N: ASR 失败，弃轮（asr_ms=16895…（ASR 共尝试 2 次））
```

超时型失败占绝对多数，另有"识别为空文本，弃轮"（无语音/噪声轮）。敞口 #16 的
"云失败各分支分布"由此首次取得真板样本；失败分支已可见、可归因，非静默。

## 9 流畅度基线（改动前后同机对照）

| 指标 | 值 | 取法 |
|---|---|---|
| 启动到五模块 running | 2.306 / 2.297 / 2.289 s（中位 2.297 s，抖动 ≤17 ms） | `systemctl restart rrd` 后 100ms 轮询 `rr3-ctl status`，三次 |
| 反射环节拍 | **888 Hz → 970 Hz**（配置目标 1000 Hz，达成率 88.8% → 97.0%） | `reflex_ticks` 300s 差分 |
| 音频帧到位率 | 99.21%（1800s，缺 708/90,000） | `pcm_frames` 差分 |
| 空帧 / 断流 | 0 / 0 | `pcm_empty_frames` / 桥链重连 |
| CPU（粗采） | `rrd` ~2%、`rr3-act` ~2–9% | `top -b -n 2 -d 3` |
| 内存 | used 206 MB / 1845 MB | `free -m` |

节拍欠账的根因与修复：`rr3_reflex_loop` 原用 `sleep(period)` 相对睡眠，每拍把
"唤醒到下一次调用"的调度开销叠进周期，误差线性累积。改为绝对截止累加
（`rr3_next_wait`：每拍只加 period，晚醒时差下一拍少睡补回，落后超一拍重置
不追帧），同一块板同一负载下 888 → 970 Hz。剩余 3% 是 Linux 睡眠粒度，再追
需 busy-wait 烧 CPU，不做。

## 10 结论与余量

- 成立：五模块装配、面板自检、表情与提示音、ESP32 音频流与反射环、板上 rr-hal 单测、
  部署面三类漂移判据。
- 余量：① OLED 与舵机的逐命令（非反射环）取证；② CRC32 拆帧失败的持续性量级；
  ③ `act.led`/`act.relay` 未接线属现场事实，装入外设后需重跑本档；
  ④ 声卡热插拔不触发 `ExecStartPre`（电平回落需重启单元或手工置位）。

## 11 板侧配置腿读数（#16 第一问）

板侧 WiFi 本次为 AP-only 档（Pi 所在 LAN 的 254 地址扫描零命中 `/api/board/state`，
`iw scan` 见 SoftAP `RR3-BOARD`），故改由 Mac 短暂接入该 SoftAP（WPA2，口令为
仓内公开缺省）取读数，取毕立即回连家用 AP（回连后 `192.168.0.161`，录音留痕）。

取法：`GET http://192.168.4.1/api/board/state` 两次（间隔 3s）＋
`GET /api/board/bindings`，均为 200。

```json
{"audio_dropped":0,"audio_on":true,"audio_sent":21936,"audio_seq":21937,"binding_mismatch":0,"expr_mode":true,"frame_mode":false,"move_fail_events":0,"pan_deg":60,"rail_low_events":0,"rail_mv":0,"rail_raw":0,"rail_tier":"unknown","rail_valid":false,"selfheal_skipped":0,"tilt_deg":93,"wander_on":false}
{"audio_dropped":0,"audio_on":true,"audio_sent":21960,"audio_seq":21961,"binding_mismatch":0,"expr_mode":true,"frame_mode":false,"move_fail_events":0,"pan_deg":60,"rail_low_events":0,"rail_mv":0,"rail_raw":0,"rail_tier":"unknown","rail_valid":false,"selfheal_skipped":0,"tilt_deg":93,"wander_on":false}
```

`/api/board/bindings` 应答为 `null`（宿主未注入绑定，板侧按编译期键运行；
`binding_mismatch=0` 与此一致）。

判读（只记读数，不外推）：

- **#16 第一问**：本次 boot 内板侧 `move_fail_events=0`——移动失败未发生；
  `selfheal_skipped=0`、`rail_low_events=0` 同窗为 0。
- 音频面：`audio_on=true`、`audio_dropped=0`，`audio_sent` 3s 内 +24
  （板侧发送节拍口径，与宿主 `pcm_frames` 的 20ms 帧口径不同，不做每秒换算）。
- 轨压面：`rail_valid=false`、`rail_tier=unknown`——本次 GPIO34 分压未接/未武装，
  与敞口 #12 的待标定态一致。
- 姿态面：`pan_deg=60`/`tilt_deg=93` 为末次下发值，非实时关节读数。
