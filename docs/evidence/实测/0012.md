# Pi 宿主 × ESP32 classic 真件会话（2026-11-16）

## 1 现场与拓扑

- 宿主 Pi 4B（Debian 13 trixie 内核 6.12），`rrd` 以 systemd 单元起，
  装配单 `pi4b-host-esp32-classic.toml`（组合形态：Pi 宿主 + ESP32 classic 板端）。
- 板端 ESP32 classic 4MB 经 Pi `pin8/pin10`（GPIO14/15）三线连 `/dev/ttyAMA0`（1.5M）。
- Pi 本地末梢：MAX7219 双片级联（`/dev/spidev0.0`）、USB 声卡
  `card 3: Device [USB Audio Device] 0d8c:0012`。

## 2 启动面

开场时 `rr3-interact` 处于 `failed`（其余四模块 running）。根因不是代码缺陷，而是
装配单 `[hardware].alsa_device = "plughw:CARD=Device"` 指向的 USB 声卡当时**未接入**
（`aplay -l` 只有 HDMI×2 与 voiceHAT）——模块 fail-closed 打开播放面失败后退出，
连续 5 次达上限被 rrd 停止重启并降级。per-unit 日志逐字给出原因：

```text
rr3-interact 退出: 打开播放面(linux)失败: HAL 参数非法: alsa 打开设备
"plughw:CARD=Device" 失败: ALSA function 'snd_pcm_open' failed with error
'No such device (19)'
```

声卡接入后重启单元，五模块全 running：

```text
NAME          TASK  PHASE
rr3-connect   2     running
rr3-act       3     running
rr3-sense     4     running
rr3-interact  5     running
rr3-brain     6     running
denied_publish = 0
```

`vcgencmd get_throttled` = `0x0`（无降压/温度限频）。

## 3 面板面（interact）

| 动作 | 结果 |
|---|---|
| `POST /api/selftest` | `verdict=pass`；speaker/relay/face 三腿 pass，wiring 与 contracts 全 pass |
| `POST /api/beep` | `{"ok":true,"result":{"played_ms":200}}` |
| `POST /api/face` happy → blink → idle | 三次 `ok=true`，`previous` 依次 idle/happy/blink |
| `POST /api/face` talk | 被 `non_pointable=["talk"]` 策略拒绝（400 语义），符合设计 |

`面板就绪: http://127.0.0.1:8080（28端点）`。

## 4 声卡电平（敞口 #24）

USB 声卡热插入后 `amixer -c Device scontents` 仍为 `14 [38%] [-23.00dB]`——批N38 件一
的 `ExecStartPre` **从未铺到板上**（`/lib/systemd/system/rrd.service` 仍是 10-31 版本）。
按仓内真值补铺后重启单元：

```text
ExecStartPre=-/usr/bin/amixer -c Device sset PCM 100%
→ Front Left/Right: Playback 37 [100%] [0.00dB] [on]
```

机制成立。`sudo reboot` 后复验：`up 1 min` 时电平仍 `100%`（`0.00dB`）、五模块全
running、`denied_publish=0`、`throttled=0x0`——跨重启保持成立。余量：运行中热插拔
声卡不会重跑 `ExecStartPre`，电平回落需重启单元或手工置位。

## 5 部署面漂移门（敞口 #25）

门由 7 件 config 扩为 16 件（模块 config 7 + 装配单 8 + systemd unit 1；unit 口径忽略
`ExecStart=`，因 rr3-pack 出包按 `--profile` 改写该行）。扩面后真板当场抓到两件：

```text
DRIFT profiles/esp32s3-mini.toml       （UART2 41/42 真板订正注释只进仓，板上仍旧 17/18）
DRIFT base/os/distro/units/rrd.service （批N38 注释未铺板）
比对 16 件：漂移/缺件 2 件
```

按仓内真值铺板后 `比对 16 件：漂移/缺件 0 件`。两件均为注释漂移、零行为差异，
但正是"仓内改了、板上没跟"的活证据。工具 self-test 六例覆盖正反两侧。

```text

Network Error: Error encountered in the status line: timed out reading response），500ms 后重试
```

超时型失败占绝对多数，另有"识别为空文本，弃轮"（无语音/噪声轮）。敞口 #16 的
"云失败各分支分布"由此首次取得真板样本；失败分支已可见、可归因，非静默。

## 9 流畅度基线（改动前后同机对照）

| 指标 | 值 | 取法 |
|---|---|---|
| 启动到五模块 running | 2.306 / 2.297 / 2.289 s（中位 2.297 s，抖动 ≤17 ms） | `systemctl restart rrd` 后 100ms 轮询 `rr3-ctl status`，三次 |
| 反射环节拍 | **888 Hz → 970 Hz**（配置目标 1000 Hz，达成率 88.8% → 97.0%） | `reflex_ticks` 300s 差分 |
| 音频帧到位率 | 99.21%（1800s，缺 708/90,000） | `pcm_frames` 差分 |
| 空帧 / 断流 | 0 / 0 | `pcm_empty_frames` / 桥链重连 |
| CPU（粗采） | `rrd` ~2%、`rr3-act` ~2–9% | `top -b -n 2 -d 3` |
| 内存 | used 206 MB / 1845 MB | `free -m` |

节拍欠账的根因与修复：`rr3_reflex_loop` 原用 `sleep(period)` 相对睡眠，每拍把
"唤醒到下一次调用"的调度开销叠进周期，误差线性累积。改为绝对截止累加
（`rr3_next_wait`：每拍只加 period，晚醒时差下一拍少睡补回，落后超一拍重置
不追帧），同一块板同一负载下 888 → 970 Hz。剩余 3% 是 Linux 睡眠粒度，再追
需 busy-wait 烧 CPU，不做。

## 10 结论与余量

- 成立：五模块装配、面板自检、表情与提示音、ESP32 音频流与反射环、板上 rr-hal 单测、
  部署面三类漂移判据。
- 余量：① OLED 与舵机的逐命令（非反射环）取证；② CRC32 拆帧失败的持续性量级；
  ③ `act.led`/`act.relay` 未接线属现场事实，装入外设后需重跑本档；
  ④ 声卡热插拔不触发 `ExecStartPre`（电平回落需重启单元或手工置位）。

## 12 CRC32 拆帧失败审计（拆帧层是否有缺陷）

**方法**：在 `rrd.service.d/tee.conf` 打开 `RR3_HAL_ESP32_TEE=/tmp/esp32-tee.bin`
（批N12 件二宿主读面原始流 tee，默认关、64MiB 上限），17:25:30 重启 rrd 取新会话；
约 12.5 分钟后 tee 到量停写，落盘 67,108,640 B（64MiB 上限前最后一片）。
离线用独立实现（magic / reserved / plen / zlib.crc32 自写扫描，不复用仓内拆帧器）逐帧复核。

```text
bytes=67108640 frames_ok=6012 frames_bad=0 hdr_bad=0 junk=0
```

同窗 `journalctl -u rrd` 的 `载荷 CRC32 不符` 计数为 0；近 5h46m（本 boot 全量日志）
亦为 0；板侧 `音频分片写不全 / UART 写失败` 计数为 0。

**故障注入（真实 dump，非合成流）**：取 dump 中间一帧（off=33,552,972，plen=11,034），
翻转其载荷首字节后重扫：

```text
frames=6012
injected_at=33552972 plen=11034 ok=6011 bad=1 bad_off=[33552972]
resync_ok=True
```

即：单字节坏一帧 → 恰丢该帧、其余 6011 帧全部还原、重同步精确落回该帧起点，无级联。
与 [`framing.rs`](../../../base/runtime/rr-ipc/src/framing.rs) 的"CRC 不符整帧丢弃、不回坏载荷里
扫 magic"实现及单测 `assembler_rejects_corrupted_payload_crc` 一致。

**判读**：

- 拆帧层无逻辑缺陷：独立实现与仓内实现在同一份真实流上给出相同结论（6012/6012 帧合法），
  故障注入下丢弃/重同步行为符合设计；
- §6 记录的 3 次失败只可能是**传输面字节错误**（三线杜邦、无硬件流控；本 rig 历史上有
  自环/接触不良实录，N37 已建议换锁扣线）；整帧丢弃 + 重扫是既定兜底，不放大为连锁；
- 局限如实登记：该 3 次发生在更早 boot，journal 非持久化已不可回溯，**未能抓现行**；
  "传输面"是由"逻辑面无缺陷 + 当前 60MB 零误码 + 历史物理脆弱实录"三方收敛，不是复现结论。
- plen 护栏（1MB，机制缺省）在幻影长度下有丢弃放大面；本次三次实录丢弃量均等于整帧
  11,161B（头完好），未触发该面，故不为此改档。

## 13 1800s 长跑复跑（§8 回归）

同机复跑一轮（17:25:30→17:55:30，wall=1800.0s），起点为 tee 开启的新 rrd 会话；
前半窗（64MiB 原始流，约 12.5min）带 tee 写盘开销。`rr3-ctl counters` 差值：

| 键 | 增量 | 判读 |
|---|---|---|
| `rr3-sense pcm_frames` | +89,241 | 期望 90,000（20ms/帧），到位 99.16%（§8 为 99.21%，同量级） |
| `rr3-sense pcm_empty_frames` | 0 | 零空帧 |
| `rr3-act reflex_ticks` | +1,746,611 | 970.3 Hz（配置目标 1000 Hz，与 §9 的 970 Hz 一致） |
| `rrd boots` | 252→252 | 零重启、零 BOD |
| 对话面 | 0 | 本窗静音，无 ASR/TTS 轮次（非链路度量） |

同窗 `载荷 CRC32 不符` = 0、板侧部分写失败 = 0，与 §12 一致。结论：长跑指标可复现，
tee 写盘开销未改变音频到位率（99.16% vs 99.21%）。
