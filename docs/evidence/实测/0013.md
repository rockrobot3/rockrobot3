# S3 单板 W6 全链真件会话（2026-11-20）

## 1 现场与拓扑

- 板：ESP32-S3 N16R8（16MB Flash / 8MB Octal PSRAM），ESP-IDF v5.2.2，
  esp-idf-hal 0.44.1，`espidf` std 单进程六任务固件。
- 供电：外部 5V/3A 插座单独供电；USB 只作串口数据线（同接外部 5V 时见 §7）。
- 功放：HENOPI-98357（MAX98357A 类单声道 I2S）@5V，SD 接 3V3 使能。

| 面 | 接线 |
|---|---|
| 云台 pan / tilt | LEDC GPIO4 / GPIO5 |
| OLED | I2C0 SDA8 / SCL9，0x3C |
| 双麦 I2S0 | BCLK6 / WS7 / SD15，16kHz 32bit stereo，L/R 时隙 |
| 功放 I2S1 | BCLK16 / LRC17 / DIN18 |
| 调试串口 | UART2 41/42，1.5M |

## 2 内存与起链

`sdkconfig.defaults` 曾因 `ESP_IDF_SDKCONFIG_DEFAULTS` 未接线而**从未被
esp-idf-sys 读取**：真板 `heap_init` 无 SPIRAM 行，dialog 独立线程与语音缓冲把内部
堆压到 18KB，`httpd` 分配失败（`esp_err=0xB008` = `ESP_ERR_HTTPD_ALLOC_MEM`）。接线后同板：

```text
PSRAM total=8388608B free=8385688B
RAM 点（int_free）：boot 312063B → mic ≈124KB → 播放面 ≈96–101KB
```

SNTP 线程 30s 后退出再回补约 16KB。六任务（net / audio-in / dialog / audio-out /
motion / ui）全 running；httpd 白名单 11 端点（含 `/api/board/dialog`、
`/api/board/oled`）。VAD 域底噪 `mono_rms≈370–400`，起音阈值定为 500。

## 3 云三跳契约

- 同源部署：`base=https://api.siliconflow.cn`；`llm_base=https://api.siliconflow.cn/v1`。
- ASR `iic/SenseVoiceSmall`（multipart，model/language/file WAV）；
  LLM `deepseek-ai/DeepSeek-V3`（OpenAI 兼容）；TTS
  `FunAudioLLM/CosyVoice2-0.5B`，voice `FunAudioLLM/CosyVoice2-0.5B:bella`，
  `response_format=pcm` 16kHz。
- 每跳超时 8s、最多 2 次、间隔 500ms；key 只进 NVS，不落日志。
- TTS 回包上限 512KB；LLM 回复截到 180B（约 60 汉字）。

## 4 全链实证

HTTP WAV（`POST /api/board/dialog`）：

```text
ASR「你好，小二，请向左看。」→ 意图 pan 60→70 → LLM → TTS → 播放
tts_played 0→1，tts_fail=0
```

麦克风整链（Mac 近场放音）：

```text
DoA bin=left deg=-33 → pan=60
VAD onset（预滚 200ms）→ 语音段入队 6240ms
ASR「请向右看。」→ actions=1 → pan=110
reply「好的,我这就向右看啦!」
TTS 2677ms → [spk] 播放完成 pcm=85678B 实耗=2612ms 误差=2%
```

## 5 DoA 3×10（hold 标定模式）

`POST /api/board/oled {token,text,hold:true}` 保持 OLED 提示；hold 期间
`rr3_expr_set` 不覆盖提示，语音段只做 VAD/DoA 不进 dialog，避免云端往返与
回复声反馈污染下一轮。

| 站位 | 结果 | 实测角 | 备注 |
|---|---|---|---|
| 正左 90° | 10/10 | −33°～−47° | 落 pan=70 |
| 正前 | 10/10 | 0°～−10° | 零 left/right 混入 |
| 正右 90° | 10/10 | 34°～43° | 落 pan=110 |

**右转落 pan=120（机械行程上限）300s 内 13 次 BOD**；左 60 亦贴边偶发。DoA 落角
收进 **70/110**（与意图三档同值，留 10° 机械余量），方向分档不变。标定后
pan=110 连续动作 `restarts=0`。

## 6 30min soak

**方法**：Mac 侧脚本每 20s `POST /api/board/dialog` 一段 16kHz mono WAV，每 5s 采
`/api/board/health` 与 `/api/board/state`，连续 1800s；原始记录 342 行。

| 指标 | 读数 | 判读 |
|---|---|---|
| 时长 | 1800s（末样本 t=1798.4） | 覆盖完整窗 |
| POST | 86 轮，85 接受 | 1 次 `{"err":"云队列满","ok":false}`（t=1708.2） |
| TTS 播放 | 3→96（+93；收尾后 97） | 85 轮 POST + 8 次回复声触发麦克风轮次 |
| `tts_fail` | 0 | 无 TTS 失败 |
| `restarts` | 0 | 零复位、零 BOD |
| 六任务 | 全程 running | 无 non_running、无 unreachable |
| `sntp` | 全程 synced | 云调用无鉴权/连接前置失败 |
| `overruns` | 恒 1 | 采样窗内未增长 |
| pan 读数 | 60 / 70 / 110 | 全程无 120 |

唯一 `云队列满` 的成因：回复播放声被麦克风收进 VAD，额外生成一轮语音段，与
soak 的下一发 POST 撞上有界队列（容量 2）。属设计内背压，不是链路故障；该轮
POST 未接受但板端继续工作。前一截 11min / 31 次播放同样 0 失败 0 复位，与本窗
合计约 41min 连续运行。

## 7 功放与供电

- 接线复核后 1kHz 提示音与 TTS 两段均听到；`tts_played` 3/3，`tts_fail=0`。
- 外部 5V/3A 单独供电：12min+ / soak 全程稳定，`restarts=0`。
- USB 5V 与外部 5V 同时接入：启动/动作瞬间可能 BOD（随后恢复）。现场建议用
  只传数据的 USB 线，或临时断开外部 5V。

## 8 结论与余量

- **成立**：S3 单板云 ASR→LLM→TTS→本板播放全链、麦克风 VAD/DoA 分段、意图
  舵机/表情、DoA 3×10、30min soak、功放出声、外部 5V 单独供电稳定。
- **余量 ①**：SNTP 线程为一次性 30s 等待，失败后不重试；未同步时云调用出现
  `open err=28674`（ESP_ERR_HTTP_CONNECT），重启后 `sntp=synced` 即恢复。可改为
  持续重试或 dialog 前显式检查。
- **余量 ②**：`profiles/esp32s3-solo.toml` 的 registry 形状未定（六任务单体固件，
  槽位绑定不等于 rrd 派生模块），留待 W8 产线批裁定；装配真值暂以
  `board/pins_s3.rs` + `sdkconfig.defaults*` 为单点。
- **余量 ③**：本档为单板自跑口径；逐跳矩阵的"3 轮"由 HTTP WAV 1 轮 + 麦克风
  整链 1 轮 + soak 86 轮构成，真实人声长句未单独加测。
