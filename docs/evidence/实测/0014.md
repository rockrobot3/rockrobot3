# ESP32 classic W7 内存实测（2026-11-21）

## 1 现场

| 项 | 值 |
|---|---|
| 芯片 | ESP32 classic rev v3.1，双核 240MHz，4MB Flash，无 PSRAM |
| MAC | `48:9d:31:01:16:d4` |
| 固件 | 应用编译时间 `Nov 20 2026 02:25:30`，ESP-IDF v5.2.2；日志含 `[autonomy]`、`[spk]` 播放面，`dialog degraded` |
| 接线 | USB 串口 `/dev/cu.usbserial-1420`；I2S0 双麦、I2S1 播放面、OLED、LEDC 均在起链日志中 |
| 采集 | `espflash monitor` 硬复位，60s 连续抓取；期间未发送任何命令 |

## 2 堆账读数

同一固件连续 12 次 boot，RAM point 读数如下（`free` 为 `esp_get_free_heap_size`）：

| 点位 | 读数 | 判读 |
|---|---|---|
| `1-boot` | **273,072B** | 内部分配可用基线 |
| `2-periph-ready` | **249,012B** | UART2/I2C/OLED/LEDC 就绪后 |
| `3-mic-smoke` | **62,844～62,860B** | I2S0 双麦与音频上行起后 |
| `4-spk-play` | **15,608～32,920B**（主体 **22,152B**） | 播放面起后；两次出现 `[spk] 起播放线程失败: OutOfMemory`，读数 15,608B / 32,920B |
| 配置腿 | `esp_err=45064`（`0xB008`） | httpd 起栈失败；9/12 次 boot 可见 |

播放面后主体余量 **22,152B = 520KB SRAM 的 4.2%**，距 W7 的 20%（约 104KB）差约 5 倍。

## 3 复位环根因

60s 内出现 **11 次 `rst:0xc (SW_CPU_RESET)`**。日志末尾可见：

```text
[periph] 配置腿启动失败 esp_err=45064（缺席照常；负值＝IDF 错误码）
[autonomy] 心跳超时 task=net（已标 dead；连续 2 拍不恢复即整机复位）
rst:0xc (SW_CPU_RESET),boot:0x17 (SPI_FAST_FLASH_BOOT)
```

根因是 `net` 心跳线程在 [`start_httpd`](../../../tools/esp32-periph-base/src/httpd/serve/start.rs)
里位于 `httpd_register` **之后**：classic 上 httpd 因 45,064B 栈需求 OOM，函数提前返回，
`net_watch_spawn` 永不执行；监督壳把 `net` 判死并整机复位，形成约 5s 一周期的复位环。

源码修复 `60381a0e`：`wifi_bringup` 成功后立即起 `net_watch_spawn`，再起 httpd。
HTTP 是配置面，不是网络在位的判据；httpd 失败仍照常点名，但不再触发 net 判死。

## 4 结论与余量

- **成立**：classic 真板可起 WiFi/I2S0 双麦/I2S1 播放/OLED/LEDC；双麦 L/R RMS
  约 34k、`L==R 0%`；堆账读数可重复（12 次 boot 同值）。
- **No-Go（当前实现）**：播放面后仅约 22KB，httpd 需 45KB；ASR 8s 段 512KB、
  TTS 回包 512KB、播放队列最多约 1MB（见计划册 §20.2）均无法落内部 SRAM。
- **未验证**：修复后的固件未重烧——本轮未在本地构建（项目铁律），CI 制品下载需
  GitHub 凭据；修复版真板 30min soak 与 `[mem]` 阶段列待下次上板窗口。
- **存储/流式候选**：本轮未测；需按计划册 §20.2 的三处改造（ASR 存储分块上行、
  TTS 边收边播、全链档不启 httpd）后再判，不把“候选”写成 Go。
