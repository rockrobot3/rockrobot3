## 2 双麦独立性（互相关，决定性）

对 `/tmp/yd48.wav`（`hw:4,0` 原生 48k 2ch，后 3 秒人声）做 2 秒窗互相关：

| 指标 | 值 |
|---|---|
| 语音段 RMS | L 1157.1 / R 307.8 |
| 最佳互相关 | **0.8761** |
| 最佳时延 | **+13 样本 @48k = 0.271 ms** |
| 零时延相关 | 0.2047 |
| 反演路径差 | 0.271 ms × 343 m/s ≈ **93 mm** |

判读：两路是**独立间隔麦**（非复制、非降噪混音），左右轴存在真实时延。
此前 `mic_baseline_mm=70` 在 16k 下 `lag_max=round(16000×70/343000)=3`，
真实时延 4.34 样本落在搜索窗外，TDOA 峰被截断 → 左右混判。**不是阵列坏**。

## 4 舵机与 DoA→pan

- **PWM 直驱**：停 rrd 后手动 `period=20 ms`、`duty=2.0 ms`，舵机明显转动
  → 信号/UBEC/共地/机械链路通。
- **act 直调**：总线调 `rr3-act/servo/command {"axis":"pan","angle_deg":110}`
  回 `{"angle_deg":110,"move_ms":800}`，PWM 落 **1,722,222 ns**。
- **根因**：`rr3-sense` 反射环向 `rr3-act/servo/command` 发
  `{"pan": target}`，而 act 的 `rr3_servo_parse_args` 只认 `angle_deg`，
  以“缺 angle_deg”拒收；ESP32 桥走板侧命令旁路不经过这条总线，故只有
  Pi 宿主档静默失效。已改 `{"axis":"pan","angle_deg":target}`（`4a6b0e58`）。
- **部署复验（通过）**：因 musl 全静态与 ALSA 互斥，CI 的 aarch64-musl 包
  不带 alsa（启动即落 placeholder），音频件按 R13 走板上原生构建
  （`build-onboard.sh` 同路径：源码同步到 `~/rockrobot3-src`，`--features alsa`）。
  部署后 sense 日志 `反射环: 后端 linux`、`音频源就绪: backend=linux`。
  左侧说话 onset `doa=-23°` → 判停后 `pan=67°`，act 回 `angle=67 move_ms=800`，
  PWM 落 **1,244,444 ns**（0.5 ms + 67/180×2 ms），舵机左转肉眼确认。

## 5 观察器协议注记

恢复的退役 Python `bus.py` 与当前 rr-ipc 头有漂移：当前头在偏移 44 新增
CRC32（保留区 48..128），旧客户端把 CRC 当保留污染拒帧。临时件已改
`OFF_CRC32=44 / OFF_RESERVED=48 / LEN_RESERVED=80` 后可注册并收事件；
该 Python 客户端只作现场观察，不进产品码。

### 6.2 第一次三轮失败：心跳被自己的 inbox 判死

现网第一次三轮（修参数前）brain 连续三任 task 7→8→9，rrd 日志：

```
广播积压丢帧 rr3-brain：收件队列满（128 帧上界），已丢 65 帧
rr3-brain 连接断开（干净收尾）→ watchdog 判死（距上次心跳 10025ms ≥ 10000ms）
```

链条：ASR 超时重试（8 s×2 = 16.8 s）期间 brain 主循环阻塞 → 收件箱在
~2.5 s 内被 `rr3-sense/audio/pcm` 填满（当时线上 PCM 以 **Event** 帧发布）→
reader 线程卡在 `send` → 心跳应答读不到 → 连续 3 拍 5 s 超时 → 模块按纪律退出。
同一根因在 rrd 侧表现为广播积压丢帧，同一故障记了两遍。

第一次修（`2cee042a`）只对 **Stream** 类型帧丢帧；但 rrd 当前只放行 Event 上行，
PCM/TTS/servo 实际全是 Event，补丁匹配不到，复测仍死。

### 6.3 根修（`5e4d8236` + `bab138fd`）

总线对 Event 的契约本来就是**尽力投递**（rrd 的 fanout 满队列同样只丢帧、不断连），
客户端把尽力投递升级成阻塞回压才是根因。修法：

- inbox 改无界通道 + `inbox_len` 水位（reader 入箱前 +1、`rr3_poll*` 取走 −1）；
- 满 256 帧时 **Event/Stream 只丢帧并记 `inbox_backlog_drop`**；
- Request/Notification 一律入箱（控制面不丢），reader 永不停在 `send` 上；
- 回归测试灌 320 帧 Event（线上真实类型），断言丢帧计数且心跳持续可应答。

实测回执：三轮后 `inbox_backlog_drop` brain=568、interact=212——新策略确实在
长动作期间丢事件面广播，而模块零重启、心跳峰 2002 ms。

  **云 ASR→LLM→TTS 三轮**（6 话轮全成，计数各 +6）。
- **根修**：总线客户端 inbox 满侧阻塞回压（长动作 → 心跳自杀）；音频件按 R13
  板上原生构建（musl 全静态与 ALSA 互斥，CI musl 包不带 alsa）。
- **进行中**：30 min soak（1800 s，五模块 health/counters 轮询）。
- **余量**：ASR 8 s 契约在长句/弱网下偏紧（本轮出现过 16.8 s 超时；修后同一
