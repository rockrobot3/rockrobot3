## 2 ① 控制台根修

### 2.1 决定性诊断

同一固件、同一 CH340 口，仅改变采集方式：

| 采集方式 | 观察 |
|---|---|
| 裸 `cat` / `stty`（DTR/RTS 保持打开时默认态） | ROM 日志可读，随后为噪声；应用行计数为 0 |
| `console-log.py`（显式清 DTR/RTS） | ROM → bootloader → app 全链可读，应用行全部在册 |

关键旁证：清两线的瞬间芯片会从复位释放并重新走一遍 `rst:0x1 (POWERON)` 启动；
即打开串口这一动作本身就能改变 EN/GPIO0 电平。现场此前据此误判成"固件控制台
配错"，实际是工装把芯片按在了复位/下载态。

### 2.2 固件侧修复（保留）

即便直接根因在工装，固件仍把配置显式化，避免 IDF 缺省随版本漂移：

- `sdkconfig.defaults`：`CONFIG_ESP_CONSOLE_UART_DEFAULT=y` +
  `CONFIG_ESP_CONSOLE_UART_BAUDRATE=115200`。
- `sdkconfig.defaults.esp32s3`：同两项再钉一遍（目标档后载覆盖），并显式
  `CONFIG_ESP_CONSOLE_SECONDARY_NONE=y`、`# CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG
  is not set`——日志只走 UART0，不在两个 USB 口分叉。

## 3 ② WiFi 软重启回连

### 3.1 根因与修复

- 旧路径只在 boot / 配网时 `esp_wifi_connect()` 一次，失败即让整条配置腿失败；
  APSTA 下 SoftAP 常开又让 net 心跳判据（STA 或 AP 有 IP）恒真，掩盖 STA 掉线
  ——软重启后首次关联失败就永久停在 SoftAP。
- 修复：首次 connect 失败只点名、不返回 Err；`wifi-sup` 线程 1s 轮询 STA netif
  是否取得 DHCP IP，掉线按 2/4/8/15/30s 退避重连；写口配网事务期间让路
  （`WIFI_TXN`），AP-only 档配网成功后补起监督线程。

### 3.2 复验时间线（串口 + HTTP 双证）

| 阶段 | 证据 |
|---|---|
| 重启前 | `GET /api/board/health` 200，`restarts=0`，六任务 running |
| 触发 | `POST /api/board/reboot` 返回 curl 56（TCP 被复位，符合 `esp_restart` 立即断开） |
| 复位原因 | `rst:0xc (RTC_SW_CPU_RST)`——软复位，非硬复位 |
| +1.7s | `DHCP server started on interface WIFI_AP_DEF with IP: 192.168.4.1` |
| +2.8s | `esp_netif_handlers: sta ip: 192.168.0.172, gw: 192.168.0.1` |
| +2.8s | `[periph] wifi-sup: STA 在线（DHCP 已得 IP）` |
| +3s | `GET /api/board/health` 200，`sntp=unknown`（新实例）、六任务 running |

STA 取得与重启前相同的地址，不需要硬复位或重新配网。

### 3.3 覆盖范围与余量

- 本轮覆盖：现场原始症状"软重启后落 SoftAP 不回连"——已消除。
- 未覆盖：首次 connect 失败 → 监督退避重连的真实失败分支。本轮日志无
  `STA 首次 connect esp_err=` 行，说明首次即成功；该分支需可复现的关联失败
  条件（如 AP 侧拒绝/信号窗）才能压测，暂以码面 + 单测口径登记。

## 4 观测面收口（同批落树）

- `build.rs` 从 `sdkconfig.defaults[.<mcu>]` 抽控制台波特率注入
  `RR3_CONSOLE_BAUD`；boot 横幅新增
  `console=uart0@115200 secondary=none（读到本行即日志口正确）`——本行本身经
  UART0 输出，"读到即自证"，杜绝下次把工装问题误判成固件问题。
- `tools/deploy/console-log.py`：raw 8N1 + 显式清 DTR/RTS + 收尾可打印率自检；
  低可打印率直接点名核对 baud 与自证行。
