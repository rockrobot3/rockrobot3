# Pi↔ESP32 classic 三线探针真机证据（窗口 C，v0.0.21 safe）

## 1 环境与接线

| 项 | 值 |
|---|---|
| 板端 | ESP32 classic 4MB rev v3.1，`v0.0.21` safe 固件（[0023](0023.md)） |
| 宿主机 | Pi 4B Rev 1.5，kernel `6.12.47+rpt-rpi-v8`，Python 3.13.5 |
| 接线 | Pi pin8(GPIO14/TX)→ESP32 GPIO19(RX)；Pi pin10(GPIO15/RX)→ESP32 GPIO18(TX)；pin6↔GND；两板各自供电 |
| 串口 | `/dev/ttyAMA0`，1.5M 8N1；`serial-getty@ttyAMA0` inactive |
| 探针 | 仓内 HEAD 同步到 Pi `/tmp/rr3-probe`；`probe_common.py` sha256 `b5bb19ba81ef0715…` |
| 服务 | 探针前后 `rrd` stop/start，收尾 `rrd=active` |

接线完成后链路探测：发送 `HELP\n` 2s 收到 482B，首行 `CMDS: OLED <text> | FACE … | PAN <deg> | …`。

## 2 带宽与线面（bw_probe 60s）

```
[1] READY: (未见 READY 横幅)
[2] HELP: OK
[3] 突发 120xPAN: OK=116/120 ERR=2
[4] 音频 60.0s: 5300917 B (86.3 KB/s) 帧=475 撕裂=0 CRC不符=0
    帧间: 行面文本=27B ｜ 乱码=0B（无段级误码）
    seq 断档=0 首=0 末=474；PCM 长度 min/max/均=8192/8192/8192（期望 8192）
```

- READY 横幅未见属预期：板已启动多轮，READY 是开机一次性横幅；`HELP` 有 `CMDS` 回包即链路成立。
- 音频 475 帧 × 8192B = 3,891,200B PCM，加帧头/编码后 5,300,917B；60s 均速 86.3 KB/s。
- 判据四项全 0：撕裂 0、CRC 不符 0、seq 断档 0、乱码 0B。

## 4 120xPAN 突发的 2 条 ERR（归因）

复现单发 120 条无间隔 `PAN 90\n`，回包 `OK=115 ERR=2`，两条 ERR 原文：

```
ERR unknown cmd "N"（HELP 看指令表）
ERR 角度超范围 0-180: 9090
```

- 前者是行首字节被啃（`PAN`→`N`），后者是两条命令粘连成 `9090`；同属**无间隔连发**下的行边界丢失，不是业务拒绝。
- 与历史结论一致：纯命令常规节奏 600/600、ERR=0；只有突发无间隔才出现少量此类碎片，且都被命令面双防线拦住（不误动舵机）。
- 本窗口判据不依赖该突发计数；如实记录 115/120，不写成 120/120。

## 7 零间隔突发对照（2026-11-25 补测）

同一固件、同一 1.5M 三线，只改命令发送间隔，每档 120 条 `PAN 90\n`：

| 间隔 | OK | ERR | 收包字节 |
|---|---:|---:|---:|
| 0 ms（背靠背） | 95/120 | 3 | 1178 |
| 1 ms | 120/120 | 0 | 1320 |
| 5 ms | 120/120 | 0 | 1320 |

- 结论：行边界丢失只在**零间隔背靠背**时出现；≥1 ms 间隔即 120/120、零误码。
  说明链路与固件行解析在正常命令节奏下无误码，问题域是"无 pacing 的洪泛"。
- 风险面：洪泛下坏行被命令面双防线拒绝（`unknown cmd` / 角度越界），未观察到
  误动舵机；真实宿主（rrd / 探针）不会以零间隔发命令行。
- 本项不引入固件改动；如后续出现零间隔生产者，先在生产者侧加 pacing，再评估
  板上 RX 环/事件队列扩容（需制品窗口与真板复验）。
