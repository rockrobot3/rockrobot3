# ADR-0002：模块模型 —— 5+1 域划分与进程级隔离

- **状态**：已接受；**`rr3-act` 的实际注册面已被 [`contracts/topics.toml`](../../../contracts/topics.toml) 收口为舵机/电机**（下表"继电器"与 `rr3-act/relay/*` 均未登记，使用前须按"契约只增不改"先 APPEND 主题；对账见 [architecture.md](../../architecture/architecture.md) §6.3）
- **日期**：2026-09-28
- **关联**：[architecture.md](../../architecture/architecture.md) · [naming.md](../naming.md)

## 背景

`legacy/core/` 以 ESP-IDF 组件形式组织（编译期链接，无进程隔离），一次崩溃全机重启；且模块边界随功能增长逐渐模糊。新平台（Linux 多进程）需要重新定义模块模型，并面向未来具身机器人演进。

## 决策

### 1. 五域 + 大脑

| 模块 | 职责 | 主要硬件/系统面 |
|---|---|---|
| rr3-sense | 感知：采集、VAD、未来更多传感器 | ALSA、I2C/SPI |
| rr3-act | 执行：继电器、未来运动控制 | gpiod、PWM |
| rr3-interact | 交互：语音播放、Web 面板、未来屏幕表情 | ALSA、HTTP |
| rr3-power | 能源：电池/充电监测、功耗策略 | PMIC/ADC |
| rr3-connect | 连接：WiFi、蓝牙、未来星闪/以太网 | NetworkManager、BlueZ |
| rr3-brain | 决策大脑：对话策略、云端 ASR/LLM/TTS、未来多模态 | Python 进程 |

划分原则：**sense/act/interact/power/connect 四域面向"身体"可平行扩展，brain 独立演进面向"智能"**；未来具身化时增加的感知/执行能力归入对应域，不新增顶层域。

### 2. 进程隔离

- 每模块 = 独立进程 = 独立崩溃域；崩溃按 restart_policy 由 rrd 处理
- 模块间零直连：一切交互经事件总线/RPC（ADR-0003）
- 模块只声明/依赖**能力名**（capabilities），不依赖具体模块名 —— 泛化核心
- brain 是唯一编排者，对话策略只存在于 rr3-brain（承接 legacy"薄壳"哲学）

### 3. 横切关注点不进模块

安全（急停/限位/低电保护）、日志、时间同步、OTA 全部在基座（base/），基座存活则安全兜底存活。

### 4. manifest 四件套

每模块固定结构：`module.toml`（身份/能力/事件/资源/健康）+ `config.toml`（运行参数）+ `src/` + `README.md`；schema 见 [architecture.md §4.1](../../architecture/architecture.md)。

## 备选方案否决理由

- **单进程多线程**：无崩溃隔离，与基座"day-one 抗崩溃"目标冲突
- **容器级隔离（每模块一容器）**：0.5L 设备资源余量小，进程级已够，容器后置
- **更多顶层域（如 ui 单独成域）**：域过多削弱"目录名=crate=进程=IPC前缀"四合一收益，屏幕表情等归 interact

## 后果

- 正面：崩溃隔离、按域分工并行开发、能力依赖仲裁支持模块替换
- 负面：跨进程通信延迟（µs~ms 级，对语音闭环可忽略）、多进程内存占用需在 config 中设 mem_limit_mb
