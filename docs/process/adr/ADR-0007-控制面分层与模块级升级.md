# ADR-0007：控制面三级分层与模块级升级双轨

- **状态**：已接受
- **日期**：2026-09-28
- **关联**：[architecture.md §7](../../architecture/architecture.md) · [ADR-0006](ADR-0006-采用AiryIPC线格式与rr-ipc分层.md) · [ADR-0002](ADR-0002-模块模型-5加1-进程隔离.md)

## 背景

通用化评估的两处硬欠账：① 当前 HAL traits 均为慢速事件级，运动控制（1kHz 闭环、关节力矩、IMU 融合）无承载方案；② 只有整镜像 A/B OTA，与"模块化"承诺矛盾——更新单个模块需整机升级。

## 决策一：控制面三级分层

| 层 | 频率 | 承载 | 典型内容 |
|---|---|---|---|
| 反射环（进程内） | 1k–10kHz | **不进总线**：act 进程内本地闭环 | 电机 FOC/PID、平衡控制 |
| 实时控制面 | 100Hz–1kHz | A-IPC over 共享内存 + `F_ZEROCOPY`/`F_URGENT`（ADR-0006 格式不变，仅换 transport） | 关节状态上报、力矩指令、音频 PCM 流 |
| 事务面 | <100Hz | A-IPC over UDS + JSON-RPC | 事件、RPC、对话、配置 |

裁定：

1. **反射环永远不出进程**——安全闭环不依赖任何总线（含共享内存），与"安全兜底在基座"原则同构
2. 总线只承载**指令与状态摘要**，不承载闭环本身
3. `trait Transport` 签名现在按零拷贝设计（buffer 所有权移交语义），shm 实现后置到 M5
4. legacy 的"PCM 不走事件总线"结论（ADR-0003）并入本决策：音频流归实时控制面 STREAM 类型

## 决策二：模块级升级双轨

| 轨道 | 对象 | 机制 |
|---|---|---|
| 整镜像 A/B OTA（M6） | base/os/内核 | slot 切换 + 断电安全 + 坏 slot 自动回滚（原方案不变） |
| 模块级更新（后置，布局先留） | modules/ 单模块 | 下载 → staging 分区 → manifest 兼容校验 → 原子 rename → 单模块重启 → 健康检查；失败自动回滚 staging |

模块级更新前置条件：

1. **契约演进规则**（contracts/ 事件负载 schema）：只增不改；破坏性变更必须升 major 并登记 topics.toml；rrd 启动时按 semver 做兼容校验（v0.0.1 现状：只增不改与前缀归属由 CI 契约测试强制；semver 兼容校验属 M1/M2 待实现）
2. **分区布局**：genimage.cfg 现在即预留独立可写模块分区，模块文件不与只读根文件系统混布
3. manifest 增补 `upgrades` 字段（semver 约束 + staging 校验开关）——字段随 schema v1 就位，实现后置

## 备选方案否决理由

- **运动控制走 UDS/JSON**：1kHz 闭环 × JSON 序列化，延迟与 CPU 不可接受
- **反射环也上总线（含 shm）**：引入总线单点故障到安全路径，违背兜底原则
- **只做整镜像 OTA**：模块组合因机而异，整镜像模式无法支撑按模块演进
- **容器/包管理器（ipk）做模块升级**：依赖 Buildroot 包体系过深，且无 manifest 级兼容校验点

## 后果

- 正面：具身化路线打通（act 域扩展无架构变更）；模块演进与整机解耦；安全路径与通信路径解耦
- 负面：shm 传输与 staging 流程属新增实现量（分别后置 M5/M6+）；契约演进规则要求 contracts/ 变更纪律
- 校验项：M2 的 IPC-T 选测覆盖 STREAM 有序（IPC-T-006）为控制面前置
