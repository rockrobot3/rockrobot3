# ADR-0015：板卡策略 —— RK3566 锚定 + 核心板过桥 + 量产自定制

- **状态**：已接受（本 ADR 只裁**板卡形态与硬件路线**，不改 ADR-0001 的 SoC/内核裁定、
  不改 ADR-0013 的 OS 双轨裁定；把"自绘板后置"细化为可执行的三步走，并钉死三条
  进 BOM 的硬件设计约束。实体落点：`base/os/` 与后续 `hardware/`，实况归 status.md）
- **日期**：2026-10-03
- **关联**：[ADR-0001](ADR-0001-平台选型-linux66-buildroot-rk3566.md)（SoC=RK3566、内核 6.6 mainline、maskrom 自烧录硬性目标）· [ADR-0013](ADR-0013-OS双轨-发行版快路与Buildroot保底.md)（板卡差异隔离在 Layer 0，payload 轨无关）· [ADR-0007](ADR-0007-控制面分层与模块级升级.md)（音频闭环延迟约束压在外置 codec 上）· [ADR-0012](ADR-0012-能力格坐标系与装配单.md)（`audio.capture`/`act.servo` 等格位的物理落地）· [architecture.md](../../architecture/architecture.md) §1/§5

## 背景

rock3 要落在瑞芯微 SoC 上，但市售成品板（Radxa ZERO 3 等）**尺寸与接口都不合 0.5L
桌面机器人形态**，且单件价（220–330 元）压不进目标成本。项目需要一条既能支撑
M0–M6 开发、又能在量产时把整板 BOM 收敛到 **150 元以内**的板卡路线。

三条硬约束互相拉扯，决定了可选空间极窄：

1. **mainline 内核**（ADR-0001）：不使用 vendor SDK——直接排除只有 vendor 支持的芯片；
2. **待机 <1W**（ADR-0001 硬性目标）：排除高功耗旗舰，且对充电 IC 静态电流与断电路径提设计要求；
3. **整板 BOM ≤150 元**（本轮新增目标）：排除 RK3568/3576/3588S，且要求降本手段落在板卡形态而非芯片降级。

## 决策

### 裁定 1：SoC 维持 RK3566 锚定（不改 ADR-0001）

RK3566 是**唯一同时满足三条硬约束**的瑞芯微芯片：4×A55 够跑 rrd + 五模块 + brain
（对话策略在云端 LLM 时 CPU 只是转发层）、1T NPU 够本地 wake word + VAD、mainline
支持最成熟（5.17 起在主线）、量产芯片价 50–65 元。**降本动作全部落在板卡形态（裁定 2）
与采购量，不动 SoC 选型。**

选型矩阵（2026-10 行情，量产档，供复查对账）：

| SoC | 判定 | 一句话理由 |
|---|---|---|
| RV1103/1106 · RK3308 · RK3506 | ❌ 主控 | RAM ≤512MB，装不下底座 + Python brain；A7 跑 JSON-RPC 总线吃力 |
| **RK3562** | ⚠️ 降本候选 | 芯片省 15–25 元，但**无 mainline、仅 vendor SDK**，与 ADR-0001 冲突（裁定 4 半年复查） |
| **RK3566** | ✅ 锚定 | 三约束全满足的唯一芯片 |
| RK3568 | ❌ | 多出的双网口/PCIe 桌面机器人用不上，白花钱 |
| RK3576 | ❌ 首版 | 超预算约 3 倍，留作二代本地 LLM 形态 |
| RK3588S | ❌ | 功耗/价格双超，被动散热困难 |

### 裁定 2：三步走板卡路线（把"自绘板后置"细化）

| 阶段 | 板卡形态 | 触发条件 | 目的 |
|---|---|---|---|
| **① 开发期（M0–M6）** | 成品板 Radxa ZERO 3 | 现状 | 软件对"哪块 RK3566 板"无感（ADR-0013 轨无关 + ADR-0012 格位坐标系），开发投入零浪费 |
| **② 过桥（形态验证 → 小批试产）** | **RK3566 核心板 + 自绘底板** | 需要合身 0.5L 形态、连接器按机器人重排时 | 核心板背书 DDR/eMMC/PMIC 高速设计；底板全低速信号，一版过概率高；总量逼近 150 元 |
| **③ 量产（出货量 >500 台）** | 全自研 SBC | 核心板谈到批量价、设计意图已在②全部验证 | 省核心板封装溢价 20–40 元，BOM 收敛进 150 元 |

**过桥是本 ADR 的核心裁定**：它同时解决"大小不合适"（底板按 0.5L 腔体画）与
"价格不合适"（避开全自研的 DDR 布线/PMIC 电源树 NRE 与改版风险）。全自研（③）
在量产前**不作为默认路线**——DDR 布线、RK809 电源树须基于瑞芯微官方参考设计改，
需硬件工程师信号完整性复核。

### 裁定 3：三条进 BOM 的硬件设计约束（fail-closed，缺一不选核心板）

1. **maskrom 自烧录可达**（承接 ADR-0001 硬性目标）：底板必须把核心板 USB OTG 引到
   USB-C，Recovery/遮蔽键布局可达。**这是选核心板时的必查引脚项**——部分厂核心板
   不引出 maskrom/eMMC 数据线，一旦漏引，自烧录目标在该板上永久落空。
2. **待机 <1W 断电路径**：底板设计"整板断电"路径（电量计 + PMOS 把核心板完全断电，
   只留 RTC 级功耗）；充电 Boost IC 须选低静态电流（Iq）方案——满载效率好的通用 IC
   待机 Iq 偏大，直接吃掉 1W 预算。核心板侧依赖内核 suspend 电源域配置（M1 敞口）。
3. **A/B OTA 需 ≥8GB eMMC**：slotA/slotB/factory + data 的分区布局（base/ota）要求
   双倍系统分区，8GB 是下限——**核心板选型不得为省钱选 4GB**。

### 裁定 4：降本与协处理器的两条后置评估（不进首版 BOM）

- **RK3562**：每半年复查一次其 mainline 化进度（与 ADR-0001 复查 Airymax distro 同节奏）。
  仅当进入内核主线、且省下的芯片差价足以覆盖移植成本时，才评估替换 RK3566；
  在此之前**接受 vendor SDK 不是选项**（ADR-0001 否决理由仍成立）。
- **RV1106 / RK3308 作协处理器**：若日后需把拾音/摄像从主控剥离（主控深睡待机时由小芯片
  守拾音唤醒，正好服务 <1W 目标），它们才有位置。**属架构预留，不进第一量产 BOM。**

## 明确不做（本轮裁定边界）

1. **不在本 ADR 定引脚表/原理图**：本 ADR 只裁板卡形态与三条硬约束；底板系统框图、
   引脚分配表、电源树、连接器定义属《板卡设计规格书》（`hardware/` 落点，随过桥阶段另立）。
2. **不改 ADR-0001 的 SoC/内核裁定**：本 ADR 是"自绘板后置"的细化，不推翻平台选型。
3. **不在 v0.0.1 引入协处理器**：见裁定 4，纯预留。
4. **不承诺 150 元在任何批量下可达**：小批量（~100 片）核心板+底板现实成本 195–260 元，
   150 元目标**仅在 1k+ 量、核心板谈到 100 元以内时成立**——此判断随询价钉死，不写死进代码。

## 备选方案否决理由

- **继续成品板到量产（不过桥）**：形态不合身、连接器不对机器人开放、单件价压不进 150 元。
- **直接全自研 SBC（跳过过桥）**：DDR 布线 + PMIC 电源树 NRE 高、改版风险集中在首版，
  与"最大程度减少开发量"（ADR-0013 精神）冲突——过桥把高速设计风险外包给核心板厂。
- **降级到 RK3562/RV1106 冲成本**：违反 ADR-0001 mainline 裁定（RK3562）或 RAM 不足以
  跑底座（RV1106），见裁定 1 选型矩阵。
- **上 RK3576 换算力**：首版超预算 3 倍，本地 LLM 非 v0.0.1 目标（对话策略在云端）。

## 后果

- 正面：板卡路线从"自绘板后置"一句变成可执行的三步走；150 元目标有了明确的达成条件
  （批量 + 核心板询价）而非口号；三条硬约束（maskrom/断电/A-B）钉进核心板选型门槛，
  避免"选了块烧不进/关不掉/OTA 不下"的核心板。
- 负面：过桥阶段引入核心板供应商依赖（引脚定义各家不同，maskrom 必查项需逐厂核对）；
  150 元目标在样机期不可达，需向整机成本核算明确区分"样机 BOM"与"量产 BOM"。
- 待钉死假设（询价后回填，不进本 ADR 正文）：① RK3566 核心板 1k+ 量报价
  （95–120 元为推算值，±30 元直接决定 150 元目标成败）；② RK809 内置 codec 的
  麦克风信噪比——**先在 ZERO 3 上实测 VAD 误触率再定是否外挂 ES8388**（ADR-0007
  音频闭环延迟与 ADR-0012 `audio.capture` 格位都压在这颗 codec 上）。
- 落点登记：本 ADR 为纯决策记录；`base/os/` 现有 Buildroot 资产（ADR-0001 保底轨）不删；
  过桥阶段的《板卡设计规格书》已起草于
  [docs/architecture/板卡设计规格书.md](../../architecture/板卡设计规格书.md)（草案 v0.1，
  含核心板核对单/电源树/引脚预算/验收计划；其 §12 开放项含舵机数量等待用户输入项）；
  `hardware/` 实物件（原理图/PCB 工程）落点随过桥项目启动另登（实况唯一归 status.md）。
