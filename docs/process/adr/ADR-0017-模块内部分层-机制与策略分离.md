## 背景

五个 Rust 模块（rr3-sense / rr3-act / rr3-interact / rr3-power / rr3-connect）的
`main.rs` 均为"上帝文件"：以 rr3-act 为样板，`rr3_run()`（L55-213）一个函数集齐
SURFACE 启动自述（L56-66）、manifest 读取与总线接入（L69-88）、HAL 探活
（L90-98）、`rr3.call` RPC 分发（L124-177）、广播订阅分发（L182-210）五类职责；
rr3-sense（探活+音频打开+采集循环+点名应答）、rr3-connect（链路拍+四 RPC 分发）、
rr3-power（采样循环+阈值判定）、rr3-interact（表情驱动+RPC 分发）同构——各模块
文件头注释自证"启动序列与 xx 同构"。

同构即重复：五份"连总线→注册→心跳→收事件→分发→传输性失败 exit(1)"循环各自
手写一份，机制（总线接入、探活、分发骨架）与策略（各模块业务规则）在同一文件里
无界线混排。architecture.md 早已立原则"模块只含机制，装配归装配单、策略归 brain、
提供者选择归 rrd 仲裁"，但该原则只约束了**模块间**职责划分，未落到模块**内部**
结构。后果有三：

1. **骨架漂移风险**：五份手写循环，任何一处总线语义修订（如心跳节奏、inbox 排空
   时机）要改五处，漏一处即行为分叉；
2. **策略渗入模块**：业务规则散在 main.rs 的 match 臂里，与机制无界线，评审时
   无法一眼确认"策略没进模块"；
3. **brain 迁移阻力**：ADR-0016 的 0.0.8 迁移需要一个 Rust 侧模块骨架作为落点，
   现状无骨架可复用。

本 ADR 只落**设计裁定**（结构、API 面、拆分映射、验收判据），不写一行 `.rs`——
实施批归 0.0.8，与 brain 迁移一次到位。

## 决策

### 裁定 1：公共骨架 crate `rr3mod`，收敛五模块同构启动序列

新 crate 落 `base/runtime/rr3mod`（与 rr-bus / rr-hal 同层；依赖方向单向：
rr3mod → rr-bus + rr-hal + rr-ipc，反向零依赖）。收敛的序列就是五模块今天各自
手写的那一段：

```
读 RR3_MANIFEST 环境变量 → Rr3BusClient::rr3_connect（连接/注册/心跳，rr-bus 既有）
→ 读 config.toml → HAL 后端选择 + 探活（Unsupported 即 exit(1)）
→ 主循环 poll/poll_wait → inbox 分发 → 传输性失败 exit(1)
```

API 面（签名级，实施时以此为准）：

```text
rr3mod::bootstrap(Rr3ModConfig) -> Result<BusHandle, String>
rr3mod::serve(bus: BusHandle, dispatcher: Dispatcher) -> Result<(), String>
BusHandle：publish / subscribe / call 三个薄封装（透传 rr-bus client，不加语义）
Dispatcher：模块机制层实现的 trait（rpc_handler + event_handler 两个入口）
```

- **心跳不重复实现**：连接/注册/心跳已在 rr-bus `client.rs`（含喂狗失败退出语义），
  rr3mod 只编排不重写；
- **`RR3_MANIFEST_ENV` 常量收编**：现五模块各自本地定义（act L37 / sense L28 /
  connect L40），收进 rr3mod 单点；
- 备选"rr3mod 并入 rr-bus"弃——rr-bus 是传输/接入面，模块骨架是编排面，混在一起
  会让纯库使用方（如 tools 伴生件）背上不需要的 config/HAL 依赖。

### 裁定 2：模块内部分层标准

| 层 | 落点 | 职责 | 禁止 |
|---|---|---|---|
| 装配层 | `main.rs`，**≤80 行** | 调 bootstrap、注册 handler、调 serve；SURFACE 启动自述 | 任何业务逻辑 |
| 接入层 | `src/boot.rs` | manifest/config 读取、HAL 选择+探活（自各 main 迁出） | 业务 match |
| 协议层 | `src/rpc.rs` | `rr3.call` 点名应答分发（自各 main 的 RPC match 迁出） | 机制重实现 |
| 机制层 | 既有文件原位（servo/led/relay/reflex/intent、audio/*、wifi/session/bt、battery/charger、face/player/panel） | 硬件访问与模块语义实现 | 引装配/协议知识 |
| 策略层 | **不在模块内**（brain + 装配单 + config.toml 参数） | 业务规则 | —— |

**红线三条（缺一不收）**：

1. `module.toml` / exposes / subscribes / 装配单 bindings **零改动**（ADR-0012 语义
   不动，重构对装配面透明）；
2. rr-ipc / rr-bus / **线上字节零改动**（golden dump + envelope_meta 契约守护为证）；
3. 策略不进模块（architecture.md 原则 4 字面执行）。

### 裁定 3：五模块拆分映射（逐模块逐段，实施批照此施工）

| 模块 | 现 main.rs 段落 | 迁出目标 |
|---|---|---|
| rr3-act | SURFACE 自述 L56-66 | 留 main（启动自述属装配面） |
| rr3-act | 总线接入+config L69-88；HAL 探活 L90-98；反射环线程宿主 | boot.rs + serve 装配段 |
| rr3-act | RPC 分发 L124-177 | rpc.rs |
| rr3-act | 订阅分发 L182-210 | intent.rs（执行器已在机制文件） |
| rr3-sense | 探活+音频打开 L60-71 | boot.rs |
| rr3-sense | 采集循环+发布 L79-95 | audio/capture.rs（循环函数化） |
| rr3-sense | inbox 排空+点名应答 L97-100 | rpc.rs |
| rr3-connect | 链路拍+状态发布 | link_loop（并入 session.rs） |
| rr3-connect | 四 RPC 分发（配网等） | rpc.rs |
| rr3-power | 电池/充电循环骨架 | rr3mod::serve 承接；机制留 battery.rs/charger.rs；阈值策略由 config.toml 参数驱动 |
| rr3-interact | 表情驱动+RPC 分发 | rpc.rs；face/player/panel 原位 |

- 每模块**独立提交**（一次提交一件事），实施顺序建议 rr3-power（最薄，验骨架）→
  rr3-connect → rr3-sense → rr3-interact → rr3-act（最厚，收尾）；
- 行号为 2026-10-06 实况锚点（HEAD `ebd4a4c` 一线），实施批开工时以当时代码为准，
  本表锚定的是**段落职责**不是行号。

### 裁定 4：brain 衔接位

本轮不纳入（ADR-0014 逐语义镜像纪律继续生效）。0.0.8 迁移时 brain crate 直接采用
rr3mod（`bootstrap + serve + Dispatcher` 同款），`bus.py` 镜像件随首件迁移退役。
rr3mod API 设计**不引 Python 侧不可用的依赖**（如不要求 Unix domain socket 之外的
平台特性——brain 现与 Rust 模块同走 UDS，无新增约束）。

### 裁定 5：实施批验收判据（0.0.8 重构批用，缺一不收）

1. conventions §2 口径 ①b 全绿（两平台实测条数如实登记）；
2. ④ 独立工程全绿（各模块 crate 独立构建）；
3. sim assemble 过（六模块装配编排不变）；
4. golden dump + envelope_meta 契约守护全绿（线上字节不变，红线 2 的机械证据）；
5. 各模块 SURFACE 启动自述输出**逐字不变**（装配面行为不变的观测面）；
6. 每模块独立提交，Conventional Commits 中文信息 + 本 ADR 引用。

## 后果

- 正面：骨架单点化消除五份重复循环的漂移面；策略/机制界线可评审；0.0.8 brain
  迁移有现成落点；
- 代价：0.0.8 引入一次模块形态手术（五模块 + 新 crate），与真件批严格不混排
  （R17 备选弃案理由）；rr3mod 成为 base 侧新公共件，其自身语义修订受五模块
  + brain 六个消费方约束；
- 不做清单：不改 rr-ipc/rr-bus 任何签名；不改装配单 schema；不给模块加"内部
  策略插槽"（策略归 brain 的原则不容第二真值点）。
