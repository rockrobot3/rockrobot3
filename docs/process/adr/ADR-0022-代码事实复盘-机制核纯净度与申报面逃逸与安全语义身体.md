## 背景：复盘暴露的不是"少做功能"，是**纲领在自己最严的地方漏了**

"机制与策略极致分离"这条纲领过去一直用来量**别人的模块**。这一轮把它量回基座、门禁与契约本身，
结果是六类违例，且**每一类都能给出可复核的符号**：

| # | 违例类型 | 已核实的代码事实（符号级） | 为什么这是主线违例 |
|---|---|---|---|
| V-1 | **机制核携带策略常数** | `rr-mech/src/control.rs` 的 `rr3_reflex_window_plan` 内 `250u64.min(cfg.saturate_notice_ms.max(1))`，并把 `(250, 2, 250)` 用 `assert_eq!` 钉成期望 | 窗粒度是**节拍策略**，不是判定机制。它写在 `#![no_std]` 零依赖叶子里，等于纲领最严的一层被自己破了一口；且 `[supplies]` 已有时序预算位，这个数**本该吃它** |
| V-2 | **契约/协议层携带部署事实** | `rr-ipc/src/transport/mod.rs` 的 `RR3_UDS_PATH_DEFAULT = "/var/run/rock3-ipc.sock"`、`transport/shm.rs` 的 `RR3_SHM_NAME_DEFAULT = "/rock3-ipc-shm"`，二者由 `rr-ipc/src/lib.rs` **无条件**再导出（连 `target_os = "none"` 也在）；`rr-hal-api` 的 `RR3_AUDIO_CFG_16K_MONO16` 注释自述"与 legacy ESP32 链路一致的默认拾音格式（16k/**单声道**/16bit）" | 套接字路径与共享内存名是**部署取向**（换 OS/换发行版就该变），不是协议；拾音缺省把"一个声道"写进跨形态契约，而现役板固件跑的是**双麦 2 通道**（`mic.rs`）——契约缺省与实机相反，换形态时缺省即错 |
| V-3 | **基座 crate 与一块具体板焊死** | `rr-ota/src/bootconf.rs` 与 `rr-ota/src/lib.rs` 各有一处 `include_str!("../../../../base/os/buildroot/board/radxa-zero3/…")`（extlinux.conf 与 genimage.cfg），A/B 槽标签靠它钉 | 守护意图（文件改名即编译失败）是对的，但做法让**基座 crate 不可移植**：换一块板就得改基座码。存在性守护应当指向"本形态的布局档"，而不是某块板的绝对路径 |
| V-4 | **申报面有逃逸通道，门只管"长得像申报的文件"** | `tools/espidf-sentinel/src/main.rs` 的 `MANIFEST_TEXT` 是**内联 Rust 字符串**，其 `[rpc] exposes` 含 `rr3-sentinel/diag/parity`；`grep diag/parity contracts/topics.toml` **零命中**——该主题**不在册**，而 `tools/rr3-sentinel-harness` 已在消费它。原因：`rr-registry/src/validate.rs` 的在册定位只作用在 `modules/*/module.toml` 上。另：`rrd/src/profile.rs` 的装配扫描只遍历 `atoms/*/assemble.toml`，**组合件层（`composite.toml`）在 base/runtime 内零消费者** | "申报即受校验"的前提是申报必须是**可解析的仓内文件**。一个 `include_str!`/内联常量就能绕过前缀归属与在册门——这不是漏配，是判据的作用域被文件类型定义了。**跨形态边界最危险**：恰恰是工具与哨兵这类"不入 modules/ 的件"最没人管 |
| V-5 | **安全语义有名字、没有身体** | `modules/rr3-act/config.toml` 注 `move_timeout_ms = 800 # 超时即停，不给堵转留机会`；实测该值的**唯一功能读者**是 `atoms/servo/mech.rs` 的 `rr3_servo_check_timeout`（缺省取上限 / 超限拒收），随后被回显进应答 `move_ms`；`src/composite.rs` 的 `rr3_handle_servo` 另有一行 println 自述"实机按时限走反射环闭环"，而 `src/reflex.rs` 环体只有 `sleep(period)` 节拍——**没有任何到时停轴路径** | 这与已结的 `cutoff_voltage_mv`（只解析不动作）同族，且更危险：它不是"诚实登记的未生效"，而是**注释与自述把它说成已生效**。纲领要求申报面 = 实现面；"保护性语义"没执行体就是没实现 |
| V-6 | **静默退化仍有条路，且纪律双标** | ① `rr-hal/src/backend.rs` 五处 `rr3_hal_backend_resolve().unwrap_or(RR3_BACKEND_PLACEHOLDER)` 把 resolve 的 `Err`（"取值不认…"文案）**丢弃不打印**——同仓 `rrd/src/probe.rs` 与批J G5 后的描述符路径都是"先 `eprintln!` 点名再落占位"，同一纪律两套做法；② esp32 档选择函数读的是环境变量并带缺省（`unwrap_or("pan")`、`unwrap_or(RR3_BRIDGE_BAUD)`=115200，而注记自认板固件已钉 921600）；③ `rr3-connect` 的 `rr3_wifi_scan_result` 恒回写 `"backend": "sim"` + `rr_hal::sim::rr3_sim_link_scan_list()` 三行假 AP 表，**与链路面实际后端无关** | ①②让"板 = 数据"在 esp32 支整体退化成"板 = 环境变量"，且写错配置无人知道；③ 是**能力缺失返回假数据而不是回错**——现场拿着不存在的热点表配网，比报错糟得多 |

另有两处**契约与运维面的结构空洞**（不是违例，是缺件）：
`rr-hal` 的 `rr3_hal_bindings_effective()`（描述符 × 应急 env 合成后的**生效**绑定）全仓唯一读者是 rr-hal 内部，
`rrd`/面板/`rrctl` 零调用 ⇒ "现场生效的是哪一份"不可查；日志环 `RR3_LOG_RING_CAP = 512` 是内存 `VecDeque`，
重启即失；失败"两本账"（缺码 + 工单号 / 无载体 + 触发条件）只活在 conventions 与 status 的散文里，
`counters` 是纯数字表、无 reason/ticket 字段。

还有一处**装配单与实机互相矛盾**（ADR-0021 裁定 1 的直接后果没人接）：`profiles/esp32-mini.toml`
头注与 `[slots].present` 写的是"三格微型形态、**无屏无喇叭**、不启用 `ui.face`"，而同一仓库里的
`tools/esp32-periph-base` 正在驱动 SSD1306（`oled.rs`）、双轴云台（`periph.rs`/`runtime.rs`）与双麦
（`mic.rs`）——**该形态自己的装配单否认自己有的东西**。

## 决策

### 裁定 1（Nn-1）：机制核可达面**零部署缺省、零产品字面量、零板路径**

四条可判红的断言（不是倡议）：

1. `rr-mech` / `rr-core` / `rr-ipc::protocol` / `rr-hal-api` 内**不得出现任何缺省数值型策略常数**：
   `rr3_reflex_window_plan` 的 `250u64` 改为吃 `[supplies]` 时序预算位（或显式入参 + 件侧 ops 槽），
   机制核只留"窗粒度 ≤ 通告周期"这条**关系**，不留那个数。
2. 机制核可达面**不得出现路径/名称型部署缺省**：`RR3_UDS_PATH_DEFAULT`、`RR3_SHM_NAME_DEFAULT` 下移到
   主承载层（`rrd`/打包/单元配置），`rr-ipc` 只留"路径由宿主提供"的参数位；对 `target_os = "none"`
   的可达面再导出时**只导出协议物**。
3. 机制核可达面**不得携带具体器件形态的缺省值**：`RR3_AUDIO_CFG_16K_MONO16` 保留为"一条具名格式"，
   但缺省权下移到描述符 `[hardware]`/件的 `ops`（本 ADR 同时解释它与实机双麦的冲突：
   契约缺省与现役固件相反）。
4. **基座 crate 不得 `include_str!` 某块板的布局文件**：`rr-ota` 的两处守护改为"由形态档给出布局文件路径"，
   守护用例仍在（存在性 + 标签逐字对账），但落点从"radxa-zero3 的绝对路径"改成"本形态的布局档"。

**为什么值得为它立 ADR**：这三处的共同点是"为了少写一处接线，把一次性的部署事实留在了永久的结构里"。
机制核是全项目唯一被承诺"跨档复用"的面，它一旦被部署事实污染，跨平台的**证明**就退化为跨平台的**宣称**。

### 裁定 2（Nn-2）：申报面必须是仓内可解析文件；门的作用域由"申报"定义，不由"目录"定义

1. **凡对外可见面（主题/RPC/发布订阅）必须来自可解析的仓内文件**，`include_str!("…文件")` 合法
   （仍落在文件上），**内联字符串常量非法**。`rr-registry` 的查册门随之扩面到 `tools/**`。
2. 即刻纠一处既成事实：`rr3-sentinel/diag/parity` **不在册**却在被消费 ⇒ 随批N1 二选一
   （入册为 `rr3-sentinel` owner 的 request 类主题，或撤申报）。哨兵行属 0.0.7 证据面，撤申报要同批改
   `tools/rr3-sentinel-harness` 的期望。
3. `rrd` 装配扫描**扩到组合件层**（`composite.toml` 的 `[assemble]` 面）：否则"住组合件的策略"
   制度性无主（既成实例：`modules/rr3-connect/src/composite.rs` 的 `pass.len() < 8`）。
   这条与 [ADR-0021](ADR-0021-三独立形态与资源供给面-能力原子化补课.md) 拟增的门 j 是同一件事，本 ADR 给它**判据**。
4. "每格一件"补**跨件唯一性**：今天 atom 级 `provides.slots == 1` 有门，但注册期两模块提供同格不冲突
   （providers 值域是集合，任一存活即算满足）⇒ 同格双件可静默并存，降级语义漂移。
   **【修订 1 撤回本条前提】**（2026-10-15 证伪审查轮，见全案 §18.8）：实测
   `rr-registry/src/atom.rs:530-536` 有仓扫描反查测试，`owner.insert(slot)` 命中即
   `panic!("格 {slot} 被两件抢占（每格一件，ADR-0019 裁定 1）")`，另有 `BUILTIN_NO_ATOM` 豁免集与
   `scanned >= 17` 打空断言 ⇒ **同格双件在测试期当场红，不是"静默并存"**。
   真正可达的位点是另一处，且此前被我写反了方向：`rrd/src/daemon.rs:357-369` 明写 providers
   "**含被拒模块**"（ADR-0009 有意设计：被拒模块仍计入可满足性宇宙，下游不连坐）⇒
   **能力可满足 ≠ 提供者真在跑**，缺的是可观测项而非唯一性门。按此改写本条（修订记录同处）。

### 裁定 3（Nn-3）：三形态各自要有**完整且自洽**的装配单；`[hardware]` 条件必填

1. `[hardware]` 由"整段可选"改判为**条件必填**：`[slots].present ∩ enabled_slots` 中任一格需要物理绑定
   （在册角色 `kind != logic`）⇒ 该段必填且键齐，否则拒 boot 并点名缺哪个键。今天它整段缺席只出现在
   esp32-mini 上，而这个形态恰恰外设最多——**"可选"是给 sim 用的，被当成了给板用的**。
2. `profiles/esp32-mini.toml` 必须**如实成为 ESP32 形态的自己的装配单**：补 `ui.face`（SSD1306）、
   `act.servo` 的两轴、`audio.capture` 双麦、`power.rail`（轨压），并补 `[pins]`/`[[supplies.domain]]`；
   与它的固件不一致的旧注释一并订正。**这是 ADR-0021 裁定 1"三形态独立"第一次落到 profile 层**。
3. `default.toml` 的 `[enabled_slots]` 里 `power.battery` 与"基础层不进本段"的自述冲突（一事实两处）
   ⇒ 随批N1 二选一改齐（建议：基础层不进记账段，注释为准）。

### 裁定 4（Nn-4）："当场可见"只有一种做法，五处 `unwrap_or` 静默落占位违规

`rr-hal/src/backend.rs` 五处 `rr3_hal_backend_resolve().unwrap_or(RR3_BACKEND_PLACEHOLDER)` 丢弃 `Err` 文案，
与同仓 probe/描述符的"先点名再降级"纪律相反。裁定：**任何降级/占位落点必须一次点名（stderr 或 counters）
后再返回占位**，且 `RR3_HAL_BACKEND` 取值不认属**配置错误**而非"未设"。
配套：esp32 支的 env 读法明写为**过渡态**（批N1 的 `[pins]` + role→具名构造表是它的终点），
过渡期内存缺省（`unwrap_or("pan")`、`unwrap_or(115200)`）不许出现在"档位会改变硬件行为"的键上——
波特率错配是**链路沉默**，不是可容错偏差。
另立一条**禁止假数据**：能力缺位的返回必须是 `Unsupported`/显式错误，不得返回写死的 sim 表
（现违例：`rr3_wifi_scan_result` 恒 `"backend": "sim"` + 假 AP 表）。假在位开关（索引 L-4）的同族。

### 裁定 5（Nn-5）：凡自称"保护性"的语义，必须有一条**执行面用例**，否则文案降级为"裁决上限"

`move_timeout_ms` 是标本：注释"超时即停，不给堵转留机会"+ println"实机按时限走反射环闭环"，
实际只有入参裁决 + 回显。裁定两条：
① **能做的先说对**：把它在文档与 config 注里改称"入参时限裁决（超上限拒收）"，不许再称"到时停轴"；
② **要保护就补身体**：真正的时限保护随 `Rr3Actuator::rr3_goto(deg, deadline_ms)`（ADR-0021 裁定 5）落地，
判据是一条**执行面用例**——注入超时 ⇒ 断言轴被停/释放激磁，而不是断言应答里回显了什么。
通用化为门禁判据：**config/注释/自述里出现"即停/兜底/关断/保护/拒动"类动词，代码里必须有一个读者
把它用于动作**；否则该处按"只回显"登记（`cutoff_voltage_mv` 已有此纪律，本裁定把它从个案升为判据）。

### 裁定 6（Nn-6）：观测面补三件"结构性空洞"，并给"两本账"一个数据结构

1. **生效绑定可查**：`rr3_hal_bindings_effective()` 的合成结果必须经 `rr3.ctl.status`（或新 RPC）暴露，
   面板出一份"当前生效绑定快照"（描述符 + 应急覆盖 + 执行件档案三者合成后的那份，不是原始文件）——
   ADR-0021 裁定 6 的那半条，本 ADR 给出接口位。
2. **日志与失败的持久性**：日志环 `512` 内存不落盘 ⇒ 崩溃/重启即失去唯一现场证据。裁定至少落一条
   有界落盘（或交 `systemd` journal，并在手册写明取数命令），并在描述符里给容量位（不再硬编码）。
3. **失败两本账结构化**：`counters` 只有数字。裁定新增一类**开放项数据结构**（status.md 的表由它生成，
   散文不再当唯一载体）：`{ 条目, 分类: 缺码|无载体, 工单号|触发条件, 证据路径, 状态 }`。
   它同时是面板覆盖率门的差集落点（谁红着、为什么红、谁负责）。
4. **微型形态的产线与升级闭环**（复盘确认今天是空的）：`rr3-pack`/`deploy/` 只覆盖 host aarch64，
   ESP32 只有手工 `espflash` runner，无镜像装配、无 OTA、无回滚面；`base/ota` 写侧只到"翻 extlinux 标志"，
   `bootcount`/`altbootcmd` 仅存在于文档表格。裁定立为**批N5**（见全案 §17），并明确要求
   **一张按形态分档的"可达终点表"**——今天的诚实话分散在十几处注记里，但没有人回答
   "新人今天能做到哪一步"。这正是复盘第四份报告给出的最硬结论：**生产面的真实缺口不是缺注释，
   是缺那张表**。

## 备选与否决

| 备选 | 为什么不取 |
|---|---|
| **只把这些记成工单，不动 ADR** | V-1/V-2/V-3 是纲领违例，不是待办：违例的判定标准本身（"什么算机制核载荷"）需要被写清，否则下一个人还会为了少接一根线把缺省塞进契约层 |
| **把 `rr3-mech` 的 `250u64` 直接搬到 config** | 搬错方向：机制核该吃**已有的** `[supplies]` 时序预算位（那是供给），另起一个 config 键就是给同一个事实再造第二个家 |
| **给 sentinel 补一份 `module.toml` 就算入册** | 治标。真正的判据是"申报面必须是可解析文件 + 门的作用域按申报而非按目录"，否则下一个工具照样逃 |
| **把 `rr-ota` 的 include_str 守护删掉图省事** | 守护是对的（布局改名要炸编译），错的只是它钉在某块板上；改指向形态档即可两全 |
| **`move_timeout_ms` 干脆删掉** | 它作为**入参裁决**是有效的（越限拒收），删掉会丢真保护；该删的是那句没兑现的注释 |
| **先做批N5（产线/OTA）再回头补纯净度** | 顺序反了：纯净度与申报面是**判据**，产线动作是**施工**；判据不立，产线脚本会把同一批部署缺省再抄一遍（第二真值点成串） |

## 后果

- 变好的：机制核重新配得上"跨档复用"这句；申报面不再有"内联即自由"的旁路；"板 = 数据"在 esp32 支
  从环境变量手里收回主权；保护性语义要么有身体要么闭嘴；现场第一次能查到"生效的到底是哪份绑定"；
  开放项从散文变成可比对的数据。
- 代价：`rr-mech`/`rr-ipc`/`rr-hal-api`/`rr-ota` 各有一处签名或导出面要改（属基座内部，对外线上字节零改动——
  这是守恒红线，改到的每一处都要有对拍用例守）；`rr-registry` 查册门扩面后 `tools/**` 的既有内联 manifest
  会**即刻变红**（这是如实，不是回退，缩分母让它绿 = 违纲领）；批N5 是纯新增工作量（烧录封装、镜像装配、
  回滚链、可达终点表）。
- 本 ADR **不主张**的：不主张 ESP32 形态已有 OTA/回滚（今天没有）；不主张 sentinel 主题的处置已定
  （入册还是撤申报，随批N1 评审判）；不主张任何阈值取值（`armed=false` 与"无真板对拍不 claim"不变）；
  不主张 V-2 的路径下移不影响装机面（`rrd.service` 与 distro README 必须同批改，否则现场 socket 找不到）。
