# ADR-0025：注册后连接的静默上界与判死权归属

- **状态**：已接受（B19 轮静态审计裁定，取代"注册后读超时暂挂"的口头结论）
- **日期**：2026-11-10
- **关联**：[ADR-0002](ADR-0002-模块模型-5加1-进程隔离.md)（模块模型）·
  [ADR-0009](ADR-0009-依赖仲裁-启动序与降级传播.md)（降级传播）·
  [ADR-0010](ADR-0010-控制通道与查询面.md)（控制旁支不注册）·
  [ADR-0017](ADR-0017-模块内部分层-机制与策略分离.md)（机制/策略分离）

## 背景

四条事实决定这个问题必须裁定而不是随手加个 `set_read_timeout`：

1. **注册前已有上界**：`pre_register_timeout_ms`（spec §5.0）挡住"连上却不注册"的
   客户端；握手成功后该超时被清零。
2. **注册后无上界**：读循环 `rr3_frame_read_cap` 阻塞等待下一个完整帧。一个已经
   注册、此后再不发送任何字节的本地客户端，会永久占住一条连接线程与一条在册
   表条目；在册表把它当"活着"，它申报的能力继续被当作在位提供者——既是线程
   与内存的慢性泄漏，也是"挂着假模块名"的本地可用性攻击面。
3. **判死权已唯一**：`rr3_reg_expire`（看门狗一拍）负责判死、广播 `failed` 与重启
   预算；连接收尾 `rr3_reg_death` 已区分 `DeferredToExitStatus` / `Silent` /
   `Broadcast` 三路，被看门狗先判死的连接走 `Silent`，**不重复广播、不双计重启**。
   任何新机制都不得给判死造第二个作者。
4. **协议已有静默判据**：模块按 `health.heartbeat_ms` 上行 `rr3.heartbeat`，且
   manifest 校验要求 `heartbeat_ms < watchdog_timeout_ms`。因此"多久没有入帧
   即异常"在协议层是可判定的，不需要新增 ping/pong 报文。

## 决策

### 裁定 1：读侧静默上界 = 2 × 该模块的 `watchdog_timeout_ms`

握手成功、登记完成后，按该模块 manifest 的 `watchdog_timeout_ms` 设置
`set_read_timeout(2 × watchdog_ms)`。健康模块的心跳间隔远小于看门狗窗口，
正常业务永远不会触发；触发即"看门狗已经（或将在此后一个窗口内）判死"。

### 裁定 2：上界只回收连接，判死权仍归看门狗

- 2 倍系数是**归属裁定**，不是余量估算：保证看门狗先到期，连接收尾必走
  `Silent` 一路——终态广播、重启预算只有看门狗一个作者，账不双计。
- 连接被回收后，该模块的在册条目已由看门狗置 `Failed`；若看门狗线程本身
  停摆（更罕见的故障），连接这一路按既有 `Broadcast` 分支记一条失败退出，
  仍是一次死亡、一次记账。
- 不新增配置项：上界由模块自己申报的 `watchdog_timeout_ms` 导出，单真值在
  manifest，不引入第二套"连接空闲阈值"。

### 裁定 3：触发文案必须能直接定位

超时返回的错误文案点名三件事：实际空闲毫秒数、上界来源（2 × 看门狗）、
判死与重启的归属。禁止复用"帧读取失败"这一泛化文案——它是 IO 故障的档，
与"对端沉默"是两种不同因。

### 裁定 4：事实缺失时不为连接设上界，并留痕

登记后取不到在册事实（正常路径不可达）时不设读超时、不 panic，打一行点名
日志。宁可退化为今天的无上界行为，也不拿错的上界误杀健康连接。

## 备选与否决

| 备选 | 否决理由 |
| --- | --- |
| 上界 = `watchdog_timeout_ms` | 与看门狗同刻竞争，判死出现两个作者；收尾可能抢在到期扫描之前广播，重启账需要额外仲裁 |
| 新增 ping/pong 报文 | 心跳报文已经在册，重复造契约；每加一种报文都要动全部模块的客户端 |
| 不设上界，靠杀进程关 socket | `SIGSTOP` 与不可中断睡眠下 kill 不生效，socket 不关；恰恰是本 ADR 要覆盖的故障 |
| 用固定 5s 常数 | 与模块自报的看门狗窗口脱钩：慢平台会被误杀，快平台回收太慢 |

## 后果

- **正向**：僵尸连接与僵尸在册条目从"永久"收敛为"至多 2 × 看门狗窗口"；
  静默路径从无日志变为一条可定位的收尾日志。
- **代价**：连接对象可能比判死多存活一个看门狗窗口（有界），窗口内该连接
  不再产生业务，也不阻塞任何其他连接。
- **热路径**：零改动。读超时只在各连接自己的 socket 上生效，无新锁、无新线程、
  无新报文。

## 验证口径

- 既有 `e2e_watchdog` 的静默用例必须同时看到两条日志：看门狗判死（原作者）
  与连接收尾（`不重复广播`）；两条都出现即证明"2 倍先判死、后回收"的次序成立。
- 健康模块（`resident` 角色持续喂狗）在测试窗口内不得出现静默超时日志。
