# ADR-0026：OTA 镜像签名与验签链

- **状态**：已接受（A1 首片：签名/验签核心与 CLI 已落地并有单测；槽位写入与板上回滚归 M6）

## 背景

M6 的 A/B 切换与 U-Boot 回滚链写侧已具备主机面能力：`rr-ota::bootconf` 改写
`root=LABEL`，`rr-ota::bootenv` 上膛/解除回滚四变量，`rr3-ota-ctl` 提供
`switch/factory/rollback` 子命令。但**升级镜像本身没有任何真实性校验**：

- 分区里的 rootfs 镜像可以被替换、截断或跨平台误刷；
- 现有流程只校验"能不能写"，不校验"是不是我们签发的、是不是给这块板的"；
- 静态审计 P1-8 明确记为"签名/回滚未闭环"，且没有 ADR 级方案。

这不是"再加一个 hash 文件"就能解决：hash 只能证明内容未变，不能证明来源；
把校验密钥写进镜像、或用对称密钥做 HMAC，都等于把信任根交给攻击者。
因此必须先裁定信任模型、签名对象、密钥生命周期与验签点，再落代码。

## 决策

### 裁定 1：信任根 = 离线/CI 持有的 Ed25519 私钥，设备只持公钥

- 签名算法固定为 **Ed25519**（RFC 8032），验签用严格模式
  （拒绝非规范编码/可延展签名）。
- 私钥只存在于签名环境（离线工作站或 CI Secret），**永不进入镜像、仓库与设备**。
- 设备只持公钥：公钥按 `key_id` 分布到安装树，验签时按 manifest 的 `key_id`
  选择；找不到对应公钥即拒，不做"任意公钥都能过"的宽松回退。
- `key_id` = 公钥 32 字节的 SHA-256 前 8 字节（16 位小写十六进制），
  由公钥派生、不单独维护，避免"密钥与 ID 对不上"的第二真值。

### 裁定 2：签名对象 = 分离式 manifest 的**原始字节**

升级制品由三件组成：

```
<image>            镜像本体（rootfs 或后续模块件）
<manifest>         严格行式清单（ASCII，LF 结尾）
<manifest>.sig     Ed25519 签名（128 位小写十六进制 + LF）
```

签名消息 = manifest 文件的**原始字节**（含末尾 LF）。签名不覆盖 image 本体，
而是覆盖 manifest 中的 `sha256` / `bytes`；image 本体由这两个字段约束。
这样签名与解析都不需要 canonical JSON/TOML，字节级可复现，避免
"同一份数据两种序列化"的歧义。

manifest 文法固定、字段有序、无注释、无空行：

```
rr3-ota-manifest 1
kind=rootfs
platform=rk3566
board=radxa-zero3
version=0.0.8
image=rr3-rootfs-rk3566-0.0.8.img
bytes=123456789
sha256=<64 位小写十六进制>
key_id=<16 位小写十六进制>
```

规则：

- 首行固定 `rr3-ota-manifest 1`；`schema` 变化升版本号，旧解析器拒新版本。
- 字段顺序固定；缺字段、重复字段、未知字段、空值、非 ASCII、CRLF 一律拒。
- `kind` 本版只接受 `rootfs`；`module` 等后续值在扩展 ADR 中另行定义。
- `image` 只允许单一路径分量（不得含 `/`、`\`、`..`、控制字符），
  防止 manifest 把验签器引到任意文件。
- `platform`/`board` 是目标兼容判据；验签方可传入期望值，不匹配即拒。
- `version` 为语义化版本；降级判据见裁定 4。
- `bytes` 与 `sha256` 必须与 image 本体一致，缺一不可。

### 裁定 3：验签顺序与失败语义（fail-closed）

`verify` 的固定顺序：

1. 读 manifest 原始字节 → 严格解析文法；
2. 读 `.sig` → 严格解析 128 位十六进制；
3. 按 `key_id` 取公钥 → 校验 `key_id` 与公钥派生值一致；
4. 对 manifest 原始字节做 Ed25519 严格验签；
5. 校验 `kind` / `platform` / `board` / `version` 策略；
6. 校验 image 的 `bytes` 与 `sha256`；
7. 全部通过才输出结果。

任何一步失败都返回**具名错误**，退出码 1（业务/校验失败）或 2（用法错）。
`verify` **不写任何槽位**；未来的写入流程必须"先 verify、后写"，且写侧不得
自带第二份验签实现。

### 裁定 4：降级判据显式，不在本版偷偷做持久化

- `verify --current-version <X>` 存在时：`manifest.version <= X` 即拒，
  除非显式 `--allow-downgrade`（用于运维回退，必须留日志）。
- 不传 `--current-version` 时只做真实性/完整性/目标兼容校验，不声称防降级。
- "当前版本"的权威来源归 rrd/安装树（后续批接线）；本版不新增第二份版本状态，
  也不伪造"已防降级"的结论。

### 裁定 5：签名的执行面与密钥载体

- `rr3-ota-ctl sign --manifest P --key-file K --sig-out S`：
  - 私钥文件格式 = 32 字节种子的 64 位十六进制（可带末尾换行）；
  - 私钥文件权限必须是 `0600`（非 unix 平台不做权限断言，但文档写明）；
  - 签名成功后原子写 `.sig`（同目录临时文件 + rename），不把私钥写进任何输出。
- `rr3-ota-ctl keypub --key-file K [--out-pub P]`：从种子派生公钥，
  打印公钥十六进制与 `key_id`；可选写出公钥文件。
- 签名工具本身不生成私钥；私钥由离线环境用系统 CSPRNG 生成
  （例如 32 字节随机数转十六进制），避免在工具里引入 RNG 依赖。
- 安装树公钥路径固定为 `ota/keys/<key_id>.pub`（相对安装根），
  由打包/装机链随包分发；设备验签时显式传 `--pub`，不隐式猜路径。

### 裁定 6：本版边界——只交付"签名/验签原语 + 运维 CLI"

本版**不**交付：

- 镜像下载、断点续传、写对侧槽、写后回读；
- `rr3.ctl.ota` 与面板 OTA 的在线入口；
- U-Boot FIT/dm-verity 等引导链验签；
- 模块级更新的签名格式（只留 `kind` 扩展位）。

这些仍归 M6 板上批；本版先把"制品可签、可验、可拒"做成可测试的单点，
后续写入链只允许调用这一份验签，禁止在 rrd/面板里再造第二份。

## 备选与否决

| 备选 | 否决理由 |
| --- | --- |
| 只放 SHA-256 校验文件 | 只证明"内容没变"，攻击者可同时替换镜像与 hash；无来源认证 |
| HMAC/对称密钥 | 验证密钥必须在设备上，等于把签名能力交给攻击者；无法做公开发布 |
| 运行时调用 `openssl`/`ssh-keygen` 验签 | 依赖外部二进制与版本差异，Buildroot 最小镜像不保证在位；TOCTOU 面更大 |
| 手写 Ed25519 验签 | 密码学实现不接受"自己写一个"；用经过审计的纯 Rust 实现 |
| 只做 U-Boot FIT 签名 | 只覆盖引导件，不覆盖 rootfs/模块件；不能替代本层 |
| JSON/TOML 清单 + canonical 序列化 | 需要额外的规范化实现与库；行式固定文法更小、字节级可复现 |
| 把公钥写死在二进制 | 轮换密钥必须重编译整机；按 `key_id` 分发布局可轮换且不牺牲 fail-closed |

## 后果

- **正向**：升级制品获得来源认证与完整性校验；跨平台误刷、坏包、篡改包
  在写入前被拒；密钥轮换有 `key_id` 扩展位；验签逻辑单点、可对拍。
- **代价**：`rr-ota` 新增两个纯 Rust 依赖（`ed25519-dalek`、`sha2`），
  `rr3-ota-ctl` 随之增大；所有 OTA 制品必须走签名流程，未签名包一律拒。
- **性能**：Ed25519 验签为常数级；rootfs 的 SHA-256 是线性扫描，只在升级时发生，
  不进入模块主循环。
- **风险**：私钥保管成为新的单点；CI Secret 泄露即失去信任根。缓解：
  私钥只在签名 job 注入、临时文件 `0600`、任务结束删除；公钥按 `key_id`
  分发，轮换不需要改验签代码。

## 验证口径

- `rr-ota::sign` 纯函数/文件边界单测：合法签名通过；篡改 manifest、篡改 image、
  错误公钥、错误 `key_id`、坏十六进制、缺字段、重复字段、未知字段、CRLF、
  路径穿越、`bytes`/`sha256` 不符、`platform`/`board` 不符、降级（带/不带
  `--allow-downgrade`）逐条拒。
- `rr3-ota-ctl` 端到端：临时目录生成种子 → `keypub` → `sign` → `verify`
  通过；逐项篡改后退出码与文案可定位；`.sig` 原子落盘无残留。
- 门禁：`cargo test -p rr-ota`、`cargo test`（rr3-ota-ctl 独立工程）、
  `check.sh` 全绿；`cargo check --target aarch64-unknown-linux-gnu -p rr-ota`
  通过（纯 Rust 依赖不引入目标 C 工具链）。
- 真实镜像签名/验签与板上写入链归 M6 板上批，本版不冒领。
