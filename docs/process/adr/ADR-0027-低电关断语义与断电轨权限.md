# ADR-0027：低电关断语义与断电轨权限

- **状态**：已接受（语义与权限裁定；执行面分阶段门控——**本版仍不关断**，与

## 背景

`rr3-power` 的 `battery.cutoff_voltage_mv` 自 0.0.5 批M MC-8① 起**声明未生效**：
配置键保留为策略数据，启动回显与面板读数都明说"本版不关断，归 M6"，唯一生效的
低电保护是 MC-5 低电禁动（执行面 servo/relay 闭锁）。这留下三个没有裁定的问题：

1. `low_voltage_mv`（禁动线）与 `cutoff_voltage_mv`（关断线）的边界是什么？
   今天两值都只是数字，没有任何机制约束 `cutoff < low`，也没有规定关断是否
   必须先经过禁动。
2. 关断要不要去抖/闭锁？电池在舵机堵转时会出现秒级压降，单拍越线就断电等于
   把"正常负载瞬态"当成"电池耗尽"，会制造比低电更严重的可用性事故。
3. 谁是执行者、凭什么执行？板上有两条断电轨 T1（PMOS 切核心板全部供电）与
   T2（舵机独立开关），`Rr3Rail::rr3_switch` 是它们的调度抓手，但今天只有
   `unavailable` 实现（恒回 `Unsupported`）。在没有任何真实执行器、也没有板上
   实测的情况下"顺手实现"关断，只能造假。

本 ADR 只裁定**语义、权限与阶段门控**，不代替实现；执行面在真实执行器与板上
证据到位前保持关闭。

## 决策

### 裁定 1：两条线是两种动作，cutoff 必须先跨 low

- `low_voltage_mv` 的语义不变：**低电段**判据，触发 `battery/low` → rrd 低电旗
  → 执行面禁动（MC-5）。它是可恢复的**提示性保护**。
- `cutoff_voltage_mv` 的语义是**不可恢复的断电请求**：只允许在已经进入低电段
  之后评估。装配/装载期校验 `cutoff_voltage_mv < low_voltage_mv`（严格小于），
  违反即拒装载并点名两键——这条是装载门判据，不靠运行期"碰巧没触发"。
- 两线之间不设第三个阈值；轻度/重度轨压（`mild_mv`/`severe_mv`）是**域压**
  的另一对象，不参与电池关断判定。

### 裁定 2：去抖 = 连续样本 + 最短持续时间，闭锁 = 一次生效

- 关断判定必须同时满足：**连续 `N = 3` 拍**采样 `≤ cutoff_voltage_mv`，
  且累计时长 `≥ 3 × sample_period_ms`；任一拍回到阈值之上（严格大于）即清零
  连续计数，重新从 1 数。`sample_period_ms` 的权威来源是 `rr3-power` 配置，
  不另设第二个周期。
- 为什么是 3 拍而不是单拍：采样周期是秒级（默认 5000ms），单拍会被负载瞬态
  击穿；3 拍 ≈ 10s 的量级足够覆盖舵机堵转，又不至于让电池在 3.0V 以下拖到
  损坏。这是**策略默认值**，可以在配置层调整，但"连续样本 + 最短时长"的
  机制形状不接受"单拍立即断电"的配置。
- 关断一旦请求即**闭锁**：同一 boot 内不再重复请求、不接受任何解除输入
  （包括 `battery/ok` 与人工 `rr3.ctl.*`）。要恢复只能冷启动后重新评估——
  电池恢复到可运行电压是物理事实，不是总线事件能证明的。
- 去抖状态机是**纯函数**（输入：采样值与时刻；输出：无 / 请求关断），主机可测，
  不依赖唤醒源、定时器或总线。

### 裁定 3：执行者唯一 = `rr3-power`，且必须先禁动、再有序停机、最后切轨

- **判定权**归 `rr3-power`（它持有电池采样与阈值）。rrd、brain、面板与任何
  `rr3.ctl.*` 写口都**不得**发起关断：关断是本地安全决策，不依赖总线可达，
  也不接受远程"替它判断"。
- **执行权**归同一进程的断电轨动作，按固定相序：
  1. **禁动**：复用 MC-5 闸门（servo/relay 闭锁），确保动作先于断电；
  2. **有序停机**：`sync` 后请求系统关机（`systemctl poweroff` 或
     `/sbin/poweroff`，与 `ctl.reboot` 同一命令族）；给内核一个有限窗口
     （`shutdown_grace_ms`，默认 30s）；
  3. **切轨**：窗口到期或关机失败 → 对装配声明 `switchable = true` 的域
     （T1；按板序连 T2）调 `Rr3Rail::rr3_switch(domain, false)`；
  4. **失败兜底**：切轨返回 `Unsupported`/错误 → 点名写日志后**不重试风暴**，
     以 1Hz 最多重试 3 次；仍失败则维持禁动并降到最低活动，不再发起第二轮
     关停（重复 `poweroff` 会把失败变成日志写放大）。
- 相序的硬约束：**任何切轨都不得早于禁动**；没有禁动确认就不允许切轨
  （无法确认时按"未确认"处理并留痕，不假设成功）。
- 切轨权限只看两件事：装配里该域 `switchable = true` 且 `armed = true`
  （"未标定不武装"的既有纪律）。两者缺一即 `Unsupported` + 点名，不准
  回退到"随便找一条轨切"。

### 裁定 4：可观测面不加新主题，关断前留痕是唯一证据

- 不新增 `battery/cutoff` 主题或事件：断电会立刻切断总线与日志，任何"关断
  事件"的消费者都拿不到它，造一个发不出去的契约面只会变成假证据。
- 可观测面固定为三段**断电前**留痕（顺序即证据链）：
  1. `battery` 低电段与关断请求的结构化日志（含连续拍数、阈值、实测电压、
     相序进度）；
  2. `sync`/关机命令的结果；
  3. 每次切轨尝试的域、结果与错误。
- 断电后能证明什么：只能证明"最后一行日志到了哪一步"。板上验证要求
  **串口控制台**同步留一份（与 rrd 日志环互相独立），否则断电即失证。

### 裁定 5：本版（0.0.8 线）执行面保持关闭，配置键维持"声明未生效"

- 本版**不实现**关断动作：`cutoff_voltage_mv` 继续只作策略数据，启动回显文案
  维持"声明未生效：本版不关断，归 M6"（文案是红线，测试逐字钉住）。
- 允许先落地、且必须主机可测的**机制半边**只有两件：
  - 装载门校验 `cutoff < low`（裁定 1）——**随本 ADR 同批落地**；
  - 去抖 + 闭锁的纯状态机（裁定 2）——**在动作开启前落地**：今天没有任何
    真实执行器读它，先写就是死代码，反而会被误当成"关断已具备"。
  两件都不得含"触发后真的切轨"的路径——动作必须等执行器与板上证据。
- 解除执行面关闭的前置条件（缺一不可）：
  1. `Rr3Rail::rr3_switch` 在 RK3566 参考机上有真实实现（GPIO→PMOS T1，
     非 `unavailable`）；
  2. 板卡设计规格书的 T1/T2 与装配 `[[supplies.domain]]` 的 `switchable/armed`
     逐域对账通过；
  3. 台架实测回执：可调电源从 3.6V 缓降，记录关断点落在配置阈值 ± 一个采样
     周期内；20 次关断循环后文件系统可挂载、无 fsck 错误；
  4. 串口与 rrd 日志两路留痕能对齐到同一相序（裁定 4）。

### 裁定 6：形态边界与"不能"的答案

- 本 ADR 只覆盖 **host 形态**（Linux 上有断电轨的板）。bare/rtos 形态没有
  T1/T2 对象，其"不可关断"是**合格答案**，但必须写进该形态的终点表，不得
  借用本 ADR 的相序假装具备。
- 没有电池的机型（纯适配器供电）不启用 cutoff；配置缺 `battery` 段即不评估，
  不把"无电池读数"解释成 0V。

## 备选与否决

| 备选 | 否决理由 |
| --- | --- |
| 单拍越线立即断电 | 负载瞬态（舵机堵转）会造成秒级压降，误关断比低电更伤可用性 |
| 用 `battery/ok` 自动解除关断闭锁 | 电池恢复到某电压不等于能支撑下一次负载；闭锁只能由冷启动清除 |
| 由 rrd 判定并执行关断 | rrd 没有电池真值，会把"最后一个读数"当成事实；且违背本地决策原则 |
| 先切 T1 再禁动 | 切轨后进程立即死亡，禁动永远没机会执行；动作顺序不可交换 |
| 新增 `battery/cutoff` 总线事件 | 断电杀死总线，"发出去了"无法被证明；消费者为零 |
| 在 `unavailable` 后端上"尽力切轨" | 恒回 `Unsupported` 时"尽力"等于假装动作，违反零桩实现纪律 |
| 关断失败后无限重试 | 日志写放大 + 在临界电压上反复关机，最坏情况下加重 brownout |

## 后果

- **正向**：两条电压线的边界、去抖/闭锁与执行相序被一次钉死；后续实现不需要
  再猜"谁来判断、谁来切、先做什么"；本版关闭动作有明确、可复核的理由。
- **代价**：`rr3-power` 后续要新增一个纯状态机与装载门判据（主机可测）；真正
  关断仍要等 RK3566 的 T1 执行器与台架证据。
- **风险**：`cutoff < low` 的装载门会拒掉历史配置中两值相等或倒置的板档——
  这是有意的 fail-closed；受影响的板档必须订正配置而不是放宽判据。

## 验证口径

- **本版可验证**（主机）：
  - 装载门（已落地）：`cutoff >= low`（含相等与倒挂）拒装载并点名，文案指向
    本 ADR；缺 `low`/缺 `cutoff` 仍走既有缺字段拒；
  - 启动回显与面板读数仍逐字包含"声明未生效：本版不关断，归 M6"。
- **动作开启前要补的验证**（随执行器批）：
  - 去抖状态机单测：单拍不触发、连续 3 拍且满最短时长才触发、任一拍回升即清零、
    触发后闭锁（继续喂低值不再产生第二次请求）、闭锁后 `battery/ok` 不解锁。
- **本版不可验证**（板上，归 M6）：真实切轨、关机窗口、20 次循环后的文件系统
  完整性、串口/日志两路对齐。未取得这些证据前，任何"已关断"的宣称都不成立。
