## 1. 版本目标与范围

### 1.1 目标（一句话）

`rrd` 按 `profiles/<机型>.toml` 装配 5+1 全模块（缺格 Degraded，fail-closed），act/power/connect
三模块从自述占位变实装（sim 后端），低电兜底走通不依赖 brain 的进程内路径，payload 以 deb
形态在发行版容器冒烟通过，远端 CI 四 job 拿到首批全绿回执——M5 sim 侧收口 + ADR-0013
快路轨首批落地。

## 4. 设计要点（边界以各 ADR 不做清单为界）

- **装配链只读一次 profile**：boot 前消费，运行期不重排（ADR-0012 裁定 4，F⊗F 非法）；
  `[os].route` rrd 运行期不读（ADR-0012 裁定 3 B3 注记）
- **探测 fail-closed**：bindings 声明的格位探测不到 → 对应模块 Degraded，绝不带病起；
  探测自身故障按"探测不到"处理；探测总时长有上限，不阻塞启动横幅
- **三模块失败语义与 sense/interact 同一口径**：业务性失败折 error 应答回话，传输性失败
  `exit(1)` 交 supervisor，不装"活着"
- **反射环最小环不进总线**：1kHz 进程内闭环（ADR-0007 裁定 1），M5 只要求宿主位与命令流存在
- **rrd 不越权发布**：兜底路径只订阅 `battery/low` 与广播 `rr3-runtime/*`（内建命名空间）；
  模块主题的发布权属各 owner，`rr3_reg_publish_check` 四道门不因 rrd 自身豁免
- **deb 打包两轨同源**：同一批二进制与契约文件进 deb（快路）与 genimage 产物（保底），
  不写两份打包逻辑（ADR-0013 裁定 5）
- **base 格恒在位，不进缺格判定**：`net.online` / `power.battery` 两格通道 boot 即在位、
  恒不降级（`contracts/slots.toml` 2026-10-03 注记）；装配链的"缺格 Degraded"只作用于
  bindings 声明的身体层/认知层 15 格（`profiles/default.toml` 基础层本就不绑模块），
  两格的运行期读数由 connect / rr3-power 发布，安全兜底仍走 architecture §7.3 的
  rrd 横切路径（D6），与"反应归策略层"注记不冲突
- **硬件线并行轨（不占本版本任务号）**：规格书 §12 开放项里 O3 核心板询价、
  O1 舵机数量确认两项不依赖板上收口，可随本版本并行推进；O2 VAD 误触率实测
  依赖 ZERO 3 到位，归板上批次（范围外口径不变）
