## 4. 设计要点（边界以各 ADR 不做清单为界）

- **actions 执行的两道归属门**：topic 必须 ∈ 发布方意图清单且 ∈ 执行模块 exposes；
  两道门任一不满足拒执行并日志点名——执行器不越权（发布侧 `rr3_reg_publish_check`
  四道门的精神在订阅执行面的对偶）
- **act 执行失败语义**：动作执行失败（HAL 写失败 / 参数裁决拒绝）折日志继续收下一帧
  （事件语义无应答回路）；传输性失败（总线写不出去）`exit(1)` 交 supervisor——与既有
  三模块口径同款
- **brain 规则面只喂 `user_text`**（ASR 结果），不碰 `reply_text`——防机器人自己的话
  触发自己的动作；规则匹配最小化（精确词表命中，不做否定语义解析），负样本进单测；
  `intent.py` 保持与 `dialog.py` 同款依赖面（stdlib、3.9 兼容语法），本机可跑单测
  （跑多少条如实登记，CI 双矩阵兜底）
- **OTA 原子翻**：引导配置改写 = 读 → 改 → 临时文件写 → rename 原子替换（断电安全
  约束"标志的翻必须发生在对侧校验通过之后"的文件系统面）；bootlimit/altbootcmd 的
  U-Boot 标准语义按 partition-layout.md 增补段为准；当前槽判定与目标槽校验的拒绝面
  （同槽幂等拒 / 非法槽名拒）随 T4 设计定稿
- **恢复出厂不写 factory**：一次性引导切 `rr_factory` 标签只改引导配置；
  partition-layout"rr_factory 任何代码路径不得写入"维持
- **legacy 消化不回写**：冻结区三阶段的第一阶段维持只读；盘点文档只引用证据路径，
  不修改 legacy 内任何文件（含已知偏差的 README 断链——退役批才注销）
- **契约只增不改**：`intent/result` 载荷加字段是 append；schema 新文件是 append；
  topics.toml 本版本一条 append——`rr3-act/relay/state`（T3 补裁定，意图执行效果的可观测面）；
  Q1 的 actions 词汇本身零新造（topic 即既有契约主题）
