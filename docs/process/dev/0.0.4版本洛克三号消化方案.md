- **板上项**：NetworkManager / BlueZ 真机后端、AP 热点真射频、面板局域网 `0.0.0.0`

  不 claim（随板上批次收口）

- **第二控制通道**：面板永远经 rr-bus 与模块同权（ADR-0006 裁定 3），不开旁路直连面
- **恢复出厂两语义合并**：面板"恢复出厂 WiFi"（清凭据回默认）≠ M6 恢复出厂
  （整槽回滚切 `rr_factory`，partition-layout 只读约束维持）——不合并、不混用
- **云侧 function-calling、OCI 分发、tcp 传输、跨机、运行期重仲裁**：各 ADR 不做清单维持

## 4. 设计要点（边界以各 ADR 不做清单为界）

- **九计数器归属表**（legacy data.c → 新架构，Q1 通道承载）：

| legacy 键 | 产生方 | 新落点 |
|---|---|---|
| boots | rrd | rrd 启动自增（基座自有，不走心跳） |
| chat_rounds | brain | `dialog.rr3_record` 成功一记一轮 |
| asr_ok / asr_fail | brain | cloud ASR 调用成败各一记 |
| llm_fail / tts_fail | brain | cloud LLM/TTS 失败各一记 |
| relay_on / relay_off | act | `rr3_relay_apply` 成功后按目标电平记 |
| errors | 各模块 | 通用可选键：模块侧可捕获异常计数；稳定性账仍以 rrd `crash_streak` 为准 |

- **心跳 counters 通道**：`rr3.heartbeat` 请求载荷 append 可选 `counters` 对象；client.rs
  心跳线程从快照点取数（模块注册自愿上报回调/原子映射），无上报则字段缺省——
  rrd 侧未知字段忽略，新旧双向兼容；bus.py 逐语义镜像并同步 brain 单测
  （ADR-0014 裁定 1"Rust 侧唯一真值点"纪律）
- **聚合与持久化**：rrd 内存聚合表（按模块名前缀 + 键归并）→ write-through 落
  `counters.json`（tmp+fsync+rename）；启动加载 + boots 自增；`rr3.ctl.counters`
  返回全表 JSON——与 `rr3.ctl.health`（心跳健康语义）分开，计数是业务运维语义
- **panel 页签 → 数据面映射**：状态页 = `rr3.ctl.health` + `rr3.ctl.counters` +
  `rr3-connect/net/link` 订阅缓存；WiFi 页 = connect 三 RPC；硬件页 = relay RPC +
  进程内 beep + 自检并列三调；系统页 = `rr3.ctl.reboot` + `wifi/forget`
  （恢复出厂 WiFi）。静态页沿用 legacy 单文件内嵌语义（`include_str!`，无外部资源），
  页面文案与端点适配新架构，192.168.4.1 等 ESP32 硬编码不搬
- **HTTP 面安全边界**：只读状态 + 白名单动作 + JSON 解析（serde_json）；读超时 +
  连接数上限；默认回环监听；不承诺公网暴露（局域网可信面声明落模块 README）
- **配网状态机**：`net/link` 增补 ap 配网态（sim 可驱动进出）；scan 返回 sim 模拟
  列表（板上换 NetworkManager 真扫描，cfg 门）；connect/forget 只改状态机与内存凭据，
  真凭据持久化后置
- **契约只增不改**：heartbeat counters 可选字段、`rr3.ctl.counters` / `rr3.ctl.reboot`
  新 ctl 方法、connect 三 RPC 主题、（若有）panel 相关事件——全部 append；
  topics.toml / manifest / 契约 pin 三处同批改纪律照旧（0.0.3 批C 首跑红的钉子）
- **退役批四件收尾**（digest §三.2 原文执行）：⑤ 门 `grep -v '^legacy/'` 排除条款撤除、
  architecture §8 标注消化完成、status.md 已知偏差注销 legacy/README 断链、
  digest 三分类表归零归档——与整树删除同一提交
