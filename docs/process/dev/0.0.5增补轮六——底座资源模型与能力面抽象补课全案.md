# 0.0.5 增补轮六 —— 底座资源模型与能力面抽象补课全案

- **状态**：**已立项，未开工**（2026-10-14）。裁定原文 =
  [ADR-0021](../adr/ADR-0021-三独立形态与资源供给面-能力原子化补课.md)；本全案是它的**施工编排与字段级设计**。
- **归窗**：**开发窗**（承 [ADR-0020](../adr/ADR-0020-版本边界-开发收口与实机验证与验证后整理.md) 裁定 1）。
  本全案产代码 + 契约 + 门 + 用例；**板上证据仍归 0.0.6/0.0.7 验证窗**，本全案不产点验结论。
  本轮唯一"改文档"的产物就是本文件与 ADR-0021 及其回写面——**它不改任何 `.rs`**。
- **与前几轮的关系**：增补轮五（R31）把三功能在 ESP32 上做到"能跑"，本全案处理的是**它跑起来时暴露的
  底座形状问题**——同一句用户口径的两面：功能落地（轮五，已发生）与抽象补课（本轮，未做）。
  分账规则沿用 0.0.5 §18.4：**已交付的板侧行为不回炉重写**，本全案只把它的**归属**从私有 crate
  迁进契约面，并立"同类故障不在第二块板重现"的门。

## 0 判据（本轮的收口标准，先立再开工）

两条，都可机械复查：

1. **五处升格判据**：每一个坑必须升格为下列之一，否则只算一次现场处置、不算收口——
   ① 供给位（`[supplies]`） ② 能力面 trait（`rr-hal-api`） ③ 描述符键（`[hardware]`/`[pins]`）
   ④ 格或主题（`slots.toml`/`topics.toml`） ⑤ 门禁判据（`check.sh` 某步）。
2. **第二平台重现判据**：同一类故障在第二个平台重现 = 抽象失败。本轮立项的直接触发器就是这条——
   引脚互斥跨平台出现过**两次**：ESP32 上 GPIO16/17↔I2C0 **实际撞上并被迫改线**（迁到 18/19，而 19
   又与点阵 VSPI 预留同脚，注释自述"点阵立项时需再迁，已在案"）；树莓派路线上 I2S 双麦与 SG90 硬件 PWM
   在 GPIO18/19 的互斥**被文档预测到**（0.0.6 §5.4 条 9"须先钉引脚预算表再采购"），靠该路线整体改挂
   ESP32 而侥幸未演化为损失。**两次都只留下注释与条款，装载期没有任何可查的数据结构**——
   侥幸不是抽象成功，因为下一个形态不会读注释。

**为什么判据 2 比"修好"更硬**：本周每个具体故障都能被一次改动修掉（换引脚、降亮度、串行走），
但修完之后**底座对下一个形态没有任何新约束**——那正是"做出来的 ESP 板的东西复用到树莓派上"失败的机制。
本轮的目标不是让 ESP32 更好用，是让**第三个形态不再犯这些错**。

## 2 三独立形态（把谱系从"主形态 + 附件"改成两轴）

| 形态（产品轴） | 承载档（技术轴） | 格集 | 链路 | 认知 | 观测面 | 现役状态 |
|---|---|---|---|---|---|---|
| **RK3566 桌面具身** | host | 全 21 格（目标态） | 自身 WiFi/以太网 | 本地或云（`cognition.*`） | rrd 日志环 + 面板 | 目标板未采购（M1 敞口） |
| **树莓派** | host | 实然 17 项 + base | 自身 WiFi | 云 API | rrd + 面板（**0.0.6 已点验的那台**） | 平台级点验待补（不新增功能码） |
| **ESP32 微型** | rtos | `act.servo`+`audio.capture`+`audio.vad`+`ui.face`+（本全案后加 `power.rail`） | 自身 WiFi（配网）；**桥是可选能力升级**，不是组成部分 | **经桥取 host 形态 = 现役唯一路径**；"直连云 API"**今天不存在**（§18 F-18：板侧对 HTTP/HTTPS/TLS/TCP 词界 grep **零命中**，无 TLS 栈即无云直连）⇒ 记为待立、不排期 | **板自己的守护输出 = 现役唯一观测面**；"板自己的配置入口"同样**零码事实**（要 HTTP 服务器选型 + 堆核算，批N4 的前件，connect **N-13**） | 四件已在板上真跑（轮五），底座形状未收 |

三条读法（这三句是本全案的约束，不是描述）：

1. **形态之间只共享机制核与契约**，不共享进程、不共享总线、不共享供电。任何"由宿主替它管外设/管观测"
   的设计都是裁定 1 作废的旧口径残留，见到就改。
2. **桥不是承载档**。`F-B 桥接微型` 这个词把"rtos 档"和"经桥"混成了一个标签；现拆为
   承载档 ∈ {host, rtos, bare} × 链路 ∈ {无桥, 经桥}，两轴独立。`ADR-0018 修订 4 ③` 那句
   "经桥档 task 号走注册态"仍然成立，只是它的条件从"是 F-B"改成"链路 = 经桥"。
3. **每个形态都要能独立回答"我此刻能给外设多少电流、哪条线接在哪、这个轴标定过没有"**——
   答不出这三问的形态不是被裁剪过的机器人，是等待复发的固件（判据同索引 §11 L-1）。

## 3 逐部件能力原子化盘点

模板固定十一问，每个部件逐条回答；**答不出某一条就是这一条的缺口**，本全案把它登记进 §1 表或 §9 批次。
十一问 = ① 现在契约里它是什么（符号级） ② 缺什么抽象 ③ 角色名 ④ profile 绑定字段 ⑤ 供给与预算
⑥ 能力面（按增长律新增，不改既有 trait） ⑦ 件申报 `handles`/`ops`/`demands` ⑧ 降级语义 ⑨ 面板可观测项
⑩ 面板可写项 ⑪ 标定/复位与"教训落点五处之一"。

**落点（⑪）**：坑 4/5/9 → **① 供给位 + ② 能力面 + ④ 格**（`power.rail`、`power.budget` 两格 + 一条
`rr3-power/rail/state` 主题；bare 档经守护输出行，不发主题）。

## 4 数据结构定形（本全案唯一"字段级"章节，其余各节都引它）

### 4.1 `contracts/roles.toml`（新建，契约层，`schema_version = 1`）

```toml
# 角色词表：跨形态共享的"这类信号叫什么、属于哪张格、能不能被降载切"。
# 消费方：profiles [pins] 的 role 外键、rr-registry 查册门、面板配置项生成、门禁六表对账。
[[role]]
name = "act.axis.pwm"        # 角色名（点分式，前缀 = 格名的动作侧）
slot = "act.servo"           # 外键 → contracts/slots.toml
kind = "power"               # 取值域封闭三值：signal | power | logic
                             #   power = 必须带 rail；logic = 无物理绑定（bus.publish 那类内建格走它）
                             #   （§18 F-27：ADR-0022 裁定 3.1 的 `kind != logic` 判据依赖这个取值，
                             #    首版字段域只写了 signal|power ⇒ 该判据当时不可判）
iface = "Rr3Actuator"        # 外键 → RR3_ASSEMBLE_HANDLE_TRAITS（门 a 的 ∃trait(role) 判据对象；
                             #   首版没有这个键，那条判据无对象可判——§18 F-32）
requires = ["controller", "channel", "physical", "rail", "failsafe"]
                             # 该角色的 [pins] 必填字段集（门 a 的 ∃key(role) 判据对象；
                             #   "合法不适用"必须显式写 none/false，留空 = 红，见 §5 缺失语义列）
direction = "out"            # out | in | io | passive
droppable = true             # 欠压降载时可否被切断
input_only_ok = false        # 该角色是否允许绑到 input-only 引脚
per_instance = true          # 一角色可多实例（双轴即两条 instance）；false 时填 instance 即红
note = "SG90 类位置舵机；行程与标定不住这里（住执行件档案）"
```

**纪律**：角色 ↔ 格 ↔ trait ↔ 描述符键的**一致性**由门禁判等（§8 门 a）。加一类外设 = 同批改多处，
一次评审；这是裁定 4 撤销"闭集"之后防止键域自由生长的**唯一**替代物。
**数表要数对**：§18 F-32 核实实际参与判等的是**六张**而非四张（`slots.toml` / `roles.toml` /
`RR3_ASSEMBLE_HANDLE_TRAITS` / 件 `handles[].desc_key` × `RR3_ASSEMBLE_DESC_KEYS` / `[pins]` 字段词表 /
平台 `role→具名构造` 表），其中两张今天已在 CI 有执法——门 a 按六表判。

### 4.1b `contracts/devices.toml`（本轮新立，第五份契约文件，`schema_version = 1`）

§18 F-26 的结果：**三处设计各自需要"器件型号 → 能力"这份数据，而 §4 首版没有立它**——
① 坑 7 的落点写"总线速率取值域按器件在册"（没有容器）；② §12.1 的器件级在位探测要"寄存器 ID /
特征字节读回比对"（没有来源）；③ §8 门 i 判"凡器件事实必须落键值"（没有键集）。
同 D10a 的"不认具体器件型号"不冲突：**装载期不认，评审期与出厂自检必须认**。

```toml
[[device]]
model = "SSD1306"           # 型号词表（门 i 与门 o 的在册源）
bus = "i2c"                 # i2c | spi | vspi | 1wire | adc | pwm（能力侧，不是引脚侧）
addrs = ["0x3C", "0x3D"]    # 合法地址集（校验⑦/门 o 对账；SSD1306 只有这两个 ⇒ 装机写第三个即红）
baud_ok = [100000]          # 速率取值域（坑 7 的落点：50k 实测恒 ESP_FAIL ⇒ 不在册即拒 boot）
id_reg = { addr = 0x00, expect = 0x00 }  # 器件级在位探测的寄存器 ID（§12.1 / L-14 的数据源）
peak_ma = 20                # 器件峰值电流（与件 demands.peak_ma 互校，校验⑨）
mate = "0.96in-OLED-FPC"    # 对端连接器（wire.mate 的外键）
```

归属：随批N1 与 `roles.toml` 同批（契约层新增，sense **S-13**；判据 = 新立的门 o，见 §8）。

### 4.2 `profiles/<形态>.toml` 的 `[pins]`（描述符第八段）

```toml

instance = "pan"            # per_instance=true 的角色必填；身份 = pin_id（见下）
controller = "ledc0"        # 取值 ∈ 该平台的在册控制器词表（与 conflicts/能力集同处一张表）
channel = 0                 # 控制器通道（**独立资源维度**，见校验③ 的三个空间）
physical = [32]             # 数组：一角色可占多脚（I2S 的 bclk+lrclk+din）
direction = "out"
rail = "rail5v"             # 外键 → [supplies.domain].name
mux_group = []              # 互斥组名（**不再自愿**：由平台 conflicts 表反推，漏声明即红，见④）
failsafe = "release"        # 复位/欠压时的期望物理态：release | hold | driven_low | driven_high
```

**`pin_id` 的定义（§18 F-3 的修法，全案所有外键都用它）**：
`per_instance = false` ⇒ `pin_id = role`；`per_instance = true` ⇒ `pin_id = role "." instance`。
`[supplies.domain]` 的绑定位、`wire.signal`、轴档案的 `pin` 键一律写 `pin_id`，**不再各造语法**。

**键归属裁定（§18 F-1，本轮最重的一处改判）**：`[pins]` 不是"第九键旁边再挂一段"，
它是**物理绑定的唯一真值点**。现役路径是
`件 handles[].desc_key → [hardware] 九键 → descriptor.rs → backend.rs`
（实读 `rr-hal/src/backend.rs:327` 取 `b.pwm_chip?`；`atoms/servo/assemble.toml:9-11` 申报
`pwm_chip` + `pwm_channel`），若 `[pins]` 与它并存，就是**同一个句柄两份取值、门只判一份**。
裁定：**六个物理键（`pwm_chip`/`pwm_channel`/`gpio_chip`/`gpio_led_line`/`gpio_relay_line`/`i2c_bus`/
`ina219_addr`）随批N1 从 `[hardware]` 下移，改由 `[pins]` 派生**；`[hardware]` 只留两个非引脚键
（`alsa_device`/`link_ifname`）。同批必须改的四处（缺一即副本滞后红）：
`rr-registry` 的 `RR3_ASSEMBLE_DESC_KEYS`、六份 `atoms/*/assemble.toml` 的 `handles[].desc_key`、
`rr-hal/src/descriptor.rs` 的键集与解析、`rr-hal/src/backend.rs` 的取值路径——
**属契约面变更，与 `schema_version` 2→3 同一批**（power **P-13** / act **A-17**）。
执法位 = 新立的**门 n 注入路径唯一**（§8）。

## 5 装载期校验（判据级，逐条写清"缺字段怎么办、红成什么"）

**本轮 §18 对这一节的改写是结构性的**，不是加条目：首版十条判据**没有一条写"字段缺失时的行为"**，
于是全部可被留空绕过（F-6）；也没有一条写"红之后是拒 boot 还是降级"，于是与门 b 的"必须拒 boot"互相矛盾（F-14）。
所以每条现在带两列——**缺失语义**（缺哪个字段即红）与**后果**（`拒` = 拒 boot、`降` = 该格 `Degraded` 且必进面板快照、
`名` = 只点名不阻断）。安全相关的 ⑤⑥⑦⑨ 一律 `拒`。
"合法不适用"必须显式写 `none`/`false`，**留空即红**——这条不是新发明，是照抄仓内已有的正确范式：
`rr-registry/src/assemble.rs` 的 `no_injection`（`handles`/`ops` 两数组均空时该键必填，否则与"漏填"不可区分，一律判红）。

| # | 校验 | 判据（逐位可判） | 缺失语义 | 后果 | 实现落点 |
|---|---|---|---|---|---|
| ① | 角色在册 | ①-a `pins.role ∈ roles.names`；①-b `per_instance` 决定 `instance` 必填还是禁填 | `role`/`instance`/`direction` 缺 → 红 | 拒 | `rr-registry` 查册门 + `rrd`/装配段 |
| ② | 所需角色齐 | ②-a `∀ g ∈ ([slots].present ∩ enabled_slots)`：`roles(slot=g) ⊆ pins.role`；②-b 轴档案的 `pin` 外键必须能在 `[pins]` 取到（F-4） | 档案缺 `pin` 键 → 红；角色未绑 → 该格降级并点名 | **降**（缺角色即缺能力，`Degraded` 必须可见；今天面板零配置可见 → 批N4 的 I-15 是它唯一出口） | `rrd` 装配链（与缺格三源合一同一处） |
| ③ | 不双占（**三个资源空间**） | ③-a 同一 `physical` 元素在启用集里 ≤ 1 次；③-b 同一 `(controller, channel)` ≤ 1 次；③-c 同一 `(bus, addr)` ≤ 1 次（F-7：板侧 LEDC 是"脚 + 通道"两维，`board.rs:146` 双轴两通道即证） | `channel` 对 `kind=power` 角色缺 → 红；`bus`/`addr` 对 I2C/SPI 器件角色缺 → 红 | 拒 | 装载期 |
| ④ | 互斥组（**双向**） | ④-a 正向：同 `mux_group` 成员至多一个启用；④-b **反向**：两条已启用 pin 的 `physical`/`controller` 命中该平台 `conflicts` 集的同一子集而未声明同组 ⇒ **漏声明即红**（F-8：坑 1 是"不同脚但同外设矩阵"，③ 抓不到，自愿式 `mux_group` 同样抓不到） | 平台 `conflicts` 集缺失 → 该平台所有 ④ 判据红（不许"无表 = 无冲突"） | 拒 | 装载期 + 平台侧 `conflicts`（与 role→具名构造表同处一张表） |
| ⑤ | 方向与能力合法（**拆两半**） | ⑤-a `direction=out` 且 `input_only_ok=false` → `physical` 不得落平台 input-only 集；⑤-b **模拟测点必须落平台 ADC 能力集**（F-9：`ADC_RAIL_PIN=34` 恰证"有 ADC 的脚是子集"，测点落 GPIO23 读回 0 mV ⇒ 档位恒真或恒假） | 平台能力集（`adc`/`input_only`/`output_only`）无数据 → 红 | 拒 | 装载期；能力集与 `conflicts` 同一份平台侧数据，被 ④⑤⑧ 共引 |
| ⑥ | 有轨、轨在册、绑定归一 | ⑥-a `pins.rail ∈ supplies.domain.names`；⑥-b `kind=power` 角色必有 `rail`；⑥-c `armed=true` 必有 `sense ≠ none` **且该测点 `age_ms ≤ max_age_ms`**（§19 Y-4 加强：无龄期的快门值不得充当拒动 / 放动的依据；**刻意不新增判定位**，免得触发 §19 X-4 那类"改一处口径要扫全仓"的改名）；⑥-d `sense`/`current_sense`/`switch` **一律写 `pin_id`** 且能在 `[pins]` 取到（F-2：首版 `sense="adc:gp34"` 是第二套语法，八条校验一条都打不到它） | `rail`/`sense` 缺 → 红（`sense = "none"` 是合法显式值，留空不是）；`armed=true` 而无 `max_age_ms` → 红 | 拒 | 装载期 |
| ⑦ | 接线闭合与**额定加总** | ⑦-a `wire.signal ⊆ pin_id ∪ {vcc,gnd}`；⑦-b `wire.net ⊆ domains`；⑦-c `rated_a × 1000 ≥ Σ(该 wire 的 feeds 闭包内 peak_ma) × 裕量`（F-10：逐条判单角色 ⇒ 主供线 1 A 载 2.2 A 峰值全绿，那正是本周 BOD 的实物形状）；⑦-d `wire.mate ∈ devices.toml 的 mate 集`（§4.1b） | `feeds`/`rated_a`/`keyed` 缺 → 红 | 拒 | 装载期 + 出厂自检（§17） |
| ⑧ | 表与绑定对账（**键定形**） | ⑧-a 键 = 三元 `(controller, role, instance)`，不是 role 也不是 instance（F-11：按 role 建键时 `controller="pca9685@0x40"` 命中同键却走 LEDC 构造 ⇒ 绿而实机控制器错）；⑧-b `controller ∈ 该平台的在册控制器词表`——**词表不是器件型号**，故与 §12 D10a"装载期不认型号"同时成立 | 构造表某三元键无绑定 / 绑定取不到构造 → 双向都红 | 拒 | 平台侧 + 装载期 |
| ⑨ | 电流预算 | `Σ demands.peak_ma (critical=true) ≤ domains[rail].current_cap_ma`；**"并发"缺省 = 全部同时**（最坏），不重叠必须是数据 `concurrency_group`，不许运行期推断（F-12：原文"并发窗口内"无数据源 ⇒ 恒可满足） | 件未申报 `demands` 而角色 `kind=power` → 红；`current_cap_ma` 缺 → 红 | 拒 | `rrd` 装载（与门 c 同步） |
| ⑩ | 栈与堆（**拆两条**） | ⑩-a `Σ task_stack_bytes ≤ 平台栈预算`；⑩-b `Σ heap_peak_bytes ≤ 平台可用堆 − 常驻`（F-13：只加总栈，则 `UART2_TX_RING=16384`、`AUDIO_Q_CAP`、渲染缓冲与**批N4 要新立的板侧配置服务**全不计） | "平台可用 RAM/堆"必须来自 `[supplies].budget`，缺 → 红 | 拒（仅 rtos/bare 档；host 档显式 `not-applicable`，不许留空） | `[supplies].budget` + 装载期 |

**合计 24 个判定位**（①② 各 2、③ 3、④⑤⑧ 各 2、⑥⑦ 各 4、⑨ 1、⑩ 2）；本节一律称**"装载期十条校验"**，
条目数不是判定位数——**引用它必须写到"第 ⑦-c 位"这一级**，否则"十条全过"这句话不可核
（同 §18 F-20 的集合宣称规矩）。
**名字撞车已在 §19 查出并修**："**十项**"在本仓另有第二个所指 = §17 **可达终点表的十项**
（出字 / 转动 / 拾音 / 播放 / 配网 / 观测 / 标定 / 烧录 / 升级 / 回滚）。两个含义共用一个词，
就是"一个事实一个名字"破了口 ⇒ 纪律固定为：**装载侧一律写"十条校验"，产线侧一律写"十项"**，
引用旧文档里的"十项校验"时须加本指针。
**这十条是"裁剪调度依据能源"的字面实现**：今天串行降级、降亮、限幅全都是它的事后补救版本。

## 6 标定与复位方案（用户点名的"电机怎么复位标定"）

**问题定性**：SG90 类位置舵机在**开环**下没有位置反馈，所以"标定"不可能标出角度，只能标出
**脉宽域与机械窗的关系**。任何把 `angle()` 回读当位置的说法都是 §1 坑 11 的重演。
可标定的对象恰为四件：**脉宽中点、方向符号、上下软挡块的脉宽、到位后是否释放激磁**。

| 路线 | 做法 | 前置 | 风险与护栏 | 本轮定位 |
|---|---|---|---|---|
| **A 工装标定** | 治具/量角器把轴固定在物理中位，逐点写脉宽（现有 `真件装配与标定手册` 的 INA219 两点标定同型流程） | 治具 | 低 | **立即可用**，随批N3 落手册与档案写入 |
| **B 电流找挡块** | 向已知方向以限流限时的步进推到硬挡块，用电流尖峰识别到位，记两端脉宽 | **`domains[].current_sense` 必须存在**（§1 坑 9：今天只有轨压、无电流） | **受控堵转**，正是烧舵机的机理 → 必须限流（`current_ceil_ma`）、限时（单步 deadline）、限次数、限单步角，失败即退回上一份档案 | **依赖 N2**，不作默认 |
| **C 开环自恢复 + 软挡块** | 上电以极低速率向一侧走到软挡块（时间窗 + 电流上限），以该脉宽为边界推中点，运行期越界**拒收点名**（不静默钳位，沿用 `axis_check` 现有 fail-closed 语义） | 档案写入面即可起步；**"自动扫到挡块"这段需逐域电流上限 ⇒ 需批N2**（§18 F-15：本行原写前置"仅档案写入面"，而护栏里的"电流上限"与路线 B 同源，今天没有采样） | 中；有采样时靠"低速 + 短窗 + 上限 + 释放激磁"四重控住；**无采样时护栏只剩时间窗，而窗内 700 mA 持续堵转正是发热本体**（坑 9 实测 ~700 mA/只）——所以 N2 之前本路线**不得自动连续扫**，只允许单步点动 + 人工确认 | **默认路线**（D13 已裁，本表此前未随 §12 回写——本轮一并补齐；批N3 自动化段随批N2 采样到位后开） |
| **D 换闭环执行器** | 带位置反馈的舵机/步进 | 新格 + 新 trait（`act.axis.enc`），走契约级评审 | 低但成本与选型变化 | **本版不做**，只在角色表预留 `act.axis.enc`（预留不 = 立格） |

**复位语义（四档，契约里必须分开写，今天混在"boot 置 90°"一句里）**：
① **归中**（到 `center_deg`，需已标定）；② **归安全姿态**（`BOOT_PAN_DEG`/`BOOT_TILT_DEG` 这类形态默认，
是策略、进 profile）；③ **失能归位**（欠压/看门狗复位后`failsafe=release` → 不保持激磁，让轴自由，
避免复位循环里反复堵转——这条是方案A"不保持激磁"的遗留敞口，本轮升为 `[pins].failsafe` 的数据）；
④ **复位后的闸门与标定态**（§19 Y-3/Y-7 新立，是这一节真正的缺口）：
`Rr3LowGate` 是纯内存的一位（`rr-mech/src/control.rs:99-125`，`rr3_low_gate_new()` → `blocked:false`），
**复位即开闸**，而 BOD 复位循环的形状正是"欠压 → 复位 → 开闸 → 再推舵机"；
同理 `calibrated` 若住在不存在的 `Rr3Store` 里（§19 Y-7），rtos 档重启后"标定过"这件事今天**无处可存**。
裁定：**运行期内存开关复位后的默认值必须是保守的那一侧**——闸门复位后默认**不开闸**，
须先取到一次合法轨压样本（`age_ms` 在 `max_age_ms` 限内）才允许进入 `trip/release` 判定；
`calibrated` 在载体实测（NVS `set_blob` 掉电原子性 / 写放大 / 容量上限三项）之前
**只允许运行期内存态**，且 §17 可达终点表的 rtos 行必须写"重启即失"这一句。
"回阈不自动重放"这句在代码上的真身是"**没有重放实现**"（控制环不持队列），
所以它不能被子孙后代当成"禁止重放已被执法"——文档措辞按此收窄（power **P-14**）。

**"未标定不得自动"是硬约束**：`calibrated=false` 的轴，`Rr3Actuator::rr3_goto` 只接受点动（带 deadline），
拒绝任何自动扫摆/表情联动动作——否则上电即拿一个假中位跑 WANDER，就是坑 9 的下一次发生。

## 7 面板 = 配置面（本全案的第四件产品要求）

**三个面，缺一不可**（今天只有第二个的一半）：

| 面 | 内容 | 今天 | 目标 |
|---|---|---|---|
| **观测** | 生效绑定快照（描述符 + 应急覆盖 + 档案三者合成后的那份）、逐域 mV/mA/tier/armed、每轴位置与 `source`、标定状态、渲染失败计数、音频丢帧、后端选择落点（含"落 sim"的显式点名） | 14 端点里 5 个 GET，全是运行态（status/data/logs/scan/keys），**零配置可见** | 面板覆盖率门的"观测半边"，逐项可查 |
| **配置** | 全部 `ops` 槽 + `[hardware]`/`[pins]` 键 + 域阈值 + 亮度阶梯 + 档案字段 | 写面只有 relay/beep/face/selftest/reboot/wifi/model-key | **覆盖率门**：`面板项集 ⊇ 可配置集`，差非空即红 |
| **动作** | 点动、回中、标定（路线 A/C 流程）、自检（`[pins]×wiring` 全交叉）、接线图 | `/api/selftest` 一个笼统端点 | 逐动作端点 + 全部留痕 |

**写权限边界（不许越界）**：面板可写 = 策略量；不可写 = 契约量（格定义、主题、字节头、角色定义、
`tier_scope`）。欠压阈与 `armed` 位属**安全相关策略量**：写须带二次确认 + 旧值回显 + 审计行
（今天面板密钥面的"值零回显"纪律是同族，把它抽成面板写面的通用规则）。

**两条本轮补的硬要求（§19 Y-1/Y-2，缺任何一条本节都是空头承诺）**：

1. **每个可写量必须标 `applies`**（`live` 即时生效｜`reboot` 重启进程生效｜`reflash` 重烧固件生效）。
   这条不是锦上添花：实测 `RAIL_MILD_MV`/`RAIL_SEVERE_MV`/`RAIL_GATE_ARMED` 是
   `pub(crate) const`（`tools/esp32-periph-base/src/board.rs:204,207,213`），全仓 `SIGHUP`/`reload`
   **零命中**，`RR3_PANEL_ROUTES` 14 端点里**没有任何阈值或 `armed` 写口**（`panel/server.rs:86-101`）
   ⇒ 今天"面板写阈值"这句话在 rtos 档等于"**重烧固件**"。UI 必须把这一点显式告诉操作者，
   写口与 `applies` 一并进门 ⑩ 的 `covers` 申报面（interact **I-19/I-20**）。
2. **落盘只许有一份实现**：仓内唯一完整的原子序是 `rrd/src/counters.rs:110-124`
   （写 tmp → `sync_all()` → 同目录 `rename` → 失败清 tmp）；而面板现存唯一的写落盘
   `panel/secrets.rs:95-105` 是 `truncate(true)` **原地覆盖、无 rename、无 fsync**，
   读侧（:44-67）遇坏 JSON 回 `Err` 且**不覆盖** ⇒ 一次掉电卡在写中间，凭据文件从此恒 `Err` 且**不能自愈**。
   裁定：**轴档案、域阈值、`armed`、凭据的写一律复用那一份原子序**，
   新实现出现第二条写路径即红（这是 L-23"新加一层没迁旧一层"在写路径上的形态，interact **I-20**）。

**rtos/bare 档的面板在哪**（这是裁定 1"三形态独立"的直接后果）：不能假设"经桥后宿主面板顺带看见它"。
方案：板侧一个**极简配置服务**（角色/域/档案/阈值的只读 + 阈值与档案的受限写），承载在 WiFi；
BLE **不立为必达**（D12 已裁：`net.bt` 改判为"bare 档运维入口"的占位，rtos 档配置面走 WiFi/HTTP）。

**这句话的代价必须自己说清（§18 F-18）**：本节的"承载在 WiFi（rtos 档已在册）"里，
"在册"指的是 `net.wifi` 这条**格的状态**，不是能力。实测板侧对 HTTP/HTTPS/TLS/TCP/BLE/gatt
**零命中**——板上的 WiFi 只用来配网与链路读数，**没有服务器、没有客户端协议栈**。
所以"板自己的配置入口"是一块**零码事实的全新工作面**：要选 HTTP 服务器组件、要算它吃掉的堆
（并入 §5 校验 ⑩-b，与 `UART2_TX_RING=16384`、`AUDIO_Q_CAP`、渲染缓冲同批加总），
还要定它是否需要 TLS（要，则凭据面又长出一块）。**这一件没做完，D6"每形态至少一条配置腿"就是空头**。
工单 connect **N-13**，排在批N4 之前作为它的**前置**（§9 已补）。

**批N5（生产与运维闭环）是 2026-10-15 全代码复盘后追加的第五批**，细则与判据见 §17。
它的排序理由与 N1–N4 不同源：N1–N4 的产物是**数据结构与门**，而 N5 的第一件交付物
（按形态分档的**可达终点表**）**不依赖任何新契约，可以先行**——因为复盘最硬的结论正是
"诚实标注处处在，但没人回答新人今天能做到哪一步"，那件事不需要等键集定形。
N5 的其余项（烧录与镜像装配、逐腿自检、回滚面、日志落盘）消费 N1–N4 的形状，故排在其后。

**顺序的裁定依据**：用户口径"**不是根据人员，是根据能源**"——批次排序按**资源约束的依赖方向**，
不按谁有空。能源（N2）在执行件（N3）之前，因为执行件的电流上限、标定路线 B、拒动语义全都以域为参照；
面板（N4）在最后，因为它显示的是前三批的形状。批 N1 之所以最先，是因为它是另外三批的数据结构前提。

## 11 不做清单（每条都写为什么不值）

| 不做 | 理由 |
|---|---|
| 把 `esp32-periph-base` 拆成"件模块进 xtensa 门"（MC-7 三缺） | 那是格位化的活，判据已在批M MC-7 登记；本全案先把**形状**立住——反过来做会得到一套没有契约支撑的拆件 |
| 上电即自动找挡块（路线 B 默认化） | 受控堵转在无电流采样 + 未标定挡块的板上 = 第二次烧舵机的最短路径（§1 坑 9/10 的直白重复） |
| 为 ESP32 形态新建独立主题前缀 `rr3-mini/*` | 前缀归属是契约级决策且依赖"独立形态是否自发布"的裁定（D14）；先改前缀会造出一批无消费者的主题 |
| BLE 全量配置面板 | `net.bt` 还是 placeholder；先把 WiFi 面的覆盖率立住，BLE 面等 D12 |
| 引入外部引脚/接线 EDA 工具链 | 底座只需要"角色-绑定-接线"三份 TOML 与八校验；引工具 = 新依赖、新失败模式，收益不比一条 `grep` 门高 |
| 把传感按器件型号扩格（DHT11 一格、BMP280 一格…） | 坐标系会瞬间爆掉且违反"格 = 能力"的定义；本全案的答法是**一张格 + 角色表 + 器件档案**（§3.5） |
| 在机制核写"能源策略" | 策略出核是纲领；本轮只新增**数据结构与判据**，域阈值/降载顺序都是 profile 与 ops 注入值 |

## 12 裁定记录（2026-10-14：D10–D15 与顺带三条，按已达成的工程思想定案）

用户口径"按最优方案决策"，所以本节**不抛选择题**，逐条给结论。每条都标出**依据的是哪条既有共识**
（而不是我的偏好），并区分两种性质：**〔原则推出〕**= 从已达成的工程思想必然得出，改动它要新立 ADR；
**〔设计默认〕**= 硬件/采购取向，我现在定，**撤回只需同批改本行与对应取值，不动结构**。

### 12.1 本轮新发现的一条**真缺陷**（裁定过程中查出来的，登记为 L-14）

核查 D15 时顺带兑现我上一轮的自证承诺：**宿主探测会不会把"从机不在"判成"在位"**。
实况与"假 ACK"不同，而且**更宽松**：`rrd/src/probe.rs` 的 `Rr3LinuxProbe::rr3_face_present`
对 I2C 只判 `/dev` 下存在任一 `i2c-` 条目，对 SPI 只判存在 `spidev`——**判的是控制器/总线适配器在位，
从不向从机地址发探问、不看应答**。后果：

- `power.charger` / `sensor.env` / `sensor.imu` 三格**只要 I2C 总线在，就恒判在位**，器件没接也绿；
- 于是缺格降级环在这三格上**照旧不转**（与索引 L-3/L-5"探测恒真"同一族，但这次不是 sim 桩，是真探针的粒度错位）；
- 而 ESP32 板侧已经用血付过"器件不应答"的代价（SSD1306 丢拍/NACK 一类），宿主侧只是**同一件事的更隐蔽版本**。

**收敛动作（归批N1，因为键集与 `[pins]` 同批才有 `addr` 可用）**：器件级探测 = 对装机档在册的
`addr` 做一次**寄存器 ID / 特征字节读回比对**（读不到或不匹配 ⇒ 该格 `Degraded`，点名到 `role` 与 `addr`），
总线级判据降为**前置条件**而非在位证据。门禁判据 = 用例必须覆盖"总线在、器件不在"这一格
（今天它不存在，所以缺陷不可见）。落点：索引 §11 新增 **L-14**、power/sense 两册各一单、status 敞口表加一行。

**这条为什么要写进文档而不是顺手改掉**：它正是本全案判据 ① 的标准案例——
"发现一个探测粒度错误"如果只改成一行代码，教训就留在 commit message 里；
升格成 ④ 格语义 + ⑤ 门禁判据（"总线在位 ≠ 器件在位"必须有反例用例）才算收口。

## 15 主线一致性二轮审查（2026-10-14：**策略仍住在机制位**的无主项清单）

用户口径"以机制和策略分离为主线"。所以这一节不做泛泛复查，只做一件事：
**逐个找出"这是策略，但它住在机制位"的位点**，并且每条必须回答三问——
① 它有没有工单号（无号 = 无主，等于没人负责）；② 它有没有执法对象（门/键/格/trait 之一）；
③ 它阻碍生产还是运维。**下列每条都在本轮用 `grep` 自核过符号现存性**（子代理报的
`RR3_BOARD_TOKENS` 差异、`"idle"` 处数等有一条不实，已剔除，见 §15.4）。

## 17 批N5（新立）：生产与运维闭环——把"新人能做到哪一步"变成一份表

复盘最硬的一条结论不是"缺代码"，而是：**每一处诚实标注都在，但没有任何一处回答"这个形态现在能走到哪一步"**。
所以批N5 的第一件交付物不是脚本，是一张表。

| 面 | 批N5 要做的事 | 判据（可证伪） | 前置 |
|---|---|---|---|
| **可达终点表** | 按形态分三行（RK3566 / 树莓派 / ESP32），每行逐格写"出字 / 转动 / 拾音 / 播放 / 配网 / 观测 / 标定 / 烧录 / 升级 / 回滚"十项的 **今天能做到｜不能｜缺什么（缺码+工单号 或 无载体+触发条件）**。**订正（§18 F-28）**：原写"由 §16 的结构化开放项数据**生成**，不手写"——§16 是散文表格、没有数据文件，而开放项数据结构是 ADR-0022 裁定 6.3 的产物、排在**批N4** ⇒ 按它自己的判据首件**不可先行**。改判：**首版手写 + 逐格标 `文件:符号` 或敞口号**，"由数据生成"随 Nn-6.3 落地后建立 | 表内每一格都能指到一个 `文件:符号` 或一条已登记敞口；出现"应该可以"这类句子即 FAIL；**每格三态各有必填字段**（"不能"必须带触发条件，"能做到"必须带符号） | 无（纯文档）；生成关系随批N4 |
| 烧录与装机 | ESP32 侧把 `espflash` 手工 runner 收成一个带版本与校验的脚本；host 侧 `rr3-pack` 扩 `[pins]`/`domains`/`wiring.toml`/轴档案入包（`.gitignore` 同批放开 `hardware/`） | **订正（§18 F-29，撤回原判据）**：原写"一个新人能在**不带 `RR3_HAL_BACKEND`** 的情况下不静默落 sim 完成出字+转动+拾音"——那三项在 rtos 形态是**板自己的**，与该环境变量无关（它只在**经桥**的宿主侧有意义），这句把 §2 条 2 刚拆开的**承载档 × 链路两轴又混回一处**。改判为两行各自独立判：**rtos 自足** = 烧录后板自己出字 + 转动 + 拾音并打守护行（无宿主参与）；**经桥** = 宿主 env/描述符齐备后三腿通，且**缺后端即红、不静默落 sim**（ADR-0022 裁定 4） | 批N1（键集与档案形状） |
| 出厂自检 | `selftest` 逐腿输出 `{腿, pass｜fail｜not-applicable, 原因}`，**恒败腿不得折算成通过**（D15 裁定）；接线自检按 `[pins] × wiring` 全交叉点名（wiring 带 `feeds` 后按 §5 ⑦-c 加总判）；出声与出字各有判据（测试音为策略件内置波形或撤端点） | **订正（§18 F-31）**：原写"把某腿强制改坏，自检整体必须变红"——若已有恒败腿，整体**已经红**，改坏前后无法区分，判据失去判别力。改判为"**逐腿结果集与预期集等值**"（三态 + 预期表），整体红绿是派生量而非判据 | 批N4 |
| 升级与回滚 | host 侧补齐 `bootcount`/`altbootcmd`/`upgrade_available` 的写入与自动回滚（今天只到"翻 extlinux 标志"）；**ESP32 侧明确本形态的回滚语义是什么**（无 FS 无 A/B 时"不可回滚"也是一句合格答案，但必须写进表） | `rr3.ctl.ota` 解除恒拒需 M6 评审；表内"不能"一格必须带触发条件 | M1（载体） |
| 运维留痕 | 日志环有界落盘（或交 journal 并在手册写取数法）；环容量进描述符（不再硬编码）；`low_power` 旗补解除路径（今天只升不降） | **订正（§18 F-30，撤回原判据半句）**：原写"`ps` 看不到环容量常量"——`RR3_LOG_RING_CAP = 512` 是**编译期常量**，从来不出现在 `ps e`（那里只有环境变量），这条**恒真**等于没写。改判为"**环容量 ∈ 描述符键集，装载期缺即红**"（与 §5 缺失语义同列）；另一半保留：一次重启后仍能取到崩溃前的最后 N 行 | 批N4 |

**为什么它是第五批而不是插进 N1–N4**：批N1–N4 产的是**数据结构与门**，批N5 消费它们才有意义
（可达终点表要读结构化开放项、装机自检要读 `[pins]`/wiring、入包要等新段形状）。
但表本身可以立刻做——它不依赖任何新契约，且它是当前**唯一能马上回答用户问题**（"现在能到哪一步"）
的交付物。故表 = 批N5 首件，其余项随批N1–N4 收敛后再排（本段"表可先行"那句已被 §18 F-28 订正）。

## 18 逐项证伪审查（第三轮，2026-10-15：给每一条具体设计配一条"能推翻它的观测"）

**本轮做的不是复查完备性**，那已在 §15/§16 各做过一轮。本轮只回答一个问题，逐条回答：
**"什么观测能推翻这条设计？"**，并把反例构造到**"不改变任何硬件形状、只改装机档或一句话，就能让门变绿"**
的粒度。三类结论算击穿：

- **① 可留空绕过**——判据的作用域由一个**自愿填写的字段**决定，不填即不判；
- **② 恒真 / 恒绿**——判据在任何配置下都满足，或建在一个没有内容的段/一个不可能出现的观测上；
- **③ 不可判定**——判据引用了文档里**没定义的等式、键集或取值域**，实现者只能自由裁量。

① 与纲领 §0 判据 ① 同族且更隐蔽：**留空比注释更隐蔽**（注释至少看得见，空字段看起来"合法"）。
本轮每条反例的前提都是我自己 grep/读码核到的 `文件:行`，不是转述。

### 18.1 三条统一结论（升格为索引 §11 **L-22 / L-23 / L-24**）

| 编号 | 结论 | 为什么这是新的一类等价失败 |
|---|---|---|
| **L-22** | **自愿填写的字段是注释搬了家**。`mux_group`/`failsafe`/`rated_a`/`keyed`/`covers` 这类"由外设作者主动声明"的位，缺声明即不判 ⇒ 本全案用来消灭"事实住注释"的数据结构，**自身成了事实的新住处**；下一个形态不会写注释，同样也不会写 `mux_group` | 前两轮打的是"事实住 prose/注释"；这一轮打的是"**判据的作用域由被检查者自己划定**"。修法只有一种：**由平台侧在册表反推该谁声明**（漏声明即红），加上**字段缺失一律红**（仓内已有正确范式：`assemble.rs` 的 `no_injection`——两数组均空时该键必填否则判红，本全案 §5 照此补一列） |
| **L-23** | **新设计自带第二真值点**：`[hardware]` 九键 / `[pins]` 字段 / `sense="i2c:…@0x40"` 串 / `wire.signal` 点分名，是**同一个"哪个信号接到哪个硬件"事实的四套语法**，而校验只覆盖第四套 | 不是抄漏，是**加了一层没迁一层**。`profiles/default.toml:64-65` 的 `i2c_bus=1` + `ina219_addr="0x40"` 与 §3.4 的 `bus="i2c0"` + `addr=0x3C` 是同域数据两种写法；件面 `handles[].desc_key` 已被 `RR3_ASSEMBLE_DESC_KEYS`（`assemble.rs:55-66`）执法，而新段没有任何一条门要求它与旧键收敛 |
| **L-24** | **判据恒真是判据缺失**：本轮抓到 5 处（⑨"并发窗口内"、门 j 落在空段、门 d 的分母粒度、"`ps` 看不到常量"、`kind != logic` 引用不存在的取值） | 这类比"门太松"更糟：**它给出绿色的确定性**，而松的门至少会在评审时被人质疑。凡判据里出现"窗口内""必要""相应"这类**没有数据源的限定词**，本轮一律按恒真处理并写明定义 |

### 18.7 审过且**成立**的（照实说，不缩水）

不是每条都被推翻。以下十条按同一把尺量过，**我构造不出反例**（构造不出的意思就是它的证伪观测已被判据覆盖）：

### 19.3 本轮新增的判据与执法（一句话版）

1. **生效路径三态**（`applies = live｜reboot｜reflash`）：凡面板 / 装机档可写量必填，缺失即红——
   与 §5"缺失语义"同一列，执法位 = 门 ⑩ 的 `covers` 申报面（interact **I-19/I-20**）。
2. **落盘原子序单点**：写侧一律复用 `counters.rs` 的 tmp→fsync→rename，**不许第二个实现**（L-23 在写路径上的形态）。
3. **复位后状态必须被设计**：每一个"运行期内存开关"（闸门、`low_power`、档位、`calibrated`）都要回答
   "复位后它是什么"，且**默认值必须是保守的那一侧**（不开闸 / 不解除 / 不自动）。§6 的复位三义据此扩为四义。
4. **新鲜度入契约**：任何被用于**判定**（而不是仅展示）的采样值必须带 `age_ms` 与 `max_age_ms`；
   无龄期的快门值不得作为拒动 / 放动的依据。
5. **故障传播表**：每条链路 / 每个窄缝都要有"重试·退避·超时·报废"四列；
   今天只有注释的地方（经桥阻塞读）在 §17 可达终点表里记为"不能 + 触发条件"，不许空着。
6. **不可判的判据要明写不可判**（X-5）：承载三档的"七位齐不齐"今天只有 2/7 位有键 ⇒
   要么补键、要么降级为"2 位机判 + 5 位靠自证表 / 运行期注册"，**三态都要写在 §12.2 的同一张表里**。

### 19.4 本轮沉淀的两条纪律（进 conventions）

- **改一处口径 = 扫一遍全仓同名字面量**。X-4 的成因不是写错，是**改判时只改了速查表与修订记录，
  没扫正文**；而正文才是被抄的那一份。纪律：任何口号 / 分母 / 判据数改动，必须 `grep -rF` 旧字面量，
  命中逐处判"历史注记（保留）/ 现行文字（改）"，并把"旧字面量在现行文字中为 0"作为收口判据
  （同我记忆里"改名要一次改完 + 旧标识符为 0 的门"）。
- **新增一层必改所有范围表述**（X-3）：批N5 立项后"批N1–N4"必须一起改；
  这类"N1–Nk"的区间写法本身就是易失分母，**引用批次范围时优先写全枚举**。
