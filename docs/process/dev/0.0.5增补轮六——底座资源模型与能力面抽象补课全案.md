# 0.0.5 增补轮六 —— 底座资源模型与能力面抽象补课全案

- **状态**：**已立项，未开工**（2026-10-14）。裁定原文 =
  [ADR-0021](../adr/ADR-0021-三独立形态与资源供给面-能力原子化补课.md)；本全案是它的**施工编排与字段级设计**。
- **归窗**：**开发窗**（承 [ADR-0020](../adr/ADR-0020-版本边界-开发收口与实机验证与验证后整理.md) 裁定 1）。
  本全案产代码 + 契约 + 门 + 用例；**板上证据仍归 0.0.6/0.0.7 验证窗**，本全案不产点验结论。
  本轮唯一"改文档"的产物就是本文件与 ADR-0021 及其回写面——**它不改任何 `.rs`**。
- **与前几轮的关系**：增补轮五（R31）把三功能在 ESP32 上做到"能跑"，本全案处理的是**它跑起来时暴露的
  底座形状问题**——同一句用户口径的两面：功能落地（轮五，已发生）与抽象补课（本轮，未做）。
  分账规则沿用 0.0.5 §18.4：**已交付的板侧行为不回炉重写**，本全案只把它的**归属**从私有 crate
  迁进契约面，并立"同类故障不在第二块板重现"的门。

## 0 判据（本轮的收口标准，先立再开工）

两条，都可机械复查：

1. **五处升格判据**：每一个坑必须升格为下列之一，否则只算一次现场处置、不算收口——
   ① 供给位（`[supplies]`） ② 能力面 trait（`rr-hal-api`） ③ 描述符键（`[hardware]`/`[pins]`）
   ④ 格或主题（`slots.toml`/`topics.toml`） ⑤ 门禁判据（`check.sh` 某步）。
2. **第二平台重现判据**：同一类故障在第二个平台重现 = 抽象失败。本轮立项的直接触发器就是这条——
   引脚互斥跨平台出现过**两次**：ESP32 上 GPIO16/17↔I2C0 **实际撞上并被迫改线**（迁到 18/19，而 19
   又与点阵 VSPI 预留同脚，注释自述"点阵立项时需再迁，已在案"）；树莓派路线上 I2S 双麦与 SG90 硬件 PWM
   在 GPIO18/19 的互斥**被文档预测到**（0.0.6 §5.4 条 9"须先钉引脚预算表再采购"），靠该路线整体改挂
   ESP32 而侥幸未演化为损失。**两次都只留下注释与条款，装载期没有任何可查的数据结构**——
   侥幸不是抽象成功，因为下一个形态不会读注释。

**为什么判据 2 比"修好"更硬**：本周每个具体故障都能被一次改动修掉（换引脚、降亮度、串行走），
但修完之后**底座对下一个形态没有任何新约束**——那正是"做出来的 ESP 板的东西复用到树莓派上"失败的机制。
本轮的目标不是让 ESP32 更好用，是让**第三个形态不再犯这些错**。

## 2 三独立形态（把谱系从"主形态 + 附件"改成两轴）

| 形态（产品轴） | 承载档（技术轴） | 格集 | 链路 | 认知 | 观测面 | 现役状态 |
|---|---|---|---|---|---|---|
| **RK3566 桌面具身** | host | 全 21 格（目标态） | 自身 WiFi/以太网 | 本地或云（`cognition.*`） | rrd 日志环 + 面板 | 目标板未采购（M1 敞口） |
| **树莓派** | host | 实然 17 项 + base | 自身 WiFi | 云 API | rrd + 面板（**0.0.6 已点验的那台**） | 平台级点验待补（不新增功能码） |
| **ESP32 微型** | rtos | `act.servo`+`audio.capture`+`audio.vad`+`ui.face`+（本全案后加 `power.rail`） | 自身 WiFi（配网）；**桥是可选能力升级**，不是组成部分 | 经桥取 host 形态或直连云 API | **板自己的守护输出 + 板自己的配置入口** | 四件已在板上真跑（轮五），底座形状未收 |

三条读法（这三句是本全案的约束，不是描述）：

1. **形态之间只共享机制核与契约**，不共享进程、不共享总线、不共享供电。任何"由宿主替它管外设/管观测"
   的设计都是裁定 1 作废的旧口径残留，见到就改。
2. **桥不是承载档**。`F-B 桥接微型` 这个词把"rtos 档"和"经桥"混成了一个标签；现拆为
   承载档 ∈ {host, rtos, bare} × 链路 ∈ {无桥, 经桥}，两轴独立。`ADR-0018 修订 4 ③` 那句
   "经桥档 task 号走注册态"仍然成立，只是它的条件从"是 F-B"改成"链路 = 经桥"。
3. **每个形态都要能独立回答"我此刻能给外设多少电流、哪条线接在哪、这个轴标定过没有"**——
   答不出这三问的形态不是被裁剪过的机器人，是等待复发的固件（判据同索引 §11 L-1）。

## 3 逐部件能力原子化盘点

模板固定十一问，每个部件逐条回答；**答不出某一条就是这一条的缺口**，本全案把它登记进 §1 表或 §9 批次。
十一问 = ① 现在契约里它是什么（符号级） ② 缺什么抽象 ③ 角色名 ④ profile 绑定字段 ⑤ 供给与预算
⑥ 能力面（按增长律新增，不改既有 trait） ⑦ 件申报 `handles`/`ops`/`demands` ⑧ 降级语义 ⑨ 面板可观测项
⑩ 面板可写项 ⑪ 标定/复位与"教训落点五处之一"。

### 3.1 家族 A · 能源（电池 / 充电 / 轨与域 / 采样 / 激磁供电）

| 部件 | ① 现在是什么 | ② 缺什么 | ③ 角色 | ④ profile 键 | ⑤ 供给与预算 | ⑥ 能力面增补 |
|---|---|---|---|---|---|---|
| 电池读数 | `Rr3Power::battery() -> Rr3BatteryState{voltage_mv,percent,charging}`，单值单域 | 多域概念；无阈值语义；无"能不能用"的判定 | `power.battery.sense` | `battery.sense = "i2c:ina219@0x40"` | `[[supplies.domain]] name="batt"` | 保留 `Rr3Power`（不动），新立 `Rr3Rail` |

**降级语义（⑧）**：`tier=Ok` 全能力；`Mild` 执行面串行 + 显示降档 + 采样降频；`Severe` **执行面拒动**
（MC-5 `Rr3LowGate` 语义：拒动、妆面不禁、回阈不自动重放）。
`armed=false` 时档位照算、越阈照报（守护输出行 + 面板），**但不驱动拒动**——这条纪律
（`RAIL_GATE_ARMED`）从"一块板的临时措施"升为**契约级字段**：任何域未标定即 `armed=false`，
装载期不许有 `armed=true` 且 `sense="none"` 的组合（校验 ⑥ 的加强形）。
**面板（⑨⑩）**：每域实时 mV/mA、tier、armed、阈值、分压比、`sensing_source`；可写 = 阈值与分压比（带二次确认）。
**落点（⑪）**：坑 4/5/9 → **① 供给位 + ② 能力面 + ④ 格**（`power.rail`、`power.budget` 两格 + 一条
`rr3-power/rail/state` 主题；bare 档经守护输出行，不发主题）。

| **带宽与节拍（UART 组帧 680ms→11.7ms）** | 板侧 `UART2_TX_RING=16384` 常量 + 注释里的因果链 | **环大小 / 分片帧数 / 波特率是资源参数**，今天住 `board.rs` | — | `[hardware]` 扩：`link.uart.baud`、`link.uart.tx_ring`、`audio.chunk_frames` | 传输供给（缝二） | 落点 = ③ 键 |

**⑧ 降级**：音频面在 `Mild` 不降（峰值电流小、非执行器）；轨压 `Severe` 也不禁声——**"拒动只拒动"
这条边界要写进契约**（今天靠 `Rr3LowGate` 的实现范围偶然成立）。
**⑨⑩ 面板**：实时电平表与丢帧计数（`audio_dropped` 与宿主 seq 断档互为对账，已在板侧注释）；可写 = 增益/分片/速率。
**⑪ 落点**：坑 7/12 + "esp32 档静默落 sim" → ③ 键 + ⑤ 门（后端选择若落 `sim` 必须在 boot 行**显式点名**，
不许静默；这条并入 §8 的 ⑨ 门）。

## 4 数据结构定形（本全案唯一"字段级"章节，其余各节都引它）

### 4.1 `contracts/roles.toml`（新建，契约层，`schema_version = 1`）

```toml
# 角色词表：跨形态共享的"这类信号叫什么、属于哪张格、能不能被降载切"。
# 消费方：profiles [pins] 的 role 外键、rr-registry 查册门、面板配置项生成、门禁四表对账。
[[role]]
name = "act.axis.pwm"        # 角色名（点分式，前缀 = 格名的动作侧）
slot = "act.servo"           # 外键 → contracts/slots.toml
kind = "power"               # signal | power（功率类必须带 rail）
direction = "out"            # out | in | io | passive
droppable = true             # 欠压降载时可否被切断
input_only_ok = false        # 该角色是否允许绑到 input-only 引脚
per_instance = true          # 一角色可多实例（双轴即两条 instance）
note = "SG90 类位置舵机；行程与标定不住这里（住执行件档案）"
```

**纪律**：角色 ↔ 格 ↔ trait ↔ 描述符键 **四表一致**由门禁判等（§8 门 a）。加一类外设 = 同批改四处，
一次评审；这是裁定 4 撤销"闭集"之后防止键域自由生长的**唯一**替代物。

### 4.2 `profiles/<形态>.toml` 的 `[pins]`（描述符第八段）


### 4.3 `hardware/<形态>/wiring.toml`（装机档：机器可查、人照它插线）

```toml
[[wire]]
connector = "J3"           # 板上连接器位号
hdr_pin = [2, 3, 4]        # 排针物理序号（与 hdr 丝印一致）
signal = ["vcc", "act.axis.pwm.pan", "gnd"]   # vcc/gnd 之外必须是 roles 在册角色
net = "rail5v"             # 电力网络 → domains 外键
mate = "SG90-3P"           # 对端连接器型号（防呆判据：不同型不许互插）
keyed = true               # 有无物理防呆
rated_a = 1.0              # 线材额定电流（> 该角色 demands.peak_ma/1000 才合格，校验判这条）
gnd_common = "star-1"      # 共地点标识（"单点共地铁律"的数据位）
```

**诚实边界（必须写在文件头）**：接线档拦不住人插错线——坑 10 的直接原因是物理的。
它的作用是把接线变成**可检查的数据**：面板出图、出厂自检逐条点名、`rated_a` 与 `demands.peak_ma`
互相校验（**用 1A 线跑 700mA 峰值 + 堵转裕量的那条投诉，从此是可判红的**）。

## 5 装载期八校验（判据级，逐条写清"谁实现、红什么"）

| # | 校验 | 判据（可证伪形式） | 实现落点 | 红时的文案 |
|---|---|---|---|---|
| ① | 角色在册 | `pins.role ∈ roles.names` | `rr-registry` 查册门 + `rrd`/装配段 | `角色 {x} 不在册（contracts/roles.toml）` |
| ② | 所需角色齐 | `∀ g ∈ ([slots].present ∩ enabled_slots): roles(slot=g) ⊆ pins.role`，缺即该格 `Degraded` | `rrd` 装配链（与缺格三源合一同一处） | `格 {g} 需角色 {r}，[pins] 未绑 → {g} Degraded` |
| ③ | 不双占 | 同一 `physical` 元素在启用集里出现 ≤ 1 次 | 装载期 | `引脚 {n} 被角色 {a} 与 {b} 同时占用` |
| ④ | 互斥组 | 同 `mux_group` 成员至多一个启用 | 装载期 | `互斥组 {g}：{a}/{b} 同启（本平台不可共存）` |
| ⑤ | 方向合法 | `direction=out` 且角色 `input_only_ok=false` → `physical` 不得落平台 input-only 集 | 装载期（平台保留集来自 role→构造表旁表） | `{n} 是输入专用引脚，不得作输出角色 {r}` |
| ⑥ | 有轨且轨在册 | `pins.rail ∈ supplies.domain.names`；`kind=power` 角色必有 `rail`；`armed=true` 必有 `sense≠none` | 装载期 | `角色 {r} 未归域 / 域 {d} 未在 [supplies] 声明` |
| ⑦ | 接线闭合 | `wire.signal ⊆ pins.role ∪ {vcc,gnd}` 且 `wire.net ⊆ domains` 且 `rated_a × 1000 ≥ 该角色 demands.peak_ma` | 装载期 + 出厂自检 | `J3.2-4 的 signal {s} 未绑 / 线额定 {a}A 载不动峰值 {ma}mA` |
| ⑧ | 表与绑定对账 | 平台 `role→具名构造` 表的键集 ⊆ `pins.instance` 并集，反之每个绑定的 `(controller,instance)` 能在表里取到 | 平台侧 + 装载期 | `构造表有 {k} 无绑定 / 绑定 {k} 无构造表条目` |

**外加两条预算校验**（与八条同批，同属装载门）：
⑨ `Σ demands.peak_ma (critical=true, 并发窗口内) ≤ domains[rail].current_cap_ma` → 超即拒 boot 并点名组合；
⑩ `Σ task_stack_bytes ≤ 平台可用 RAM`（rtos/bare 档，`[supplies].budget`）。
**这两条是"裁剪调度依据能源"的字面实现**：今天串行降级、降亮、限幅全都是它的事后补救版本。

## 6 标定与复位方案（用户点名的"电机怎么复位标定"）

**问题定性**：SG90 类位置舵机在**开环**下没有位置反馈，所以"标定"不可能标出角度，只能标出
**脉宽域与机械窗的关系**。任何把 `angle()` 回读当位置的说法都是 §1 坑 11 的重演。
可标定的对象恰为四件：**脉宽中点、方向符号、上下软挡块的脉宽、到位后是否释放激磁**。

| 路线 | 做法 | 前置 | 风险与护栏 | 本轮定位 |
|---|---|---|---|---|
| **A 工装标定** | 治具/量角器把轴固定在物理中位，逐点写脉宽（现有 `真件装配与标定手册` 的 INA219 两点标定同型流程） | 治具 | 低 | **立即可用**，随批N3 落手册与档案写入 |
| **B 电流找挡块** | 向已知方向以限流限时的步进推到硬挡块，用电流尖峰识别到位，记两端脉宽 | **`domains[].current_sense` 必须存在**（§1 坑 9：今天只有轨压、无电流） | **受控堵转**，正是烧舵机的机理 → 必须限流（`current_ceil_ma`）、限时（单步 deadline）、限次数、限单步角，失败即退回上一份档案 | **依赖 N2**，不作默认 |
| **C 开环自恢复 + 软挡块** | 上电以极低速率向一侧走到软挡块（时间窗 + 电流上限），以该脉宽为边界推中点，运行期越界**拒收点名**（不静默钳位，沿用 `axis_check` 现有 fail-closed 语义） | 仅档案写入面 | 中；靠"低速 + 短窗 + 释放激磁"控住 | **建议默认**（D13 待用户裁） |
| **D 换闭环执行器** | 带位置反馈的舵机/步进 | 新格 + 新 trait（`act.axis.enc`），走契约级评审 | 低但成本与选型变化 | **本版不做**，只在角色表预留 `act.axis.enc`（预留不 = 立格） |

**复位语义（三档，契约里必须分开写，今天混在"boot 置 90°"一句里）**：
① **归中**（到 `center_deg`，需已标定）；② **归安全姿态**（`BOOT_PAN_DEG`/`BOOT_TILT_DEG` 这类形态默认，
是策略、进 profile）；③ **失能归位**（欠压/看门狗复位后`failsafe=release` → 不保持激磁，让轴自由，
避免复位循环里反复堵转——这条是方案A"不保持激磁"的遗留敞口，本轮升为 `[pins].failsafe` 的数据）。

**"未标定不得自动"是硬约束**：`calibrated=false` 的轴，`Rr3Actuator::rr3_goto` 只接受点动（带 deadline），
拒绝任何自动扫摆/表情联动动作——否则上电即拿一个假中位跑 WANDER，就是坑 9 的下一次发生。

## 7 面板 = 配置面（本全案的第四件产品要求）

**三个面，缺一不可**（今天只有第二个的一半）：

| 面 | 内容 | 今天 | 目标 |
|---|---|---|---|
| **观测** | 生效绑定快照（描述符 + 应急覆盖 + 档案三者合成后的那份）、逐域 mV/mA/tier/armed、每轴位置与 `source`、标定状态、渲染失败计数、音频丢帧、后端选择落点（含"落 sim"的显式点名） | 14 端点里 5 个 GET，全是运行态（status/data/logs/scan/keys），**零配置可见** | 面板覆盖率门的"观测半边"，逐项可查 |
| **配置** | 全部 `ops` 槽 + `[hardware]`/`[pins]` 键 + 域阈值 + 亮度阶梯 + 档案字段 | 写面只有 relay/beep/face/selftest/reboot/wifi/model-key | **覆盖率门**：`面板项集 ⊇ 可配置集`，差非空即红 |
| **动作** | 点动、回中、标定（路线 A/C 流程）、自检（`[pins]×wiring` 全交叉）、接线图 | `/api/selftest` 一个笼统端点 | 逐动作端点 + 全部留痕 |

**写权限边界（不许越界）**：面板可写 = 策略量；不可写 = 契约量（格定义、主题、字节头、角色定义、
`tier_scope`）。欠压阈与 `armed` 位属**安全相关策略量**：写须带二次确认 + 旧值回显 + 审计行
（今天面板密钥面的"值零回显"纪律是同族，把它抽成面板写面的通用规则）。

**rtos/bare 档的面板在哪**（这是裁定 1"三形态独立"的直接后果）：不能假设"经桥后宿主面板顺带看见它"。
方案：板侧一个**极简配置服务**（角色/域/档案/阈值的只读 + 阈值与档案的受限写），
承载在 WiFi（rtos 档已在册）或经桥以 RPC 暴露；BLE 只读诊断 + 配网是 **D12** 待裁的那条。

| **N3 执行件档案与 `Rr3Actuator`** | 关节成为对象，标定有方案 | `Rr3Actuator`/`Rr3Position{source}`/`Rr3ActProfile`；档案文件与读写；`Rr3Store` 窄缝（rtos 档落 NVS）；行程三处收敛（门 g）；标定路线 A/C 实施 + B 的护栏用例（禁用于 `hard_stop=unknown`）；`sensor`/`digital-in` 两 trait 立格评审（家族 E） | 档案改动可回滚；未标定轴自动动作被拒（用例）；schema/config/board 三处行程字面量只剩一处读者 | N1；**D13**（默认路线）；路线 B 另需 N2 |
| **N4 面板配置面与覆盖率门** | 用户点名的操作面板成立 | 面板观测/配置/动作三面扩端点；覆盖率门（门 d）；接线图与出厂自检逐条；BLE 只读诊断路径随 **D12** 裁后再动 | 覆盖率门从红转绿的面数逐批登记（不许缩分母）；手机在同一网段真连一次（证据归验证窗） | N1–N3 的键集与档案形状（否则面板无处可显示）；**D11/D12** |

**顺序的裁定依据**：用户口径"**不是根据人员，是根据能源**"——批次排序按**资源约束的依赖方向**，
不按谁有空。能源（N2）在执行件（N3）之前，因为执行件的电流上限、标定路线 B、拒动语义全都以域为参照；
面板（N4）在最后，因为它显示的是前三批的形状。批 N1 之所以最先，是因为它是另外三批的数据结构前提。

## 11 不做清单（每条都写为什么不值）

| 不做 | 理由 |
|---|---|
| 把 `esp32-periph-base` 拆成"件模块进 xtensa 门"（MC-7 三缺） | 那是格位化的活，判据已在批M MC-7 登记；本全案先把**形状**立住——反过来做会得到一套没有契约支撑的拆件 |
| 上电即自动找挡块（路线 B 默认化） | 受控堵转在无电流采样 + 未标定挡块的板上 = 第二次烧舵机的最短路径（§1 坑 9/10 的直白重复） |
| 为 ESP32 形态新建独立主题前缀 `rr3-mini/*` | 前缀归属是契约级决策且依赖"独立形态是否自发布"的裁定（D14）；先改前缀会造出一批无消费者的主题 |
| BLE 全量配置面板 | `net.bt` 还是 placeholder；先把 WiFi 面的覆盖率立住，BLE 面等 D12 |
| 引入外部引脚/接线 EDA 工具链 | 底座只需要"角色-绑定-接线"三份 TOML 与八校验；引工具 = 新依赖、新失败模式，收益不比一条 `grep` 门高 |
| 把传感按器件型号扩格（DHT11 一格、BMP280 一格…） | 坐标系会瞬间爆掉且违反"格 = 能力"的定义；本全案的答法是**一张格 + 角色表 + 器件档案**（§3.5） |
| 在机制核写"能源策略" | 策略出核是纲领；本轮只新增**数据结构与判据**，域阈值/降载顺序都是 profile 与 ops 注入值 |

## 14 敞口（本全案立完仍不知道的）

| 敞口 | 触发条件 | 为什么不能在本全案里消掉 |
|---|---|---|
| 域的阈值与分压比取值 | 真板接分压网络 + 万用表对拍（≤2%） | "无真板证据前不接闸、不 claim"是既有纪律（`RAIL_GATE_ARMED`），本全案只立对象 |
| 逐域电流采样 | INA219/采样电阻 per-domain 到位 | 标定路线 B 与预算校验的运行期半边都依赖它；硬件未定（D10） |
| 树莓派与 RK3566 的 `[pins]` 真值 | 各自装机档完成 | 两个形态今天都没有机器可查的接线表；本全案给形状与演练实例，不给事实 |
| 面板覆盖率 | 门 d 建成并逐面转绿 | 分母是设计产物（可配置集），分子要写端点；一轮做不完，且**必须如实红着** |
| 接线错误本身 | 出厂自检 + 防呆选型 | 软件拦不住人插错线（§4.3 诚实边界）；本轮把它变成可查、可校验、可拒绝选型，**不宣称能阻止** |
| `bare` 档面板与凭据 | 一块真无 OS 的板 | 与 §14.4 的"bare 档真板"轨同一前置；本轮不为其写码 |
