## 2 开发计划（三件依序，每件一笔提交）

排序依据＝**本机可做先行、真板件合并上板会话**：件二代码面排查不占板先做 →
件一（run6 600s）＋件二真板取证＋件三（改值实录）同一次上板会话串跑。

| 件 | 对象 | gated | 判据要点（原文落点） |
|---|---|---|---|
| 一 | **批D④ 判据②**：600s 稳态复测再攻（run6） | 真板 | 口径 **gaps=0**（run4 gaps=92 → run5 gaps=24，收窄 4×，断流型病灶全零——[status.md 批N9 件三注记](../../status.md)）；命令形态（CLI 以 [rr3-audio-rec main.rs](../../../tools/rr3-audio-rec/src/main.rs) :42/:584 为准，批N9 会话实录命令行未落档、本批补录）：`rr3-audio-rec <UART2桥设备> --secs 600 --out rr3-audio-600s-run6.wav`（baud 缺省 921600）；INFO 对账（chunks/gaps/err/restarts/resyncs/reconnects）＋wav 落盘同 run5 证据面；**过＝判据② 结项**；不过＝如实敞口不冒领 PASS，纵向对比判读（收窄/走平/恶化三态），同批注记敞口 16 第二问量级取数 |
| 二 | **批N9 件四副证**："事件门拒收：事件体非 JSON"病灶排查 | 本机先行＋真板取证 | 打印点已定位：宿主侧 [rr3-audio-rec main.rs :746](../../../tools/rr3-audio-rec/src/main.rs) ← :219（`serde_json::from_slice(&body)` 失败，事件体来自板侧事件帧）；排查面＝板侧事件帧组装与发送路径（`esp32-periph-base` 事件面）vs 宿主 `FrameAssembler` 读面，判定截断发生在板侧发送/UART 链路/宿主接收哪一环；与散布丢片同族嫌疑**并案判读**（批N9 件四注记原口径）；真板取证随件一 run6 同跑（事件门拒收出现次数×时刻×gaps 时刻对表）；产出＝病灶定案注记（含"修不修、归哪批"结论，修复不预设在本批） |
| 三 | **敞口 21 行为半边**：改取值 → 板上行为随之变化实录 | 真板 | 消费路径查实（本计划册落档前）：板侧注入值真消费点＝`rr3_board_bindings_i2c_pair()`（[oled.rs :170/:230](../../../tools/esp32-periph-base/src/oled.rs) I2C 真值、[runtime.rs :40](../../../tools/esp32-periph-base/src/runtime.rs)、[main.rs :178/:184](../../../tools/esp32-periph-base/src/main.rs) boot 解卡拒 fail-closed）——**行为半边取值对象按消费路径事实定形为 [hardware] i2c_sda/scl 键**（[esp32-mini.toml :120-121](../../../profiles/esp32-mini.toml)）；`[[pin]].physical` 板侧无消费点（装配锚只对账不进消费路径，批N9 件五定案），其变化面（宿主载荷＋对账✗）已随批N9 件五②失配对照（ledc_pan=30）实录；判据＝改 `i2c_sda` 取值 → 宿主注入下发 → 板侧 I2C 消费面行为随之变化实录（器件探测/总线行为变化点名）＋对账✗ fail-visible 副证 → **改回原值 → 行为复原实录**；两实录齐 → [status.md 敞口 21 行](../../status.md)结项（行文注明"行为半边按消费路径事实定形"）；正向对账✓十键与抽注入 fail-closed 两半边已随批N9 件五收 |
