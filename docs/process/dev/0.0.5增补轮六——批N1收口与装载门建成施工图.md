# 批N1 收口与装载门建成 施工图（增补轮六 · 第八轮）

> **For agentic workers:** REQUIRED SUB-SKILL: 用 `superpowers:subagent-driven-development`（推荐）或
> `superpowers:executing-plans` 逐任务实施。本文步骤用 `- [ ]` 复选框跟踪。
> **执行机器约束**：Task 3 起全部是 Rust 代码任务，**必须在装有 aarch64/Linux 工具链的那台设备或 WSL2 上跑**
> （Windows 侧 `rr-bus` 依赖 `std::os::unix`，十步门禁编不过）；本机只做 Task 1/2 的契约文本与文档。

**Goal:** 把已开工的批N1 收口到"底座能说出自己接了什么"，并消灭施工侧跑出来的三处文档分叉。

**Architecture:** 契约层（`contracts/*.toml`）是引脚/器件/平台事实的唯一真值点；`rr-registry` 只做**读表与查册**，
`rrd/src/profile.rs` 做装载期判定（拒 boot / 降级点名 / 仅点名三态后果）；`check.sh` 把可静态断言者接成门。
本方案不顺带建能力面 trait——`rr-hal-api` 的 7 个句柄面属批N2/N3，与本文的判据建成交付面不重叠。

**Tech Stack:** Rust 2021 · `toml` · `serde_json`（夹具）· cargo test · bash 门禁 `tools/ci/check.sh`。

**Spec:** [0.0.5增补轮六——底座资源模型与能力面抽象补课全案.md](0.0.5增补轮六——底座资源模型与能力面抽象补课全案.md)
§4.1/§4.1b/§4.2/§4.6、§5 装载期十条校验（24 判定位）、§8 十六条门、§10 DoD、§21 闭合五问与 `基-1…基-22`。

## Global Constraints（每个任务都隐含遵守）

- 主干 `dev/hubs-01`；**不 PR/merge 到 `main`**；**不改写已发布历史**（禁 amend/rebase）。
- 远端只有 atomgit（remote 名 `origin`）。文档轮与代码轮分开提交，提交信息必须写开工单号。
- `contracts/` **只增不改**；语义变更 = 破坏性 = 升 `schema_version` 并走契约级评审。
- 引用版本号改动**必须写常量名**：`RR3_PROFILE_SCHEMA_VERSION`（现 **3**）与 `RR3_ASSEMBLE_SCHEMA_VERSION`（现 2）
  是两个域，裸写"schema 2→3"会指错常量。
- 引用门必须写全前缀：设计编号（门 n）/ 拟步号（⑨-n）/ 工单号（基-14）三者各自成立，**不写"第 8 把门"**。
- **分母写死**：装载校验一律称"十条校验 / 24 个判定位"；产线侧一律称"十项"；两个"十"不同物。
- 判据三态后果（`拒` / `降` / `名`）照 §5 第 5 列逐条实现，**不许统一实现成"只点名"**。
- "合法不适用"必须显式写 `none`/`false`/`[]`，**留空即红**（范式 = `rr-registry/src/assemble.rs` 的 `no_injection`）。
- `SKIP ≠ PASS`：本机跑不了 `cargo test` 的任务，回执一律写"未跑（工具链缺位）"，不许用 SKIP 充数。
- 进度只写 `docs/status.md`；architecture §3 是全仓唯一目录树事实源（新增 `contracts/platform/` 须同批改它）。
- 历史存档节只追加不改写；文档符号名锚定、不写行号。
