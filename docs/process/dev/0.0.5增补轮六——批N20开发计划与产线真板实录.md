## §2 施工注记（逐件回填）

### 件一 产线装配＋首烧实录（2026-10-23，全链证据行原文）

- **装配全链**（`bash tools/deploy/image-esp32.sh --release`，12:28–12:35）：① 验证面五步
  PASS（工具链门 espflash 4.6.0＋esp 工具链 rust-src＋ldproxy＋esp-clang＋IDF v5.2.2；
  构建 `Finished release profile [optimized] in 6m 57s`；ELF 在树；descriptor 三查
  0x120＋0xABCD5432；干跑止步）→ ② 装配面 `App/part. size: 1,086,848/4,128,768 bytes,
  26.32%` → ③ 自校验四查 PASS（0x1000=e9 / 0x8000=aa50 / 0x10000=e9 / 整片 4194304 B）。
- **施工波折（如实登记）**：首跑构建失败——release build 目录 CMake 缓存源目录不匹配
  （cache 记 `.embuild/.../v5.2.1` 残留，当前 `IDF_PATH`＝v5.2.2）；清
  `target/.../release/build/esp-idf-sys-5a2db0ec265003c0/` 重 configure 后过。缓存残留
  非码面问题，重跑即绿。
- **尺寸真相（批N18 记录订正依据）**：espflash 报 app 1,086,848 B 与批N18 记录
  「release 444,576 B 槽内 42.4%」矛盾，三步定案——① esptool image_info 段表独立验证
  （DROM 201,636＋IRAM 43,584＋IROM 767,540 等 6 段，加总与 espflash 吻合，App version
  =01c15f2）；② worktree 挂批N18 收口点 `c6d9200` 冷构建 release＝**1,086,784 B**
  （差 64 B＝批N19 摘面，排除码面漂移）；③ 带 WiFi 栈的 espidf std 应用物理上不可能
  444 KB（libnet80211/libpp 链入即超）——**444,576 B 系批N18 测量/记录错误**，本批订正
  （订正正文落件三）。
- **分区表真相（本批新事实）**：IDF 构建表 bin 手读 factory@0x10000/**0x100000**（1MB，
  partition-layout.md 批N18 段手读无误）；而 merged@0x8000 实读 factory length=
  **0x003F0000**——`espflash save-image --merge` 未显式传 `--partition-table` 时用
  **espflash 内置默认模板表**（nvs@0x9000/0x6000＋phy@0xf000/0x1000 起点、长度与 IDF 表
  完全一致，factory 加长撑满 4MB 尾）。两表下 app 均可跑：IDF 表语义超槽 3.66%（bootloader
  按段表加载不按槽界，批N9 debug 8.2% 先例在案）、模板表语义槽内 26.32%。装配面
  「镜像表≠构建表」缺口如实登记（不改判烧录格，订正落件三）。
- **首烧实录**（12:53–12:56）：`espflash write-bin 0` 直烧 merged 4MB 全量 **98 秒写入**
  （NVS 随片清空＝产线首烧语义）→ `espflash monitor --non-interactive` 30s 抓 boot：
  板上分区表 `2 factory factory app 00 00 00010000 003f0000`（模板表实证）；boot 段表
  加载 `segment 4: paddr=00050020 size=bb834h (768052) map`；`App version: 01c15f2`；
  **「从干净机器到能出字/转动/听到声」三达**——OLED `I2C 扫描应答 [3C] ✓`＋
  `boot 画面已出（4 行）`；LEDC `姿态到位 pan=60 tilt=98（LEDC 回读 pan=60° tilt=98°）`；
  双麦 `[mic] 16074Hz L rms=34371 peak=57599 | R rms=34266 peak=57599` 连续流＋
  `RAM point=2-periph-ready free=250660B` / `3-mic-smoke`。
- **fail-honest 实证（批N13 订正语义真板回声）**：直烧清 NVS＋本构建未注入编译期源 →
  `[periph] 配置腿未装配（NVS 无存档且 RR3_BOARD_WIFI_SSID 未注入）——N-13 服务面缺席，
  板其余功能照常`——不冒领配置腿，WiFi/httpd 不起、板其余功能全数照常。件二① 实录前
  须带编译期注入（`RR3_BOARD_WIFI_SSID/PASSWORD` env）重构建重烧。
