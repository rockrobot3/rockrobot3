# 0.0.5 增补轮六——批N5 首件——按形态分档可达终点表

本文件是批N5 首件交付物：回答全案 §17 复盘最硬的那条结论——"每一处诚实标注都在，但没有任何一处
回答'这个形态现在能走到哪一步'"。首版手写，逐格标 `文件:符号` 或已登记敞口号（改判口径见 §1）。

## 1 判据与口径

**判据原文**（唯一真值点，本表不复述理由）＝[全案 §17 批N5 行](0.0.5增补轮六——底座资源模型与能力面抽象补课全案.md)：

1. 按形态分三行（RK3566 / 树莓派 / ESP32），每行逐格写十项（出字 / 转动 / 拾音 / 播放 / 配网 / 观测 / 标定 / 烧录 / 升级 / 回滚）的"今天能做到｜不能｜缺什么"；
2. 表内每一格都能指到一个 `文件:符号` 或一条已登记敞口；出现"应该可以"这类句子即 FAIL；
3. 每格三态各有必填字段：**"不能"必须带触发条件**（缺码＋工单号，或无载体＋触发条件），**"能做到"必须带符号**。

**改判口径**：首版手写＋逐格标 `文件:符号` 或敞口号（[索引 §14.6](../../design/模块设计索引.md) 生产与运维闭环行、
[开发计划 §3 批N5 段](0.0.5增补轮六——批N2至批N5开发计划与第十轮决策拍板.md)；原句"由结构化开放项数据生成、禁手写"
自相矛盾，经证伪审查轮订正作废）。"由 `docs/openitems.toml` 生成"的生成关系随生成器本体建立，
本版**不随本批宣称生成器**。

**三态判定口径**（本表自定，全表统一执行）：

- **能做到**＝机制在树且该形态载体在位（板/件不缺），格内给 `文件:符号`；板上证据半边未取的括注敞口号注记，不改判；
- **不能（无载体）**＝机制在树但载体不在（板未采购 / 真件未到 / 形态语义无此格），缺什么写"无载体＋触发条件"，机制符号照列供指认；
- **不能（缺码）**＝机制不在树，缺什么写"缺码＋工单号"。

**引用约定**：敞口号＝[status.md 敞口表](../../status.md) 行号，引用不复制；行号只作取证时点注记（基-37）。
**取证时点**：2026-10-20，基线 `b6d5902`。

**形态两轴**：三行是三台并列独立机器（RK3566 桌面具身 / 树莓派 / ESP32 微型，两两零关系，桥是链路选项——
architecture §12.7）；承载档位 RK3566 与树莓派同属 host 档、ESP32 属 rtos 档。树莓派行已发生的真板证据
（0.0.6 批D deb 真装 `efd224f`、批F4 板上 `rr3-sim --chain` 全链 mock 闭环）按 D11 口径登记：mock 档
不充当真件在位证据。ESP32 行的板侧事实源＝`tools/esp32-periph-base` 外设底座（OLED＋双轴舵机＋INMP441
双麦，增补轮五批B/批D 真板实录在案）＋装配单 `profiles/esp32-mini.toml`（桥接三格样例，F-B 行）。

## 4 维护纪律

1. **改判时机**：敞口行结项、器件到货、批件收官时，对应格的改判与取证时点更新列入**该批件的交付清单**逐格执行；每格改动必须复核其所引 `文件:符号` 仍在（实-16：抄侧再跑一次）。
2. **生成器升级路径**：`docs/openitems.toml`（ADR-0022 裁定 6.3，批N4 件九首笔落树）是开放项数据结构源；
   生成器本体建成前本表保持手写，建成后本表由数据生成、手写版降为历史时点——此升级不随批N5 首件宣称。
3. **边界**：本表不产任何平台级点验结论；"板上跑过"的句子只出现在 0.0.6/0.0.7 与其证据文件里
   （[开发计划 §5](0.0.5增补轮六——批N2至批N5开发计划与第十轮决策拍板.md)／§6 DoD 5 同款纪律）。
   格内"真板实录在案"指增补轮五批B/批D 已发生的验收记录（其出处即所引 `文件:符号` 的注释注记），不新增宣称。
