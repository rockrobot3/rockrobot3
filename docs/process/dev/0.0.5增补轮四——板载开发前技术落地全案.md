## 3. 技术点落地清单（深度基准四件套体例）

### 3.1 工程基础面（两板共用）

**A1 CI 首跑回执（批W2）**
- 操作步骤：`git mv .github/workflows/ci.yml .gitcode/workflows/ci.yml` + 载体说明行 → 推双远端 → atomgit 侧触发首跑 → 逐 job 收回执
- 预期输出：八 job（conventions/lint/brain-unittest×2/ipct003/distro-smoke/buildroot-assembly/sim-assemble）回执到账
- 判定标准：全绿=结项；个别红=逐 job 缺口登记（环境缺工具链/超时），不以 SKIP 冒充绿（R16 纪律）
- 失败处置：runner 环境缺口列"本机无法收口"新增行，宿主结论维持 Q4；不阻塞其余批次

**A2 counters 落盘节流（批W3，W4 裁定后）**
- 操作步骤：rrd 在册表宿主 flush 时机改造（心跳合并写：M 秒或 N 次心跳触发一次 + SIGTERM/优雅关停强制 flush）→ 单测（写次数计数器断言 + 关停数据完整断言）→ 既有 ctr 测试回归
- 预期输出：1000 次心跳落盘次数 ≤ ceil(1000×间隔/M)+1；kill -TERM 后重读计数与内存一致
- 判定标准：新单测绿 + 全量门禁绿；eMMC 写频次量化数入提交信息
- 失败处置：若关停 flush 依赖的信号路径在 root/non-root 下行为差异，回退方案=脏标记+周期 flush（W4 备选②），裁定记录补记

**A3 HAL env 键位总表（批W7）**
- 操作步骤：grep 全部 `RR3_HAL_*` 键位 → 与缺省值/单位/含义成表（PWM_CHIP/CHANNEL、GPIO_CHIP、GPIO_LED_LINE/RELAY_LINE 及 battery/link 新增键）→ 落 `base/os/distro` 手册或 reference 节
- 判定标准：表内每个键与代码 env 名逐字一致（符号名锚定，不写行号）
- 失败处置：发现代码缺省值与手册不一致 → 以代码为准修文档，差异登记

**A4 板上线触发件清单（批W7，显式化不新做）**
- 内容：板上 `cargo test -p rr-hal` 补跑（rsync 口径同批F1）、socket 放行真机复验、部署链回归演练——三项各自的操作步骤/判定/失败处置成清单落 status.md 敞口表注记
- 判定标准：清单在案，板上线即照单执行

### 3.2 树莓派真件支撑面（0.0.6 真件档前置）

**B1 F5a④battery + ⑤link 后端（批W4a/W4b，W3 裁定后）**
- 操作步骤：battery = INA219 I2C linux 后端（i2c-dev 字节接口，寄存器读电压/电流/功率，标定系数 env 可覆写）+ sim 档对拍；link = NetworkManager 后端（`nmcli`/D-Bus 取链路状态，`RR3_HAL_LINK_IFACE` 键）+ sim 档对拍——各一批一件，先例同批F5a ①②③（单门 target_os、纯 std、能力面各判各的）
- 预期输出：两 trait 后端并入 rr-hal；`cargo test -p rr-hal` 全绿零警告
- 判定标准：门禁全绿；env 键位进 A3 总表；boards 笔记回填
- 失败处置：I2C 无真板验证 → 以 sim 档 + 寄存器协议单测收口，真读数标定（万用表两点 ≤2%）列入真件档判据，不冒充

**B2 真件装配与标定手册（批W5）**——把已锁定硬件约束落成 runbook（每件四件套）：
- USB 麦克风：≥2ch UAC 免驱，`arecord -l` 输出判定（≥2 subdevices/channels）、双通道 `arecord -D ... -c 2 -f S16_LE` 抓样、失败=退换货口径（单通道/不可关降噪即不符）
- 舵机：UBEC 1S(3.0–4.2V)→5V/3A 独立轨、**UBEC/Pi/电池单点共地**（否则 PWM 无参考电平）、50Hz/0.5–2.5ms↔0–180° 核对步骤、堵转 ~700mA/只 供电余量核对
- 显示：MAX7219 SPI 三线（GPIO19/23/24）接线表 + `spidev` 出帧核对步骤（与 Rr3FaceFrame 帧面一致）
- 电源：TP4056 必带保护板；INA219 两点标定流程（万用表两点读数、偏差 ≤2% 才判过）
- ESP32 UART2：GPIO17→RXD / GPIO16←TXD / 共地，**3.3V TTL 严禁 5V**
- 判定标准：手册落档过 ⑤ 门；器件型号与 0.0.6 §5.4 BOM 定案一致，到货复核差异即改手册

### 3.3 ESP32 支撑面（0.0.7 批D1/E 前置）

**C1 espidf std 构建链冒烟（批W1，W6 裁定后）**
- 操作步骤：ESP-IDF v5.x 经乐鑫官方 `dl.espressif.com/github_assets` 镜像获取（GitHub 直连 18KB/s 纪律）→ ldproxy 环境注入 → `cargo build --target xtensa-esp32-espidf`（std hello 件，tools/ 下独立工程）→ 版本/路径钉死登记（外置不进仓，Q5 同款纪律）
- 预期输出：std ELF 出树；`idf.py` 与 cargo 链二选一路径跑通
- 判定标准：构建绿 + 版本记录落档；工具链门（esp-uart-echo-check.sh 同款 SKIP 纪律）扩一条 std 路
- 失败处置：esp-idf-sys/xtensa std 链不可行 → 如实登记 + 触发 Q2 复裁（no_std+esp-hal 回退，批D1 判据等价换算），不硬闯

**C2 rr3-bridge 桥件设计（批W6，落 0.0.7 修订版 5）**
- 形状钉死：bridge = transport 级连接多路器（R15）——UART↔UDS 字节透传零解析、每哨兵一条 uds 连接、连接寿命与重启管理、桥自身零策略零新契约（哨兵完整语义进城）
- 判定标准：批E 可照设计直写；R15/R20 复核零冲突
- 失败处置：透传语义与 uds 握手门冲突点 → 裁定点显式列出回 0.0.5，不混入批E 实施

**C3 e2e 双档判据（批W6）**：macOS 档（Q6 宿主）+ 树莓派档（复用批F4 `--chain` 口径：RR3_SIM_PANEL_ADDR 注入、denied_publish=0 等判据）各成四件套 runbook
**C4 S3 切换预案（批W6）**：触发=批D1 剩余堆 <20% 或 std 不可起（R19）；差异点=target/`CONFIG_SPIRAM`/PSRAM 堆池；到货验收单（USB 口、Flash 容量、引脚兼容）四件套
