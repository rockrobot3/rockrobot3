## 1 背景与目标

用户裁定版本路线：**0.0.6 主题 = 树莓派验证 rock3 系统可行性（跨平台快速部署）**；
0.0.7 方向 = ESP32 板子（本方案只做边界预留，见 §7）。

**为什么树莓派是正确的验证物**：ADR-0013 把 rock3 的交付物定义为 Layer 1 payload——
"在 Linux 起来之后的一切"，板卡差异归 Layer 0 白拿上游。此前所有验证（distro-smoke
容器冒烟、ipct003 交叉对拍）都在**同构环境**里发生；树莓派（BCM SoC + Debian 系
Raspberry Pi OS）与 RK3566 是 Layer 0 完全不同的两家芯片——若 payload **不改一行产品
代码**就能在树莓派上装机、装配、boot、巡检，"跨平台快速部署"就从设计声明变成
实测事实。这是 ADR-0013 成立与否的第一次真板检验。

**两阶段验证边界（修订版 2，R1 裁定）**：

**阶段一 = 部署语义验证（原方案主体，批A–D 已实测大半通过）**：

- 做：deb 装机 → `rrd --profile` 装配链 boot → 模块总线链路 → `rr3-ctl` 运维巡检
  → systemd 开机自启与重启恢复——**部署语义全链**。
- 不做：真硬件后端验证（ALSA 采集 / NetworkManager 链路 / 电池计）——HAL 板上件
  尚为占位骨架（`Unsupported` 显式回错），真硬件批次归属后置（§5 已知边界）；
  RK3566 特性面（NPU 唤醒、RK809 codec、待机 <1W）——树莓派上不存在这些面，
  它们的验证仍归 Radxa ZERO 3 / 过桥核心板（ADR-0015，见 Q5）。
- **阶段一专属判据：全程零产品代码改动**（原判据 5 收窄归此——"跨平台"证据在
  阶段一成立，不因阶段二存在而稀释）。
- 收尾件（R3/R6 裁定）：boots 数据目录缺陷修复 + boards 笔记补录 ctl socket
  root/sudo 现状条目。

**阶段二 = 真机功能链（新主题，R1 裁定加入；用户 2026-10-05 需求原文：语音交互、
根据语音判定方向、舵机转向、丰富表情）**：

- 做：语音采集 → 意图判定（brain，`RR3_BRAIN_CLOUD=mock` 先行，R4）→ DoA 判向 →
  舵机转向 → 表情输出——**真机功能全链**；允许产品代码改动（HAL 真后端、表情
  状态机扩展、判向-转向编排）。
- 硬件注入口径（R2 裁定，**修订版 3 R11 订正**）：麦克风/舵机未到位期间走 sim
  注入口先行开发；真件到位**不是"只动 HAL 后端"**——①音频面有 linux（ALSA）后端
  可直接启用，但须**交叉构建带 `alsa` feature**（现交叉产物不带，板上默认 sim）；
  ②舵机/GPIO 面 linux 后端**不存在，须新写**（[backend.rs](../../../base/runtime/rr-hal/src/backend.rs)
  显式 `linux` 时舵机/GPIO/power/link 一律回落 placeholder `Unsupported`，`linux.rs`
  只实现音频类）；③显示面**须先立 trait**（[rr-hal](../../../base/runtime/rr-hal/src/lib.rs)
  现仅有 AudioSource/Sink、PwmServo、GpioOut、Power、Link 六个 trait，无显示 trait，
  连"改后端"的插槽都没有）。采购敞口登记不阻塞开发（详见 §5.4 R11 口径）。
- 不做：真云凭据联调（R4 裁定另批）；RK3566 特性面（归属不变）。

### Q1：版本主题与 ADR-0016 裁定 4 的排期冲突

ADR-0016 裁定 4 已裁"brain 迁移实施归 0.0.6 专项，0.0.6 立专项方案"；用户现裁定
0.0.6 = 树莓派验证。二者只能取一：

- a：0.0.6 单主题 = 树莓派验证；brain 迁移专项顺延（0.0.7 为 ESP32，brain 专项
  排 0.0.8 或与 ESP32 收口后统筹），ADR-0016 增修订记录——只修"实施批次归属"的
  排期事实，裁定 1/2/3 的切分表、不变量、部署形态目标**一字不动**（先例：
  ADR-0013 以修订记录修订 ADR-0001 的主次轨，决策实质不变）。理由：ADR-0016
  自评迁移实施"属独立版本体量"，与树莓派验证混排会让两个主题互相拖收口节奏。
- b：0.0.6 双主题 = 树莓派验证 + brain 首件（`bus.py` → rr-bus）。理由：板上批次
  受外部条件约束（板卡到手、人工操作），brain 首件是纯本地可完成的活，可填等待
  窗口；且不动刚裁定的 ADR。代价：首件牵动模块形态转换（Python 模块 → Rust crate
  骨架），实施细节需批评审，版本体量变大。

**裁定**：a——0.0.6 单主题 = 树莓派验证；brain 迁移专项顺延（0.0.7 = ESP32、
brain 专项归属 0.0.8，写死防再漂移）；ADR-0016 加修订记录只修排期（2026-10-05）。

### Q2：树莓派型号与 OS

- **建议**：型号不锁——payload 对 Layer 0 无感正是本方案的验证目标，手头现有或
  易得的 64 位树莓派皆可（≥1GB 内存即可；五 Rust 模块 + rrd 每模块
  `mem_limit_mb = 16`，内存压力极小；Zero 2 W 亦可）。OS 建议
  **Raspberry Pi OS Bookworm 64-bit**（Debian 12 系，与 distro-smoke 的
  `rust:bookworm` 同系 glibc，systemd 在位）。
- 待用户确认：手头是否已有树莓派、型号；若无，是否随本版采购（敞口登记，不阻塞
  批B/C/D 开发）。

**裁定**：a——用户确认**手头已有 Pi 4B / Pi 5**（批D 板上演练无采购敞口）；型号
不锁维持，OS 按 Raspberry Pi OS Bookworm 64-bit（2026-10-05）。

### Q3：aarch64 deb 出包路径

## 5 设计要点

### 5.1 aarch64 交叉出包链（批B 的实体）

```
cargo build --target aarch64-unknown-linux-musl --release   # 批B 实况：musl 静态 + rust-lld
  ├─ base/runtime 工作区（rrd）          # 不带 alsa feature → 板上默认 sim 后端
  ├─ modules/rr3-{act,connect,interact,sense,power}
  └─ tools/rrctl
→ 注入产物装配（两轨同源约定，照 distro-smoke ③）：
  payload/{rrd, rr3-ctl, rr3-modules/<name>/{bin,manifest.toml}}
→ rr3-pack --payload … --repo … --out rockrobot3_0.0.6_arm64.deb --stage-only
→ staging 树 scp 到板 → 板上 dpkg-deb --build → dpkg -i
```

- **交叉链（批B 实况，修订版 4 订正）**：`aarch64-unknown-linux-musl` 目标 +
  `RUSTFLAGS="-C linker=rust-lld"`——macOS 本机无 aarch64 glibc sysroot、brew Tier 3
  无 bottle，musl std 自带完整 libc，产物全静态零依赖（[pack-arm64.sh](../../../tools/deploy/pack-arm64.sh)
  落库实现，`file` 断言 `statically linked`）。
- **音频件板上原生构建（修订版 4，R13）**：musl 全静态与 alsa（alsa-sys 绑 C
  libasound 动态库 + 运行时插件）**结构性互斥**，交叉路径不存在——真件档换装时
  `rr-hal`（带 `alsa` feature）与依赖件（rr3-sense/rr3-interact）**在板上构建**
  （板上装 `libasound2-dev` + pkg-config；板上 rustc 实测 ≥1.82 过 workspace 锁为
  解锁门，不达标 rustup aarch64 或转备选 gnu 自产 sysroot），宿主 musl 静态五件 +
  rrd + ctl 不变，staging 合流后 `dpkg-deb --build`；pack-arm64.sh 静态断言仅限宿主
  构建件（板上构建件断言 = 动态 ELF aarch64 + ldd 含 libasound）。
- **板上构建承载（修订版 5，洞 L）**：板上原生构建三件承载落
  `tools/deploy/build-onboard.sh`——①**源码同步**（rsync 工作树到板 `~/rockrobot3-src`，
  排除 `target/`）；②**依赖通道**（板上有外网则直连 crates.io；无外网则 `cargo vendor`
  随源码同步 + `.cargo/config.toml` 指向本地 vendor）；③**产物归位**（板上
  `cargo build -p rr3-sense -p rr3-interact --features alsa --release` 后，二进制写入
  staging 树 `payload/rr3-modules/<name>/bin`，供板上 `dpkg-deb --build`）。构建能力
  归属 **批F1**（洞 M——真麦档在批F4 验收，构建能力不得推迟到批F5）。
- 脚本落点建议 `tools/deploy/pack-arm64.sh`（真板出包与 CI distro-smoke 分工：
  前者宿主交叉出 staging，后者容器内本机构建真装——两者共用 rr3-pack 与注入
  约定，不互抄装配）。
- **_rr3-brain 不进包**（distro.toml 缺格点名语义维持——这同时是"装机诚实边界"
  的断言点：boot 日志必须出现 `拒绝启动 rr3-brain：缺格 cognition.dialog`）。

  总线落 act 格位——编排只在装配单 bindings 与既有主题上表达，**零新契约**
  （契约只增不改纪律；若判向结果确需新主题，随批评审 append，不让编排私带通道）。
- **pcm 承载（R7）**：阶段二语音链 sense→brain 本地音频流**明走 Event JSON
  `pcm_b64`（s16le base64）过渡承载，不引新 schema**——在册 `kind="stream"` 与本
  承载形状不一致属 uds 期实况，brain 侧消费 `pcm_b64` 字段并本地解码；`kind="stream"`
  在册事实与 topic 语义面不动（Q3 裁"不冻结"针对 shm 期，阶段二在 shm 之前既不冻结
  也不新建契约件）。DoA 承载沿用本节口径（sense 侧音频格位，零新契约）。
- **表情扩展**：现有五态表情机扩多帧动画与状态集；显示件适配层按 HAL 后端分型
  （sim 注入口 / LED 点阵 / OLED），**切换须先立 rr-hal 显示 trait 再实现后端**
  （R11，见下）。
- **HAL 补工口径（R11，订正 R2 末句）**：真件到位**不是"只动 HAL 后端选择"**——
  ①舵机/GPIO：**新写** `linux.rs` PWM/GPIO 后端 + 后端选择函数补 linux 分支，并对齐
  "rr3-act 开机探活遇缺能力即 `exit(1)`"的 boot 语义（否则真板 act 起不来）；
  ②显示：**先立 `Rr3Display`/`Rr3Face` trait** 再实现 LED 点阵/OLED（现无显示 trait）；
  ③音频：板上采集/播放须**板上原生构建带 `alsa` feature**（R13——musl 全静态与
  alsa 结构性互斥，交叉路径不存在；板上装 `libasound2-dev` + pkg-config）——**构建
  能力归批F1**（洞 M：真麦档在批F4 验收，故不得推迟），**换装验收归批F5**（与
  PWM/显示合并验收）。
  注：R2 原文把"改 HAL 后端选择"与"改装配单 bindings"并列属概念错位——按
  [ADR-0012](../adr/ADR-0012-能力格坐标系与装配单.md)，bindings 决定格位→模块装配、
  不驱动 HAL 后端分型，二者正交（改 bindings 不能替代写后端）。
- **换装演练判据（R11 订正）**：sim 后端切换真后端时**编排与契约零改动**，但
  **HAL 后端代码本身需要新增**（不是"只动后端选择"）——"硬件未到位不阻塞开发"
  口径（R2/R9）的自证在于：换装只动 HAL 后端实现 + 装配单 bindings 两处，产品
  编排逻辑与契约件零改动。
- **音频件构建路径（R13）**：宿主 musl 静态件（rrd/rr3-ctl/五模块宿主构建件）与
  板上原生音频件（rr3-sense/rr3-interact 带 `alsa` feature）staging 合流出包（§5.1
  分工段）；pack-arm64.sh 静态断言仅限宿主构建件，板上构建件断言 = 动态 ELF
  aarch64 + ldd 含 libasound。采购前档（sim 档）不受影响——宿主 musl 产物照旧全链。
- **采购与承载（R14）**：采购口径 = **USB 麦克风阵列（≥2 麦多通道 UAC）或 I2S
  2-Mic HAT** 二选一（R8 框架不变，加"阵列"限定——普通 USB 单麦无声源方向信息，
  DoA 真件档不可达）；双麦采集期总线 `pcm_b64` **下混 mono**（DoA 在 sense 内部
  落档，结果新主题随批评审 append），brain 消费面零改动；选 USB 阵列则 I2S 让位 →
  SG90 可用硬件 PWM（GPIO12/13），互斥消失，选 I2S HAT 则维持软件 PWM/PCA9685。
- **阶段二引脚预算表（R8，采购前钉死）**：

  | 脚号 | 用途 | 冲突结论 | 处断 |
  |---|---|---|---|
  | GPIO18 | I2S SCLK / 硬件 PWM 通道 | **I2S 与硬件 PWM 物理互斥** | 保 I2S 则 PWM 让位 |
  | GPIO19 | I2S FS / 硬件 PWM 通道 | 同上 | 同上 |
  | GPIO20 | I2S DIN | 仅 I2S | — |
  | GPIO21 | I2S DOUT | 仅 I2S | — |
  | GPIO12 | 硬件 PWM 通道 | 不与 I2S 冲突 | 可作舵机 PWM |
  | GPIO13 | 硬件 PWM 通道 | 不与 I2S 冲突 | 可作舵机 PWM |
  | GPIO2/3 | **硬件 I2C**（SDA1/SCL1） | PCA9685 / OLED 显示件占用 | 软件 PWM 不得复用（洞K 补行） |
  | GPIO4/17… | 软件 PWM（gpiod/sysfs）可用 | 与 I2S/I2C 不冲突 | 备选舵机通道 |

  **处断**：I2S 双麦与 SG90 硬件 PWM 不能同时启用——**软件 PWM（gpiod/sysfs）或
  I2C PWM 扩展（PCA9685）驱动 SG90**，或**麦克风改 USB 麦克风阵列（≥2 麦多通道
  UAC，R14——普通 USB 单麦无声源方向信息，DoA 真件档不可达）**（树莓派原生 ALSA，
  避开 I2S 占用），二选一按实际板型（Pi 4B / Pi 5 的 PWM/I2S 复用以板为准）定；
  选 USB 阵列则 I2S 让位，SG90 可用硬件 PWM（GPIO12/13）——互斥随选型消失（R14）。
  采购口径相应微调：**麦 USB 阵列/I2S 二选一（R14 加"阵列"限定）+ SG90 + 独立 5V
  供电 + 必要时 PCA9685**。
- **阶段二运维小批（R12）**：①[rrd.service](../../../base/os/distro/units/rrd.service)
  注入 `RR3_REBOOT_OK=1`（或如实改 [conn.rs](../../../base/runtime/rrd/src/conn.rs)
  注释为"由运维环境注入"，二选一按阶段二是否要真 reboot 定——现 unit 未注入，真板
  reboot 恒拒）；②ctl socket 加组放行（`RuntimeDirectory` + 属主组，牵动
  [ADR-0010](../adr/ADR-0010-控制通道与查询面.md) 权限模型，须 ADR 增补或裁定记录）。
  归阶段二（批F5），阶段一不动（"零产品代码改动"判据含不改权限模型）。
- **真件矩阵升格全能力面（R18，修订版 6）**：R9 矩阵原五行（语音/意图/DoA/舵机/
  表情）不动，扩至八行——①**真电池**：battery/charger linux 后端**新写**（R11
  扩围；[backend.rs](../../../base/runtime/rr-hal/src/backend.rs) 显式 `linux` 时

### 5.5.1 环境准备 runbook（六步，逐步四件套）

**步 1｜系统基线核验**

- 操作：

  ```bash
  head -2 /etc/os-release && uname -m
  ```

- 预期输出（样例）：

  ```
  PRETTY_NAME="Debian GNU/Linux 13 (trixie)"
  NAME="Debian GNU/Linux"
  aarch64
  ```

- 判定：Debian 12 bookworm / 13 trixie 皆可（R4 实测 trixie python3 ≥ 3.11 过
  tomllib 门；bookworm 与 distro-smoke 同系 glibc），且 `uname -m` = `aarch64`
  即过——32 位用户态（armv7l）不过。
- 失败处置：`armv7l` → 烧错了 32 位镜像，重烧 Raspberry Pi OS (64-bit)；无
  `/boot/firmware` 目录 → 老镜像（§5.5.3 件 5 路径以 /boot 为准需相应调整），建议
  重烧 Bookworm+。

**步 2｜apt 逐包安装**

- 操作（一条命令；逐包用途见后注记）：

  ```bash
  sudo apt update && sudo apt install -y \
    build-essential pkg-config libasound2-dev \
    libi2c-dev i2c-tools \
    gpiod gpiod-tools \
    network-manager \
    curl git
  ```

  逐包用途：`build-essential` 板上原生编译链（R13）；`pkg-config` alsa-sys 探测
  libasound；`libasound2-dev` ALSA C 头与链接件（musl 全静态与它结构性互斥，板上
  原生构建正是为了吃上它）；`libi2c-dev` + `i2c-tools` ADC/显示件调试
  （`i2cdetect`/`i2cget`）；`gpiod` + `gpiod-tools` GPIO 调试（`gpioinfo`/`gpioset`）；
  `network-manager` 配网面（connect 真 wifi 后端的系统侧承载）；`curl` + `git`
  rustup 与源码同步。
- 预期输出（样例）：尾行 `X newly installed, 0 to remove …` 无 error。
- 判定：`dpkg -l build-essential pkg-config libasound2-dev i2c-tools gpiod network-manager 2>/dev/null | grep -c ^ii` ≥ 6 即过。
- 失败处置：`Unable to locate package` → 先确认 `sudo apt update` 无源错误
  （`/etc/apt/sources.list` 被裁剪则换完整版镜像）。

**步 3｜用户组**

- 操作：

  ```bash
  sudo usermod -aG dialout,gpio,i2c,audio $USER
  # 退出重新登录后：
  groups
  ```

- 预期输出（样例）：`<user> adm dialout sudo gpio i2c audio …`（各组齐在）。
- 判定：`dialout gpio i2c audio` 四组全在即过。
- 失败处置：某组不存在 → `sudo groupadd <组名>` 后重跑 usermod（i2c 组由
  i2c-tools 创建，步 2 先行即有）；重登仍缺 → `whoami` 确认同一用户、SSH 会话
  需完全重开（组变更不随 `su` 生效）。

**步 4｜rustup 板上安装**

- 操作：

  ```bash
  curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y --profile minimal
  source "$HOME/.cargo/env"
  rustc --version
  ```

- 预期输出（样例）：`rustc 1.85.0 (…)`。
- 判定：**≥ 1.82 即过**（R13 解锁门：workspace 依赖锁要求，批B 实测口径）。
- 失败处置：版本低 → `rustup toolchain install <所需版本> --profile minimal &&
  rustup default <所需版本>`；下载慢/失败 → 板上外网敞口走洞 L vendor 通道
  （`cargo vendor` 随源码同步，见 §5.1 板上构建承载段）。
- **实测校准（批F1 板上构建实测，2026-10-06）**：rustup 官方通道从板上 WiFi 拉不动
  （rustup-init 迟迟不落，~5 min 无进展），TUNA rustup 镜像对二进制 403——
  **apt 路线实测最快**：Debian 13 (trixie) 自带 `rustc/cargo 1.85.1`（≥1.82 过门，
  零额外通道），`sudo apt-get install -y --no-install-recommends rustc cargo` 即达
  （板上 apt 源 `deb.debian.org` 直连 ≈57KB/s 且 http method 会空转卡死、TUNA pool
  对 deb 同样 403，**sources 切 [USTC](https://mirrors.ustc.edu.cn/debian/) 实测秒级**；
  切源前先备份 `sources.list.d/*.sources`）。boards 笔记 §8 环境备注同录。

**步 5｜磁盘/内存断言**

- 操作：

  ```bash
  df -h / | sed -n '2p' && free -h | sed -n '2p'
  ```

- 预期输出（样例）：

  ```
  /dev/mmcblk0p2   29G  6.1G   23G  22% /
  Mem:             3.7Gi       220Mi       3.1Gi       38Mi       434Mi       3.4Gi
  ```

- 判定：`/` 可用 ≥ 6G 且 Mem available ≥ 2G 即过（板上构建 rr-hal + 依赖的峰值
  需求；Pi 4B 4GB / Pi 5 无压力）。
- 失败处置：磁盘不足 → `sudo raspi-config` Expand Filesystem 扩 SD 分区或换
  ≥32G 卡；内存不足 → 建临时 swap：

  ```bash
  sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && \
    sudo mkswap /swapfile && sudo swapon /swapfile
  ```

  （敞口：swap 拖慢构建，启用即在 boards 笔记登记。）

**步 6｜板上构建 sanity（R13 解锁门）**

- 操作（源码已在板——洞 L `build-onboard.sh` 源码同步先行）：

  ```bash
  cd ~/rockrobot3-src/base/runtime
  cargo check -p rr-hal --features alsa
  ```

- 预期输出（样例）：首跑拉取 crates 后尾行 `Finished dev [unoptimized + debuginfo] target(s) in …s`，无 `error`。
- 判定：编译成功即过——这是"板上原生构建"可行性的解锁门，过不了则音频件全链
  受阻（R9 真麦必达失去构建路径）。
- 失败处置：`alsa-sys` 报找不到 libasound → `pkg-config --exists alsa && echo ok`
  断言失败则回步 2 补 `libasound2-dev`；crates.io 拉不动 → 洞 L vendor 通道。

### 5.5.2 硬件接线手册（逐件六列表 + 整机供电拓扑）

> **断电接线纪律**：所有接线在整机断电下进行；多电源系统先共地再上电。六列定义：
> 序号 / BCM（GPIO）/ 物理脚号 / 连接对象 / 信号方向 / 供电轨与共地。

**接线 1｜SG90 ×2（BOM #2/#3，硬件 PWM GPIO12/13——R22 定案档）**

| 序号 | BCM（GPIO） | 物理脚号 | 连接对象 | 信号方向 | 供电轨与共地 |
|---|---|---|---|---|---|
| 1 | GPIO12（PWM0） | 32 | SG90-A 信号线（橙） | Pi → 舵机 | 舵机电源走 UBEC 5V 独立轨（BOM #3），**禁接 Pi 5V** |
| 2 | GPIO13（PWM1） | 33 | SG90-B 信号线（橙） | Pi → 舵机 | 同上 |
| 3 | — | 2/4（Pi 5V） | （不接） | — | UBEC 5V+ → 舵机红线 ×2；堵转峰值 ~700mA/只，Pi 5V 轨带不动 |
| 4 | — | 6（Pi GND） | 舵机棕线 ×2 汇流 | — | UBEC GND 与 Pi GND **单点共地**，否则 PWM 无参考电平 |

  注记：舵机频率 50Hz，脉宽 0.5–2.5ms（中位 1.5ms）；PWM0/PWM1 引出由
  `dtoverlay=pwm-2chan` 使能（§5.5.3 件 5）。

**接线 2｜USB 麦克风阵列（BOM #1，无 GPIO——核验替代接线表）**

- 操作：

  ```bash
  arecord -l && cat /proc/asound/cards
  ```

- 预期输出（样例，PS3 Eye）：

  ```
  card 1: rr3mic [rr3mic], device 0: USB Audio [USB Audio]
    Subdevices: 1/1
  ```

- 判定：阵列卡在表且卡 id 为 `rr3mic`（udev alias 固定后）即过。
- 多通道核验（DoA 的前提）：

  ```bash
  arecord -D hw:rr3mic -c 4 -f S16_LE -r 16000 -d 2 /tmp/test.wav && ls -l /tmp/test.wav
  ```

  文件 ≈ 256KB（16000 × 2B × 4ch × 2s）即过。
- 失败处置：卡号漂移 → §5.5.3 件 3；录出全 0 / 声道数不足 → 确认选购件为
  ≥2 麦多通道 UAC（普通 USB 单麦无声源方向信息，DoA 真件档不可达，R14）。

**接线 3｜ADC 分压板（BOM #5，I2C）**

| 序号 | BCM（GPIO） | 物理脚号 | 连接对象 | 信号方向 | 供电轨与共地 |
|---|---|---|---|---|---|
| 1 | GPIO2（SDA1） | 3 | INA219/ADS1115 SDA | 双向 | VCC 取 Pi 3.3V（物理脚 1） |
| 2 | GPIO3（SCL1） | 5 | INA219/ADS1115 SCL | Pi → 传感器 | 板载上拉已起，无需外加 |
| 3 | — | 1（3.3V） | 器件 VCC | — | 3.3V 轨 |
| 4 | — | 6（GND） | 器件 GND | — | 与电池组 GND 共点 |
| 5 | — | — | 电池母线经分压网入采样口 | 电池 → 板 | 分压比注记见下 |

  分压比注记：电池组标称电压超 ADC 量程时先分压（R1 串 R2 到地，采样点取 R2 两端，
  分压比 = (R1+R2)/R2，选 1% 精度电阻；两点标定见 §5.5.4 链⑤ 步 2）。地址：
  INA219 = 0x40、ADS1115 = 0x48（`i2cdetect -y 1` 核验）。

**接线 4｜显示件 MAX7219 LED 点阵（BOM #4 定案件，SPI；SSD1306/I2C 为存档备选）**

| 序号 | BCM（GPIO） | 物理脚号 | 连接对象 | 信号方向 | 供电轨与共地 |
|---|---|---|---|---|---|
| 1 | GPIO10（MOSI） | 19 | MAX7219 DIN | Pi → 显示件 | VCC 取 5V（物理脚 2） |
| 2 | GPIO11（SCLK） | 23 | MAX7219 CLK | Pi → 显示件 | 3.3V 电平一般可直接驱动，不识别时加电平转换 |
| 3 | GPIO8（CE0） | 24 | MAX7219 CS | Pi → 显示件 | SPI 使能 `dtparam=spi=on`（§5.5.3 件 5） |
| 4 | — | 2（5V） | MAX7219 VCC | — | 5V 轨 |
| 5 | — | 6（GND） | MAX7219 GND | — | 共地 |

**接线 5｜整机供电拓扑（文字图）**

```
锂电池组 ── TP4056（充电管理，板载保护必须有）── 电池母线（标称 Vbatt）
                                                ├── ADC 采样（经分压网，接线 3）
                                                └── UBEC 5V/3A（BOM #3）
                                                     ├── Pi 5V（GPIO 2/4 口直供或 USB-C，二选一按实测）

         ——单点原则，避免地环路（舵机抖动与 ADC 漂移的常见根源）
```

[unit](../../../base/os/distro/units/rrd.service) 的增量以注记标注）：


  "目录方案"占位。**【裁定已回填 2026-10-07】批F5b 裁定走"socket 建后
  chgrp/chmod 属主组"路线（二选一之后者，牵动面小、两轨共用、与 ADR-0010
  裁定 2"文件权限位即访问控制"直配）——上三行 RuntimeDirectory/Mode/UMask

### 5.5.4 逐链路验收 runbook（七链，判据 7–15 的操作实体）

> 每步四件套（操作=完整命令 / 预期输出=样例回显 / 判定=过分界 / 失败处置=分支）。
> 链①→② 有序，③④⑤⑥⑦ 在各自前置件落位后可独立验。逐失败模式速查总表见
> §5.5.5。

**链①｜语音采集（判据 7 真件档，前置：接线 2 + 件 1–3）**

1. arecord 手工采样核验（不依赖任何 rockrobot3 件）：
   - 操作：`arecord -D rr3mic -c 4 -f S16_LE -r 16000 -d 2 /tmp/mic.wav && ls -l /tmp/mic.wav`
   - 预期输出（样例）：`-rw-r--r-- 1 pi pi 256036 … /tmp/mic.wav`。
   - 判定：文件大小与理论值（256000B）差 ≤10% 且 `aplay -D rr3mic /tmp/mic.wav`（或
     任意外放）回放可闻。
   - 失败处置：`Device or resource busy` → §5.5.5 行 4；录出全 0 → 增益/通道映射
     （`alsamixer -c rr3mic` 拉采集增益，链②共用）。
2. sense 上板换真后端启动：
   - 操作：

     ```bash
     sudo systemctl edit rrd        # 加：Environment=RR3_HAL_BACKEND=linux
     sudo systemctl restart rrd
     journalctl -u rrd -n 30 --no-pager
     ```

   - 预期输出（样例）：rr3-sense spawn 行 + 注册成功行；`rr3-ctl status` 中
     sense 行 PHASE 为在册活态（渲染以实况为准）。
   - 判定：sense 在册且 30s 不退（探活过 = ALSA 设备打开成功——backend 语义
     `Unsupported` 即 exit(1)，退了就是没换装成功）。
   - 失败处置：sense 反复重启 → journal 找 `Unsupported` / 打开失败行；**ALSA 层
     不通不进模块层**——回步 1 手工核验（分层排查纪律）。
3. 帧计数增长观察：
   - 操作：`rr3-ctl counters | grep -A3 -i sense`（间隔 30s 跑两次对比）。
   - 预期输出（样例）：

     ```
     MODULE          KEY               VALUE
     rr3-sense       pcm_frames_pub    214
     ```

   - 判定：两次采样间计数单调增长。键名以板上实测回填（若 counters 暂无 sense
     键，以 `rr3-ctl logs` 的发布日志替代并登记键位敞口，随批F 实装补）。
   - 失败处置：计数不增 → `rr3-ctl status` 看**拒发布计数**列（发布归属四道门，
     rrd-registry §8）+ `rr3-ctl logs | grep -i audio`。

**链②｜DoA 判向（判据 8 真件档，前置：链① 全过）**

- 操作：声源（人声/敲击）分别在阵列正左、正右各发声 5 次；
  `journalctl -u rrd -f | grep -i doa`。
- 预期输出（样例）：`doa: sector=left (conf 0.62)` / `doa: sector=right (conf 0.71)`
  （落档形式以 sense 实装为准）。
- 判定：左右各 5 次中 ≥4 次落正确半区（±90° 粗分档口径，R2）。
- 失败处置：全落一侧 → 通道接反（对调通道序，核对 `arecord` 通道 ↔ 物理麦映射）；
  置信度整体极低 → 采集增益过低或声源过远（<1m 复测）。

**链③｜舵机转向（判据 8 真件档，前置：接线 1 + 件 5）**

1. 底层核验（不经模块，验 PWM 硬件面）：
   - 操作：

     ```bash
     echo 0 | sudo tee /sys/class/pwm/pwmchip0/export
     echo 20000000 | sudo tee /sys/class/pwm/pwmchip0/pwm0/period    # 50Hz
     echo 1500000 | sudo tee /sys/class/pwm/pwmchip0/pwm0/duty_cycle # 中位 1.5ms
     echo 1 | sudo tee /sys/class/pwm/pwmchip0/pwm0/enable
     ```

   - 预期输出（样例）：三行 tee 回显各配置值；舵机臂**到中位并静止**。
   - 判定：中位静止不抖即过。
   - 失败处置：抖动 → §5.5.5 行 7（供电/共地）；无 pwmchip → `dmesg | grep -i pwm`
     查 overlay 是否生效（件 5）。
2. 链路触发（判向 → 转向编排）：
   - 操作：复跑链②发声，`journalctl -u rrd -f | grep -i act`（或批F3 后经 interact
     面板手动触发）。
   - 预期输出（样例）：`servo: turn sector=left -> -45deg`（落档形式以实装为准）。
   - 判定：转向动作与声源侧一致、转角目测可达。
   - 失败处置：act 无反应 → `rr3-ctl status` 查 intent 订阅链与拒发布计数；
     **注**：通用 RPC 注入（`rr3.call`）不在 rrctl 现有六子命令内，登记另批敞口
     （不为本批新写）——真件验收走编排链或面板，不经 CLI 直注。

**链④｜表情输出（判据 9 真件档，前置：接线 4 + 件 5 SPI）**

- 操作：mock 全链跑一轮（`RR3_BRAIN_CLOUD=mock` unit 环境，判据 10）或批F3 后
  经面板逐态触发；观察 MAX7219。
- 预期输出：待命/听取/转向/播报/低电五态各自帧序可见；多帧动画过渡连续（帧集
  随批F3 状态集）。
- 判定：五态逐一可见 + 至少一个多帧动画连续播完。
- 失败处置：全黑 → `ls /dev/spidev0.*` + 接线 CLK/CS 逐列核对；显示错乱 → SPI
  模式/速率（实装时定稿）。存档备选 SSD1306（I2C）复活时排查 NACK（§5.5.5 行 6）。

**链⑤｜电源真电池（判据 12，前置：接线 3 + 批F5a battery linux 后端换装）**

1. 原始读数：
   - 操作：`i2cdetect -y 1 && i2cget -y 1 0x40 0x02 w`（INA219 总线电压寄存器
     0x02，字序按器件手册换算；ADS1115 选型时换 A0 转换寄存器）。
   - 预期输出（样例）：i2cdetect 表 `0x40` 位出 `40`；i2cget 回 `0x2c31` 样例值。
   - 判定：器件在表且读数 ≠ 0xffff（全 1 通常是开路/未接）。
   - 失败处置：表空 → §5.5.5 行 6。
2. 两点标定：
   - 操作：万用表量母线满电 V1 与放电至 ~70% 的 V2 两点；记录对应原始值 R1/R2；
     线性换算 k = (V2−V1)/(R2−R1)、b = V1 − k·R1；写入 battery config.toml 标定段
     （config 件随批F5a 落库，格式 `[[calib]] raw=… volt=…`）。
   - 预期输出：标定后任测第三点，换算值与万用表差 ≤2%。
   - 判定：第三点偏差 ≤2% 即过。
   - 失败处置：漂移大 → 分压电阻换 1% 精度；系统性偏移 → 共地点压差（回查
     接线 5 单点共地）。
3. 事件与低电边沿：
   - 操作：`rr3-ctl status` 看 power 行；调低 config 阈值至当前电压之上触发低电
     边沿；`journalctl -u rrd | grep -i battery`。
   - 预期输出（样例）：`battery: state=discharging volt=7.62 pct=68`；边沿
     `battery: low-threshold crossed (7.05 < 7.20)`。
   - 判定：事件出且边沿**一次触发即到、不往复抖动**（迟滞生效）。
   - 失败处置：事件不出 → power 模块探活退（linux 后端未换装完成，回 §5.2 判据
     12 前置）；边沿抖 → 阈值迟滞参数不足（随批F5a config 定稿）。

**链⑥｜网络真 wifi（判据 13，前置：件 4 + 批F5a link linux 后端换装）**

- 操作：件 4 配网全套 → 断网（拔 AP）30s → 恢复 →
  `nmcli -f GENERAL.STATE dev show wlan0` + `rr3-ctl status` connect 行 +
  `journalctl -u rrd | grep -i link`。
- 预期输出（样例）：系统层 `GENERAL.STATE: 100 (connected)`；总线层
  `link: down -> up`（connect 发布的链路拍状态翻转）。
- 判定：配网一次成功、断网 30s 自恢复无人工、系统层与总线层状态一致翻转。
- 失败处置：配网失败 → `journalctl -u NetworkManager -b | grep -iE 'fail|auth|reason'`
  （auth → PSK 错；5G 不可见 → country 未设）；连上但总线无翻转 → connect 后端
  未换装（状态源仍在 sim 档）。

**链⑦｜运维链（判据 14/15，前置：§5.5.1 全过即可，与链①–⑥ 独立）**

1. 看门狗判死重启（SIGSTOP 冻结心跳路径）：
   - 操作：

     ```bash
     pgrep -f rr3-modules/rr3-sense        # 取 PID
     sudo kill -STOP <pid>
     journalctl -u rrd -f                  # 观察判死→重启计划→重新注册
     ```

   - 预期输出（样例日志序）：

     ```
     rrd heartbeat timeout: rr3-sense (last beat 3.2s ago > timeout 2.0s)
     rrd 判死 rr3-sense：重启计划 delay=2s (attempt 1/5)
     rrd spawn rr3-sense (attempt 1)
     rrd rr3-sense 注册 ok (phase=alive)
     ```

   - 判定：超时判死行 + 重启计划行 + 重新注册行齐（退避上限与
     rrd-registry §7 判死语义一致）。
   - 失败处置：无判死 → 心跳超时配置与冻结时长不匹配（冻结 ≥ 2× 超时再观察）。
2. SIGKILL 直杀路径（supervisor 兜底）：
   - 操作：`sudo pkill -9 -f rr3-modules/rr3-sense && sleep 5 && rr3-ctl status | grep sense`
   - 预期输出（样例）：journal 有子进程退出捕获 + 重启行；status 回在册活态。
   - 判定：模块自动回归在册，无人工介入。
   - 失败处置：不重启 → journal 尾部找"重启计划耗尽"行（attempt 上限语义见
     rrd-registry §7）；`Restart=always` 未生效回件 1。
3. systemd 级（判死 rrd 本体）：
   - 操作：`sudo systemctl kill -s KILL rrd && sleep 4 && systemctl status rrd --no-pager | head -5`
   - 预期输出（样例）：`Active: active (running)`；journal 有
     `Main process exited, code=killed, status=9/KILL`。
   - 判定：4s 内自恢复 active（Restart=always + RestartSec=2）。
4. 断电恢复（判据 15 前半）：
   - 操作：整机断电 30s → 上电待 boot 完成 → `rr3-ctl counters | grep -A1 -i rrd`
   - 预期输出（样例）：`rrd    boots    7`（值较断电前 +1）。
   - 判定：boots 跨断电**累积**（RR3_DATA_DIR 持久化语义，批E' 修复的验收延伸）。
   - 失败处置：重置为 1 → §5.5.5 行 8。
5. 真 reboot 两档（判据 15 后半，两档都验）：
   - 档 a（未注入，预期恒拒）：`sudo systemctl edit rrd` 注释
     `Environment=RR3_REBOOT_OK=1` 行 → restart → `rr3-ctl reboot`。
     预期输出（样例）：`reboot 拒绝：RR3_REBOOT_OK 未注入（rrd 双重门，ADR-0010）`
     （文案以 rrd 实际回显为准）+ 机器**不**重启。
   - 档 b（注入，预期真重启）：edit 恢复该行 → restart → `rr3-ctl reboot` →
     机器真重启，上电后 `rr3-ctl status` 链路自恢复。
   - 判定：两档行为相反且各自成立——缺一不算过（判据 15）。
   - 失败处置：档 a 仍重启 → `systemctl show rrd -p Environment` 断言 env 未清；
     档 b 不重启 → 板上 deb 未含新 unit（重装 deb）。

### 5.5.5 失败处置总表（九行速查；链内分支的汇总索引）

| 失败模式 | 典型特征 | 排查序列 | 处置动作 |
|---|---|---|---|
| rustc 版本不足 | cargo 报 edition/依赖锁错误 | `rustc --version` 对照 ≥1.82（R13 门） | `rustup toolchain install <ver> --profile minimal && rustup default <ver>` |
| UAC 卡号漂移 | 插拔后 sense 打不开原卡号 | `cat /proc/asound/cards` 插拔前后对比 | 件 3 udev alias 固定 + 件 2 asound.conf 指别名 |
| 板上 RAM 不足 | 编译进程被 kill / 系统卡死 | `dmesg \| grep -i oom` + `free -h` | 2G swapfile（§5.5.1 步 5）；启用即在 boards 笔记登记敞口 |
| alsa 设备打不开 | sense 探活退 / arecord 报 busy | `arecord -l` → `fuser -v /dev/snd/*` → `sudo alsactl init` | 杀占用者；`alsactl init` 重置；仍不通回 §5.5.1 步 6 sanity |
| WiFi 配网失败 | `nmcli con up` 报错 / 连不上 | `journalctl -u NetworkManager -b \| grep -iE 'fail\|auth\|reason'` | reason=auth → PSK 核对；5G 不可见 → country 未设（件 4）；DHCP 失败 → AP 侧排查 |
| I2C NACK | `i2cdetect -y 1` 空表 / 读数 0xffff | 六列接线逐列核对 → 上拉 → 地址核对 | 断电重接 SDA/SCL/VCC/GND；确认 3.3V 轨；地址对表（INA219=0x40 / ADS1115=0x48 / SSD1306=0x3C） |
| 舵机抖动 | 静止位高频抖动 / 啸叫 | 独立供电轨否 → 单点共地否 → 脉宽抖否 | UBEC 独立轨（BOM #3）+ 单点共地（接线 5）；软件脉宽抖归 act 后端实装修 |
| boots 不累积 | 每次重启 counters boots=1 | `systemctl show rrd -p Environment` 断言 RR3_DATA_DIR；`ls -l /var/lib/rockrobot3` | unit 注入 + 目录存在（批E' 修复复检；手装环境 `sudo mkdir -p /var/lib/rockrobot3`） |
| socket 权限拒 | 非 root `rr3-ctl` 报 Permission denied | `ls -l /var/run/rock3-ipc.sock`；`groups`；`systemctl show rrd -p UMask -p RuntimeDirectoryMode` | 批F5b 放行落位前用 `sudo` 巡检（批E' 登记的现状口径）；落位后核 UMask=0002 + 组归属 |

## 7 与 0.0.7（ESP32）的边界预留

**本方案不做 ESP32 任何实现与设计**，只登记方向事实供 0.0.7 方案立项：

- ESP32 非 Linux 主控，**不进 ADR-0013 的三层模型**（Layer 0/1/2 的语境是
  "Linux 起来之后"；ESP32 上没有 Linux 起来）。它不能走 deb/payload 路径，
  这不是缺陷而是模型边界。
- 候选接入路径（0.0.7 方案再裁）：**a. 桥接模块**——Linux 侧 bridge 模块把
  串口/USB-CDC 链路上的 ESP32 对端翻译成总线语义，线上格式复用 AiryIPC 128B
  帧（[ADR-0008](../adr/ADR-0008-传输层trait定型与uds实现.md) 的 transport trait
  预留第三实现位）；**b. 协处理器**——ADR-0015 裁定 4 同位角色（拾音/唤醒
  剥离，服务待机 <1W）。
- 遗留联动：ESP-IDF 密钥门（历史遗留敞口）在 0.0.7 立项时一并清理。
- 版本排期已写死（Q1 裁定）：**0.0.6 = 树莓派验证（本方案）、0.0.7 = ESP32、
  brain 迁移专项归属 0.0.8**——ADR-0016 修订记录与本条互为印证，不再漂移。
- 0.0.7 立项前置裁定已由 0.0.5 重裁轮 R5 给出：**四层验证梯子**（契约 parity →
  USB-CDC/UART 传输层 → 模块层 → Linux 桥接跨芯片 e2e；层①②必达、层③④按实测
  内存裁），方案新立落
  [0.0.7 版本洛克三号ESP32系统级验证方案](0.0.7版本洛克三号ESP32系统级验证方案.md)。
