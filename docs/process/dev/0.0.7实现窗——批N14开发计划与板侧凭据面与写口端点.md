**不排项（如实登记，防定性拖散）**：

| 项 | 归宿 |
|---|---|
| `cred_store` 键进 `[hardware]`/绑定域（N-10 ② 键半边） | **缓批**，两条硬依据：① 绑定域扩键＝**契约级三处同批**（rr-ipc `RR3_BOARD_BINDING_KEYS` 10→11＋rr-hal `Rr3HalBindings` 字段集＋rr-registry `RR3_ASSEMBLE_DESC_KEYS`，contract.rs 机判钉三面——bindings.rs :67 原文"扩键走契约级评审"）；② **架构事实：桥上注入晚于 WiFi 起栈**（绑定经 `rr3.set_bindings` 在桥连接后到达，而凭据读取在起栈线程 `start_httpd` 内——boot 读链**不可能**消费桥上键），键的唯一可能读者只剩"注入后一致性校验"（薄读者）——本批不立薄读者；对象以 namespace 常量 `"rr3"` 单真值落码，键半边随绑定域扩批评审另批，**N-10 ② 行不结项** |
| 板侧写口密码下限策略（legacy"至少 8 位"） | **不随批**——该规则是宿主面板契约字面量（connect 册 §9 断言：`pass`、"密码至少 8 位"属 legacy 面板依赖），板侧写口仅形制校验（SSID 1..=32B／密码 ≤64B，与编译期注入路径 spawn 侧 32/64 同口径）；下限统一随 N-11 ②③ 批次对表 |
| TLS | 批N4 件二定案**不做**（四理由在案）维持 |
| 真板行为取证（写口 curl 实测／回退实录／`esp_get_free_heap_size` 对账） | 真板验证窗（板不在手） |
| 敞口 13 余量（镜像装配/OTA/回滚） | 另批（批N12 §1 同口径维持） |

## §2 件表

### 件一：板侧凭据存储对象（`cred.rs` 立件，N-10 ② 主体半边）

- **形状**（机制与策略分离）：纯逻辑层＝形制校验（`ssid 1..=32B / pass ≤64B`，空密码＝开放
  网络合法，与编译期路径同口径）＋凭据值类型**不派生 `Debug`/`Display`**（零回显的第一道
  机器墙）；NVS 窄缝层＝`nvs_open`（namespace `"rr3"` 单真值常量，键 `wifi.ssid`/`wifi.pass`）
  → `nvs_get_str`/`nvs_set_str` → `nvs_commit`——**读时现取**（不缓存不驻留）、**不落日志**
  （错误点名只出键名与长度不出值）、**零回显是契约要求**（本件注释钉死＋既有 state/bindings
  JSON 形状单测续钉：凭据字段结构性不可达）。
- **boot 读链切换**（[httpd.rs](../../../tools/esp32-periph-base/src/httpd.rs) spawn 段）：
  `nvs_flash_init` 前移 spawn（失败＝配置腿缺席 fail-honest，同批N13 口径）→ **NVS 优先**（`rr3_cred_read`）
  → **编译期回落**（`option_env!` 两 env，批N13 面貌原样）→ 都缺＝缺席照常。NVS 空时行为与
  批N13 逐字一致（零回归——真板会话链不感知）；`start_httpd` 内 nvs 步随之移除（前移非删除）。
- **判据**：`tools/ci/esp32-periph-base-check.sh` 甲面构建两步 PASS（本机 esp 工具链真跑非
  SKIP）＋cred.rs 单测（形制域／NVS 键名常量单真值／值类型无 Debug 形制）＋decisions §4 变更行。

### 件二：HTTP 写口两枚（`RR3_BOARD_ROUTES` 扩 POST 行）

- **端点集**：
  - `POST /api/board/wifi`——**事务性配网写口**：读旧值（事务域内暂驻，用后即弃）→ 形制
    校验 → `rr3_cred_write`（NVS）→ STA 重配置重连（`esp_wifi_disconnect`→`set_config`→
    `esp_wifi_connect`）→ **有界等连**（`esp_wifi_sta_get_ap_info` 探测，500ms×12 封顶）
    → 败即**回退**（NVS 复原旧值／原空态 erase＋同法重连）→ 应答 `{ok, connected, reverted}`
    **如实取读数不 fake**（同 connect RPC"connected 永不因请求成功而置真"纪律）。回退即事务：
    "写坏凭据板掉网"砖路径消灭（fail-safe 方向——新凭据连不上时板仍以旧凭据可达，NVS 状态
    同步复原）；最坏阻塞 ~12s（httpd 单请求串行，配置动作可接受，注释写明）。
  - `POST /api/board/reboot`——动作面写口（同 host 面板 relay/beep 动作先例）：应答
    `{ok, action:"reboot"}` 后 `esp_restart()`。
- **method 面改造**：handler 从 `(*req).method` 读真实 method（替代批N13 硬编码 `"GET"`），
  注册面按表行 method 映射（`http_method_HTTP_GET=1`/`HTTP_POST=3`，生成绑定已核对）；
  路由纯函数扩 POST 臂，`route_table_matches_dispatch` 零漂移单测同步扩。
- **并发面**：esp_wifi 调用集中在写口 handler（IDF 内部锁序列化，官方线程安全口径）；
  **有界等待不持 bus 锁**——写口全程不碰 `Bus`（凭据面与运行态观测面零交集，锁面零新增）。
- **申报面**：`wifi` 行 applies=`"live"`（即时生效）；`reboot` 行 applies=空（动作面，同 host
  relay/beep 先例）；covers 全空维持（凭据不在 ⑩ 分母五路）；板侧 covers 形制单测词表不变
  （`""`/`"live"` 已容）。check.sh ⑩ 两源扫描对 POST 行：covers 空＝分子零贡献，**门 d 数字
  零变动对账**（分母 82／covers 申报 88／红账 0／基线零改动）。
- **判据**：甲面构建两步 PASS＋单测（路由零漂移含 POST／形制域／wifi 应答 JSON 零凭据字段）
  ＋check.sh 全量 PASS＋门 d 数字零变动核对＋decisions §4 变更行。
