### 件二：编译期注入烧录→boot 取证（前置＝用户提供 2.4GHz AP 凭据）

- **步骤**：`RR3_BOARD_WIFI_SSID/PASS` env 前缀构建（`option_env!` 编译期烘焙）→ 烧录
  → boot 日志取证。
- **判据**：boot 日志「凭据源=编译期」（cred_source 点名串，永不出值）＋WiFi 起栈＋
  DHCP 得 IP（curl 可达前件）＋RAM 打点续记（heap 对账：boot free 与
  `heap_reserved_bytes=98816` 预留口径对照，批N10 contract pin）＋若 env 变更未触发
  重编则如实记录处置（touch/clean）。
- **取证实录**（2026-10-22/23，AP＝WXYYBG 2.4G ch11）：env 前缀构建 **option_env! 变更
  自动触发重编**（cargo env 跟踪，33.87s Compiling esp32-periph-base——无需 touch）；
  boot 日志 :96「配置腿起（N-13，凭据源=编译期）: http://0.0.0.0:80/api/board/*（白
  名单 4 端点…）」＋:101 `wifi:connected with WXYYBG, aid=5, channel 11, BW20`＋:113
  `esp_netif_handlers: sta ip: 192.168.0.167`（与 Mac 192.168.0.186 同网段）。
  **本件抓出批N14 两枚真板缺陷（修复提交 745b598／9b348f5）**：①boot 起栈链
  `esp_wifi_start()` 后缺 `esp_wifi_connect()`（esp_wifi_start 只起驱动不自动连——
  板永不关联、无 got ip）；②等连判据 `esp_wifi_sta_get_ap_info` 在**关联瞬态
  （auth/assoc→run，4-way 握手前）即返 ESP_OK**——坏凭据被误判成功→不回退→NVS
  残留坏凭据＝**真砖路径**（真板波形：关联 run 后 3s 被 AP 踢回 init 反复；救砖＝
  `espflash erase-region 0x9000 0x6000` 擦 NVS 分区）——修复＝判据改 **DHCP 得 IP**
  （`esp_netif_get_ip_info` 的 ip.addr 非 0，密码错永远到不了 DHCP 物理可靠）＋
  STA_NETIF 句柄留存。**heap 对账**：WiFi+httpd 起栈常驻实测＝修复版 mic-smoke 点
  124896B − 无凭据版 167748B＝**42852B**，远小于 `heap_reserved_bytes=98816` 预留
  ——预留充足不溢（boot 270648B 与无凭据版逐字节同＝起栈前零漂移）。

### 件三：curl 读面实测（GET 两端点＋400 形制面顺带）

- **步骤**：Mac curl 打板 IP `/api/board/state`、`/api/board/bindings`（应答形状＋
  **零凭据字段**实录）；顺带实录未注册路径 404、`POST /api/board/wifi` body 越界/
  缺字段 400 拒收（HTTP 层失败不读全，批N14 契约）。
- **判据**：两 GET 应答 JSON 与单测钉死形状一致＋凭据字段结构性缺席＋400/404 面与
  契约一致。
- **取证实录**（板 IP 192.168.0.167）：`GET /api/board/state` → 200 全形（
  `{"audio_dropped":0,…,"pan_deg":60,"rail_mv":398,"rail_tier":"severe","tilt_deg":98,…}`
  ——**零凭据字段**结构性缺席实录）；`GET /api/board/bindings` → `null`（桥未注入
  现状如实）；未注册路径 → **404** ✓；POST wifi body 600B 越界 → **400 拒收不读全** ✓
  （批N14 HTTP 层契约）；body 缺 pass 字段（form 误投）→ 200
  `{"connected":false,"ok":false,"reverted":false,"stage":"body"}`——业务层如实应答
  四字段形状与单测钉死一致 ✓。**写口 body 是 JSON**（`{"ssid":..,"pass":..}`，
  rr3_wifi_write_body 解析），curl 实测必须 JSON 投递（form 串解析败 stage=body，
  形制面如实）。

### 件四：写口事务实录（两回退分支全覆盖）

- **步骤**（顺序设计吃满两个回退分支）：
  1. `POST /api/board/wifi` **坏凭据**（旧值 None）→ 有界等连败 → **回退走 erase
     分支**（幂等回原空态）→ 应答 `{ok, connected:false, reverted:true, stage}` 如实；
  2. `POST /api/board/wifi` **好凭据**（即件二注入组）→ 等连成 → `connected:true`、
     NVS 写入；
  3. **reboot** → boot 日志「凭据源=nvs」＝**NVS 读链切换真板证实**（批N14 件一
     主判据）；
  4. `POST /api/board/wifi` **再坏凭据**（旧值 Some）→ 回退走**写回分支**（旧凭据
     复原重连）→ 应答 reverted 如实 → 板仍以旧凭据可达（砖路径消灭真板证实）。
- **判据**：`connected` 永不因请求被接受而置真（坏凭据实录应答 connected=false）
  ＋两回退分支各实录一笔＋stage 串如实点名＋全程板不掉网（回退后 curl 仍可达）。
- **取证实录**（缺陷二修复后固件，全序四步）：
  1. **坏凭据**（NVS 空旧值 None）`{"ssid":"WXYYBG","pass":"wrongpass9999"}` → 事务
     等连败（DHCP 判据下 4-way 握手败）→ erase 回原空态 → 板停断态（None 分支
     「原空态＝停在断态，不 connect」语义）→ curl 40s 超时、应答随断网丢失（
     **物理事实**：None 旧值回退后板无网，应答 TCP 必死——应答不可达非缺陷，是
     原空态语义的必然后果）；RTS 复位后「凭据源=编译期」复活＝**erase 生效实证**
     （NVS 无残留，缺陷二修复有效）；
  2. **好凭据** `{"ssid":"WXYYBG","pass":"12345678"}` → 板上事务成功（NVS 入档＋
     重连 2s，IP 不变 192.168.0.167、state 200 复核）——但应答 TCP 随 reconnect
     断链丢失（curl exit 56 recv failure）＝**动作面写口应答物理不可达**（第二处
     同型事实，见件五注记）；
  3. **reboot**（详见件五）；
  4. **再坏凭据**（旧值 Some=好凭据）→ 等连败 → **写回分支**：NVS 复原好凭据＋
     重连成功 → 板 20s 内自动恢复在线（**state 200 实录＝「新凭据连不上时板仍以
     旧凭据可达」砖路径消灭的真板实证**）；RTS 复位后「凭据源=nvs」＋连 WXYYBG
     ＋得 IP＝**写回内容正确实证**。
  `connected` 判据全程如实（坏凭据零误报——修复后）；stage 串点名（reverted/）。
  **应答不可达事实汇总**：wifi 写口三笔 POST（坏/好/再坏）应答均未送达 curl——
  reconnect/erase 断链杀 TCP 是物理必然，客户端确认只能靠旁证（板重新可达后
  GET state/bindings＋复位后 boot 凭据源点名）；批N14「应答 {ok,connected,
  reverted,stage} 如实取读数」契约的**取读数半边真板成立**（板上状态转移全部
  正确），**送达半边物理不成立**（除非动作后延迟应答——裁定留收口，不影响
  fail-safe 语义）。

  放指针——实录细节不进两表（基-34 三处旧落点只给指针纪律）。
- **取证实录**（2026-10-23）：`POST /api/board/reboot` → 应答未送达（http=000——
  `httpd_resp_send` 后 `esp_restart()` 杀 lwIP 缓冲，数据未出网卡＝**重启动作面
  应答物理不可达**，与 wifi 写口 reconnect 断链同型；板侧重启行为正确）→ 板重启
  → boot :96 **「配置腿起（N-13，凭据源=nvs）」**＋:101 连 WXYYBG＋:112 得 IP
  192.168.0.167——**NVS 读链切换真板实锤**（批N14 件一主判据：NVS 优先读链全链
  走通，cred_store 键 `wifi.ssid`/`wifi.pass` namespace `"rr3"` 真板持久化生效）。
  与件四 3 步 reboot 合并计算，两处 reboot（写口触发一次＋RTS 物理复位多次）boot
  链全部完整、无 panic/abort/Guru。
