### 件二：写口/reboot 动作面应答物理不可达行为裁定（旁证契约化 vs 延迟应答）

- **事实基线**（批N15 真板实录，取证基线 `d07de82`）：写口事务实现**已经是**"事务完成后应答"
  （读旧值→写 NVS→STA 重配置重连→有界等连→败即回退→如实应答四字段）——应答时刻已是最终
  时刻，不存在"更延迟"的应答位；但 reconnect 本身杀 socket（STA 重配置断链＝TCP 会话随网络
  栈状态死亡）、restart 直接复位＝应答字节物理送不出。真板实录：坏凭据 POST 后 curl 35s
  超时应答丢失；reboot 应答先行落链仍不可达。
- **裁定**：**旁证契约化**——「延迟应答」无余量（已是最终应答，socket 死亡是链路物理事实非
  实现顺序问题；改"先应答后做事"则丢四字段事务结果语义，属协议面重造不在本批）；四字段应答
  契约保留（取读数半边真板成立、送达尽力而为）＝**「确认」语义从应答通道旁证化**：
  - 写口生效确认＝板重新可达后 `GET /api/board/state` 的 `connected` 字段（新凭据连上＝生效；
    板仍以旧凭据可达＝回退生效——砖路径消灭真板实证语义）；
  - reboot 确认＝复位后 boot 横幅「凭据源=…」点名（NVS 读链切换两处实锤同源）。
- **落点**：decisions §3 补行（结案态——批N15 收口时该余量登记于 §4 收口行未入 §3，本批
  **补入即结**如实注记，防静默消失）＋§4 变更记录行＋[httpd.rs](../../../tools/esp32-periph-base/src/httpd.rs)
  模块文档写口段落契约注记＋connect 册 N-10 行对表注记。
- **判据**：裁定值与旁证确认语义在 decisions §3 行文可查；httpd.rs 模块文档与 connect 册
  N-10 行注记同口径；甲面门两步 PASS 零 warning；码面零行为改动（diff 只在 `//!` 注释区）。
