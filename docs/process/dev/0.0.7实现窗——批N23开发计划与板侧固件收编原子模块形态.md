## §2 收编语义裁定（三不三立）

**取证基础**：atom 校验器两道格主面法则——`provides.slots` 恰一项（rr-registry
[atom.rs](../../../base/runtime/rr-registry/src/atom.rs) :228）与板无关断言（:156，manifest 全文本
不得出现引脚/厂商/产品名）；仓级"每格一件"唯一性扫描根＝`modules/`（:513-516，`root.join("modules")`，
tools/ 不在执法域）；composite `unit` 词域仅 `"process"`（[composite.rs](../../../base/runtime/rr-registry/src/composite.rs) :53，
扩域走契约级评审）；`power.rail`/`power.budget` 在 `BUILTIN_NO_ATOM` 豁免集（atom.rs :500-506，
立无源码空原子件即 D15 所防空壳件）。

**三不**：

1. **不冒领格主**——板侧执行面件**不立 `atom.toml`**：`provides` 恰一格与板无关断言两道法则都按
   宿主格主立法，板侧执行件立了要么违"恰一格"（格主是宿主件）、要么说"板无关"的谎。格位对齐由
   件头注申报（servo↔act.servo / face↔ui.face / capture↔audio.capture），计划册＋status.md 同源对账。
2. **不扩契约词域**——composite `unit` 词域不含固件执行单元，扩域＝契约级评审；本批红线"不改对外
   契约"（topics/128B 字节/module.toml 申报面/slots 格名）不碰，故**不立 module.toml/composite.toml**
   （固件不进城——路线二裁定"板不注册总线身份"在案，无读者的 manifest 数据即 MC-8 判据要清的
   "在册无读者"反模式）。
3. **不 fork 校验器**——registry 校验器不复用裁剪（裁剪即第二真值点）；板侧门维持 xtensa 构建＋
   `--no-run` 单测编译两步既有口径，板侧纪律由生成物对账（既有门 f）＋单测＋对账锚承担。

**三立**：

1. **立 `atoms/<n>/` 件目录形态**——机制核收拢为 `mech.rs` 纯函数，落**文件级**机制/策略分离
   （board.rs 现状"机制护栏/策略集中"仅注释分界（board.rs :34/:236-244），收编落为文件分界）。
2. **立策略集中点显式化**——`board.rs` 收纯策略面：策略常量＋装配对账锚（`RR3_BIND_*` 十枚）＋
   对账纯函数；换板只动本文件的既有纪律升为文件边界。
3. **立格位对齐申报**——件头注（mech.rs 模块文档）申报所服务的格位与机制边界，三处同源
   （件头注/本册/status.md 对账行）。

**不立件面**（如实注记）：`power.rs` 轨守护不立 atoms/（`power.rail` 在 `BUILTIN_NO_ATOM` 豁免集，
先例＝rr3-power 件内机制切片与板侧守护无独立原子目录）；`httpd.rs`/`cred.rs`/`link.rs`（net.* 被裁
格位，板侧配网基础设施非格位能力）、`frame.rs`/`state.rs`/`commands.rs`/`runtime.rs`/`periph.rs`
（指令面与两面编排，非格位机制）均维持现状。
