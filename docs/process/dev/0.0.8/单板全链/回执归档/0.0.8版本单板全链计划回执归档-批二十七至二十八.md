## 批27·2026-11-24 回执（弃用面升级 + 两处误红根修）

**已收口**

1. **弃用面巡检与升级**（`db860d2`）：三线最近全码头的 annotations 里唯一 warning
   是 `actions/cache@v4` 被强制跑在 Node 24（Node 20 已弃用）。同批升级四件：
   `cache` v4→v5（4 处）、`docker/login-action` v3→v4（4 处）、
   `docker/setup-buildx-action` v3→v4（1 处）、`softprops/action-gh-release`
   v2→v3（1 处），`ACTION_MATRIX` 单点同步，`ci-workflows.md` 记运行时基线。
   发布路径三件只在 tag 执行（v3 历史回执不覆盖 v4/v3），status 记敞口。
   **证据**：`db860d2` 的 buildroot dtb 腿用 cache v5 实跑成功；`b507855` 的
   esp32 双腿 success 且注解只剩 `esp-build-size` notice（Node 20 warning 消失）。
2. **runbook B 漂移复核**（`33523a33`）：镜像名（`ghcr.io/rockrobot3/rockrobot3`）、
   固件 OCI 名、`image-smoke.sh file|run`、`VERSION` 同源校验与 `publish.yml` 逐项
   一致；SBOM/签名当前**未启用**（三腿 `docker build` 直推、固件 oras），runbook
   如实标注；合并清单的 attestation 注释同步纠正为"容忍未来启用"。
3. **riscv 目标 ISA 误红根修**（`06542544`）：`33523a3` 的 platforms 红在
   `rr-bus-api` 的 `inbox_full_heartbeat`（riscv64gc gnu + QEMU）。测试在首拍
   心跳见 `drops > 0` 就退出，QEMU 慢时那一拍只丢了个位数，0.27s 即断言失败。
   改为等到达标值 64 才退出、上界 10s、取历史最大值——判据仍是原断言值，不是
   放水。`b507855` 的 riscv 腿 success。
4. **dtb-backport fuzz 假告警根修**（诊断 `0608a894`，修复 `b5078552`）：该告警
   自 11-23 起每跑必响。把命中行写进注解后取到原文
   `Hunk #1 succeeded at 79 with fuzz 1`；本地用 GNU patch 2.7.6 对**逐字命中**的
   纯插入 hunk 复现同一行（玩具样本同样复现），判定为纯插入 hunk 的 fuzz 假阳性，
   不是上下文漂移。改用 `git apply --check` + `git apply -p1` 严格比对（非仓目录
   实测可用），删除 fuzz 告警——偏移即红，不再有静默 fuzzy 应用。
   `b507855` 的 dtb 腿 success 且注解 0。
5. **status 记账**（`2db995e5`）：action 运行时基线改为"全量 Node 24 档 + 发布
   路径待 tag 回执"，不留"已验证"的过度表述。

**验证**：`b507855` 的 `gate`/`integration`/`platforms`/`buildroot` **四线 success**；
本地 workflows / gate_steps / metrics / baselines 审计与文档门全绿；Node 20
warning 在 esp32 双腿已消失。

## 批28·2026-11-24 回执（YAML 盲区补位 + 增量语义误红根修）

**已收口**

1. **workflow 语法/表达式盲区补位**（`62c4996f` 立，修 `0084466b`/`01f52150`/
   `7d2853d5`/`e98e1c0c`）：`workflows_audit` 是文本扫描器，缩进或表达式类型写坏时
   GitHub 会整文件不跑，而文本门仍绿——gate `scripts` job 增 `actionlint`（官方
   release 1.7.7 + sha256 校验；关 shellcheck/pyflakes 只留语法与上下文判据）。
   安装路径定 `$HOME/.local/bin` + `GITHUB_PATH`（`/usr/local/bin` 在 runner 上
   不可写）；该版 `-color` 是布尔开关，CI 非 TTY 直接不传。**四次红全部按注解
   定位根修**：install-action 工具表无 actionlint（exit 76）→ 改官方 release；
   资产落盘名与 checksums 清单不一致 → 按原名落盘；`-color=never` 非法 → 去参数；
   各阶段失败逐条压 `::error title=actionlint-install::`，免日志鉴权可归因。
   最终 actionlint 对六份 workflow **零发现**，gate scripts 步实跑通过。
2. **riscv 目标 ISA 误红再根修**（`704077bb`）：`62c4996` 的 riscv 腿再次红在
   `inbox_full_heartbeat`（10.21s 超时）。真因是心跳 `counters` 为**自上一拍以来的
   增量**（conn.rs 心跳口径），测试却取单拍最大值判 ≥64——QEMU 慢时 64 次丢弃摊到
   多拍，单拍最大值永远到不了 64。改为按拍累加、30s 上界、达标即止；判据值仍是
   64，不放水。`e98e1c0c` 的 riscv 腿 success。
3. **流水线失败面信息打印**：安装/校验/校验和不一致各阶段都自带点名注解（本轮
   实测四次红均靠注解直接定位，未依赖鉴权日志）。

**验证**：`e98e1c0c` 的 `gate`/`integration`/`platforms` **三线 success**；
`buildroot` 停在 `b507855`（本次未动 buildroot 路径，仍 success）；本地
workflows / gate_steps / metrics / baselines 审计与文档门全绿。
