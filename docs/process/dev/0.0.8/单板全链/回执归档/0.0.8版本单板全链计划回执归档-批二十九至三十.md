## 批29·2026-11-24 回执（unit 日志分界 + runbook C 实错修正）

**已收口**

1. **per-unit 日志 spawn 边界行**（`c3b88507`）：`<socket>.log/<unit>.log` 是 append
   语义，历次重启的输出混在一处，真板卡住时分不清"这是第几次拉起后的行"。每次
   spawn 先写一行 `===== rrd spawn <name> attempt=<n> at <epoch_ms> =====`——attempt
   与 rrd.log 的 `spawn` 行同值，壁钟毫秒用于对时；e2e 断言同步加上
   （[e2e_unit_log.rs](../../../../../../base/runtime/rrd/tests/e2e_unit_log.rs)）。integration 的
   matrix ⑥（`cargo test -p rrd --tests`）在 `c3b8850` success，新断言真跑通过。
2. **runbook C 漂移实错修正**（`cf6fe6fb`）：探针的 baud 参数只接受 termios 档名
   （或 `B<digits>`），裸 `1500000` 会被 `probe_common.baud_of` 以"未知波特率档名"
   拒绝——runbook C 原两条命令照抄必失败。改为 `B1500000`；这是"每轮抽一个窗口"
   制度首次抓到实错（此前 A/B 两轮为 0 命中）。
3. **计划册归档五**（`524616bf`）：批27–批28 回执迁入
   [归档五](0.0.8版本单板全链计划回执归档-批二十七至二十八.md)，正文 467→380 行；
   §0 维护线改"五次"，§11 索引补行。

**验证**：`cf6fe6fb` 的 gate success；`c3b88507` 的 integration（含 rrd e2e）与
platforms success；归档后文档门绿、相对链接 0 断。

## 批30·2026-11-24 回执（发布面 provenance/SBOM + runbook D 复核）

**已收口**

1. **发布面证明面**（`d7044430`）：三条镜像腿由 `docker build` 直推改为
   `docker buildx build --push --provenance=mode=max --sbom=true`，单架构清单各带
   provenance + SBOM attestation；riscv 腿复用 `build-riscv-image.sh --push`
   （buildx 推后 `docker pull` 同 digest 再跑两段冒烟，判据打在发布物上）。
   `workflow_rules` 的推送判据改为"`docker push` 或脚本 `--push` 二选一"——
   判据是"发布腿必须真推送"，不钉命令形状；runbook B 增 attestation 计数命令与
   "每腿 ≥2"判据；`ci-workflows.md` 与 status 同批记账（status 明写缺 tag 窗口
   回执、签名未启用）。**证据**：`d7044430` 的 gate success（actionlint 过
   publish.yml）、platforms 的 riscv-image 腿 success（脚本默认分支重构未破坏
   构建门）；`--push` 分支只在 tag/main 触发，按纪律留窗口回执，不冒领。
2. **runbook D 复核**（`ca30eb0a`）：证据要求由三样补到**五样**（环境指纹 /
   采样窗口 / 样本数 / 原始数据 / 目标三元组——代码判据一直是五样，文档漏写两样，
   窗口照文档准备会判"证据不足"）；`--evidence` 示例由占位 `00XX.md` 改为实际下一号
   `0023.md`；前置由 `hardware/*/axis` 收窄为"**所用装配档**的
   `hardware/<档名>/axis/`"（实测仅 esp32-mini 与 pi4b-solo 有轴档案，全局表述会
   误导成所有档都必须有）。
3. **轮末质量**：计划册 457 行（<500）；metrics 重复率 0.41%、CC 2.46/8、>50 行
   生产函数 0、panic 2，全部持平。

**验证**：`ca30eb0a` 的 gate success；`d7044430` 的 integration/platforms success；
本地 workflows / gate_steps / metrics / baselines 审计与文档门全绿。
