## 批21·2026-11-24 回执（ESP 构建体积评估 + 面板测试 env 根修）

**已收口**

1. **流水线信息面修正**（`36a0ab1e`）：目标 ISA 单测步文案由"两 crate"改为
   "纯逻辑 crate"（实际十 crate，成员单点在脚本）；esp32-gates 增"构建树体积
   快照"步（`du` target/embuild，`::notice` 匿名可读）。只读数，不改判据。
2. **首推红根修**（`b239a797`）：gate 的 conventions 红在 `rr3-interact` 面板测试
   `selftest_legs_fail`——`RR3_BUS_PATH_ENV` 是进程全局，`selftest` / `service`
   两处夹具各自 set/remove，并行时一处 remove 把另一处的连接翻到缺省套接字。
   根修：tests 模块加进程级 `RR3_ENV_LOCK`（毒锁内继续），两处夹具共同持锁覆盖
   `set → connect → remove`；复跑三线 success（run `45343589795`，11m47s）。
3. **ESP 构建缓存评估（结论：不做）**：注解读数 classic target=4.6G、S3
   target=3.2G；`/tmp/rr3-embuild` 在快照时不存在（na，登记存疑，不冒领）。
   GitHub 仓库缓存上限 10GB 且需与 esp 工具链缓存共存，两芯片 target 缓存会引发
   淘汰抖动，收益不稳。**决定不启用 target 缓存**；快照步保留作后续证据。

**验证**：本地 rustfmt、`bash -n`、只读审计全绿（重复率 0.41%、CC 2.46/8、
>50 行 0、panic 2、锁内 I/O 0、unsafe 0）；流水线 `b239a797` 的
`gate`/`integration`/`platforms` **三线 success**。
