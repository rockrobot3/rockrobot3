## 批40·2026-11-25 回执（ESP32 classic 烧录 + Pi 三线探针）

**已收口**

1. **A 窗口 classic**（[0023](../../../../../evidence/实测/0023.md)，`e8934ab4`）：用 `v0.0.21`
   发布资产烧录（app 1,112,816/3,080,192 B，NVS 保留），ELF/bootloader/分区表
   sha256 与发布清单及仓内真值一致；启动自证 `surface=esp-rs-std`、
   `console=uart0@115200 secondary=none`、`chip=esp32` 齐全；机制面九点
   （UART2 1.5M@GPIO18/19、I2C 0x3C、OLED、rail、LEDC、I2S 双麦、httpd、
   SoftAP、姿态 60/93）逐条在位。S3 full 无板未执行。
2. **C 窗口 Pi 三线探针**（[0024](../../../../../evidence/实测/0024.md)）：接好
   Pi pin8/10 ↔ ESP32 GPIO19/18 + 共地后，`bw_probe` 60s 音频 475 帧
   **0 撕裂 / 0 CRC / 0 断档 / 0 乱码**、PCM 全 8192；`frame_probe`
   **10/10**，`U3_FRAME_DIGEST=5432ac1f…` 与历史三端逐字相等；
   `set_bindings applied=true, mismatch=0`；rrd 探针前停、收尾恢复 active。
3. **E 窗口 classic 信息面**（随 0023）：一次启动能把 RAM 三点、UART2、I2C/OLED、
   rail、LEDC、I2S、httpd、SoftAP、姿态逐行点名，卡住点可直接定位。
4. **突发归因**：120 条无间隔 PAN 连发 115/120 OK、2 ERR、3 无回包；两条 ERR 为
   行首被啃与两行粘连，属无间隔突发下的行边界丢失，历史结论一致，双防线拦住
   未误动舵机；不写成 120/120。
5. **现场处置**：Pi 接线时重启导致 `/tmp` 清空，探针目录重同步（哈希对拍后运行）；
   `rrd` 探针前后 stop/start，最终 active。

**观察项（不记缺陷，下轮裁定）**：启动早期出现一次
`[mic] dump 逐窗不变（疑似 SD 虚接/停摆） 00…`，随后周期行 RMS 非零；判为暖机窗
全零触发，固件侧可加暖机抑制，但需下一次流水线制品 + 真板复验。NVS 内 WiFi 凭据
非本场 SSID，STA 重连如实记录；classic 无 STA/sntp 属既有 No-Go。
