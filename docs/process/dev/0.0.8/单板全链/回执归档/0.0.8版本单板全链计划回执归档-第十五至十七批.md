## 11 第十五批回执（2026-11-24，接归档 §20.14）

**已收口**

1. **契约解析单点**（`29e96876`）：module/atom 校验里字段规格原为每轮两次解析
   （未知键反查一次、逐字段一次），改为一轮一次、两处共用同一只读 `Vec`；错误文案与
   判据逐字不变。评审**否决**全局 `OnceLock` 缓存——校验不在运行热路径（rrd 启动不
   重解析 manifest 契约），缓存只增生命周期与 API 约束，收益不成立。
2. **云端传输拆分**（`579c4aab`）：`cloud/client.rs` 470→360 行，HTTP 传输（共享
   Agent/连接池、POST、带帽读体）抽 `cloud/http.rs` 113 行；模块头声明的三分职责与
   目录一致，判据/文案逐字保留；测试门面 `cloud.rs` 改指向 `http`。
3. **ESP 依赖缓存**（`acd746a8`）：`platforms` 的 esp32-gates 双腿加 crates 注册表
   缓存（只 `~/.cargo/registry` 与 `~/.cargo/git`，键随 `**/Cargo.lock`，
   restore-keys 兜底）。上一轮双腿红在 rsproxy 504 的全量下载暴露面，本件直接削减。
4. **计划册归档**（`12f1877e`）：§10–§20.14（1112 行）迁入
   [归档册](0.0.8版本单板全链计划回执归档-十至二十.md)，章节号不变；本册
   1428→326 行，符合 §0 自定 500 行维护线。ADR-0030/0031、实测 0014、status 的
   §20.2 引用改指归档同号；本地全量相对链接自检 0 断。
5. **尾部文件复评**：`rrd/topics_load/tests.rs` 470 行判**留**——单域（topics 装载
   契约）测试面，按夹具/叠加/错误再分会造人工边界；`cloud/client.rs` 已拆到 360；
   全仓最大源文件 470 行。
6. **镜像面治理结论**：rsproxy 参数分布在 11 个脚本/工作流共 52 处，属"脚本注入、
   Cargo 配置不硬编码镜像"的既有裁定；不引入第二镜像、不做单源化（需改 11 文件，
   收益未证）。已加的双退避与注册表缓存先观察；同一出口再红 ≥2 次再立项。

**验证**：本地只跑 rustfmt 1.100.0 与 `tools/ci/*.py` 只读审计——重复率 0.41%、
CC 均值 2.46/最大 8、>50 行生产函数 0、超长函数名 0、panic 2 ≤ 基线 2、锁内 I/O 0、
未注释 unsafe 0、规约门 29 步与流水线结构审计全绿。流水线：`29e96876`/`acd746a8`/
`12f1877e` 的 run 被后续推送按并发组取消（结果不再作为回执）；累计树以 `579c4aab`
为准，`gate`/`integration`/`platforms` **三线 success**（含 ESP32 classic/S3 双腿与
新增注册表缓存步、五芯片交叉、riscv 镜像、host-macos）。

## 12 第十六批回执（2026-11-24，接 §11）

**已收口**

1. **校验门面一致性收敛**（`d0ab7adc`）：
   - 类型错文案单源：`rr3_type_err` 上移至 `validate` 门面，module/atom 共用；
     删除 atom 三处内联格式串（string/list/int）。
   - 无规则 list 的形状判据对齐：module 侧此前"有规则才逐项验"，atom 侧一直
     逐项验；现两侧一致——无规则也逐项拒非字符串项，堵住契约演进出无规则
     list 时的 fail-open。
   - 新增两例单测（`validate/manifest/tests.rs`）：无规则 list 拒非字符串项、
     布尔项只报一条形状错。
   - 评审留档：atom 的 publishes/subscribes 只验 topic 形状、不查主题注册，属
     ADR-0019"atom 只声明形状"口径，**非漂移**，不改。
2. **ESP 注册表缓存复核**（只按 CI 可见面）：同锁第二次运行（`d0ab7adc`，
   run `45320500957`）缓存步骤成功；缓存步时长由首轮 0–1s 变为 2–3s（出现恢复
   动作），classic 腿作业 17m21s→13m43s、S3 腿 9m48s→11m06s。单样本不足以归因，
   登记观察；匿名日志 403，命中细节不可读，不冒领命中结论。
3. **ghcr 托管复核**：匿名 token 端点对 `rockrobot3/rockrobot3` 与
   `rockrobot3-firmware` 均回 401——包不在匿名可拉面，拉回校验需凭据窗口；
   正式制品托管证据沿用既有 publish 回执，不冒领新证据。

**验证**：本地 rustfmt + 只读审计全绿（重复率 0.41%、CC 2.46/8、>50 行 0、
panic 2、锁内 I/O 0、unsafe 0）；流水线 `d0ab7adc` 的 `gate`/`integration`/
`platforms` **三线 success**（含 ESP32 classic/S3 双腿、五芯片交叉、riscv 镜像、
host-macos）。

## 13 第十七批回执（2026-11-24，接 §12）

**已收口**

1. **目标 ISA 单测最小面**（`eaac7a8e`，修复 `3cce38ad`）：新增
   `tools/ci/platform/cross-tests.sh`，在交叉腿把 `rr-ipc` / `rr-registry` 的测试二进制
   按目标方式真跑——rockchip `aarch64-unknown-linux-musl` 进 `linux/arm64` 容器、
   riscv64 `riscv64gc-unknown-linux-gnu` 走 `qemu-riscv64 -L`；原生腿不重复跑
   （gate ①b 全量覆盖）。判据从"构建 + 打印用法 + 128B 头对拍"扩到"语义断言在
   目标 ABI 上执行"。
2. **首推红与根修**：riscv 腿首推红在目标 ISA 单测步——唯一跨架构 self-exec 用例
   `uart_excl_cross_rej`（`current_exe` 再执行）在未注册 binfmt 的 gnu 腿不成立。
   处置不是绕过判据：该用例在 gnu 腿**显式跳过并点名**（musl 腿 binfmt 在、宿主
   gate 全量，两处仍覆盖），其余用例全跑；同时脚本补构建失败与单二进制失败的
   `::error` 单行注解，避免下次只剩 exit code。`3cce38ad` 复跑：rockchip 与 riscv
   两腿目标 ISA 单测 success。
3. **校验文案剩余并源**（`b4a7402e`，修复 `6386a2f1`）：`字段 … 第 N 项应为字符串`
   的 module/atom 两份拷贝并到 `validate` 门面 `rr3_item_err`；首推 gate 红在
   E0425（漏导入），根修后复绿——顺带实证 gate 对独立工程（mkmodule/sim/pack）
   的编译面覆盖有效。

**验证**：本地 `bash -n`、rustfmt、只读审计全绿（重复率 0.41%、CC 2.46/8、
>50 行 0、panic 2、锁内 I/O 0、unsafe 0）；流水线 `3cce38ad` 的
`gate`/`integration`/`platforms` **三线 success**，含两交叉腿目标 ISA 单测真跑、
ESP32 classic/S3、host-macos。
