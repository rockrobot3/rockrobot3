# 0.0.8 出厂镜像网络与时间面裁定材料（批346）

本文件是 [decisions.md §3](../../decisions.md) "出厂镜像（RK3566）网络与时间面"一行的
**裁定材料**：只摆事实、代价与可判终态，不代替拍板。事实均可用 §6 的命令复核。

## 1 事实（每条带取证点）

1. **镜像没有网络栈**：`base/os/buildroot/configs/rock3_zero3_defconfig` 的用户态包只有
   `BR2_PACKAGE_ALSA_LIB` / `BR2_PACKAGE_ALSA_UTILS`（Python 已随批337 退役），无
   NetworkManager / wpa_supplicant / DHCP 客户端配置，也无 NTP 客户端。
2. **connect 的 linux 面依赖 `nmcli`**：`rr-hal` 的链路/配网后端是 NetworkManager
   的 `nmcli` 子进程（`base/runtime/rr-hal/src/lib.rs` 的 linux 后端说明与
   `modules/rr3-connect/src/boot.rs` 的就绪/轮询注释）。镜像缺 nmcli 时 connect 仍能
   起到，但链路读数失败、配网 RPC 无法落地。
3. **板载 WiFi 走 SDIO，驱动不在 mainline 6.6**：板级 dts 回移补丁里有 `sdmmc1` +
   `sdio-pwrseq` + `wifi_reg_on_h`（`board/radxa-zero3/patches/0001-*.patch`），没有
   芯片级 compatible；Linux 6.6 的 `MAINTAINERS` 无 AIC8800 条目（板载模组型号待
   硬件丝印核对）。⇒ **WiFi 的硬前件是厂商驱动＋固件，与"装不装 NetworkManager"无关**。
4. **时间同步缺位**：镜像无 NTP 客户端、无 RTC 兜底；brain 的 TLS 用 rustls +
   webpki-roots（`modules/rr3-brain/Cargo.toml`，不依赖系统 CA），但证书有效期校验
   依赖系统时钟。无时间源时首次云调用会以证书时间错失败——**brain 目前也不检查
   时钟是否就绪**（代码里无时钟门），这是与传输选型解耦的独立缺口。
5. **USB 主机/设备面在内核里可用**：arm64 defconfig（6.6）含 `CONFIG_USB_DWC3=y`、
   `CONFIG_USB_GADGET=y`、`CONFIG_USB_CONFIGFS=m` 与
   `CONFIG_USB_CONFIGFS_{NCM,ECM,RNDIS}=y`；板级 dts 有 `usb2phy0_otg` 节点。
   ⇒ 不依赖 WiFi 驱动，可用 **USB NCM/ECM 网卡（gadget）** 给板子一条有线网络旁路。
6. **Buildroot 2024.02.11 的包面**：`network-manager`、`wpa_supplicant`、`chrony`、
   `ntp` 四个 `Config.in` 均在库；无 `aic8800-firmware` 专用包（`linux-firmware` 在库，
   是否含该模组固件未核）。
7. **附带发现（devtmpfs）**：arm64 defconfig 有 `CONFIG_DEVTMPFS_MOUNT=y`，/dev 由内核
   预挂；fstab 里再写 `devtmpfs /dev` 会在每次启动产生一条 "already mounted" 错误行
   （非致命）。建议下次镜像批次删除该行并加镜像断言；本条不影响网络/时间面。

## 2 选项与代价

| 选项 | 内容 | 代价/风险 | 验证面 |
|---|---|---|---|
| A 厂商驱动 + NetworkManager | 交叉编译 SDIO WiFi 驱动（out-of-tree）＋固件，装 NetworkManager + wpa_supplicant | 驱动随内核版本维护；dbus 依赖增大镜像；固件许可与再分发需核；mainline 6.6 无驱动可依 | 真板：`nmcli device status` 见 wlan0 并联网；connect `net/link` 读数正常 |
| B 换链路后端（wpa_supplicant/iw） | connect 的 linux 链路/配网面重写，去 dbus | **不解决 WiFi 驱动前件**；Pi 档与 RK3566 档出现两套后端 | 同 A 的网络判据 + connect 单测/演练双后端 |
| C USB gadget 旁路 | 内核 configfs 起 NCM/ECM，宿主侧共享网络；镜像装 DHCP 客户端 + NTP | 不是基础设施 WiFi；交付形态多一条线；需宿主配合 | 真板：`ip -br addr` 见 usb0 并拿到地址；宿主 ping 通 |

**关键结论**：A/B 共享同一硬前件（驱动＋固件）；C 可绕过该前件但改变交付形态。
传输选型与时间同步可解耦：**无论选哪条，时间同步都要单独落地**。

## 3 时间同步机制

| 机制 | 优点 | 缺点 |
|---|---|---|
| chrony | 首启可 `makestep` 立即校时；长期漂移控制好 | 多一个守护进程与配置面 |
| busybox ntpd | 无新包 | applet 是否编入需核；能力弱、无漂移控制 |

共同前提：**先有网络，再有时间**；无 RTC 的板子首启时钟为 1970。建议无论选型如何，
都加一道**时钟就绪门**（brain 首呼云前检查年份/偏移，未就绪则等待并点名），该门与
传输无关，可先落。

## 4 可判终态（真板前置）

1. 网络：`nmcli device status`（A/B）或 `ip -br addr`（C）显示目标接口 `connected`
   / 有地址；`rr3-ctl` 的 connect 链路读数与装配单一致。
2. 时间：`chronyc tracking` 偏移 < 100 ms（或等价 ntpd 读数），系统年份 ≥ 2025。
3. 顺序：启动日志能证明"时间就绪"发生在 brain 首次云调用之前（时钟门点名行）。
4. 回归：以上成立时，六模块 running、`denied_publish=0`、brain 零重启。

## 5 推荐与触发

- **不裁缺省态维持现状**（镜像无网络/NTP），与 status 敞口账一致；不得在无真板时
  声称任一路径可用。
- 触发条件（任一成立即拍板）：① 板载模组型号与厂商驱动可编译进 6.6 并取得固件
  再分发许可；② 产品要求 RK3566 镜像首次联网（交付/演示/远程运维）。
- 无论传输选型，**时钟就绪门**可先作为独立小批落地（纯 Rust，可单测）。

## 6 取证命令（复核用）

```sh
# 包面
grep -nE 'BR2_PACKAGE_(ALSA|NETWORK|WPA|CHRONY|NTP)' base/os/buildroot/configs/rock3_zero3_defconfig
# 板级 SDIO WiFi 节点
grep -nE 'sdmmc1|sdio-pwrseq|wifi_reg_on' base/os/buildroot/board/radxa-zero3/patches/0001-*.patch
# connect 的 nmcli 承载
grep -rn 'nmcli' base/runtime/rr-hal/src/lib.rs modules/rr3-connect/src/boot.rs
# 时间依赖
grep -n 'rustls\|webpki' modules/rr3-brain/Cargo.toml
# buildroot 包是否存在（raw 200/404）
for p in network-manager wpa_supplicant chrony ntp; do
  curl -s -o /dev/null -w "$p %{http_code}\n" \
    "https://raw.githubusercontent.com/buildroot/buildroot/2024.02.11/package/$p/Config.in"
done
# 内核面（jsDelivr 镜像，避开 raw 限流）
curl -fsSL "https://cdn.jsdelivr.net/gh/torvalds/linux@v6.6/arch/arm64/configs/defconfig" \
  | grep -nE 'DEVTMPFS_MOUNT|CFG80211|USB_(GADGET|CONFIGFS|DWC3)'
```
