## §2 立册裁定（零行为改变＋机制/策略分离两红线）

1. **签名逐字**：`Dispatcher` 三入口（§2.3）/ `Rr3ModConfig<C>` 两字段（§2.4）/
   `bootstrap<C>` 返 `(BusHandle, C)`（§2.4）/ `serve(bus, dispatcher, poll_wait)`
   （§2.5）/ `load_config_text(config_env, manifest_path)`（§2.4）——全部照方案档
   签名逐字落地，不发明新语义；机制层内部函数守"私有不加前缀"惯例（§2.1 原文）。
2. **`BusHandle::call` 增 timeout 显式实参（规格疏漏订正，如实登记）**：方案 §2.2 写
   `pub fn call(&self, topic: &str, args: &Value) -> Result<Value, String>` 无超时——
   底座 `rr3_call_topic(topic, args, timeout)` 必收超时实参，若骨架签名不带，超时值
   就得烤进 rr3mod 常量＝策略进机制（违机制/策略分离）。裁定：`call(&self, topic:
   &str, args: &Value, timeout: Duration)`——超时是调用方策略，批1–批5 消费方各自
   带现值进来（现用点位：interact 面板线程 rr3.call），骨架零缺省值。`args: &Value`
   → 内部 `clone()` 进 `rr3_call_topic`（借入形状对齐 §2.2 原文）。
3. **BusHandle 落地形**：`#[derive(Clone)] pub struct BusHandle { client: Rr3BusClient }`
   ——Rr3BusClient 本身 Clone（rr-bus-api client.rs :245-250"同一连接的另一个句柄，
   Arc 共享"自证），四方法透传（publish→rr3_publish / call→rr3_call_topic /
   counter_bump→rr3_counter_bump / connected→rr3_connected）；**刻意不提供
   subscribe / 注销**（§2.2 原文：线上无订阅注册帧，给"注册"形状即假 API；订阅过滤
   是 Dispatcher::on_event 本地职责）。
4. **文案逐字清单**（零行为改变判据，单测钉原文）：死亡探针「总线已断开（reader
   EOF）：交 supervisor 按 restart_policy 裁定」；缺 manifest「缺环境变量
   RR3_MANIFEST（rrd spawn 注入；直跑请指向 module.toml）」；「总线就绪: name=… task=…」
   一行；config 读失败「读 config {path} 失败: {e}」（§2.8-3 与 §2.4 原文口径）。
5. **sense 归一不进本批**：§2.6 自 pacing 归一与 §2.7 config 语义分叉裁定随**批3**
   兑现（含前置核对件），批0 骨架只提供 `poll_wait: Duration` 实参与
   `load_config_text` 单点，不预设 sense 语义。
