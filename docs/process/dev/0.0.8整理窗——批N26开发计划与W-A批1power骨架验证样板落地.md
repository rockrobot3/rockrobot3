**取证发现（方案快照与现状六笔漂移，施工以现状为准，语义零改动优先）**：

1. **现落点漂移**：映射表三列首列「现落点（rr3-power/src/main.rs）」——0.0.5 批B③ 原子重铺
   后机制主体在 `src/composite.rs`（main.rs 已是 16 行薄装配，组合件五件套②）。
   方案目标树意图不受影响（composite 消解三处，见 §2 裁定 1），仅首列落点表述过时。
2. **exposes 漂移**：§4.1 树下注「rr3-power 无 exposes（module.toml 无 `[rpc]`）」＋
   「on_rpc 兜底理论不可达纯防御」——module.toml :24-25 实有
   `[rpc] exposes = ["rr3-power/ops/list"]`（0.0.5 批N4 件九二）。on_rpc 是**真事务面**：
   ops 槽快照应答＋未知主题点名文案「rr3-power 只 exposes …，收到 …」。§4.1 对 ADR-0017
   五层表「不设 rpc.rs」的解释结论保留（RPC 面薄，分发臂落 dispatch.rs on_rpc），
   但「无 exposes」断言与「理论不可达」论据作废。
3. **节拍数漂移**：§4.1「on_tick = battery/charger 双节拍＋低电边沿」＋WBS 判据「serve
   骨架承载双节拍」——现状为**三节拍**（battery/charger/rail，批N2 件五轨压面）＋低电
   **两沿**（low/ok 一对沿先 recover 后 cross，批N5 件二笔3）。§4.1 Dispatcher 字段级规格
   缺 `ok_seq` / `rail_seq` / `rail_judge` / `next_rail` / `rail_dev` / `rail_backend`
   六字段与判定核切片（`rr3_rail_tier_of` / `Rr3RailJudge` / `rr3_rail_beat`，P-9 归属搬家件）。
4. **载荷组装面漂移（与 P-7 冲突）**：目标树「battery.rs 原位不动（含
   `rr3_battery_state_body` / `rr3_battery_low_body`）」——0.0.5 批I P-7 已将
   `*_body` json! 组装上移 composite.rs 承载层（原子件不承载线格式，机制/承载分离）。
   body fns 随 composite 消解迁 dispatch.rs，**不回退进 atoms**（P-7 是后于方案快照的
   明确工程决策）。
5. **门面冲突（方案未提，立册新增发现）**：check.sh 两处硬编码扫描 composite.rs——
   ⑦-c 组合件门（:295）`rust) req="src/main.rs src/composite.rs"` 强性要求组合件实体
   存在 src/composite.rs；⑧-a 对拍计数门（:485-491）扫描「atom mech.rs ＋ 模块
   src/composite.rs」找 parity 两腿。composite.rs 消解即**双门双红**；§6.2 批1 触达面
   （:614）未列 tools/ci/check.sh。门随批订正见 §2 裁定 6。
6. **单测随迁面**：§4.1「`config_parse_*` 两单测随迁」——实际 composite.rs tests 共
   **19 测**：config 解析 4 测（covers_repo_shape / rejects_missing_sections_and_fields /
   rejects_inverted_rail_thresholds / clamps_zero_period_to_one）随解析函数归 boot.rs；
   载荷体 4 测＋parity 两腿 6 测＋轨压归属搬家 5 测（含 rail_judge 板侧对拍与
   ⑥-c2 两条执法用例）随 body fns/判定核归 dispatch.rs。条数落 conventions §2 于收口登记。

**留底方法一笔订正**：§6.1 SURFACE 留底命令 `> /tmp/power-before.txt` 只截 stdout——
模块输出全走 stderr（eprintln），照抄会拿到空文件假绿。施工按 `> file 2>&1` 留底
（方案命令笔误，随批订正登记；diff 判据本身不变）。

## §2 裁定

1. **composite.rs 消解三处落点**（语义零改动，逐字迁）：
   - `main.rs`（装配层，≤80 行）：SURFACE 启动自述（battery+charger chain）→
     `bootstrap`（Rr3ModConfig{config_env=Some("RR3_POWER_CONFIG"), parse_config=boot::rr3_power_config_parse}）
     → config 就绪行＋rail 监测就绪/未启用行（装配段回显，cutoff「声明未生效」文案逐字红线）
     → `boot::rr3_power_probe` → `boot::rr3_rail_probe` → Dispatcher 构造 → `serve`。
   - `boot.rs`（接入层）：`rr3_power_config_parse`＋`Rr3PowerCfg`/`Rr3RailCfg`＋4 config 测
     ＋电源面探活编排（`rr3_hal_power` 选择＋首读探活＋「电源面就绪: …」回显，返回
     `(dev, backend, first)` 三元）＋轨压面探活编排（`rr3_hal_rail` 选择＋up 时探活＋
     「轨压面就绪: …」回显，返回 `(rail_dev, rail_backend)`）。探活失败 Err 上抛
     （「电源面探活失败({backend}): {e}」/「轨压面探活失败({rail_backend}): {e}」文案逐字）。
   - `dispatch.rs`（机制层注册面）：`Rr3PowerDispatcher` 全字段（§2.1 方案规格＋裁定 2
     扩形六字段）＋`on_tick`（battery 拍：读数→counter 先行→周期流→先 recover 后 cross
     两沿；charger 拍：last 派生；rail 拍：up 才跑，读数→rr3_rail_beat→周期流＋边沿
     守护行）＋`on_rpc`（ops/list 快照／未知主题 Err 点名）＋`*_body` 载荷组装面＋
     轨压判定核切片＋15 测。`battery_seq`/`charger_seq`/`low_seq`/`ok_seq` 四 seq 独立计数。
   - atoms battery/charger 原位不动（`#[path = "../atoms/…"]` mod 声明随 main.rs 保留，
     归属按五件套②现状）。
2. **Dispatcher 字段级规格按现状扩形**：方案快照缺 rail/ok 六字段属规格疏漏，随批订正
   登记（照批N25 `BusHandle::call` timeout 先例）；HAL 句柄类型照 rr-hal backend.rs 现状。
3. **on_rpc 语义**：`topic == "rr3-power/ops/list"` → `Ok(json!({"ops": 快照}))`；
   其余 → `Err(format!("rr3-power 只 exposes {RR3_OPS_LIST_TOPIC}，收到 {topic}"))`——
   serve 骨架 Err 折 `{"error": e}` 应答，与现行 wire 形状逐字等价（现行 Ok(json!({"error":…}))）。
4. **回显落点与顺序**（stdout/stderr 逐字判据）：电源面就绪/轨压面就绪＝boot.rs 探活编排内
   （映射表字面「迁文件」）；config 就绪/rail 监测行＝main.rs 装配段。全序：SURFACE 行 →
   总线就绪（bootstrap 内）→ config 就绪 → rail 监测就绪/未启用 → 电源面就绪 →
   轨压面就绪（up 时）。
5. **last 种子**：探活首读仍作 `Dispatcher.last` 初值（charger 拍派生源，现语义）；
   `next_battery`/`next_charger`/`next_rail` 构造即 `Instant::now()`（首拍即采）。
6. **门随批订正**（照批N25 cargo tree 断言订正先例，门与被门约束的代码同批绿）：
   ⑦-c rust 分支改「src/main.rs 必在 ＋ src/composite.rs / src/dispatch.rs 至少其一」
   （批2–批5 过渡态：未拆模块有 composite.rs、已拆模块有 dispatch.rs，全程可判）；
   ⑧-a 对拍计数门扫描路径扩为「mech.rs ＋ composite.rs ＋ dispatch.rs ＋ rpc.rs」
   （只增不减，power 腿落 dispatch.rs，其余模块暂留 composite.rs）。check.sh 纳入批1
   触达面（§6.2 清单遗漏随批补）。
7. **Cargo.toml 仅加 rr3mod 依赖行**（§6.1 ③「零 .rs 之外的改动面」字面）；
   rr-ipc / rr-core 等既有依赖不裁（unused path dep 不报错，保守零风险面）。
8. **不涉面**：base/runtime 成员表／cargo tree 断言（rr3mod 零新依赖关系，power 是
   modules/ 独立 workspace）；module.toml / composite.toml / config.toml / 装配单零改动
   （红线 1）；status.md 零改动（快照锚定 dc3a1d6，重锚归批6）。
