## §2 裁定

1. **composite.rs 消解四处落点**（语义零改动，逐字迁）：
   - `main.rs`（装配层，≤80 行）：SURFACE 启动自述（wifi→session→bt chain，序不变）→
     `bootstrap`（Rr3ModConfig{config_env=Some("RR3_CONNECT_CONFIG"),
     parse_config=boot::rr3_connect_config_parse}）→ config 就绪行（「config 就绪: link
     report={}ms nmcli timeout={}ms」逐字）→ `boot::rr3_connect_probe`（链路面）→
     `boot::rr3_connect_provision`（配网面）→ bt 相位构造＋「蓝牙面: phase=…（骨架，真后端
     板上后置）」回显（方案映射行「留装配面（自述属装配）」字面）→ Dispatcher 构造 →
     `serve(bus, &mut dispatcher, RR3_POLL_WAIT)`（100ms 原值）。
   - `boot.rs`（接入层）：`rr3_connect_config_parse`＋4 config 测（Rr3LinkCfg 引用原位
     wifi.rs，本层不复制类型）＋链路面探活编排（`rr3_hal_link(timeout_ms)` 选择＋首读探活＋
     「链路面就绪: {backend} up=… ssid=… rssi=…」回显，失败「链路面探活失败({backend}): {e}」
     Err 上抛，返回 `(dev, backend)` 二元）＋配网面编排（`rr3_hal_wifi_store` 构造＋在册
     查询＋「配网面就绪: …」回显＋prov restored/new 初始化，失败「配网凭据在册查询失败
     （{store_backend}）: {e}」Err 上抛，返回 `(store, prov)` 二元——store_backend 只用于
     回显，不进 Dispatcher）。
   - `rpc.rs`（协议层）：四 `rr3_handle_*` 逐字迁（session: opened / wifi: connect / wifi:
     forget 三行 eprintln 随迁）＋载荷组装与参数下钻面八函数＋`rr3_connect_ops_snapshot`
     （签名随状态拆分适配 `(wifi_cfg, bt_up)` 两参，json! 体逐字）＋6 测（载荷 4＋handler 2）。
   - `dispatch.rs`（机制层注册面）：`Rr3ConnectDispatcher`（§2.1 方案七字段＋裁定 2 扩形
     两字段）＋`on_rpc` 五臂（四 handle 调用＋ops/list 快照臂＋兜底文案逐字）＋`on_tick`
     链路拍（HAL 读数失败「链路读数失败（{backend}）: {e}」Err 上抛——**不加 counter_bump**，
     现状无计数器，观测面零改动；`edge.rr3_link_edge_cross(st.up)` 翻转即发＋周期保底＋
     mode 随流）＋`on_event` 空 `Ok(())`（「订阅面为空是设计」注释语义迁本文件 doc）。
   - `rr3_config_load` 整函数消解：路径段（RR3_CONNECT_CONFIG_ENV 覆盖＋manifest 同目录
     缺省）由 rr3mod `load_config_text` 承接（bootstrap 内），boot.rs 只留解析函数。
   - atoms wifi/bt/session 三件原位不动（`#[path = "../atoms/…"]` mod 声明随 main.rs 保留）。
2. **Dispatcher 字段级规格按现状扩形**：方案快照缺 `store`/`bt_up` 两字段属规格疏漏，随批
   订正登记（照批N26 裁定 2 先例）；HAL 句柄类型照 rr-hal backend.rs 现状
   （`Box<dyn rr_hal_api::Rr3Link>`）。构造序 `new(dev, backend, store, wifi_cfg, bt_up, prov)`；
   `edge`/`link_seq=0`/`next_report=Instant::now()` 构造即初始化（首拍由 edge 基线分支保证
   必发，与现状语义一致）。
3. **on_rpc 语义**：五臂 match 照现状顺序（session→scan→connect→forget→ops/list→other）；
   业务性失败 Err 返 serve 折 `{"error": e}` 应答，与现行 `unwrap_or_else` wire 形状逐字
   等价；兜底文案「rr3-connect 只 exposes {RR3_SESSION_TOPIC} 与
   wifi/scan|connect|forget|ops/list，收到 {topic}」逐字。
4. **回显落点与顺序**（stdout/stderr 逐字判据）：SURFACE 七行 → 总线就绪（bootstrap 内）→
   config 就绪（main 装配段）→ 链路面就绪（boot::probe 内）→ 配网面就绪（boot::provision 内）→
   蓝牙面（main 装配段）。与留底序列逐字对齐。
5. **Cargo.toml 仅加 rr3mod 依赖行**（§6.1 ③「零 .rs 之外的改动面」字面，照批N26 裁定 7）；
   rr-ipc / rr-bus-api / rr-core 等既有依赖不裁（帧解析符号 opcode/Rr3PayloadType/
   RR3_METHOD_CALL/Rr3BusClient 随主循环消解进 serve，unused path dep 不报错，保守零风险面）。
6. **不涉面**：check.sh 零改动（⑦-c OR 化＋⑧-a 四路批N26 已就位，取证笔7 落档）；
   module.toml / composite.toml / config.toml / 装配单零改动（红线 1）；atoms 三件零改动；
   status.md 零改动（重锚归批6）；模块 README 零改动（无 composite 引用）。
