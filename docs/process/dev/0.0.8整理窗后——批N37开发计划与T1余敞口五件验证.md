## 3 现场批 runbook（件四操作序；顺序 = 先不动执行面的件，再动执行面的件）

**开机序**：Pi 上电 → `ssh pi@<board-ip>` → T1 全链起（rrd ＋ sense(esp32) ＋ brain ＋ interact；装配档 `profiles/pi4b-host-esp32-classic.toml`）→ `rr3-ctl status` 五模块全 running。

1. **条目5 千次 ping**（不动执行面，先跑）：
   `python3 -u tools/pi-periph-probe/ping_probe.py B1500000 1000`
   预期：`[PASS] 千次 ping 0 失败`＋RTT 统计行。记录 RTT 中位数与基线（0.0.6 sim 时代 Mac 宿主 rr3.ping 基线随批N37 取数首立，之后只降不升同门 d 纪律）。
   失败处置：MISS 集中出现→查串口线/波特率（板 boot 横幅 baud 对表）；随机分布→查供电与 UART2 地弹。
2. **条目9 30 分钟滑移**：跑前 `rr3-ctl counters > /tmp/n37_counters_pre.txt`＋`date +%s.%N`；
   `python3 -u tools/pi-periph-probe/longrun.py B1500000 1800`；期间正常问答对话（真实负载）；
   跑后同取 counters＋时间戳。判据：longrun ①-⑥ 全绿（帧丢失 0）＋**心跳滑移**＝各模块 Δ心跳数×心跳周期 vs Δ墙钟偏差 ≤2%。
   失败处置：滑移超预算→diff 两份 counters 找掉拍模块，查其心跳线程与 CPU 占用。
3. **条目6 唤醒率 10 句**：系统在跑（全链，非探针），对板麦说"你好洛克＋一句话"×10（间隔 ≥5s 过冷却窗）。
   判定表逐句记：唤醒是否触发（brain 回应）／ASR 转写可读否。判据：唤醒 ≥9/10、转写可读 ≥8/10。
   失败处置：唤醒漏检→VAD 阈/增益对表（U 轮续4 口径 750）；转写差→查 ASR 语言与增益参数。
4. **条目7 DoA 证据采集（半边）**：`python3 -u tools/pi-periph-probe/doa_probe.py` 六轮定向喊话（左×2/右×2/中×2）。
   产出 = 带真值标注的三特征证据（供锚点重建裁定）；**本批不跑 3×10 形式验收**（卡点如实登记：锚点重建未裁）。
5. **条目4 轨压两点标定**（最后做，需接线）：断电接 GPIO34 分压（按 [hardware/pi4b-host-esp32-classic/wiring.toml](../../../hardware/pi4b-host-esp32-classic/wiring.toml) 供给域真值）→ 上电 → 万用表表笔同点实测 ×2（两个不同负载态）→ 各发 `RAIL` 读板值。判据：两点误差均 ≤50mV；UBEC 供电全程无 BOD 复位（`boots` 计数不增）。
   失败处置：误差大→查分压电阻实际比值对 `ADC_RAIL_DIVIDER_NUM/DEN`；读数跳变→查焊点与 ADC 参考源。

## 3.1 现场实录（件四，2026-11-01 逐件追加）

**A 段·上链验证（16:55–16:58）**：
- Pi IP 变更 <board-ip>→**<board-ip>**（网络段迁移，mDNS `<board-host>.local` 定位），板在线 `up 11 min`。
- 开机初检发现 **rr3-interact failed（task=14，连续崩溃 5 次达上限被 supervisor 运行时降级）**——死因 fail-closed 实证（`/run/rock3-ipc.sock.log/rr3-interact.log`）：USB 声卡不在位，`alsa 打开设备 "plughw:CARD=Device" 失败: No such device (19)`，播放面探活失败 exit(1)。行为符合设计（探活 fail-closed→supervisor 退避→降级停启）。
- 处置：用户插回 USB 声卡（`card 3: Device [USB Audio]`）→ `systemctl restart rrd` 清降级态 → **五模块全 running、denied_publish=0**。
- **顺手兑现 boards §10 欠账之一**：非 root `rr3-ctl status` 直连成功（0.0.6 批F5b `fab7b6c` 的 socket ACL `chmod 0o660+chgrp rockrobot3` 修复真机复验通过，板上巡检不再需要 sudo 前缀）。

**B 段·条目5 千次 ping（17:10–17:15）——PASS**：
- 前置排查两笔如实登记：①板侧一度完全静默（两次探针全 MISS、实收空字节；裸 UART 测 3s 零字节）——根因＝**三线 UART 未接**（板挪至 Mac 边取电时线组脱开；期间还发生一次被本地拒绝的命令实际已抵达 Pi 执行、留下无 timeout 僵尸探针与重启后的 sense 双写端口，已 `kill` 清理并记为流程教训：本地拒绝发生在远端派发之后时不再可信，重发前必须先查远端残留进程）；②板经 Mac USB 供电＋console 旁听证实板本体健康（双麦 16kHz 采样 rms 正常）。
- 三线接复（板 GPIO18→Pi RXD / GPIO19←Pi TXD / GND 共地）后存活测试：3s 收 **263120 字节**，INFO 回包全字段（`pan=60 tilt=93 rail=284mV tier=severe audio=on seq=232 drop=0 free=92692B min_free=31720B`）＋音频流帧连续。
- **千次 ping 实测（`ping_probe.py B1500000 1000`）**：`次数=1000 应答=1000 缺失=0`，`RTT ms: 中位=2.1 P95=2.4 最大=77.3 最小=1.7`——**判据条目5 PASS（0 失败）**；**T1 UART 面 RTT 基线首立＝中位 2.1ms**（判据原文的"Mac 宿主基线"为 sim 时代 UDS 面，无在档数值；本次按计划册预定即首立基线，此后只降不升对账）。探针单次往返含 5ms 轮询量化，读数偏保守仍达 2.1ms。
- 观察两笔记账（不判 FAIL，供后续批）：板沿用上会话 `audio=on` 连续流（探针混流跑通，bw_mixed 同口径）；`min_free=31720B` 低于 longrun 判据⑤的 100KB 线——条目9 长跑时重点盯（若持续走低即堆水位问题立新敞口）。
- 取数后链路已恢复：五模块全 running、denied_publish=0。

**C 段·条目9 前置排障——"说话无回应"根因链与两处策略面修复（17:20–19:30）**：
- **症状**：用户连续说话 10 分钟零回应、舵机不识位。诊断链逐层实证：①音频流健康（pcm_frames 严格 50 帧/s 递增）；②brain 仅收 1 轮且"识别为空文本弃轮"；③线面干净（bw_probe 60s：476 帧/撕裂 0/CRC 不符 0/seq 断档 0/乱码 0B——三线重接后接触良好）。
- **根因①部署陈旧（实锤）**：Pi 部署面 `config-esp32.toml`＝10-21 旧标定（`rms_start=650/silence_tail_ms=700/window_rms_min=650`），repo 10-31 深夜重标（`500/400/500`）**从未铺到部署面**（含 Pi 上 `~/rockrobot3-src` 源码副本同样陈旧）——旧 `silence_tail=700` 下 VAD 进入 in_speech 即锁死（U/V 轮实测最长安静段 620ms<700ms），utterance 只能 8s 硬切→ASR 空文本，与 10-31 深夜注释记录的病理逐字吻合。铺新 config 后 VAD 恢复点火（asr_ok +4）。
- **根因②声学失配（tee 解帧实证）**：HAL tee（`RR3_HAL_ESP32_TEE`，批N12件二机制）3.4MB 解帧后——**底噪恒定 585 > 新阈 rms_start=500**（VAD 永远看不到安静＝segmentation 结构失效），语音峰值仅 728–1131，对比度 1.35–1.87×。根因＝整机换位+Mac USB 供电环境变化（10-31 深夜标定环境：底噪 380）。换独立电源后底噪未回落（620–680）→ 供电非主因，环境声学已变。
- **修复（策略面 config，零代码）**：42s 分段实录（15s 静+25s 说）重标 `rms_start=650/window_rms_min=650`（底噪余量 1.10×/语音余量 1.12–1.74×，词间停顿 586–600<650 判停可用），`silence_tail_ms=400` 维持；repo 定标注释四订 + 部署面同步。**复测 PASS**："你好洛克，今天天气怎么样"→ 语音应答 + 舵机转向均恢复。
- **音量处置**：USB 声卡硬件混音器 PCM 38%（-23dB）→ **100%（0dB）**＋ `volume_pct` 70→100（repo+部署面同步）。
- **流程教训一笔**：板载 console `[mic] rms=40155 peak=123135` 是固件内部放大刻度（peak 已超 s16 上限），**不能与流内 PCM RMS 对表**——本次排查先用它对标 VAD 阈差点走偏，后被 rms_probe/tee 解帧纠正。
- **新增敞口一笔**：ALSA 混音器电平为易失状态（重启回落 38%），持久化机制（deploy/boot 脚本预置 amixer）未建——件五回写时登记。
