## 2 B 轨（本窗可执行）

### B60 CI 专用门覆盖补齐（openitems 唯一 open 项）

- **事实**：`.github/workflows/ci.yml` 的 `esp32-gates` job 只跑
  `esp32-periph-base-check.sh` 与 `esp32s3-periph-base-check.sh` 两档；
  `esp-uart-echo` / `espidf-std-hello` / `espidf-sentinel` /
  `rr3-act-sense-espidf` 四门仍只在人工清单（`docs/openitems.toml` 已登记为 open）。
- **判据**：专用门在 CI 里缺席时，平台工程编译中断可长期隐形（批B13 的 E0412 即
  由此存活）。门已写、未接线等于没有门。
- **处置**：`esp32-gates` job 增四个 step，工具链缺位照既有三门的 SKIP 明说纪律；
  每 step 名字带门名，失败可一眼定位到门。
- **验收**：静态解析 job steps 含四门；本地三门可跑（xtensa 缺则 SKIP 明说）；
  `check.sh` 不回归、指标不动。
- **残余**：GitHub runner 实跑回执归 A 轨（增量 job 变更需一次远端绿）。

### B61 M6 回滚链写侧接线（无硬件半边）

- **事实**：`base/runtime/rr-ota/src/bootenv.rs` 已实现
  `rr3_rollback_arm(limit, altcmd)`（四变量上膛）与 `rr3_rollback_ok()`（解除），
  并有宿主 env 文件的全链单测；但 `rr3-ota-ctl` 只有 `slots` / `switch` /
  `factory` 三个子命令，板上没有任何入口能调这两个函数。
- **判据**：写了但无调用点的能力等于不存在（"机制在库、入口为零"）。
- **处置**：`rr3-ota-ctl` 增 `rollback arm --limit N --altcmd C --env P` 与
  `rollback ok --env P` 两子命令；`switch` 保持默认不隐式上膛（显式优于隐式），
  用法文本与退出码沿用 0/1/2 既有口径。
- **验收**：宿主临时 env 文件全链单测（上膛四变量、解除两变量、`altcmd` 空 /
  `limit=0` / env 缺三条错误面逐条点名）；`check.sh` 绿。
- **残余**：真实 `fw_setenv` 载体与 bootcount 真生效归 A-M6。

### B62 INA219 器件级读回与分流校准（#19 缺码半边）

- **事实**：`rr-hal/src/linux_power.rs` 只读 `0x02`（总线电压）与 `0x04`
  （电流，未配校准恒 0），README 自述 `charging` 在校准前恒 false；
  `contracts/devices.toml` 的 `id_reg=0x399F` 判据源没有任何执行点。
- **判据**：器件"在不在"与"读数可不可信"是两件事，缺 `0x00` 读回就分不清
  "没接"与"接了但坏"；缺校准就把电流恒 0 当真实读数。
- **处置**：打开总线后读 `0x00` 校验 ID（取自 devices 表），不符点名拒；
  分流校准值计算抽纯函数（`calibration = 0.04096 / (R_shunt × I_lsb)`），
  成功写入 `0x05` 后才把 `charging` 判据打开。
- **验收**：纯函数算例单测（两组 R/I_lsb 标称值）+ 帧编码单测；ID 不符的点名文案
  可定位到"器件 vs 坏了"；`check.sh` 与 `arm64-cross-check.sh` 不回归。
- **残余**：真器件读回归 A-INA。

### B63 平台事实表取值核对（#17，跨芯片）

- **事实**：`contracts/platform/raspberry-pi-4.toml` 与 `rk3566.toml` 自述
  "演练实例，待器件核对"，但两者的 `[[controller]]` / `adc_pins` /
  `input_only_pins` / `conflict` 已被装载校验 ④-b/⑤-a/⑤-b/⑧ 消费。
- **判据**：判据读的是"被当成真值的数据"，数据不核就是假判据；而"不许编"
  要求每个取值可指到机器可查的来源。
- **处置**：以 Linux 内核 DTS（`bcm2711` / `rk3566`）与板卡规格书为来源逐键取值，
  每键带来源注记；DTS 直读不到的键**显式留空并注记"待器件"**，不猜。
- **验收**：两份表仍是合法 TOML、形状校验与既有红例（⑤-a/⑤-b/⑧-b）全过；
  每个非空取值有来源注记；不制造未核事实。

### B64 运行流畅度：sim 采集热路径去每样本查找

- **事实**：`rr-hal/src/sim.rs` 每采样点调用 `rr3_sim_wave_at`（4 项线性查表）与
  `rr3_sim_gain`（每次 `match`）；采集是持续热路径，查找成本按采样率线性放大。
- **判据**：行为必须逐点等价（golden 向量不动）才允许优化；确定性地基不能变。
- **处置**：`open` 时把波形函数指针与每通道增益/相位预解到 `Rr3SimOpen`，
  `read` 直达函数指针；DoA 参数一次性算好。
- **验收**：现有 sim 单测与 golden 向量逐点相等；27 用例全绿；指标不退化。

### B65 打印可定位审计（跨模块一致）

- **事实**：各模块错误文案前缀不统一（同一类失败有"拒绝…""…失败""…不在位"
  三种起头），排查时需读全文才知道是哪一层。
- **判据**：可定位 = 一眼看出"模块 + 动作 + 对象 + 原因"，不靠上下文猜。
- **处置**：只统一**新错误面**与本次改动触及的文案；历史文案不动（改写会破坏
  既有断言与日志基线）。
- **验收**：本次新增/修改的每条错误面都能独立成立；不新增重复文案（重复率不涨）。

## 3 顺序与纪律

1. 顺序：B60 → B61 → B62 → B63 → B64 → B65；每件一个 commit，推三远端并
   `git ls-remote` 三指针核对。
2. 每件收口跑：`check.sh` 全量 + `metrics.py`；涉 aarch64 面加
   `arm64-cross-check.sh`；涉 ESP 面加三门（缺工具链 SKIP 明说）。
3. 指标红线：dup ≤ 3.0%、mean CC ≤ 2.50、max CC ≤ 13、长名 0，任何一件都不得
   以"下批再降"为由破线。
4. 不修并给原因的既有项继续维持：跨进程写并发（正解单写进程）、行内注释改写、
   引号键名、`rr-hal` ensure 竞争、`docs/status.md` 全量重锚（需专轮）。
