## 3 下一轮任务清单（续轮三产出）

### P0（先做，阻塞收口）

1. **ADR-0028 tag + Secret 正回执**（外部依赖，未取得前不冒领）
   - 缺的一手：仓库 Secret `RR3_OTA_SIGNING_KEY`（64 hex）+ 一次 `v*` 标签推送；
   - 已有判据：`ota-bundle` 门正例 + 三负例；release job 无 Secret 即红；
   - 取得后：status M6 由"实装待回执"改为"实装 + 回执"，partition-layout
     发布段去掉"待外部"限定，并把 ghcr 两制品 digest 记入 status。

### P1（稳定性与流水线治理）

2. **CI 冷启动基线取回归档**：从 `integration` 的 sim-chain job 输出取
   "启动基线"行（首/末/最大 + 全列），补进 status 的基线段；若与热态差异大，
   注明 runner 首执行特性——只记录，不改阈值。
3. **publish 合并标签冒烟回执**：仍需 tag 或带凭据的 `workflow_dispatch`；
   无凭据时改做静态审计（tag 触发面、镜像名真值、action 版本）并如实登记。
4. **文档过期断言巡检（续）**：以"待回执 / 未实装 / 尚未 / 仍缺 / 今天还没有"
   为关键词扫 `base/os/**`、`base/ota/**`、`docs/status.md` 与计划册，逐条对现状
   核验；只改已被代码或回执证伪的句子。
5. **status 历史段清理（小步）**：上一轮 P2-8 提前做——删重复清单与已失效的
   "待回执"陈述，不重写历史注记。

### P2（品味与欠账）

6. **docker/login、setup-buildx、actions/cache 升级**：三者都在发布/全量构建面，
   等 P0 正回执后一次性升到 v4/v4/v6 并取一次 tag 回执；本轮只登记不升。
7. **实时性基线**：在 sim 稳态跑一轮（≥60s），采 `max_jitter_ms` 计数与 health
   的 `since_beat_ms` 分布，写进 status 的"运行流畅度基线"段；先观测，不调阈值。
8. **unsafe/FFI 审计**：统计生产面 `unsafe` 块与 `extern` 声明（GPIO/I2C/ALSA
   剩余面），逐个核对安全前置条件与注释是否在场；只做审计与必要注释，不重构。

## 4 纪律

- 每件一个 commit，推 origin/github/gitcode 三远端，核对三指针；
- 每件收口跑 `check.sh` + `metrics.py`；涉 `base/os/buildroot/**` 的改动必须确认
  没有在跑的全量构建（并发组 `cancel-in-progress` 会取消它）；
- 指标红线：重复率 ≤3%、CC 均值 ≤2.50、最大 ≤11、panic ≤73、长名 0、长睡 0；
- 不伪造板上证据：所有"已收口"必须带本机或 CI 可复核的回执。
