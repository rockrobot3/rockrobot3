## 2 rr3mod 公共骨架——签名级规格

### 2.1 crate 落点与依赖面

- 落点 `base/runtime/rr3mod/`，与 rr-bus / rr-hal 同层，进 `base/runtime` workspace

### 2.2 公共常量与类型

```rust
// base/runtime/rr3mod/src/lib.rs

/// rrd spawn 注入的 manifest 绝对路径（supervisor.rs 契约环境变量）。
/// 现五模块各自本地定义（rr3-act / rr3-sense / rr3-connect / rr3-power / rr3-interact
/// 的 main.rs 各一份 `RR3_MANIFEST_ENV`）——收编单点，模块侧本地常量随拆分退役。
pub const RR3_MANIFEST_ENV: &str = "RR3_MANIFEST";

/// 总线薄封装：透传 Rr3BusClient，不加语义。Clone 语义与 rr-bus 一致
/// （同一连接的 Arc 共享句柄——rr3-interact 面板线程现用法）。
#[derive(Clone)]
pub struct BusHandle { /* Rr3BusClient，私有 */ }

impl BusHandle {
    pub fn publish(&self, topic: &str, body: Value) -> Result<(), String>;
    pub fn call(&self, topic: &str, args: &Value) -> Result<Value, String>;
    pub fn counter_bump(&self, key: &str, by: u64);
    pub fn connected(&self) -> bool;
    // 刻意不提供 subscribe / 注销：线上无订阅注册帧（全量扇出 + 本地过滤，
    // rrd-registry 的 fanout 语义），给"注册"形状即假 API；
    // 订阅过滤是 Dispatcher::on_event 的本地职责。
}
```

### 2.3 Dispatcher trait（机制层注册面）

模块机制层实现本 trait，`serve` 骨架回调。三入口对应三类输入/节拍，
错误语义两档：**业务性失败折 error 应答**（`on_rpc` 返 `Err`），
**传输性/设备级失败上抛致命**（`on_event` / `on_tick` 返 `Err` → `serve` 上抛 →
main `exit(1)`）——与现行五模块逐字同款，本 trait 不发明新语义。

```rust
pub trait Dispatcher {
    /// rr3.call 点名应答（协议面）。Ok → result 应答体；Err → {"error": …} 折返。
    /// 需要发布状态流的处理（如 rr3-act servo 命令的限速 state 发布）在返回前
    /// 经 bus 完成——发布 → 应答的现行顺序不变。
    fn on_rpc(&mut self, topic: &str, args: &Value, bus: &BusHandle)
        -> Result<Value, String>;

    /// 广播事件（订阅面）。topic 本地过滤（不匹配直接返回 Ok）；发布副作用
    /// （如 rr3-act intent 执行后的 relay/state 摘要）经 bus 完成。
    fn on_event(&mut self, topic: &str, body: &Value, bus: &BusHandle)
        -> Result<(), String>;

    /// 帧无关节拍（每圈一次，poll_wait 分帧之后）：rr3-connect 链路拍 /
    /// rr3-power 双节拍 / rr3-sense 自 pacing 采集 / rr3-interact 面板动作排空。
    /// Err = 传输性/设备级（HAL 读数失败、发布写失败）→ 上抛致命。
    fn on_tick(&mut self, now: Instant, bus: &BusHandle) -> Result<(), String>;
}
```

### 2.4 bootstrap 收敛序列

```rust
/// 装配参数（装配段 main.rs 构造）。C = 模块 config 形状（rr3-interact 无 config
/// 解析面，用 `()` 空形状）。
pub struct Rr3ModConfig<C> {
    /// config 覆盖环境变量名。现四模块各持一份：rr3-act `RR3_ACT_CONFIG_ENV` /
    /// rr3-connect `RR3_CONNECT_CONFIG_ENV` / rr3-power `RR3_POWER_CONFIG_ENV` /
    /// rr3-sense `RR3_SENSE_CONFIG_ENV`（后者在 audio/mod.rs）；None = 只认
    /// manifest 同目录 config.toml。
    pub config_env: Option<&'static str>,
    /// config 文本 → 模块配置形状。TOML schema 解析与缺字段点名文案**留模块侧**
    /// （各模块文案形状是装配观测面，不统一）；C = () 时传 `|_| Ok(())`。
    pub parse_config: fn(&str) -> Result<C, String>,
}

/// 收敛序列（ADR-0017 裁定 1 序列的前四段）：
/// 读 RR3_MANIFEST → Rr3BusClient::rr3_connect（连接/注册/起心跳，rr-bus 既有，
/// 含喂狗失败退出语义）→ load_config_text → parse_config。
/// 返回 (BusHandle, C)——对 ADR-0017 `bootstrap(Rr3ModConfig) -> Result<BusHandle, String>`
/// 的参数细化：config 形状必须交还装配段（各模块 schema 不同），总线句柄是唯一
/// 公共产物。打印"总线就绪: name=… task=…"一行（现行文案逐字保留）。
pub fn bootstrap<C>(cfg: Rr3ModConfig<C>) -> Result<(BusHandle, C), String>;

/// config 路径解析单点：config_env 设了读 env 路径；未设读 manifest 同目录
/// config.toml。读失败 Err（文案沿用现行形状："读 config {path} 失败: {e}"）。
/// rr3-act / rr3-connect / rr3-power 三处逐字重复的路径解析随批0退役。
pub fn load_config_text(config_env: Option<&'static str>, manifest_path: &str)
    -> Result<String, String>;
```

- **HAL 选择 + 探活不进 bootstrap**：HAL 后端选择函数各模块不同
  （`rr3_hal_servo` / `rr3_hal_gpio_out` ×2 / `rr3_hal_audio_source` /
  `rr3_hal_link` / `rr3_hal_power` / `rr3_hal_audio_sink`），探活句柄类型强耦合
  模块语义。归各模块 `boot.rs`（接入层），失败文案沿用现行形状
  （"…面探活失败({backend}): {e}"），`Unsupported` 即 `Err` → main `exit(1)`
  ——rr-hal 占位件"显式回错不静默退化"的契约不变；
- **SURFACE 启动自述不进 bootstrap**：[ADR-0017](../adr/ADR-0017-模块内部分层-机制与策略分离.md)
  裁定 3 已钉"SURFACE 自述留 main（启动自述属装配面）"——装配段在各机制文件的
  `SURFACE` 常量 chain 后逐行打印，**输出逐字不变**是批1–批5 的验收判据之一。

### 2.5 serve 主循环骨架（逐步骤）

```rust
/// 主循环骨架（ADR-0017 裁定 1 序列的后三段：poll_wait → inbox 分发 → 传输性失败
/// 上抛）。poll_wait 作实参——五模块现值不同（rr3-act/rr3-interact 250ms、
/// rr3-connect/rr3-power 100ms、rr3-sense 等价 0，见 §2.6），不进公共配置。
pub fn serve(bus: BusHandle, dispatcher: &mut impl Dispatcher, poll_wait: Duration)
    -> Result<(), String>;
```

逐步骤规格（实施照抄；现行五模块主循环的逐字语义）：

1. **总线死亡探针**：`!bus.connected()` 即返
   `Err("总线已断开（reader EOF）：交 supervisor 按 restart_policy 裁定")`
   ——文案逐字保留（现行五模块同款）。背景：断开后 `poll_wait` 立即返回空 Vec，
   与"暂时没帧"不可区分，不探测就满转成僵尸；
2. **分帧**：`for frame in poll_wait(poll_wait)`；`opcode != SEND` 跳过；
   `rr3_frame_body` 解不开只排空；
3. **RPC 面**：`Request` 且 `method == rr3.call` → 剥 `id` / `params.topic` /
   `params.args` → `dispatcher.on_rpc(topic, args, &bus)`：
   `Ok(reply)` / `Err(e) → {"error": e}` → `rr3_reply_call(trace_id, id, reply)?`
   （`?` 即传输性失败上抛——应答写不出去不装活着）；
4. **订阅面**：`Event` → `dispatcher.on_event(topic, body, &bus)?`；
   其余 payload（Notification/Stream 等）只排空；
5. **节拍**：`dispatcher.on_tick(Instant::now(), &bus)?`；
6. 回到 1。

`main` 收尾形状（装配段，≤3 行）：`rr3_run` 返 `Err(e)` →
`eprintln!("rr3-<module> 退出: {e}")` + `std::process::exit(1)`——
"模块不装活着，死交给 supervisor 按 restart_policy=always 重启"语义随
`serve` 上抛路径单点化。

### 2.6 两形状归一（rr3-sense 的自 pacing 循环）

rr3-sense 现循环与另四模块不同形：`rr3_poll()` **非阻塞**排空 inbox + 采集后
补足 `frame_ms` 余量睡眠。归一方案：`Rr3ModConfig.poll_wait = Duration::ZERO`
（`rr3_poll_wait(ZERO)` ≡ `rr3_poll()`，同为非阻塞排空），采集序列进
`on_tick`——read（阻塞至一帧）→ downmix → publish → VAD 边沿 → 余量睡眠
全在 tick 内，时序行为不变。等价性由批3 验收的 sim 采集链 e2e 对账
（pcm 流帧数 / VAD 边沿数与改造前同输入同输出）。

### 2.7 config 装载的形状统一与 rr3-sense 差异登记

- act / connect / power 三模块：`config_env` 设了读 env 路径，未设读 manifest
  同目录 config.toml——三处路径解析逐字重复，`load_config_text` 单点化零语义差；
- **rr3-sense 差异（现状如实登记）**：`RR3_SENSE_CONFIG` 未设时
  `rr3_sense_config_load` **不读任何文件**，直接以空文本走 parse 得"登记默认值"
  （audio/mod.rs 注释自证"config.toml 的值即默认值的登记处"）；而仓内
  `modules/rr3-sense/config.toml` 实际存在且承载同名默认值。这是现行五模块中
  唯一的路径语义分叉；
- **裁定（随批3 兑现）**：sense 改用 `load_config_text` 统一形状（未设 env →
  读 manifest 同目录 config.toml）。语义等价性由**前置核对件**保证：批3 开工前
  逐字段核对 `modules/rr3-sense/config.toml` 与 `rr3_sense_config_parse("")`
  的内建默认值一致（不一致则先修 config.toml 再拆分，两件事两个提交）；
  sense 既有单测 `config_parse_defaults_on_empty_*` 原位保留，另加
  "config.toml 文件值 = 内建默认值" 的漂移钉子用例。

### 2.8 批0 单测面（形状钉子）

## 3 分层标准与红线（转写 [ADR-0017](../adr/ADR-0017-模块内部分层-机制与策略分离.md)，不另立）

1. `module.toml` / exposes / subscribes / 装配单 bindings **零改动**；

3. 策略不进模块（architecture.md 原则 4 字面执行）。

### 4.6 线程宿主与共享句柄所有权（跨线程面全清单）

| 并发面 | 现共享物 | 拆分后归属 | 不变量 |
|---|---|---|---|
| 心跳（rr-bus client 内部线程） | client 自持 | 不变——rr3mod 不碰心跳 | 喂狗失败退出语义随 `rr3_connect` 原样 |
| act 反射环（进程内 1kHz，ADR-0007 裁定 1） | `reflex::rr3_reflex_loop(cfg.reflex, bus.clone())` | spawn 函数化 `boot.rs::rr3_act_spawn_reflex`；该 BusHandle clone 只归反射环 | 反射环与主循环 Dispatcher **零共享状态**（现况即如此，拆分不许引入共享） |
| interact 面板线程（HTTP） | `Rr3PanelShared { bus: bus.clone(), bus_path, actions: act_tx, link }` | 构造函数化 `panel::spawn_host(shared)`；Dispatcher 持 `act_rx` + `link` Arc | `link`：面板线程只读 / 主循环（on_event）只写，Mutex 语义不变；`act_tx → act_rx` 通道方向不变 |
| 总线多句柄 | `Rr3BusClient` Arc Clone 同连接 | `BusHandle: Clone` 同语义 | 面板的 rr3.call 与主循环应答互不干扰（rr-bus 既有） |

**线程安全边界**：`Dispatcher` 只在主线程被 `serve` 以 `&mut` 回调，**不要求
Send/Sync**；跨线程物只有 `BusHandle`（Clone）与 `link` Arc——rr3mod 不引入
任何新锁、不新增任何线程。

### 6.1 公共四件套（批0–批5 每批同一模板，批号替换 crate 名）

改造前后 SURFACE 逐字比对：

```bash
# 拆分前留底、拆分后重跑，两份 stdout diff 必须为空
# （模块 crate 是独立 workspace，二进制在各模块自己的 target/ 下）

```

**② 预期输出（回显样例）**：check.sh 逐行 `PASS` + 汇总"所有规约检查通过"；

`header 一致` / 容器 diff 为空（缺 Docker/交叉目标则逐行 `SKIP` 并注明缺失项）。

**③ 判定标准**：①–⑤ 门全绿；④ 域内该 crate 独立构建绿；sim assemble 六模块装配
编排不变；golden 逐字节一致（SKIP 不算绿，如实登记）；SURFACE diff 为空；
零 `.rs` 之外的改动面 = 该模块 Cargo.toml 加 rr3mod 依赖行（`git diff --stat` 对账）。

**④ 失败处置**：单批 `git revert` 回滚本批（骨架批0 不回滚——回滚消费方批即可，

SURFACE 不齐 = 装配观测面泄漏，回改装配段/rpc.rs 文案，**不回改机制层**；
sim assemble 红 = 装配面被改动（红线 1 嫌疑），先 diff module.toml 与装配单再定位。
