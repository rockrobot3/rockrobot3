# 0.0.8 全仓静态生产审计（2026-11-07）

**范围**：仓库全量 tracked 源码与装配数据；硬件不在身边，本轮**只做静态审计**，
不冒充任何上板结论。审计基线为 `aae01fc`（全量 `check.sh` 已绿）；构建均在
`/tmp/rr3-audit` 或既有 CI 目录，不在源码区新增产品构建。

**方法**：四组只读扫描（panic/并发、桩/装配单虚报、安全/路径、brain/OTA/桥/音频）
＋一组质量扫描（`cargo fmt --check`、`cargo clippy`、函数名/圈复杂度/重复块启发式、
tracked 产物与文件头）。`jscpd` 未安装，重复率用 6 行归一化块启发式，**不是精确
token 重复率**；`cargo test` 与 esp 工具链 crate 未在本轮重跑。

## 1 P0（生产阻断）

### P0-1 esp 构建档写死本机绝对路径（**本轮已修**）

- 证据：[.cargo/config.toml](../../../tools/esp32-periph-base/.cargo/config.toml)
  原 `[env] IDF_PATH` 为某台开发机的绝对路径（已脱敏）。这既违反“源码区不暴露
  本地开发路径”，也让换机/CI 必须改源码才能构建 esp 档。
- 根因：把“离线构建钉”的个人机器路径当成了仓库默认，而不是环境/CI 注入。
- 修复：删除该行；`tools/ci/esp32*-check.sh` 本就用 `$HOME` 下版本钉克隆自行
  `export IDF_PATH`；本地直接 `cargo +esp build` 前由 shell 显式 export。
- 残留：该路径仍在 git 历史中；是否重写历史由用户裁决（本轮不擅自改写历史）。

### P0-2 `net.bt` 是 placeholder，却被 5 份装配单当作 present/bound

- 证据：[contracts/slots.toml](../../../contracts/slots.toml) `net.bt` 明确
  `status = "placeholder"`（“骨架占位，占位 ≠ 通过”）；
  [pi4b-host.toml](../../../profiles/pi4b-host.toml)、
  [pi4b-host-esp32s3.toml](../../../profiles/pi4b-host-esp32s3.toml)、
  [pi4b-host-esp32-classic.toml](../../../profiles/pi4b-host-esp32-classic.toml)、
  [default.toml](../../../profiles/default.toml)、
  [distro.toml](../../../profiles/distro.toml) 仍把 `net.bt` 写进
  `[bindings]`/`[enabled_slots]`/`[slots].present`。
- 运行证据：[rr3-connect/main.rs](../../../modules/rr3-connect/src/main.rs) 启动
  自述 `蓝牙面: phase=…（骨架，真后端板上后置）`；N44 的
  [0010](../../evidence/实测/0010.md) 只证三模块 running，未证 BT。
- 影响：装配单/状态面声称蓝牙在位，实际是骨架；违反“严禁演示性功能”。
- 根因：`slots.toml` 的 `status` 没有成为装配单 present/bind 的硬门。
- 修法：5 份装配单移除 `net.bt`；`enabled_slots` 的 `rr3-connect` 只留
  `net.wifi`；`[slots].present` 同步；`rr3-connect` 的 BT 原子/自述保留为
  placeholder，但不进生产装配面。后续真后端落地再把 `status` 改回 `normal`
  并恢复绑定。

### P0-3 无 ALSA feature 时 HAL 后端静默落 `sim`

- 证据：[rr-hal/backend.rs](../../../base/runtime/rr-hal/src/backend.rs)
  `rr3_hal_backend_default()`：Linux 且编进 `alsa` 才 `linux`，否则 `sim`；
  多数装配单本身不声明 HAL 后端，依赖 systemd/手工 export
  `RR3_HAL_BACKEND=linux`（N44 drop-in 有，独立运行/换机易漏）。
- 影响：漏设环境时真实硬件面落 sim，`selftest`/面板仍可能“通过”，属于
  生产假验证；与“严禁桩实现”直接冲突。
- 根因：后端选择是部署环境事实，却没有成为装配单的显式数据，也没有
  fail-closed 校验。
- 修法：装配单增加 HAL 后端声明（`host` 档至少 `linux`，组合档再分
  `audio_backend`/`periph_uart`），`rrd` 装载期校验并在缺失时拒启；手工运行
  同样走该数据，不靠隐式缺省。

### P0-4 `pi4b-host-esp32s3`/classic 组合档不可复现

- 证据：[pi4b-host-esp32s3.toml](../../../profiles/pi4b-host-esp32s3.toml)
  `[hardware]` 只有板侧 GPIO 键，没有宿主 UART 设备键（`RR3_HAL_PERIPH_UART`
  所需）；`rr3-sense` 采集需要 `RR3_HAL_AUDIO_BACKEND=esp32`，profile 未声明
  （classic 档仅在注释里提到）；`rr3-act`/`rr3-interact`/`rr3-sense` 对同一
  `/dev/ttyAMA0` 的 `Rr3UartConn` 是跨进程 flock 单消费者。
- 影响：N42 的“五模块 running”不能等同于板侧舵机/OLED/音频路径已通；W6 本轮
  只证了**探针宿主**（Pi UART0 ↔ S3 UART2，U3 10/10），**全 rrd 五模块组合档未跑**。
  装配单对外声称 act.servo/audio.capture/ui.face 在位，实际可复现性不足。
- 根因：组合档把“板侧十键”当成了宿主侧完整装配，缺少每能力面的后端/UART
  归属数据；单 UART 的 owner 与命令旁路没有在装配面定死。
- 修法：组合档补 `hal_backend`/`periph_uart`/`audio_backend`；明确 UART 单
  owner（建议 `rr3-sense` 持 conn，act/display 走命令旁路），或把板侧
  act/display 明确绑到 board 端点；`ui.face` 与 S3 OLED 的归属二选一并写清；
  全 host 栈跑通后再标通过。

### P0-5 源码区存在未跟踪构建产物

- 证据：`base/ota/rr3-ota-ctl/target/`、`tools/*/target/` 等目录在源码树内
  （均被 `.gitignore` 忽略，tracked 计数为 0，但目录仍在现场）。
- 影响：违反“严禁在源码区路径内有任何产品的编译/构建”；换人/打包时易被
  误带入制品或污染产物判断。
- 根因：本地构建默认 target 落在源码区，未统一到源码区外。
- 修法：统一 `CARGO_TARGET_DIR` 到源码区外（如 `/tmp` 或专用 build 目录），
  清理现有 target；CI/文档固化该约定。
