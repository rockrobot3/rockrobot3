## 二、发现与处置（两处，均已修复）

### 2.1 esp32s3 平台表 UART2 冲突集漂移（P1，修复 4501b8c）

- 现象：`contracts/platform/esp32s3.toml` 的 `[[conflict]] group="uart2"` 钉
  `pins = [17, 18]`、controller 注记同旧值；而 `tools/esp32-periph-base/src/
  board/pins_s3.rs` 已有 2026-10-29 真板订正迁钉 **41/42**（原 17/18 经板内
  缓冲双向不通，批N35件十四排障结案）。
- 时序：契约建档（7da2c5d，批N35件八）在先、真板订正（85bbcaa）在后，
  profile `esp32s3-mini.toml [pins]` 键值当时已同步（uart2_tx=41/uart2_rx=42），
  **仅平台事实表漏更**。契约自述取值来源即 pins_s3.rs——漂移违背
  "production 真值单点"，且 ④-b 互斥判据会把 41/42 当作无冲突脚。
- 处置：契约表 conflict pins → [41,42]、controller 注记与 why 补订正出处；
  profile 头注引脚清单同步（原写 17/18）；`platform.rs` 对 s3 仅 parse 不钉
  冲突值，rr-registry platform 测试全绿零改动。带日期史录（验证计划 §14、
  §6.6 结案段）按惯例原文不回改。

## 三、核过无损项（六条，逐条取证）

1. **Pi 绑定三方一致**：`profiles/pi4b-board.toml` bindings（i2c_sda=2/scl=3/
   uart2_tx=14/rx=15）== `tools/pi-periph-base/src/board.rs` `BIND_*`（2/3/14/15）
   == 契约 i2c1/pwm0 语义（GPIO2/3 即 I2C1、pwm0=pwmchip0 双通道）；契约
   `conflict = []` 显式空带注记（裁定②合规，演练实例真机对账入 status.md 敞口）；
   `reconcile_bindings` 只判四键、失配逐条计数不拒收——口径与契约角色域一致。
2. **linux_pwm 可移植**：sysfs 根为构造参数（默认 /sys/class/pwm 是文档常量
   非逻辑硬编码）、chip/channel 全走生效物理绑定**无代码缺省**（批D④
   fail-closed）、假 sysfs 树单测确定性不触硬件、Drop 只归还自己导出的通道。
   /sys/class/pwm/pwmchipN 是内核标准 ABI——Pi（dtoverlay=pwm-2chan）与
   RK3566（pwm-rockchip）同形，芯片差异全部在绑定数据侧，无平台名分支。
3. **linux_gpio 可移植**：chardev UAPI v1（/dev/gpiochipN，内核 4.8+ 现役
   UAPI），ioctl 常量自算、root/chip 绑定注入；RK3566 出厂内核（4.19/5.10+）
   满足。v2 接口并存不影响 v1 语义。
4. **nmcli_support 假设显式**：nmcli 子进程承载、起失败显式点名
   （"NetworkManager/nmcli 不在位？"）、输出 1MiB 帽防刷屏、超时守护终止
   ——宿主板须装 NetworkManager 是**显式假设**（报错指路），非静默退化。
5. **esp32audio ↔ 板侧 mic.rs 帧面同形**：宿主四道门（dst=宿主 → Event 前缀
   → topic=`rr3-sense/audio/pcm` → format=s16le + rate/seq/ms 必备 + b64）
   与板侧 `audio_chunk_to_frame` 组帧逐键同形；task 位形双侧同源
   rr_periph_proto（ADR-0024 单点，board.rs re-export）；主题侧 = topics_gen
   生成物（contracts/topics.toml 单源）、宿主侧字面量同值锚定 + 双侧测试
   防分叉。32bit I2S 帧在板侧截 16bit（`chunk_to_pcm`：24bit 高位有效 →
   截 16bit + 增益钳位）——**线上格式恒 s16le**，宿主只吃 16bit，无跨线
   格式漂移面。
6. **rk3566 消费面闭环**：演练实例，`platform.rs` 单测
   `rehearsal_shapes_are_pinned` 钉五条构造（pwm0 pan / gpiochip0 led / relay /
   i2c1 battery meter）与 default.toml 现役绑定逐条对账；`conflicts = []`
   显式空合规。

## 四、遗留观察（非缺陷，转后续批）

- **I2S 控制器未进 esp32/esp32s3 平台表**：表内现役控制器（ledc0/i2c0/uart2/
  adc1/gpio0[/vspi]）覆盖的是 roles.toml 在册角色的 (controller, role,
  instance) 构造对账域；音频采集（`audio.capture` normal 格）尚无 role.slot
  指向（⑨-a 报告模式 A=13 在账），I2S 引脚（4/27/26 与 6/15/7）仅由
  pins_*.rs 装配锚 + mic.rs 具名装配承载。**音频若后续进装配单角色域，
  须先补 I2S 控制器登记**——否则 ③-b/⑧ 判据对音频脚失明。立此存照。
- Pi 契约 input_only/ADC 全空是"演练实例待器件核对"的在账口径
  （status.md 敞口），真机对账归后续板批——非本轮缺陷。
