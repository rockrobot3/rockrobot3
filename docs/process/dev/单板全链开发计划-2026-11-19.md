## 0 口径与假设

### 0.1 全链定义（唯一口径，不再分叉）

```text
唤醒/VAD → 云 ASR → 云 LLM → 云 TTS → 本板播放 → 意图 → 舵机/表情/听声识位
```

| 环节 | 边界（谁做） | 成立判据 |
|---|---|---|
| 唤醒/VAD | 板端本地 | 16 kHz mono s16 采集；onset/offset 边沿入事件；静音期不误触发 |
| 云 ASR | 板端发、云返回 | multipart WAV 上传；返回非空文本 |
| 云 LLM | 板端发、云返回 | OpenAI 兼容 `/chat/completions`；返回非空 reply |
| 云 TTS | 板端发、云返回 | `/v1/audio/speech`，**只收 PCM/WAV**；板端不解码 MP3/AAC |
| 本板播放 | 板端 | 声音从**本板**扬声器出，不借宿主声卡 |
| 意图 | 板端本地 | ASR 文本 → `{topic, args}`；不依赖云端 function-calling |
| 舵机/表情/听声识位 | 板端 | pan 落角 + 表情帧 + DoA 三档判向 |

### 0.2 三种实现形态

| 形态 | 运行载体 | 组成 | 定位 |
|---|---|---|---|
| **Pi 4B 单板** | Raspberry Pi OS（Linux，distro 快路） | `rrd` + 六模块全部跑在本机 | 最快兑现；复用现有模块化栈 |
| **ESP32-S3 单板** | ESP-IDF v5.2.2 std | 单进程多任务自治固件 | N16R8：16 MB Flash / 8 MB PSRAM；MCU 全链主目标 |
| **ESP32 classic 单板** | 同一固件，`--features esp32` | 单进程多任务自治固件 | 4 MB Flash / 520 KB SRAM / 无 PSRAM；**先过内存门** |

### 0.3 已裁技术口径

1. ESP32/S3 走 **ESP-IDF std 单进程自治固件**，不做严格 `no_std` 裸金属全链：
   裸金属没有 WiFi/TLS/音频输出栈，520 KB SRAM 也放不下云语音全链的缓冲。
   既有 `tools/esp32-uart-echo`（`no_std` + xtensa-none-elf）只作机制/末梢证据保留。
2. 自治 = **单进程 + 多任务 + 进程内总线**；没有 `rrd`、没有 UDS、没有进程派生。
   既有 `rrd` 的 UDS/watchdog/派生面全在 `#[cfg(unix)]` 下，不从 MCU 复用。
3. 云对话 API 口径与 `rr3-brain` 现网一致：
   ASR `/v1/audio/transcriptions`、LLM `/chat/completions`、TTS `/v1/audio/speech`（`response_format=pcm`）。
4. API key 落 NVS（ESP）/ secrets 文件（Pi）；**不编译进固件、不进日志**。
5. TLS 根证书随固件；开机 SNTP 对时；证书或时间失败**显式点名并拒绝明文回退**。
6. 播放与拾音半双工：TTS 播放期关麦或门控（沿用 `rr3-sense` 的 tts_gate 语义），本轮不做 AEC。
7. 语音格式：采集 16 kHz mono s16；播放 PCM/WAV；设备不支持目标采样率时板端重采样或向云端请求支持率。
8. 内部协议不新造：进程内仍用 `rr-ipc` 帧与 `contracts/topics.toml` 既有主题；
   云端请求形状复用 `rr3-brain` 已跑通的实现，不写第二份。

### 0.4 本轮明确不做

- 不以"Pi 宿主 + ESP32 末梢"为**目标形态**；`pi4b-host-esp32-classic` / `-s3` 只降级为测试台架保留。
- 不把 UART 桥链算作单板全链（那是双板）。
- 不做 MP3/AAC 解码、不做 ASR/TTS 流式（首轮整段；流式另立项）。
- 不在 classic 内存门未过之前承诺 classic 全链。
- RK3566 未到货，不排执行，只保留清单。
- 不为"将来可能"预造抽象；W1/W2 的抽取只为消除现有两份同源实现，不新增第三份。

### 1.2 事实纠正（防口径回潮）

- "Pi4 + S3 已能单板全链"**不成立**：S3 只有板级外设 30 min 证据（[实测/0009](../../evidence/实测/0009.md)），无语音全链。
- "Pi 当宿主"不是目标；Pi 必须自己当板（本机麦、本机舵机、本机声卡），才叫单板。
- "classic 有双麦与舵机"只证明末梢能力；它没有扬声器，全链必须新增 I2S DAC/功放 + 扬声器。
- `pi4b-board.toml` 的 rtos 双轴档是"Pi 当板端点、Mac/Pi 宿主经桥"的旧形态，**不是** Pi 单板形态。

### 1.3 物料缺口（不阻塞代码开工，阻塞真机验收）

| 板 | 缺件 | 用途 | 阻塞面 |
|---|---|---|---|
| Pi 4B | ≥2 通道 USB 麦阵列（或双麦 + 立体声输入声卡）；SG90 pan + 5 V UBEC | DoA / 转向 | Pi 单板的听声识位与舵机 |
| ESP32-S3 | MAX98357A 或同级 I2S 功放 + 8 Ω 扬声器 | 本板播放 | S3 全链出声 |
| ESP32 classic | 同 S3；若内存门不过，备选 ESP32-WROVER（带 PSRAM 的同族模组） | 本板播放 / 内存 | classic 全链 |

## 3 目标架构

### 3.1 Pi 4B 单板

```text
USB 双麦 → ALSA capture → rr3-sense(VAD/DoA) ─┐
                                              ├→ 总线 → rr3-brain(ASR/LLM/TTS) → rr3-interact(ALSA sink) → 本机扬声器
                                              └→ rr3-act(sysfs PWM pan) → 舵机
rrd spawn 六模块；MAX7219 表情；nmcli 链路
```

- 新档 `profiles/pi4b-solo.toml`（host tier）：十格绑定
  `audio.capture` / `audio.vad` / `audio.playback` / `act.servo` / `ui.face` / `net.wifi` / `cognition` 四格。
- `[hardware]`：`alsa_device`、`link_ifname`；`[[pin]] act.axis.pwm pan`（pwmchip0 ch0 → GPIO12）
  + `[[pin]] ui.face.spi`（spidev0.0）。
- 舵机面**只要求 pan 单轴**（DoA 左右转头即可）；tilt 不作 Pi 全链判据，保留为可选。
- 不需要 `pi-periph-base`；旧双板档继续作台架。
- 剩余缺口：麦阵列、pan 舵机、DoA 通道标定、Pi 上带 `alsa` feature 的构建与装机。

### 3.2 ESP32-S3 自治固件

```text
supervisor-lite（状态机 / 看门狗 / 重启计数）
net      WiFi STA + SNTP + esp_http_client(mbedTLS)
audio-in I2S0 RX 双麦 16k → 下混 + VAD/DoA → 语音段缓冲（PSRAM）
dialog   ASR → LLM → 意图 → TTS 请求（半双工门控）
audio-out I2S TX → MAX98357A → 本板扬声器
motion   LEDC pan/tilt（periph-mech 限位/缓速）
ui       OLED 表情
cfg      NVS：WiFi、API key、DoA 通道偏置
```

- 进程内总线：`rr-ipc` 帧 + 内存队列；主题沿用 `contracts/topics.toml` 既有词表。
- 配置：`profiles/esp32s3-solo.toml`（rtos tier 扩展或新 tier，W0 裁定），
  编译期 `include_str!` 嵌入；可变凭据只走 NVS。
- 内存策略：PSRAM 放音频环与 TLS 大块；内部 SRAM 只放栈与热路径。
- 闪存：16 MB 可做双 OTA 槽；classic 4 MB 单槽，**不承诺自动回滚**。

### 3.3 ESP32 classic 自治固件

- 同一固件 `--features esp32`；PSRAM 缓冲全部改内部 SRAM，先测再谈全链。
- 门：boot 后 30 min 稳态 `esp_get_free_heap_size` ≥ 20% SRAM，且 TLS 握手 + 3 轮对话无 OOM。
- 不过门则如实登记终态：classic 保留"机制/末梢板"形态；或改用同族 WROVER（带 PSRAM）承载 classic 全链。

### 4.1 W0 细化

- ADR 内容：三独立形态、自治固件边界、solo 档语义、云 API 口径、TTS 只收 PCM。
- 裁定项：solo 档用现有 `rtos` tier 还是新增 tier；固件配置以 profile 编译期嵌入还是独立 `config.toml`。
- 契约页：[单板全链云 API 契约](单板全链云API契约-2026-11-19.md)——三家端点、鉴权头、请求/应答体、超时与重试上限、错误分级。

### 4.2 W1 细化

- 先移 VAD（状态机 + 整数 RMS），再移 DoA（ILD 反演 + 偏置/死区），最后移切段与 WAV 头。
- 每移一件：原模块改为引用新 crate，golden 向量与用例同批迁移，**不改判据数值**。
- 新 crate 禁 std 专属类型；需要分配时用调用方传入的缓冲。

### 4.3 W3 细化

- 任务表固定六项（net / audio-in / dialog / audio-out / motion / ui），supervisor-lite 只做状态与重启。
- 总线消息沿用 `rr-ipc` 帧；进程内投递用有界队列，满队列点名丢弃，不阻塞音频线程。
- 看门狗：每任务心跳位，超时点名并整机重启；重启计数落 NVS。
- 网络：断线指数退避重连；SNTP 失败时拒发云请求并显式报"时间未同步"。

## 6 验收矩阵

### 6.1 逐跳判据（三板同口径）

| 环节 | 判据 |
|---|---|
| 唤醒/VAD | 正常说话 5/5 触发 onset；静音 60 s 0 次误触发；TTS 播放期 0 次自触发 |
| 云 ASR | 3/3 返回非空文本；文本语义可读（人工判定） |
| 云 LLM | 3/3 返回非空 reply；8 s 内返回，超时须显式降级播报 |
| 云 TTS | 3/3 返回非空 PCM/WAV；板端不解码其他格式 |
| 本板播放 | 3/3 从本板扬声器出声；播放完成事件驱动下一状态 |
| 意图 | "向左看 / 向右看 / 回中" 3/3 命中；"开灯 / 关灯" 3/3 命中（接线存在时） |
| 舵机 | pan 落角 70°/90°/110° ±3°；DoA 左/右时转向方向正确 |
| 表情 | 待机 / 聆听 / 说话 / 转向四态可见切换（Pi MAX7219、ESP OLED） |
| 听声识位 | 左/中/右各 10 轮，每侧 ≥8/10；偏置与死区按现场标定登记 |

### 6.2 系统级门（每板都要过）

| 门 | 判据 |
|---|---|
| 冷启动 | 上电到"待唤醒"≤60 s；记录实测值 |
| 30 min soak | 连续对话 ≥10 轮；无 panic、无重启、无看门狗复位 |
| 内存（MCU） | 稳态 free ≥20% SRAM；PSRAM 使用量有上限登记 |
| 断网 | 60 s 内显式报"网络不可用"；恢复后 60 s 内可再对话；**不得静默冒充全链** |
| 凭据 | 固件与日志中无明文 key；NVS/secrets 读取失败显式点名 |
| 证据真实性 | 单板全链证据必须来自**该板自跑**；宿主代理、双板组合、sim 档不计 |

## 7 风险与 Go/No-Go 门

| 风险 | 触发点 | 处置 | 门 |
|---|---|---|---|
| classic SRAM 不足 | W7 测量 | 裁缓冲 / 降功能 / No-Go 终态；备选 WROVER | 30 min free ≥20% |
| S3 TLS + 音频缓冲争内存 | W6 | PSRAM 承载大块；内部 SRAM 只留热路径 | 3 轮 + 30 min 无 OOM |
| TTS 供应商只给 MP3 | W2/W4 | 请求 PCM 失败即显式报错；换供应商或加代理，**不引入解码器** | 3/3 PCM 非空 |
| 4 MB 单槽无自动回滚 | W8 | 不承诺自动回滚；重烧恢复为唯一路径并写入文档 | 回滚语义有明确终态 |
| 播放期自触发 | W4 | 半双工关麦/门控 | 播放期 0 次自触发 |
| Pi 声卡只有单声道输入 | W5 | 换 ≥2 通道阵列；单声道则不承诺 DoA | DoA 3×10 |
| 云延迟波动 | 全阶段 | 8 s 超时 + 降级播报；记录 P50/P95 | 每轮 8 s 内或显式降级 |
| 单核 classic 负载 | W7 | 降采样率/裁 UI；仍不过则 No-Go | 播放不卡顿、VAD 不掉帧 |
| 证据口径漂移 | 全阶段 | 单板自跑才计数；双板台架证据单独标注 | 证据按 6.2 最后一行 |
| 配置漂移 | W3/W5 | solo 档进仓、固件编译期嵌入、NVS 只存凭据与标定 | 装配单与设备读数对账 |

**总 Go/No-Go**：Pi4 与 S3 必须过全部系统门；classic 过了才进 W6 等价的全链验收，
不过则按 §3.3 登记终态——**不把"No-Go"写成空白**。
