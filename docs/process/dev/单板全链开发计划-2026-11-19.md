## 0 口径与假设

### 0.1 全链定义（唯一口径，不再分叉）

```text
唤醒/VAD → 云 ASR → 云 LLM → 云 TTS → 本板播放 → 意图 → 舵机/表情/听声识位
```

| 环节 | 边界（谁做） | 成立判据 |
|---|---|---|
| 唤醒/VAD | 板端本地 | 16 kHz mono s16 采集；onset/offset 边沿入事件；静音期不误触发 |
| 云 ASR | 板端发、云返回 | multipart WAV 上传；返回非空文本 |
| 云 LLM | 板端发、云返回 | OpenAI 兼容 `/chat/completions`；返回非空 reply |
| 云 TTS | 板端发、云返回 | `/v1/audio/speech`，**只收 PCM/WAV**；板端不解码 MP3/AAC |
| 本板播放 | 板端 | 声音从**本板**扬声器出，不借宿主声卡 |
| 意图 | 板端本地 | ASR 文本 → `{topic, args}`；不依赖云端 function-calling |
| 舵机/表情/听声识位 | 板端 | pan 落角 + 表情帧 + DoA 三档判向 |

### 0.2 三种实现形态

| 形态 | 运行载体 | 组成 | 定位 |
|---|---|---|---|
| **Pi 4B 单板** | Raspberry Pi OS（Linux，distro 快路） | `rrd` + 六模块全部跑在本机 | 最快兑现；复用现有模块化栈 |
| **ESP32-S3 单板** | ESP-IDF v5.2.2 std | 单进程多任务自治固件 | N16R8：16 MB Flash / 8 MB PSRAM；MCU 全链主目标 |
| **ESP32 classic 单板** | 同一固件，`--features esp32` | 单进程多任务自治固件 | 4 MB Flash / 520 KB SRAM / 无 PSRAM；**先过内存门** |

### 0.3 已裁技术口径

1. ESP32/S3 走 **ESP-IDF std 单进程自治固件**，不做严格 `no_std` 裸金属全链：
   裸金属没有 WiFi/TLS/音频输出栈，520 KB SRAM 也放不下云语音全链的缓冲。
   既有 `tools/esp32-uart-echo`（`no_std` + xtensa-none-elf）只作机制/末梢证据保留。
2. 自治 = **单进程 + 多任务 + 进程内总线**；没有 `rrd`、没有 UDS、没有进程派生。
   既有 `rrd` 的 UDS/watchdog/派生面全在 `#[cfg(unix)]` 下，不从 MCU 复用。
3. 云对话 API 口径与 `rr3-brain` 现网一致：
   ASR `/v1/audio/transcriptions`、LLM `/chat/completions`、TTS `/v1/audio/speech`（`response_format=pcm`）。
4. API key 落 NVS（ESP）/ secrets 文件（Pi）；**不编译进固件、不进日志**。
5. TLS 根证书随固件；开机 SNTP 对时；证书或时间失败**显式点名并拒绝明文回退**。
6. 播放与拾音半双工：TTS 播放期关麦或门控（沿用 `rr3-sense` 的 tts_gate 语义），本轮不做 AEC。
7. 语音格式：采集 16 kHz mono s16；播放 PCM/WAV；设备不支持目标采样率时板端重采样或向云端请求支持率。
8. 内部协议不新造：进程内仍用 `rr-ipc` 帧与 `contracts/topics.toml` 既有主题；
   云端请求形状复用 `rr3-brain` 已跑通的实现，不写第二份。

### 0.4 本轮明确不做

- 不以"Pi 宿主 + ESP32 末梢"为**目标形态**；`pi4b-host-esp32-classic` / `-s3` 只降级为测试台架保留。
- 不把 UART 桥链算作单板全链（那是双板）。
- 不做 MP3/AAC 解码、不做 ASR/TTS 流式（首轮整段；流式另立项）。
- 不在 classic 内存门未过之前承诺 classic 全链。
- RK3566 未到货，不排执行，只保留清单。
- 不为"将来可能"预造抽象；W1/W2 的抽取只为消除现有两份同源实现，不新增第三份。

### 1.2 事实纠正（防口径回潮）

- "Pi4 + S3 已能单板全链"**不成立**：S3 只有板级外设 30 min 证据（[实测/0009](../../evidence/实测/0009.md)），无语音全链。
- "Pi 当宿主"不是目标；Pi 必须自己当板（本机麦、本机舵机、本机声卡），才叫单板。
- "classic 有双麦与舵机"只证明末梢能力；它没有扬声器，全链必须新增 I2S DAC/功放 + 扬声器。
- `pi4b-board.toml` 的 rtos 双轴档是"Pi 当板端点、Mac/Pi 宿主经桥"的旧形态，**不是** Pi 单板形态。

| 板 | 器件 | 状态 | 剩余工作 |

| ESP32-S3 | 同级 I2S 功放 + 8 Ω 扬声器 | **在位** | I2S TX 代码、功放使能/去爆音、全链集成 |

## 3 目标架构

### 3.1 Pi 4B 单板

```text
USB 双麦 → ALSA capture → rr3-sense(VAD/DoA) ─┐
                                              ├→ 总线 → rr3-brain(ASR/LLM/TTS) → rr3-interact(ALSA sink) → 本机扬声器
                                              └→ rr3-act(sysfs PWM pan) → 舵机
rrd spawn 五模块（无 rr3-power：Pi solo 不装电池格）；MAX7219 表情；nmcli 链路
```

- 新档 `profiles/pi4b-solo.toml`（host tier）：十格绑定
  `audio.capture` / `audio.vad` / `audio.playback` / `act.servo` / `ui.face` / `net.wifi` / `cognition` 四格。
- `[hardware]`：`alsa_device`、`link_ifname`；`[[pin]] act.axis.pwm pan`（pwmchip0 ch0 → GPIO12）
  + `[[pin]] ui.face.spi`（spidev0.0）。
- 舵机面**只要求 pan 单轴**（DoA 左右转头即可）；tilt 不作 Pi 全链判据，保留为可选。
- 不需要 `pi-periph-base`；旧双板档继续作台架。
- 器件已在位（双麦/声卡/SG90/UBEC）；剩余缺口：接线、DoA 通道标定、Pi 上带 `alsa` feature 的构建与装机。

### 3.2 ESP32-S3 自治固件

```text
supervisor-lite（状态机 / 看门狗 / 重启计数）
net      WiFi STA + SNTP + esp_http_client(mbedTLS)
audio-in I2S0 RX 双麦 16k → 下混 + VAD/DoA → 语音段缓冲（PSRAM）
dialog   ASR → LLM → 意图 → TTS 请求（半双工门控）
audio-out I2S TX → MAX98357A → 本板扬声器
motion   LEDC pan/tilt（periph-mech 限位/缓速）
ui       OLED 表情
cfg      NVS：WiFi、API key、DoA 通道偏置
```

- 进程内总线：`rr-ipc` 帧 + 内存队列；主题沿用 `contracts/topics.toml` 既有词表。
- 配置：`profiles/esp32s3-solo.toml`（rtos tier 扩展或新 tier，W0 裁定），
  编译期 `include_str!` 嵌入；可变凭据只走 NVS。
- 内存策略：PSRAM 放音频环与 TLS 大块；内部 SRAM 只放栈与热路径。
- 闪存：16 MB 可做双 OTA 槽；classic 4 MB 单槽，**不承诺自动回滚**。

### 3.3 ESP32 classic 自治固件

- 同一固件 `--features esp32`；PSRAM 缓冲全部改内部 SRAM，先测再谈全链。
- 门：boot 后 30 min 稳态 `esp_get_free_heap_size` ≥ 20% SRAM，且 TLS 握手 + 3 轮对话无 OOM。
- 不过门则如实登记终态：classic 保留"机制/末梢板"形态；或改用同族 WROVER（带 PSRAM）承载 classic 全链。

### 4.1 W0 细化

- ADR 内容：三独立形态、自治固件边界、solo 档语义、云 API 口径、TTS 只收 PCM。
- 裁定项：solo 档用现有 `rtos` tier 还是新增 tier；固件配置以 profile 编译期嵌入还是独立 `config.toml`。
- 契约页：[单板全链云 API 契约](单板全链云API契约-2026-11-19.md)——三家端点、鉴权头、请求/应答体、超时与重试上限、错误分级。

### 4.2 W1 细化

- 先移 VAD（状态机 + 整数 RMS），再移 DoA（ILD 反演 + 偏置/死区），最后移切段与 WAV 头。
- 每移一件：原模块改为引用新 crate，golden 向量与用例同批迁移，**不改判据数值**。
- 新 crate 禁 std 专属类型；需要分配时用调用方传入的缓冲。

### 4.3 W3 细化

- 任务表固定六项（net / audio-in / dialog / audio-out / motion / ui），supervisor-lite 只做状态与重启。
- 总线消息沿用 `rr-ipc` 帧；进程内投递用有界队列，满队列点名丢弃，不阻塞音频线程。
- 看门狗：每任务心跳位，超时点名并整机重启；重启计数落 NVS。
- 网络：断线指数退避重连；SNTP 失败时拒发云请求并显式报"时间未同步"。

## 6 验收矩阵

### 6.1 逐跳判据（三板同口径）

| 环节 | 判据 |
|---|---|
| 唤醒/VAD | 正常说话 5/5 触发 onset；静音 60 s 0 次误触发；TTS 播放期 0 次自触发 |
| 云 ASR | 3/3 返回非空文本；文本语义可读（人工判定） |
| 云 LLM | 3/3 返回非空 reply；8 s 内返回，超时须显式降级播报 |
| 云 TTS | 3/3 返回非空 PCM/WAV；板端不解码其他格式 |
| 本板播放 | 3/3 从本板扬声器出声；播放完成事件驱动下一状态 |
| 意图 | "向左看 / 向右看 / 回中" 3/3 命中；"开灯 / 关灯" 3/3 命中（接线存在时） |
| 舵机 | pan 落角 70°/90°/110° ±3°；DoA 左/右时转向方向正确 |
| 表情 | 待机 / 聆听 / 说话 / 转向四态可见切换（Pi MAX7219、ESP OLED） |
| 听声识位 | 左/中/右各 10 轮，每侧 ≥8/10；偏置与死区按现场标定登记 |

### 6.2 系统级门（每板都要过）

| 门 | 判据 |
|---|---|
| 冷启动 | 上电到"待唤醒"≤60 s；记录实测值 |
| 30 min soak | 连续对话 ≥10 轮；无 panic、无重启、无看门狗复位 |
| 内存（MCU） | 稳态 free ≥20% SRAM；PSRAM 使用量有上限登记 |
| 断网 | 60 s 内显式报"网络不可用"；恢复后 60 s 内可再对话；**不得静默冒充全链** |
| 凭据 | 固件与日志中无明文 key；NVS/secrets 读取失败显式点名 |
| 证据真实性 | 单板全链证据必须来自**该板自跑**；宿主代理、双板组合、sim 档不计 |

## 7 风险与 Go/No-Go 门

| 风险 | 触发点 | 处置 | 门 |
|---|---|---|---|
| classic SRAM 不足 | W7 测量 | 裁缓冲 / 降功能 / No-Go 终态；备选 WROVER | 30 min free ≥20% |
| S3 TLS + 音频缓冲争内存 | W6 | PSRAM 承载大块；内部 SRAM 只留热路径 | 3 轮 + 30 min 无 OOM |
| TTS 供应商只给 MP3 | W2/W4 | 请求 PCM 失败即显式报错；换供应商或加代理，**不引入解码器** | 3/3 PCM 非空 |
| 4 MB 单槽无自动回滚 | W8 | 不承诺自动回滚；重烧恢复为唯一路径并写入文档 | 回滚语义有明确终态 |
| 播放期自触发 | W4 | 半双工关麦/门控 | 播放期 0 次自触发 |
| Pi 声卡只有单声道输入 | W5 | 换 ≥2 通道阵列；单声道则不承诺 DoA | DoA 3×10 |
| 云延迟波动 | 全阶段 | 8 s 超时 + 降级播报；记录 P50/P95 | 每轮 8 s 内或显式降级 |
| 单核 classic 负载 | W7 | 降采样率/裁 UI；仍不过则 No-Go | 播放不卡顿、VAD 不掉帧 |
| 证据口径漂移 | 全阶段 | 单板自跑才计数；双板台架证据单独标注 | 证据按 6.2 最后一行 |
| 配置漂移 | W3/W5 | solo 档进仓、固件编译期嵌入、NVS 只存凭据与标定 | 装配单与设备读数对账 |

**总 Go/No-Go**：Pi4 与 S3 必须过全部系统门；classic 过了才进 W6 等价的全链验收，
不过则按 §3.3 登记终态——**不把"No-Go"写成空白**。

| httpd 栈 | 16,384 B（`HTTPD_STACK_SIZE`）；失败码 `0xB008` = `ESP_ERR_HTTPD_ALLOC_MEM` | [`start.rs`](../../../tools/esp32-periph-base/src/httpd/serve/start.rs) / IDF v5.2.2 `esp_http_server.h` |
| 云 worker 栈 | 24,576 B | [`cloud.rs`](../../../tools/esp32-periph-base/src/cloud.rs) `TTS_STACK` |
| mic / 播放线程栈 | 16,384 B × 2 | [`mic.rs`](../../../tools/esp32-periph-base/src/mic.rs) / [`playout.rs`](../../../tools/esp32-periph-base/src/playout.rs) |

**W7-b2 后**：上表“TTS 回包”行已不适用——回包 4KB 流式、播放环 16KB，
512KB Vec 与“2 条全量”队列均删除；**W7-b3a 后**“ASR 上行”行的两份临时体
（256KB s16le + 256KB multipart）也已删除，只剩语音段本体与 TLS。剩余静态
峰值由语音段缓冲、TLS 收发缓冲与无 PSRAM VAD 决定。旧行保留为 W7 实测当时
的实现口径。

**终态（当前实现）**：classic 4 MB Flash / 520 KB SRAM、无 PSRAM 的当前实现 **No-Go**——
不是“差一点”：修复版实测播放面后 `free=34,336 B` / `int_free=61,160 B`（6.6% / 11.8%
SRAM），httpd 以 `0xB008`（`ESP_ERR_HTTPD_ALLOC_MEM`，栈 16,384 B）仍失败；旧固件 60s 内 11 次复位，修复版 60s 零复位只证明
复位环已治。静态面上无 PSRAM 时 [`voice.rs`](../../../tools/esp32-periph-base/src/mic/voice.rs)
直接停用本地 VAD/分段，TTS 512 KB 全量回包与播放队列 2 条全量 PCM 任一都超过可用内部堆。
该终态指**当前实现**，不是 classic 硬件终态。

**存储/流式候选**：要让“RAM 只做工作台、数据落存储”成立，必须同时改三处，缺一不可：

1. **ASR 上行**：语音段顺序写 flash（或边采边写），multipart 按 Content-Length 从存储
   分块写 `esp_http_client_write`；RAM 只留 20 ms 块 + 4 KB 搬运窗。
2. **TTS 下行**：`esp_http_client_read` 每 4 KB 直接投 I2S 播放环（8–16 KB），不聚合成
   完整 Vec；淡入/淡出按首末块标记。**已落树（W7-b2）**。
3. **常驻面裁剪**：全链档不启 httpd（配网/诊断单独档），压掉 16 KB 栈 + 会话分配；
   TLS 用 asymmetric/dynamic 缓冲；任务栈按实测下调。

存储只解决“整段数据不能常驻”，不解决 TLS 握手/收发缓冲；flash 写寿命与 16k mono
32 KB/s 的持续写入也要在 W7 记账。候选方案在真板测出 `30 min free ≥20% SRAM` 前不判
Go，也不排 classic 全链。

W7 采样面已落 [`mem.rs`](../../../tools/esp32-periph-base/src/mem.rs)：阶段边界打印
`[mem] stage=<阶段> phase=<点位> free/int_free/int_min/psram_*`，点位含
`httpd/start-*`、`mic-voice`、`http-open/rx-first/rx-done`、`tts/fetch-*`、
`playout/start|done|fail`、`dialog/start|asr-ok|llm-ok|done`。本轮已用 CI 制品重烧
并抓到 boot→periph→mic→playout→httpd 的 `[mem]` 列；`httpd` 之后的云/对话阶段因
httpd 起栈失败、VAD 停用、SNTP 无凭据未进入。**下一触发条件**＝存储/流式改造落地且
板上有可用 WiFi 凭据后，抓一轮 boot→WiFi→SNTP→TLS→3 轮对话→30 min 的 `[mem]` 列；
在此之前保持“当前实现 No-Go / 候选未证”，不得用某一时点的 `free` 代替峰值。

### 20.3 W7-b4 真板 30min 与终态裁定（2026-11-22）

**首轮（classic 4MB / 无 PSRAM；CI 制品 `d5963ce3` 重烧）**：30 min soak 完成。
全程 **1 次上电复位、0 次 Guru/panic/心跳超时/OOM**；`status free` 61 个样本
**36,288–36,448 B**，`min_free=1,884 B`；MIC 采样率 899 个窗口
**15,947–16,130 Hz**（无崩塌）；播放面、WiFi/SoftAP、net 心跳均在线。

| 点位 | 实测 | 判读 |
|---|---|---|
| `2-periph-ready` | 244,500 B | 语音/spool 预算 258,048 B 未达 → `[spool] 跳过` |
| `3-mic-smoke` | 58,440 B | 本地 VAD 停用（`[mic] 本地 VAD/分段停用`） |
| `4-spk-play` | 17,688 B | 16 KB 环 + 16 KB 栈起来；播放面在线 |
| HTTP 门 | 最大连续块 2,304 B < 40,960 B | HTTP 降级关闭，WiFi/net 照起 |
| `status` 稳态 | 36.4 KB（7.0% SRAM） | 远低于 Go 门 20%（104 KB）；`min_free=1.9 KB` |

**为什么必须加门（真板逐层红因，均按根因修）**：
1. spool 写线程 6 KB 栈 < 线程启动→`recv_timeout` 的 7.2 KB 链 → 启动复位环
   56 次（`9b6ca4a` 改 12 KB）。
2. 语音常驻路径约 48 KB，启动面余量仅约 34 KB → WiFi 16 KB 分配 panic
   （`9b6ca4a` 加 spool 堆预留门）。
3. `httpd_start` 16 KB 任务在碎片堆失败（`0xB008`），失败窗挤掉播放线程
   16 KB 栈（`91da54a` 加最大连续堆门，只关 HTTP）。
4. 关 HTTP 后总空闲 32.6 KB 但最大连续块仅 15.3 KB → 播放栈仍 OOM
   （`d4dfccb6` 起栈前等连续块合并，最多 2 s）。
5. net-watch 16 KB 栈在 WiFi 后 8 KB 连续块处 OOM，net 假死
   （`6c204a1` 改 6 KB；本线程只做 1 s 轮询 + 心跳）。
6. 监督壳对“从未启动”与“停跳失联”都打印“即将复位”，与实际复位判据不符
   （`d5963ce3` 拆成两行点名；只有曾心跳后失联才复位）。

**裁定**：W7-b 的存储/流式候选**没有**让 classic 全链成立——
- 稳态 36.4 KB = 7.0% SRAM，`min_free` 仅 1.9 KB，TLS 握手/收发无余量；
- HTTP 配置面关闭、本地 VAD 停用，classic 上既无 ASR/TTS 触发面，也无语音入口；
- 语音常驻 48 KB 与 WiFi/播放/TLS 不能共存，靠“再调一调”不成立。

**保留与拆走**：TTS 4KB 流式（W7-b2）与 ASR 4KB 分块上行（W7-b3a）继续有效；
spool 记录/写线程机制保留给有 PSRAM 或更大 SRAM 的机型（S3 当前走 PSRAM 内存
路径，不起写线程）。classic 4MB 的结论是 **No-Go（全链/板上 VAD）**，S3 是
语音板；这是平台能力分工，不是共享机制缺陷。

**遗留（下一轮结构改进）**：音频面起栈先于网络服务（或统一启动期堆预算表）；
播放栈按实测下调并把 4 KB 块移到堆。
**已收（2026-11-22）**：发布固件随带与 app 同一 IDF 构建树的 bootloader，
并与分区表 CSV、烧录说明一起进 release 资产与 ghcr OCI（publish `firmware`
job；资产集由 `workflows_audit` 断言）。

#### 20.13.2 CC=8 余量裁定（2026-11-24，34 处，全数留）

口径：`metrics.py` 生产面（测试面截除），最大 8 = 基线；逐条裁定“拆/留”。
**原则**：分支必须对应一个现场归因或一次状态迁移；拆后若只能靠共享可变状态或
返回码二次解释，判“留”——显式线性分支优于跨函数隐式状态。34 处均 ≤44 行，
在 50 行审查阈值内。

- **协议/载荷逐字段校验（8）**：`rr3_req_parse`、`rr3_topic_check`、
  `rr3_pin_str_req`、`rr3_wifi_cred_check`、`rr3_cloud_fields`、
  `rr3_model_row_input`、`rr3_row_view`、`rr3_check_pkg`——逐字段点名是
  fail-closed 的稳定性要求，拆分只会把“哪个字段坏”变成调用方二次推断。
- **I/O 错误归一（9）**：`rr3_alsa_open`、`rr3_alsa_advance`、`rr3_read_timeout`、
  `rr3_read_into`、`read_line`、`run`、`reader_reconnect`、`rr3_log_sink_append`、
  `rr3_backfill_tail`——每条分支对应一种线面/设备现场（超时、EINTR、欠载、轮转），
  归因不能合并。
- **状态机/命令分发（8）**：`rr3_conn_serve`、`on_rpc`、`serve`、`cloud_run`、
  `rr3_down_step`、`on_tick`、`rr3_cmd_ui`、`rr3_dialog_body`——迁移线性，臂表化
  已做过一轮；再拆需跨函数传递连接/缓冲状态。
- **数值/绘制/对拍（9）**：`rr3_parity_run`、`rr3_play_feed`、`rr3_steady_check`、
  `rr3_boot_ms_parse`、`ensure`、`rr3_peer_call`、`rr3_tail_collect`、`servo_set`、
