## §1 立题（两条需求 + 现场证据）

**需求 ①（分轴限幅数据化）**：用户（2026-10-12）要求 pan±20°/tilt±10° 分轴限幅。方案C 已在
**板侧**做成 `Axis::range`（pan[70,110]/tilt[80,100]），但宿主 `modules/rr3-act/config.toml` 的
`angle_limit_deg` **仍是一份单区间**（默认轴 pan，靠 `RR3_HAL_PERIPH_AXIS` 选轴）——两轴无法在
配置面并存描述，是权宜态。

**需求 ②（低电压降级：并行 → 串行）**：用户要求"检查整板电压，电压不够时舵机由并行改**先左右
后上下**串行转动"。这是**降级继续动**，与 MC-5"低电禁动"（执行面拒动）**语义不同**——两者是
**两档**，不是同一档。

**现场证据（方案C 已录）**：真板云台舵机堵转（SG90 ~700mA/只持续流动）+ 5V 取自板载 USB/拓展坞
直供 → **5V 轨跌落** → **BOD 复位循环**（`Brownout detector was triggered`）→ 串口节点与 OLED
反复掉线。**关键缺口**：5V 轨电压**现无任何检测手段**（现仅 INA219 测**电池**电压，属电源树上游，
不是舵机供电轨本身），故欠压既看不见、也响应不了。降级串行的物理依据 = **削瞬时电流峰值**：
两轴并行驱动的峰值电流叠加，串行（先 pan 到位再 tilt）把峰值摊开。

## §2 范围

**做**：① 5V（舵机供电轨）电压的**观测**——硬件采点 + 上报通道；② 欠压**分级降级**语义（串行/
拒动两档）；③ 分轴限幅下沉到 config 数据面；④ 阈值数据化 + 真板标定口径。

**不做**：不改舵机机械/电气限位本身；不重定义 MC-5 的拒动语义（只做"两档"的分界与联动）；
不新增主题计数（复用既有 `rr3-runtime/system/power` 广播面，见 §4）。

## §4 技术要点（裁定通过后的施工面，草案）

1. **采点与链路（Q1）**：5V 轨 → 分压电阻 → ESP32 **ADC1** 空闲通道（经典 ESP32：ADC1 = GPIO32–39，
   其中 **32/33 已占 LEDC 双轴**，34–39 输入专用；**禁 ADC2**——与 WiFi 冲突）。板侧周期采样、
   上报格位面（`power.*` 或 ESP32 协处理器的能力面，随批C 的格位化承载）。
2. **判定核（Q2）**：欠压判定**复用** `rr-core::control::Rr3LowEdge`（回阈 + 迟滞），不重写第二个
   边沿判定点（"一个事实一个真值点"）；两档 = 同一判定核上两条阈值线。
3. **降级编排（Q3）**：轻度欠压 → 舵机下令由"并行两轴"改**先 pan 后 tilt**（削峰）；重度欠压 →
   按 MC-5 拒动（执行面拒动、妆面不禁、回阈 + 迟滞解禁且不自动重放被拒的令）。
4. **分轴数据面（Q4）**：`modules/rr3-act/config.toml` 的 `angle_limit_deg` 单区间 → pan/tilt
   双区间（或 `[rr3-act.servo.pan]` / `[rr3-act.servo.tilt]` 分节，形状二选一由契约评审定）；
   板侧 `Axis::range` 与之一一对应（**一处数据、两处读**，不许板侧常量与 config 各写一份真值）。
5. **可观测（Q2 配套）**：欠压档位与降级动作计入 counters（承 A-6 / MC-11 的可观测纪律），
   使"电压不够→降级了/拒动了"看得见。

## §9 现场验收实测（2026-10-12 真板，方案C 新固件）

板载口 `/dev/cu.usbserial-1410`（控制台 / UART0）+ 外部 CP2102 `/dev/cu.usbserial-0001`（UART2）。
pyserial 手持 DTR/RTS 去断言开 1410 硬复位进运行模式抓 boot。

| 项 | 实测 | 判定 |
|---|---|---|
| 控制台状态行 | `[periph] surface=esp-rs-std crate=esp32-periph-base oled=i2c0@21/22 servo=ledc@32/33 cmd=uart2@115200 line+frame`；boot 全档（ELF SHA256 `1e330dd12…`、编译 `Oct 12 2026 10:51:03`、`rst:0x1 POWERON_RESET`） | ✅ 新镜像在跑 |
| I2C / OLED | 扫描应答 `[3C]`；**400k init 失败 → 降 100k 第 2 次重试过**；`OLED ✓ boot 画面已出（4 行）` | ✅ 硬件通，**信号边际**（上拉/线长偏弱，非死件） |
| LEDC / 舵机 | `pan=GPIO32 tilt=GPIO33 中位90° duty pan=1229 tilt=1229 (max=16384)` | ✅ 板侧置中成功 |
| **UART2 限幅字段** | `INFO …90 tilt=90 lim=pan[70,110]/tilt[80,100] wander=off phase=0 oled_last="(boot)" free=273528B min_free=272780B` | ✅ **取证**（新固件 tilt 80-100） |
| UART2 链路质量 | 我发的 `INFO`/`HELP` 行有一行到达即被污染 → 板回 `ERR unknown cmd`；回包亦有坏字节（`cmd "ERR"` 段） | ❌ **双向字节污染**（非固件 bug：接线 / 共地 / 电平） |

**两个现场症状的软件侧定位（均非固件 bug）**：
1. **OLED 无"胶囊眼"**：胶囊眼是**帧面 `rr3-interact/face/expression` 专有**（`frame_handle_face` →
   `oled_capsules`）；`oled_last="(boot)"` 证明自 boot 起**从未收到任何 face / OLED 命令** → 宿主
   没发（或发出后被 UART2 上行污染吞掉）。OLED 本体完好（boot 4 行已出）。
2. **舵机发烫 / 未到位**：实测 `pan=tilt=90`（中位）、`wander=off phase=0` → **固件没在驱动它**；
   "没转向正常位置" = 命令经 UART2 上行被污染 → 板侧收不到 → 停在 90。发烫属**物理 / 供电 / 装配**
   （堵转保持），头号嫌疑 = 舵机未走 UBEC 独立 5V 轨（[0.0.6 BOM #3](0.0.6版本洛克三号树莓派验证方案.md) 记"待采购"）
   → 欠压堵转发热，且正是本件 Q1 要观测的那条轨。**这直接验证 Q1 的优先级**。

**验收结论**：限幅字段与板侧置中 **PASS**；**宿主驱动面（UART2）仍未通**，是"胶囊眼不出 / 舵机不
转向"的唯一软件侧闸门；发烫属供电/装配面，转用户物理核查（见 §3 Q1 与 PA-R2）。

| **控制面/运行面分离** | 控制面线程独占 UART2（不碰 I2C/LEDC），运行面线程独占 I2C0+LEDC；`Arc<Mutex<Bus>>` 通信，锁不跨 I2C | boot SURFACE 行 `planes=ctrl+runtime serial-servo`；`INFO` 在 SCAN（~6s）期间即时应答 |
| **I2C 健壮性（配套）** | 400k→100k + GDDRAM 分块写（≤32B）+ 写重试 6×5ms + boot init 5 次重试 | 10/10 复位 boot 画面全出（§9 旧值"400k 失败降 100k"→ 直接 100k 稳过） |
| UART2 链路 | 现场仍劣化（板→Mac 前导乱码 + 自收包） | 属物理接线（非固件），转用户物理核查；Mac→板方向干净，命令可解析 |

**与 Q1 的关系**：Q1（5V 轨观测）**仍未施工**——本批只在"无观测"前提下按用户裁定先做**静态串行
降级**（比 MC-5 拒动更轻的一档）。欠压**动态**分级降级（Q2 双阈值）待 Q1 测点接线后接续。

## §11 现场处置续批（二）——OLED 表情不出的根因定案与"供电分时仲裁"（2026-10-12）

用户现场追加裁定（"OLED 屏幕没有显示出表情……舵机没有正常转向……注意考虑到整个板子的电压
问题……在极限资源下也能够正常地系统运行"）。本批**不新增硬件**，只用真板实验把根因定死，
再据根因做软件仲裁。施工落 `tools/esp32-periph-base/src/main.rs`（提交
`fix(esp32,periph): OLED 表情不出的根因修复——供电分时仲裁 + I2C 强制重同步`）。

### 定案过程（真板实验链，全部可复现）

1. **长度阶梯探针**（boot 期 1/2/4/17/31/32/33 字节各写一次）：全部 Ok ⇒ 故障与**单笔长度**无关。
2. **逐页轨迹**：init 8 页全 Ok、boot 文本 4 页全 Ok、表情首帧页 0/1/2 Ok、**页 3 中途起恒败**
   ⇒ 与**数据内容**无关、与**已点亮面积/电流**有关。
3. **舵机前后对拍**：boot 队列序为"先表情、后 Move"。表情在舵机动作**前**出得来；Move 之后
   微动作渲染**恒败**。
4. **逐轴掉 duty 试探（决定性一步）**：故障态下把两轴 `set_duty(0)` → **同一笔页写立刻 Ok**；
   重新激磁 → 立刻又败。⇒ **根因 = 舵机保持电流与 SSD1306 电荷泵抢同一 5V 轨**。
5. **欺骗性判据登记**：故障态下**地址单笔探测仍"通过"**（弱上拉下总线已死时的**假 ACK**），
   单靠"扫描能不能看到 0x3C"判活会被骗——必须看**多字节页写**。

### 修复（供电分时仲裁，运行面单线程内零重叠）

| 机制 | 落点 | 作用 |
|---|---|---|
| 舵机让位 | `RtPeriph::servo_release()`，`runtime_loop` 每次动作收尾调用 | 除"正在移动/扫描"外一律 duty=0，把 5V 轨整段让给 OLED |
| I2C 强制重同步 | `i2c_bus_recover(true)` | **无条件**打 9 SCL 时钟 + STOP——电机换向噪声会在**空闲期**把从机 I2C 状态机顶进半途态（此时 SDA 仍高，旧的条件版不触发、救不回来） |
| 亮度降级阶梯 | `OLED_CONTRAST_LEVELS` = 0x4F→0x3F→0x2F→0x1F | 整屏渲染失败即降档重来（boot 首帧通常自降一档到 0x3F 后稳定） |
| 缓速软启动 | 每轴 2°/20ms（=100°/s）逐档逼近 | 把整段跳变的电流尖峰摊成涓流 |

### 真板复验（3 次 35–40s 采集，板载 1410 控制台）

`anim_fail=0 capsule_fail=0 resets=0 bod=0`；`姿态到位 pan=60 tilt=98（LEDC 回读
pan=60° tilt=98°，记账 60°/98°）`——即"胶囊眼上屏"与"舵机转到指定角（中位左转 30°、
中位上抬 8°）"**同时达成且板子不复位**。修复前同条件实测 `anim_fail` 达 15–25 次/30s
（即表情肉眼可见地卡死）。

### 代价与遗留（如实登记，不计入"已解决"）

- **舵机不保持激磁**：两次命令之间 duty=0，位姿靠齿轮摩擦维持，长时间静置可能缓慢下沉；
  `WANDER` 由"连续平滑扫摆"退化为"碎步逼近"。**要"保持位姿 + OLED 同时稳定"必须上硬件**：
  舵机独立 UBEC 轨，或 OLED 模块 VCC/GND 就近并 ≥100µF 电解 + 0.1µF 陶瓷。
- **BOD 敞口未闭**：板载 5V 直供下舵机启动/整定偶发 `Brownout detector was triggered`
  （真板实录 1 次）。boot 以"先表情后舵机"排序保住可见性；根治仍需 UBEC。
- **UART2 指令面现场仍不可测**：CP2102（0001）呈回环，需用户核查物理接线；
  本轮舵机证据取自 **LEDC 寄存器回读**（硬件侧），不依赖 UART2。
- **Q1/Q2 维持未施工**：本批依旧是"无观测"下的静态仲裁；拿到 5V 测点后接动态分级。
