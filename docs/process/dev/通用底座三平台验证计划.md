## 0. 一页结论：谁当宿主，谁当板

**宿主只能是 Pi 4B 或 Mac，板可以是三块中的任意一块。** 原因是职责不对称：

- 宿主必须跑完整的模块化栈（rrd + rr3-act/sense/interact/brain + 面板 + LLM/ASR/TTS），
  需要 std、文件系统、网络与进程模型——ESP32 不具备，故 ESP32 永远不能当宿主。
- 板只负责实时外设面（OLED、舵机、轨压、麦克风）与**线上契约**（`rr-ipc` 帧 +
  `rr-periph-proto`），只要有 UART 与五个外设端口，任何平台都能当板。

据此得到三档，覆盖「宿主换 OS」与「板换平台」两个方向：

| 档位 | 宿主 | 板 | 验证的核心问题 | 语音/DoA | 代码改动量 |
|---|---|---|---|---|---|
| **T1** | **Pi 4B** | **ESP32 classic（已在手）** | 接缝①在 Linux/ARM 宿主上成立；整机功能链在非 Mac 宿主成立 | 有（板麦采集 + USB 声卡回放） | 零代码，仅装配档 + Pi 环境 |
| **T2** | **Mac** | **ESP32-S3 N16R8（面包板）** | 接缝②在第二种 MCU（不同架构/Flash/PSRAM/引脚）上成立 | 有（板麦采集 + Mac 回放） | 仅构建/引脚/装配档 |
| **T3** | **Mac** | **Pi 4B（当板，仅外设面）** | 接缝②不绑定 ESP 芯片：同一宿主、同一线上字节驱动非 ESP 板 | 无（本档明确不做） | 需先做 P0-A 机制核抽取 |

**为什么 Pi 出现在两档**：T1 证「Pi 能当宿主」，T3 证「Pi 能当板」。
同一块硬件两种角色都成立，才能证明「宿主/板」是**协议角色**而不是**硬件身份**——
这是整套通用性论证里最强的一条。

**为什么 T3 必须最后做**：当前五个端口 trait 是固件 `pub(crate)`，OLED/frame/periph
等机制仍与 esp-idf 类型同文件；Pi 要「同件复用」而不是「抄一份」，必须先做 P0-A。
若跳过 P0-A 直接抄代码，T3 只能证明「我们又写了一个板」，不能证明「底座通用」。

**执行顺序按物料与依赖排，不按档号排**：
`T2（S3 已到手）→ T1（等 USB 声卡到货）→ P0-A → T3`。
T1 与 Pi 系统准备可并行，T2 的引脚/构建批次不依赖 T1。

## 1. 验证对象的精确定义：两条接缝

```
┌────────────── 宿主进程（Pi 4B / Mac）──────────────┐
│ rrd · rr3-act · rr3-sense · rr3-interact · rr3-brain │
│                    ▲                                │
│              接缝①  rr-hal-api 契约 trait            │
│                    ▼                                │
│  sim / linux / mac / esp32_uart 四个宿侧后端         │
└────────────────────┬────────────────────────────────┘
                     │ 线上契约（不随平台换）
                     │ rr-ipc 帧 + rr-periph-proto 单点真值
┌────────────────────▼────────────────────────────────┐
│                板侧机制层                            │
│  frame · servo 缓速 · OLED 自愈降亮 · 轨压判定       │
│                    ▲                                │
│              接缝②  ports.rs 五端口 trait            │
│                    ▼                                │
│  esp-idf 驱动薄壳（classic / S3） / Linux 驱动薄壳（Pi）│
└─────────────────────────────────────────────────────┘
```

- **接缝①**：宿主模块与 HAL 后端之间。验收方式 = **换宿主 OS，模块代码零改**。
- **接缝②**：板侧机制与平台驱动之间。验收方式 = **换板平台，机制代码零改**。
- **中间线上契约**：两端都不许因平台变化而改字节格式；验收方式 = **三块板回包字节等价**。

通用性不是「能在三块板上跑起来」，而是**三条零改**：换宿主零改、换板零改、换平台零改。
本计划用 U1–U6（§3）把这句口号变成可执行判据。

## 5. W0：Pi 4B 宿主准备（零代码）

### 5.1 系统

1. Raspberry Pi OS **Bookworm 64-bit**，`sudo apt update && sudo apt full-upgrade`。
2. 串口：`sudo raspi-config` → Interface → Serial → **关闭 login shell、保留 hardware**；
   删除 `/boot/firmware/cmdline.txt` 里的 `console=serial0,115200`。
3. 为拿到稳定 PL011（921600 必需）：`/boot/firmware/config.txt` 加 `dtoverlay=disable-bt`，
   `enable_uart=1`；`/dev/serial0` 应指向 `ttyAMA0`。
4. I2C：`dtparam=i2c_arm=on`；用户加入 `i2c` 组（或板侧程序以 root 跑）。
5. PWM 两通道：`dtoverlay=pwm-2chan,pin=12,func=4,pin2=13,func2=4`，
   重启后 `/sys/class/pwm/pwmchip0/` 出现 `pwm0`/`pwm1`。
6. 关闭无关服务，确保 20ms 音频帧节拍不被包管理/桌面抢占：用 Lite 镜像，不装桌面。

### 5.2 工具链（重要：不要在 1–2GB Pi 上硬编全仓）

- 首选：Mac 上交叉编译 `aarch64-unknown-linux-gnu`（`cross` 或 `gcc-aarch64-linux-gnu`），
  `rsync` 到 Pi，只跑产物。
- 次选：Pi 上装 Rust，仅 `cargo build --release -p rr3-sim`，`-j2` + 2GB swap；
  整仓 `cargo test` 不在 Pi 上跑（门禁在 Mac/CI 跑）。

### 5.3 USB 声卡与回放

1. `aplay -l` 找到 USB 声卡 CARD 名（不钉卡号）。
2. 装配档 `[hardware] alsa_device = "plughw:CARD=<USB声卡名>"`；
   应急覆盖 `RR3_HAL_ALSA_DEVICE`。
3. `speaker-test -D plughw:CARD=<名> -c2 -t sine` 验证回放。
4. 采集**不走 USB**：采集仍是板麦 I2S → UART → 宿主 `rr-hal::esp32audio`。
   这样避免「单 `alsa_device` 键无法同时表达两张卡」的契约缺口。

### 5.4 串口时延

CP2102 默认 `latency_timer=16ms`，会直接吃掉音频上行预算：

```bash
echo 1 | sudo tee /sys/bus/usb-serial/devices/ttyUSB0/latency_timer
```

写入 udev 规则固化（`/etc/udev/rules.d/99-rr3-cp2102.rules`），否则重启回 16ms。

### 5.5 W0 验收

- `./rr3-sim --help` 在 Pi 上可跑；
- `/dev/serial0` 以 921600 与 classic 板互通（`rr3.ping` 回包）；
- `aplay -l` 与 `speaker-test` 通过；
- `ttyUSB0` latency_timer = 1。

## 6. W1 = T2：Mac 宿主 × ESP32-S3 N16R8

### 6.1 为什么先做 T2

S3 已在手，且 T2 不动宿主代码，风险局限在「构建 + 引脚」一层；先把第二种 MCU
跑通，T1 的整机验收就有了「板侧不是唯一变量」的对照。

### 6.2 构建档

`tools/esp32-periph-base/.cargo/config.toml` 增加目标段，**默认 `[build]` 仍走
classic**（既有 runbook 不变），S3 构建显式给 target 与 MCU：

```toml
[target.xtensa-esp32s3-espidf]
linker = "ldproxy"
runner = "espflash flash --monitor"
rustflags = ["--cfg", "espidf_time64"]
```

```bash
MCU=esp32s3 cargo +esp build --target xtensa-esp32s3-espidf \
    --no-default-features --features esp32s3
```

芯片档必须走 Cargo feature：esp-idf-sys 发射的 `cargo:rustc-cfg=esp32s3` **只作用于其
自身 crate，不跨 crate 传播**，本固件内 `cfg(esp32s3)` 恒假。故 `Cargo.toml` 声明
`default = ["esp32"]` + `esp32s3`，classic 构建零改动，S3 构建显式切档。
`[env]` 的 `MCU=esp32` 未设 `force`，外部 env 优先；esp-idf-sys 按 MCU 自动叠加
更具体的 `sdkconfig.defaults.esp32s3`。芯片专属档（公共项仍来自 `sdkconfig.defaults`）：

```
CONFIG_ESPTOOLPY_FLASHSIZE_16MB=y
CONFIG_ESP32S3_DEFAULT_CPU_FREQ_240=y
CONFIG_SPIRAM=y
CONFIG_SPIRAM_MODE_OCT=y
CONFIG_SPIRAM_SPEED_80M=y
```

门禁：新增 `tools/ci/esp32s3-periph-base-check.sh`（复制 classic 脚本，换 target /
芯片 feature / ELF 路径），要求构建 + 单测编译全绿。

### 6.3 引脚表（N16R8 专用）

**N16R8 的 GPIO26–37 被 Flash/Octal PSRAM 占用，classic 的 26/27/32/33/34 在 S3 上不可用**，
因此不能沿用 classic 线束，必须单独做一套杜邦线。建议表：

| 功能 | S3 引脚 | 约束说明 |
|---|---|---|
| UART2 TX（指令面） | **GPIO17** | 走 GPIO Matrix，任意脚；避开 strapping |
| UART2 RX | **GPIO18** | 同上；921600 初版可降 460800 |
| I2C SDA | **GPIO8** | OLED 0x3C；面包板先 100k，失败降 50k |
| I2C SCL | **GPIO9** | 同上 |
| LEDC pan | **GPIO4** | 50Hz / 14bit |
| LEDC tilt | **GPIO5** | 与 pan 同 timer0 |
| I2S BCLK | **GPIO6** | INMP441 SCK |
| I2S WS | **GPIO7** | INMP441 WS |
| I2S SD | **GPIO15** | INMP441 SD |
| ADC 轨压 | **GPIO1** | ADC1_CH0；ADC2 与 Wi-Fi 冲突不可用 |
| 控制台 | USB 原生 19/20 | 或板载 CP2102 走 UART0 43/44 |

**禁用区**：GPIO0/3/45/46（strapping）、19/20（USB）、26–32（Flash）、33–37（Octal PSRAM）、
43/44（控制台 UART0）。

### 6.4 代码改动

1. `board.rs` 的引脚常量改为按芯片档分文件：
   `#[cfg(feature = "esp32")] mod pins_classic; #[cfg(feature = "esp32s3")] mod pins_s3;`
   （esp-idf-sys 的 rustc-cfg 不跨 crate，故用本 crate 的 Cargo feature），
   其余策略量（波特率、角度行程、缓速步长、轨压阈值）**保持同一份**。
2. 新增装配档 `profiles/esp32s3-mini.toml`：`[platform] chip = "esp32s3"`，`[hardware]`
   十键照抄 `esp32-mini.toml` 词表、逐键改值；`[[pin]]` 按 §6.3。
3. `contracts/platform/` 若缺 `esp32s3.toml` 则补档（芯片事实表：双核 LX7 240MHz、
   16MB Flash、8MB Octal PSRAM、可用 GPIO 区间）。
4. 启动横幅增加 `chip=esp32s3 pins=s3` 自证行，便于证据辨认。
5. **不改** `rr-periph-proto`、不改宿主、不改机制层。

### 6.5 接线与供电

- 面包板 921600 初版不稳是常态：先 **460800** 跑通全功能，再升 921600；
  升档失败只允许改波特率与线长，**不许改协议**。
- 双 INMP441 的 3V3/GND 就近共地；SCK/WS 可并线，SD 各自独立（与 classic 相同拓扑）。
- 舵机独立 5V UBEC，UBEC/板/舵机单点共地；S3 的 5V 引脚只取信号参考，不供舵机。
- 轨压分压 1:1 仅占位，必须与万用表两点标定后才算通过。

### 6.6 T2 验收

1. 构建可复现：`MCU=esp32s3`、Flash 识别 16MB、PSRAM 识别 8MB、横幅正确。
2. 五端口全通：UART2 帧面、I2C 扫描 0x3C、LEDC 两轴、ADC 采样、I2S 双麦。
3. **U3**：与 classic 跑同一命令脚本，回包 canonical digest 相同。
4. **U5**：舵机全表 duty digest、OLED 单页字节 digest 相同。
5. 语音链：Mac 宿主 `--audio-backend esp32 --sink-backend mac`，10 句唤醒/ASR，
   DoA 三方向（左/中/右）≥ 8/10 正确。
6. 时序：20ms 帧节拍记档，p99 抖动不劣于 classic 基线的 1.5 倍。
7. 30 分钟连续跑：无重启、无 OOM、帧丢失 0、`min_free` 记档。
8. **U4 自检**：`git diff` 中 `base/runtime/rr-hal`、`modules/`、`tools/sim` 为 0。

## 7. W2 = T1：Pi 4B 宿主 × ESP32 classic 板（整机主验收）

这是**产品形态最接近真实**的一档：Pi 当大脑，ESP32 当外设板，语音全链在 Linux/ARM 上跑。

### 7.1 装配档

新增 `profiles/pi4b-host-esp32-classic.toml`：

- `[platform] tier = "host"`、`chip = "raspberry-pi-4"`（平台表
  `contracts/platform/raspberry-pi-4.toml` 已存在，直接复用）；
- `[hardware] alsa_device = "plughw:CARD=<USB声卡>"`、`link_ifname = "wlan0"`；
- `[[pin]]` 按 classic 板真值（pan/tilt/led/relay/轨压/OLED 由 bindings 十键表达）；
- `[bindings]` 与 `distro.toml` 同构；
- 板侧绑定的十键由装配档注入，值与 `profiles/esp32-mini.toml` 对齐。

演练入口沿用既有 runbook（不新造 CLI）：

```bash
RR3_HAL_PERIPH_UART=/dev/ttyUSB0 \
RR3_HAL_PERIPH_BAUD=921600 \
RR3_SENSE_CONFIG=<repo>/modules/rr3-sense/config-esp32.toml \
rr3-sim --brain --audio-backend esp32 --sink-backend linux --keep
```

### 7.2 验收（按「先外设、再语音、再云端」三段）

**A. 外设面**

1. 板侧横幅五项全 ✓；`rr3.set_bindings` 回显与装配档逐键一致。
2. OLED 4 行 boot 画面 + 胶囊眼 idle 动画。
3. 舵机 pan 0/90/180、tilt 30/90/150 逐点，量角器误差 ≤ 3°；五点 SCAN 全过。
4. 轨压：与万用表两点标定，误差 ≤ 50mV；UBEC 供电下不触发 BOD。
5. 1000 次 `rr3.ping`：0 失败，RTT 中位数记档（与 Mac 宿主基线比，允许 ≤ 2×）。

**B. 语音与 DoA（核心用例）**

6. 10 句唤醒 + ASR：唤醒成功 ≥ 9/10，转写可读 ≥ 8/10。
7. DoA 三方向各 10 次：分箱准确 ≥ 8/10；转向完成后点头手势不丢。
8. **flock 互斥**：音频流期间 OLED/舵机命令走 sense 命令旁路，不打断音频、
   不出现「语音一半卡死」。
9. 连续 30 分钟问答：时钟滑移在 2% 预算内，帧丢失 0。

> 工程意义：T2 只证「板能换」，T1 才证「宿主能换」。T1 的语音/DoA 是**接缝①的

## 8. W3 = P0-A：端口 trait 共享化与机制核抽取（T3 的前置）

### 8.1 目标

把「板侧机制」从「esp-idf 驱动薄壳」里剥出来，让 Pi 板能用**同一份机制代码**，
只换最底层的五个端口实现。

### 8.2 步骤

**A1. trait 迁入共享面**

- 把 `tools/esp32-periph-base/src/ports.rs` 的五个 trait（`Rr3UartPort`、`Rr3I2cPort`、
  `Rr3PwmChannel`/`Rr3PwmPort`、`Rr3AdcPort`、`Rr3ClockPort`）迁到
  `base/runtime/rr-periph-proto/src/ports.rs`，改为 `pub`。
- 理由：proto 已依赖 `rr-ipc`（`Rr3ByteStream` 就在那里），不新增 crate，保持「协议 +
  端口契约」单点真值。
- esp32 侧删除本地 `ports.rs`，改 `use rr_periph_proto::ports::*`；**行为不变**。

**A2. 机制核 `tools/periph-mech`**

只搬**与平台无关**的部分，不搬线程模型、不搬驱动构造：

- `frame`：整帧收/回包，泛型于 `Rr3UartPort + Rr3ClockPort`（现 `frame.rs` 已是此形）；
- `oled_codec`：命令/页/位图纯字节编码（从 `oled.rs` 剥离），I2C 事务泛型于
  `Rr3I2cPort`；
- `periph_core`：请求分发 + 状态机（pan/tilt 角度、对比度档、轨压判定），泛型于
  五端口；`servo` 缓速与 `face` 胶囊几何继续复用 `tools/atoms/*/mech.rs`；
- `rail_judge`：纯判定表（阈值 → 分档）。

**不搬**：`main.rs`、`state.rs` 的线程/`Arc<Mutex>`、`runtime_loop`、`mic`、`httpd`、
`commands` 的控制面循环——这些是各平台的适配层职责。

**A3. esp32 适配层收薄**

- `RtPeriph` 只保留驱动字段与五端口实现，分发调用 `periph_core`；
- 门禁：`esp32-periph-base-check.sh` + `cargo test -p rr-periph-proto` +
  `cargo test -p rr-periph-mech`；
- **对拍**：迁移前后同一命令脚本的 OLED/舵机字节流 digest 必须相同（防搬运走样）。

**A4. 文档**

在 ADR-0024 追加「机制核与适配层边界」一节，登记 A2 的搬运清单与不搬清单。

### 8.3 P0-A 验收

- classic 固件行为零变化（U5 digest 相同）；
- `rg "esp_idf" tools/periph-mech` = 0；
- `cargo tree -p rr-periph-mech` 无 esp-idf；
- 全量门禁绿。

## 9. W4 = P0-C：Pi 4B 板侧五端口后端

### 9.1 新 crate

`tools/pi-periph-base`（std，Linux only）：

| 端口 | 实现 | 说明 |
|---|---|---|
| `Rr3UartPort` | 复用 `rr_ipc::Rr3UartConn` 包装 `/dev/serial0` | 零新写串口代码，直接进 `Rr3ByteStream` |

### 9.2 接线表

| 功能 | Pi 物理脚 | 说明 |
|---|---|---|
| UART TX（Pi→宿主 CP2102 RX） | GPIO14 / pin 8 | `/dev/serial0` → `ttyAMA0` |
| UART RX（Pi←宿主 CP2102 TX） | GPIO15 / pin 10 | 交叉接；GND 必共 |
| I2C SDA | GPIO2 / pin 3 | OLED 0x3C + ADS1115 0x48 同总线 |
| I2C SCL | GPIO3 / pin 5 | GPIO2/3 自带 1.8k 上拉，100k 可用 |
| PWM pan | GPIO12 / pin 32 | `pwm0` |
| PWM tilt | GPIO13 / pin 33 | `pwm1` |
| 舵机电源 | 独立 5V UBEC | 禁接 Pi 5V；UBEC/Pi/舵机单点共地 |
| 5V 轨压 | ADS1115 A0 ← 2×10k 分压 | 5V→2.5V，落在 ±4.096V 量程内 |

- 新增 `profiles/pi4b-board.toml`（Mac 宿主 × Pi 板）：

5. ADS1115 轨压与万用表误差 ≤ 50mV；无器件时 Err 行为符合契约。

## 12. 风险与处置

| 风险 | 触发面 | 处置 |
|---|---|---|
| 面包板 921600 信号完整性 | T2 | 先 460800；升档失败只调波特率/线长/驱动档，不改协议 |
| S3 ADC 曲线与 classic 不同 | T2 | 两点标定；把标定系数放装配档，不进机制核 |
| N16R8 的 26–37 不可用 | T2 | 按 §6.3 重做线束；classic 线束禁止直接插 S3 |
| Octal PSRAM 与引脚冲突 | T2 | 不路由 33–37；开 PSRAM 前后各跑一次 `min_free` |
| Pi 编译内存不足 | W0/T1 | Mac 交叉编译 + rsync；或 `-j2` + swap |
| Pi 串口 console 占用 | T3 | 关 login shell、删 `console=serial0`、`disable-bt` |
| sysfs PWM 被别的 overlay 占用 | T3 | 只用 `pwm-2chan`，不与音频 HAT overlay 并存 |
| ADS1115 量程不足 | T3 | 2:1 分压 + ±4.096V；禁止直测 5V |
| Pi 5V 被舵机拉塌 | T1/T3 | 独立 UBEC，单点共地；先表情后激磁的既有顺序不变 |
| 单 `alsa_device` 键 | T1 | 采集走板麦，回放走 USB 卡；不改契约 |
| flock 互斥导致语音期间 OLED 不刷新 | T1/T2 | 属预期行为；舵机命令走旁路，OLED 等音频结束 |

| 用 if 分支抹平平台差异 | 全档 | U1/U2 直接判失败；先登记接缝泄漏再决策 |
