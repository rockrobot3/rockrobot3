# 洛克三号 RockRobot III

## 跨芯片平台快速部署的具身机器人底座

开放原子开源大赛 · 开源智能硬件解决方案赛道｜交付形态：软硬一体底座（机制核 + 主承载层 + 字节级契约 +
装机包 + 平台级点验矩阵）｜代码、架构文档、21 份 ADR 与门禁脚本公开托管于
`atomgit.com/rockrobot/rockrobot3`

洛克三号不是一台机器人，而是**一个能从一台机器人裁出一串机器人的底座**，解决行业里最贵的一件事：
**换一块芯片就把软件重做一遍**。做法是让同一份机制核在带 Linux 的板子、跑 FreeRTOS 的 ESP32、纯裸机三档
硬件上都能成立，把"换板"压缩成**写两件码、交一份七段描述符、填一行点验矩阵**；带自研外设的形态还要
第三件码——平台侧的"角色 → 引脚构造"表（`esp-idf-hal` 要具名引脚类型，这处不对称消除不掉，
ADR-0021 把它写进契约而不是藏进口号里）。这不是提案——它已在树莓派、
经典 ESP32、macOS 三个不同宿主/板卡上分别跑到过。

## 一、背景：我们踩的坑正好是行业的坑

洛克三号最初是一个 ESP32 桌面机器人固件项目。复盘发现成本大头不在功能，而在**同一套能力遇到第二种硬件
就要重来**：Linux 板与 MCU 之间隔着两套 SDK、构建链、调试方法与故障定位习惯，而这套基座里绝大部分内容与
芯片无关——行业每做一个新形态，都从"重新搭一遍软件基座"开始。

于是交付物从"某一块板的镜像"改成**一份可安装的底座**，老固件整树退役并留下可回溯标签（`v0-pre-legacy`）。
起点是 Rockchip RK3566 桌面陪伴机器人（约 0.5L），终点是被裁到不同预算的各种具身形态。开源是逻辑必然：
底座的收益只有被别人复用才成立，所以架构、契约、决策记录、验收矩阵连**门禁脚本本身**一起进仓，任何人能
照着把机制搬到新板，也能逐条检查我们的宣称有没有证据。

## 二、核心方案：跨芯片快部署凭什么成立

### 2.1 两层一切、三档承载

底座切成**机制核**（与 OS 无关、`core + alloc` 可达、契约级冻结）与**主承载层**（有 OS 才叠加）。但"两层"
不等于"两档"：早期按"有没有操作系统"画线，跑 FreeRTOS 的 ESP32 无处可归——它有 OS 却没有 Linux 那样的
主承载层。判据因此改判为**四类平台供给的齐备度**（时基、内存、事件循环、传输）：

| 承载档 | 典型硬件 | 交付形态 |
|---|---|---|
| **host 全承载** | RK3566 / 树莓派 / 任意 Linux 板 | 守护 `rrd` + HAL 后端 + 契约 + 装配单 + deb 装机包 + 六模块 |
| **rtos 轻承载** | ESP32 + FreeRTOS | 同一机制核的切片 + 一个能力面后端 + 一条字节流实现 |
| **bare 无承载** | 纯裸机 / 定时器驱动 | 机制核 + 本地守护输出行 + 平台看门狗喂拍 |

运行期由 `rrd` 负责注册、心跳、看门狗判死、自愈重启、依赖仲裁与启动序、降级传播；六个功能模块各自独立
进程（sense / interact / act / connect / power / brain，前五者 Rust、brain 纯 Python 标准库）；OS 侧**双轨**
（Buildroot 全镜像保底、发行版 deb 快路优先）；意图以结构化 `actions[]` 上总线，执行侧经**归属门 + 开放门**
两道白名单判定，越权拒执行、折日志、不断链。

### 2.2 三处窄缝：把"可移植"钉成接口而不是形容词

跨平台能否落地，取决于平台之间**必须相接的缝隙有多窄**。全部跨 OS 语义收敛成三处，逐条有代码形状与门禁执法。
第四条"资源与语义缝"（引脚角色绑定 + 能源域 + 两端常量副本）由 ADR-0021 在 2026-10-14 定形——它管的就是
本周实机暴露的那一类失败：插线冲突、轨压被拉塌、执行器无对象可标定。本节只写已落地并取到证据的前三条。

**缝一 · 能力面去平台形状。**七个硬件 trait（`Rr3PwmServo`/`Rr3GpioOut`/`Rr3AudioSource`/`Rr3AudioSink`/
`Rr3Power`/`Rr3Link`/`Rr3Display`）全部**同步签名**：去 `async`、去 `Send + Sync`，值类型去 `String`/`Vec`
改定长缓冲（`Rr3SsidText` 32B、`Rr3ErrText` 128B、`Rr3FaceFrame = [u8; 8]`）。增长律：**新执行器只能新增
trait，禁止给既有 trait 加方法**，否则一块板的改动会牵连所有板。

**缝二 · 总线只需要一条字节流。**整条通信栈对平台的要求收敛成两个方法，RPC 连接面在其上 blanket 实现——
宿主档走 Unix 域套接字、板档走 UART、第三块板可以是 SPI 或别的，**契约与上层一行不改**：

```rust
pub trait Rr3ByteStream {
    fn rr3_read_into(&mut self, buf: &mut [u8]) -> usize;
    fn rr3_write_all_bytes(&mut self, buf: &[u8]) -> usize;
}
```

**缝三 · 注入面是数据不是代码。**每个原子件把"要哪个能力句柄、取自描述符哪个键"（`handles`）与"暴露哪些
参数槽、类型与非法值收敛方向"（`ops`）写成装配清单，装载门与运行期双重校验；缺格、句柄缺、句柄值错、
后端未实装、参数非法五种情况各有行为定义。

**判定核下沉成零依赖 crate。**控制与安全原语（限速门、低电边沿、饱和检测、行程钳位）剥成 `rr-mech`：
`#![no_std]`、不依赖仓内任何其它 crate，仍由 `rr-core` re-export、既有引用点逐字不变。因为板档固件必须
直接吃判定核（桥断时安全核也要成立），而 `rr-core` 背着总线语义栈——**这是机制核与承载层真的可组合的
最简可证面**。

### 2.3 坐标系冻结与七段描述符：换板只改数据

换板要稳定，前提是问问题的方式不变。能力面冻结成契约文件：**21 张能力格**（基础 5 / 身体 12 / 认知 4，
状态三态为正常 18、占位 3、退役——占位必须写填实触发条件）、**30 条主题契约**（前缀归属、kind、稳定等级、
退役标记在册，越权发布运行期拒绝并计数）、**128 字节定长消息头**（AiryIPC 开源线格式）；纪律是"只增不改"，
并为被证伪的承诺开了 **retired 号位下线**出口（号位保留、义务解除，否则纪律会逼出空壳件）。主线三步由此
定型：**立格 → 造件 → 成面**，固定的是格、变化的是件，答不出"填哪个格"的模块就不该造。

平台差异不写进代码缺省（缺省一律 fail-closed，不回落任何一块具体板的引脚），全部落到**七段描述符**
`[os] [platform] [supplies] [slots].present [bindings] [enabled_slots] [hardware]`；芯片平台档与底板走线被
强制分成两段——换底板只改 `[hardware]`，换芯片只改 `[platform]` 与 `[supplies]`。两份真实装配单的对照就是
证据：

| 段 | 参考机 `default.toml`（RK3566 档） | 微型形态 `esp32-mini.toml`（ESP32 档） |
|---|---|---|
`[platform]` | `tier = "host"` | `tier = "rtos"` |
`[supplies]` | 六位（看门狗三键 + 时序预算三键），`watchdog_feeder = "rrd"` | 同一组键，`watchdog_feeder = "rr-core"`（板侧无守护进程，由机制核运行环喂） |
`[slots].present` / `[bindings]` | 16 格在位 / 16 条绑定 | 3 格（舵机 + 拾音 + VAD）/ 3 条绑定 |
`[hardware]` / `[os]` | 9 键物理绑定（pwm、GPIO 行号、I2C 与地址、ALSA、网卡）/ `route = "distro"` | 两段整缺省——九键是宿主 Linux 语义、`route` 是 Linux 镜像轴 |

这份文件里**没有一行代码**，却是"微型形态"的完整定义；被裁格位的理由与裁剪自检三问（被裁格里无人依赖 /
被裁主题申报面同步退役 / 安全核仍在板侧）就写在它的注释里。

### 2.4 于是"换一块板"的完整动作

1. 写**一个能力面后端**——只实现本平台需要的那几个 trait（没有新硬件就一个都不写）。
2. 写**一条字节流实现**——上面那两个方法。
3. 交**一份七段描述符**——档位、四类供给、时序预算、在位格集、绑定、启用格集、物理走线。
4. 填**一行点验矩阵**：① 字节契约对拍 ② 机制核在目标三元组编译且无 std 逃逸 ③ 供给自证 ④ 描述符装载
   ⑤ 安全核生效 ⑥ 生命周期 ⑦ 时序达标；其中③④是装载门（证描述符没撒谎），①②⑤⑥⑦是行为证据。
5. 产品码、对外主题、能力格表**零改动**（功能守恒红线）。

迁移成本不给笼统数字，给三段判断：**覆盖内近零**（既有 trait 覆盖的板只写后端与描述符）、**覆盖外有界**
（新执行器 = 新增一个 trait，工作量与新接口形状相关，不牵连既有板）、**未定档有主**（裸机档守护输出与
看门狗语义已定形，尚无第三块板兑现，敞口挂台账并带归属批次）。

## 三、已经取得的板上证据

| 面 | 硬件与环境 | 板上事实 |
|---|---|---|
| **host 全承载** | 树莓派 aarch64 / Debian 13（Layer 0 与目标 RK3566 **完全不同**） | deb 装入 → 开机自动启用 → **六模块全部 `running`、越权发布计数 `denied_publish = 0`**；整机重启后全栈自愈、启动计数跨重启累积；配网凭据后端持久化（断电重启仍在册）；硬件探测五面真值接线（缺格显式降级，不许恒真） |
| **rtos 轻承载** | 经典 ESP32（xtensa LX6 + esp-idf） | 字节契约在 xtensa **编译期**与宿主逐字节对拍；UART 实测 128B 头完整收发、半帧与坏 magic 双拒不进死锁；`rr-core::runtime` 跑在 FreeRTOS 上（心跳 195–204 ms，安全核逐拍与宿主 **bit-for-bit** 一致）；UART↔UDS 桥端到端 16 项 PASS / 0 FAIL，含真拔 USB 断链自愈；微型形态行**七列点验收口**，安全核 200 拍直方图 min 198 / avg 200 / max 299 ms；实测该平台形状（LX6 无 64 位原子，计数降 `AtomicU32`） |
| **外设与传感** | ESP32 独立微型形态（rtos 档）+ SSD1306 + 双轴云台 + INMP441 双麦 | OLED 真出字与表情面；舵机过桥 round-trip **90/45/135/90 逐度一致**（证据对象 = 设定值回显一致，不是位置反馈——开环舵机无位置反馈，故 ADR-0021 把"回读可信度"写进契约类型）；双麦 I2S 采集经 UART 上行、宿主落 wav；UART 组帧 680 ms → **11.7 ms** |
| **语音链与云边** | 云 ASR/LLM/TTS + 本地播放面 | TTS 下行 PCM 分帧发布并有**跨语言（Python 产 / Rust 消费）golden 对拍**；播放面增益与起播水位参数数据化、占位波形退役；真云三腿冒烟通过；密钥经手机 Web 面板录入 → 仓外 0600 文件 → 运行期现读 → 真实应答，值全程零回显 |
| **第三个宿主档** | macOS（手写 CoreAudio AudioQueue 绑定，零外部依赖） | 真麦克风全链路首通——同一能力面在第三个宿主由**完全不同**的后端兑现："后端可替换"是被跑过而不是被声称 |

软硬一体的失败通常不在算法而在电气与总线：CP2102 的 DTR/RTS 翻转会复位板子并污染首帧（补齐开口净化与
UART 超时读机制）；SG90 堵转约 700 mA/只触发板载 Brownout 复位循环，据此定案"舵机保持电流与 SSD1306
电荷泵抢同一条 5V 轨"，落成供电分时仲裁、分轴行程限幅、5V 轨 ADC 双阈值迟滞欠压判定与重度拒动。

## 四、应用场景：形态就是装配单

- **桌面陪伴 / 教育科研**：host 档 16 格全启用，即本文描述的交付形态。
- **微型具身终端与形态族群**：只留三格（舵机 + 拾音 + VAD），BOM 下探 MCU 级，认知留在宿主侧。
- **行业语音交互终端**（接待 / 示教 / 适老 / 无障碍）：拾音 + 表情播放 + 认知，裁掉执行面；认知层可换本地
  引擎摆脱云依赖，配网、面板、自愈、日志环是现成运维面。
- **边缘巡检与行业专用硬件**：执行 + 链路 + 电源；A/B 升级分区已预留，低电禁动这类安全语义在机制层而非
  应用层。
- **具身算法载体 / RISC-V 新 SoC 基线**：任意格子集，按 §2.4 五步接入——迁移成本可量化而不靠承诺。

## 五、创新点

1. **跨芯片平台快速部署被落成可施工、可验收的接口**（最大创新）：三处窄缝 + 零依赖判定核 + 七段描述符，
   把移植压缩成"写两件码、一份数据、一行矩阵"，三档判据取自平台供给齐备度而非"有没有 OS"。
2. **能力格坐标系 + 一板一装配单**：21 格 / 30 主题 / 128B 线上格式冻结成契约，缺格三个来源合一判定——
   "快速部署"唯一**能被机械检查**的表达方式。
3. **字节契约跨架构逐字节对拍**：x86_64、aarch64 + qemu、xtensa 编译期常量断言、arm64 容器 CI 四路同一条
   golden，拦住"同一份代码在不同架构上悄悄改了线上字节"。
4. **零策略载荷有静态执法，且门禁自己也被门禁检查**：禁词扫面 + 逐件两腿对拍计数 + 依赖闭包分级 +
   注入面校验 + "清单一致由脚本判等"的自指门。
5. **一套可复用的证据方法学**：承载档 × 七列点验矩阵与 retired 号位下线机制；三条硬纪律——代码可达 ≠
   板上跑过、SKIP ≠ PASS、失败分"缺码 + 工单号"与"无载体 + 触发条件"两本账。
