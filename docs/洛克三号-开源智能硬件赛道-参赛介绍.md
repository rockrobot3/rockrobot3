# 洛克三号 RockRobot III —— 跨操作系统的具身机器人底座

> 开放原子开源大赛 · 开源智能硬件解决方案赛道 参赛介绍
> 交付形态：软硬一体底座（机制核 + 承载层 + 字节级契约 + 装机包 + 验收矩阵）
> 代码与全部设计与决策记录公开托管于 AtomGit：`atomgit.com/rockrobot/rockrobot3`

## 一、项目背景

具身智能硬件行业有一个长期未被解决的问题：**每换一块芯片，就要重写一遍软件。**桌面形态用 Linux 板，
微型形态用 MCU，中间是两套 SDK、两套构建链、两套调试方法。项目预算的大头不是算法，是"把同一件事
在第二块板上再做一遍"。

洛克三号最初的形态是一个 ESP32 桌面机器人固件项目。我们在把它做完整之后发现，真正值钱的不是那
台机器人，而是**从它身上抽出可复用机制**的那件事。于是整个项目重新定向：交付的不是某一块板的镜像，
而是一个**具身机器人底座**——同一套机制既能落在带 Linux 的全承载板（起点是 Rockchip RK3566 桌面陪伴
形态，体积约束约 0.5L），也能落在不带 Linux 的微控制器（经典 ESP32 这类 MCU），还能继续裁到更小的
形态。老固件整树退役并留下可回溯标签（tag `v0-pre-legacy`），机制逐条搬进新架构。

底座由此立了一条纲领：**机制与策略极致分离。**每一行代码只用一个问题裁定归属——这是机制还是策略。
答"机制"留在机制核；答"策略"让位，经参数槽与描述符**数据化注入**，或整体迁到上层。机制核内出现
厂商名、产品名、业务阈值、`if (vendor == …)` 一律算架构违例，由静态门禁 fail-closed 拦截。

我们选择开源路线，是因为底座的价值必须靠别人复用才成立：架构文档、20 份架构决策记录（ADR）、
字节级契约文件、开发规约、验收矩阵与**门禁脚本本身**全部进仓公开，任何人可以照着仓内文档把这套机制
搬到一块新板上，并检查我们的每一条宣称有没有对应证据。

## 二、技术架构

### 2.1 两层一切、三档承载

底座切成**机制核**（与操作系统无关、`core + alloc` 可达、契约级冻结）与**主承载层**（有操作系统才叠加）。
这条切线不等于"有 OS / 没 OS"两档：真正的分档判据是四类平台供给（时基、内存、事件循环、传输）的齐备度，
于是可落三档——

| 承载档 | 典型板 | 交付内容 |
|---|---|---|
| host 全承载 | RK3566 / 树莓派 / 任意 Linux 板 | `rrd` 守护 + `rr-hal` 能力后端 + 契约 + 装配单 + 安装器 + 六模块 |
| rtos 轻承载 | ESP32 + FreeRTOS | 同一机制核的一个切片 + 一个能力面后端 + 一个字节流实现（有 OS，无主承载层） |
| bare 无承载 | 纯裸机 / 定时器驱动 | 机制核 + 本地守护输出行 + 看门狗喂拍 |

### 2.2 跨操作系统从"设计里存在"变成"可施工"：三处窄缝

跨平台不靠抽象层口号，靠三处被钉死的最小接缝：

1. **能力面契约去平台形状**：`rr-hal-api` 七个 trait 全部同步签名，去 `async`、去 `Send + Sync`、值类型
   去 `String`/`Vec`，改定长缓冲（`Rr3SsidText`、`Rr3ErrText`、`Rr3FaceFrame = [u8; 8]`）。新执行器
   只能新增 trait，禁止给既有 trait 加方法。
2. **总线只需要一条字节流**：`Rr3ByteStream` 两个方法（`rr3_read_into` / `rr3_write_all_bytes`），
   RPC 连接面在其上 blanket impl。宿主是 UDS，板上是 UART，第三块板上可以是别的——契约不变。
3. **注入面是数据不是代码**：每个原子件的 `handles`（要哪个能力句柄、取自描述符哪个键）与 `ops`
   （参数槽、类型、来源键、非法收敛方向）写成装配清单，由装载门与运行期双重校验。

判定核进一步下沉成**零依赖叶子 crate `rr-mech`**（`#![no_std]`，不依赖仓内任何其它 crate）。板档固件
按需引入它而不被总线语义栈牵连——这是"安全核在桥断、在无 OS 的板子上仍然成立"的实现前提。

### 2.3 格 / 件 / 面：固定的是格，变化的是件

底座的能力坐标系是冻结的：**21 张能力格**（基础层 5、身体层 12、认知层 4）与 **30 条主题契约**
逐条登记在册（含前缀归属、kind、稳定等级与退役标记），线上消息头 **128 字节定长**，采用 AiryIPC
开源线格式。演进纪律是"只增不改"，并为被证伪的承诺开了 **retired 号位下线**出口（号位保留、义务解除），
否则"只增不改"会制度性地制造空壳件。

主线三步是 **立格 → 造件 → 成面**：讨论"要不要加一个模块"先问"它填哪个格"，答不出格就不该造。
五件套样板由生成器 `rr3-mkmod` 产出，不手写。平台差异全部落到数据面：**七段描述符**
（`[os]` `[platform]` `[supplies]` `[slots].present` `[bindings]` `[enabled_slots]` `[hardware]`），
一板一份装配单——芯片平台与底板走线在数据上被强制分开，换底板不动平台档。

运行期由 `rrd` 编排：注册握手、心跳、看门狗判死、按 `restart_policy` 自愈重启、依赖仲裁与启动序、
降级传播、日志环与运维计数持久化。六个模块各自独立进程（sense / interact / act / connect / power /
brain），前五者 Rust、brain 为 Python 纯标准库（零 pip 依赖，便于算法侧快速替换）。操作系统侧走
**双轨**：Buildroot 全镜像保底，发行版 deb 包快路优先。

### 2.4 执法面：宣称必须有读者

- **自动化用例 810 条**（Rust 751 + Python 59），CI **9 个 job**，本地门禁**十步**：编译 / 全量测试 /
  契约形状 pin / 主题前缀归属 / 独立工程编译 / 文档门 / 逐件测试真跑 / 静态断言（含零策略载荷禁词扫面、
  五件套计数、入口体量）/ 件级判据三门（两腿对拍计数、依赖闭包、注入面校验）。
- **点验矩阵**（承载档 × 七列）是平台级验收的唯一形式：① 字节契约跨架构对拍、② 传输载体、
  ③ 供给自证、④ 描述符装载、⑤ 安全核生效、⑥ 生命周期、⑦ 时序直方图。其中 ③④ 是装载门（证描述符
  没撒谎），①②⑤⑥⑦ 是行为证据；出数入口 `matrix.sh` 已接进 CI job。
- **门禁自己也必须被扫**：新建机制核面 crate 必须同批进禁词扫面与 xtensa 目标清单，并由脚本判这三处
  清单一致（自指判等），防止"文档宣称有门、门实际没扫"。
- 证据纪律：**"代码可达"与"板上跑过"是两个证据对象，不许互充；SKIP 不等于 PASS；失败分"缺码 + 工单号"
  与"无载体 + 触发条件"两本账登记。**版本也按交付物类型分窗——开发窗产码、验证窗只产证据且禁改码、
  整理窗产结构，避免"同版改码让本版已取证据作废"。

## 三、板上的证据（不是路线图）

| 层 | 板 / 环境 | 已经跑过的事实 |
|---|---|---|
| host 全承载 | 树莓派（aarch64 / Debian 13，Layer 0 与目标 RK3566 **不同**） | `dpkg -i` → postinst 自动启用 → 六模块全部 `running`、越权发布计数 `denied_publish = 0`、`sudo reboot` 后全栈自愈、`boots` 计数跨重启累积；配网凭据由后端承载持久化（断电重启仍在册）；五面硬件探测真值接线（缺格必须显式降级，不许恒真） |
| rtos 轻承载 | 经典 ESP32 | 四层梯子全绿：字节契约 xtensa 编译期对拍；UART 载体板级实测 128B 头完整收发、半帧与坏 magic 双拒不进死锁；机制核真板消费者（`rr-core::runtime` 在 FreeRTOS 上跑，心跳 195–204ms，安全核逐拍与宿主 **bit-for-bit** 一致）；UART↔UDS 桥端到端 16 项 PASS / 0 FAIL，含真拔 USB 的断链自愈。esp32-mini 行七列点验收口，200 拍时序 min 198 / avg 200 / max 299ms。并实测出该平台形状：LX6 无 64 位原子，计数与发号降 `AtomicU32` |
| 外设与传感 | ESP32 协处理器 + SSD1306 + 双轴云台 + INMP441 双麦 | OLED 真出字与表情面（含生命感微动作）；舵机 round-trip 90/45/135/90 逐度一致；双麦 I2S 采集经 UART 上行、宿主落 wav（真板实录）；UART 组帧从 680ms 优化到 11.7ms |
| 语音链与云边 | 云 ASR/LLM/TTS + 本地播放面 | TTS 下行 PCM 分帧发布并有**跨语言 golden 对拍**基准；播放面参数（增益 / 起播水位）数据化实装，占位波形退役；真云三腿 opt-in 冒烟通过；密钥经手机 Web 面板录入 → 仓外 0600 权限文件 → 运行期现读 → 真连应答，值全程零回显 |
| 第三个宿主档 | macOS（手写 CoreAudio AudioQueue 绑定） | 真麦全链路首通——同一能力面在第三个宿主上由不同后端兑现，验证"后端可替换"不是纸面承诺 |

现场踩坑与处置同样是交付的一部分：CP2102 的 DTR/RTS 翻转会复位板子、开机 banner 污染首帧（补开口净化
与 UART 超时读机制）；SG90 堵转 700mA/只的持续电流触发板载 Brownout 复位循环（供电分时仲裁、分轴限幅、
5V 轨 ADC 双阈值迟滞欠压判定 + 重度拒动 + 观测面）。软硬一体方案的失败通常不在算法，而在这些位置。

## 四、应用场景

同一底座按格裁剪，不改产品码：

- **桌面陪伴与教育科研（host 全承载）**：16 格身体层+认知层全在位，能听、会回应、有表情、可动。
  教学与科研价值在于契约与 ADR 全公开，可当作"一个真实系统的完整切片"来教。
- **微型具身终端（rtos 轻承载）**：只留 `act.servo` / `audio.capture` / `audio.vad` 三格，
  BOM 下探到 MCU 级，一台底座的机制换成一串形态各样的小机器人。
- **行业语音交互终端**（接待、示教、适老陪伴、无障碍交互）：裁掉执行面只留 sense + interact + brain，
  认知层可换本地引擎以摆脱云依赖；配网、面板、自愈、日志环这些"运维面"是现成的。
- **边缘巡检与行业专用智能硬件**：act + connect + power 三件组合，分区布局已为 A/B 升级与恢复出厂
  预留；低电禁动这类安全语义在机制层，不在应用层。
- **具身智能算法的实体化载体**：意图以结构化 `actions[]` 上总线、经归属门与开放门两道白名单执行，
  算法侧只需产出意图，不必碰硬件；这是把模型能力接进真实身体的稳定可编程面。
- **RISC-V / 新 SoC 的适配基线**：跨档判据写在数据面（供给四件 + 时序预算 + 看门狗），新平台按
  "写两件码 + 交一份七段描述符 + 填一行点验矩阵"接入，迁移成本可被量化而不靠承诺。

## 五、创新点

1. **把"跨操作系统"落成可施工接口，而不是抽象层口号。**三处窄缝（能力面去平台形状、字节流总线、
   数据化注入面）+ 零依赖判定核 `rr-mech`，让同一份控制与安全语义在全承载 / 轻承载 / 无承载三档上
   都成立，且已在 xtensa 与 aarch64 上取到板上证据。
2. **能力格坐标系 + 一板一装配单。**21 格 / 30 主题 / 128B 线上字节冻结为契约文件，缺格的三个来源
   合一判定，换板 = 改数据。这是"快速部署"唯一可以被检查的表达方式。
3. **机制核零策略载荷有静态执法，且门禁自己也被门禁检查。**禁词扫面、五件套计数、两腿对拍按件名前缀
   计数、依赖闭包分级、注入面校验，加上"清单三处一致由脚本判等"的自指门。
4. **字节级契约跨架构逐字节对拍。**x86_64 宿主、aarch64 交叉 + qemu、xtensa 编译期常量断言、
   arm64 容器 CI 真跑四路同一条 golden，杜绝"同一份代码在不同架构上悄悄改了线上字节"这一类最难查的缺陷。
5. **一套可复用的证据方法学。**承载档 × 七列点验矩阵、retired 号位下线机制、"代码可达 ≠ 板上跑过"、
   "SKIP ≠ PASS"、缺码与无载体分账——把开源项目里最常见的"文档宣称已实现"变成可被机械推翻的陈述。
6. **软硬一体的现场闭环能力。**供电分时仲裁、欠压双阈值迟滞拒动、行程分轴限幅、UART 失步重同步与
   超时读机制，都有实测前后对比；这类能力决定行业方案能否从展台走进部署现场。

## 七、一句话

洛克三号想交付的不是一台更聪明的机器人，而是**让"再做一台不同形态的机器人"这件事，
从重写一遍变成改一份数据、写一个后端、填一行矩阵。**
