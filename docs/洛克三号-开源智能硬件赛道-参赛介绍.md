# 洛克三号 RockRobot III

## 跨芯片平台快速部署的具身机器人底座

开放原子开源大赛 · 开源智能硬件解决方案赛道｜交付形态：软硬一体底座（机制核 + 主承载层 + 字节级契约 +
装机档 + 平台级点验矩阵 + 可复跑门禁）｜代码、架构文档、24 份 ADR 与门禁脚本公开于
`atomgit.com/rockrobot/rockrobot3`。本文数字取自语义基线 **`f64451e`**，每个数都附产出它的命令或仓内文件。

洛克三号不是一台机器人，而是**一个能从一台机器人裁出一串机器人的底座**，解决行业里最贵的一件事：
**换一块芯片就把软件重做一遍**。做法是让同一份机制核在带 Linux 的板、跑 FreeRTOS 的 ESP32、纯裸机三档硬件上
都能成立，把"换板"压缩成**写一个后端、交一份八段描述符、填一行点验矩阵**。这不是提案——同一份机制核今天跑在
四个宿主/芯片档上：树莓派、经典 ESP32（xtensa LX6）、**新到的 ESP32-S3 N16R8**、macOS；而 S3 从拆封到
五端口装配全过，**契约表与产品码一行都没改**（§3）。

洛克三号最初是一个 ESP32 桌面机器人固件项目。复盘发现成本大头不在功能，而在**同一套能力遇到第二种硬件就要重来**：
Linux 板与 MCU 之间隔着两套 SDK、构建链、调试与定位习惯，而基座里绝大部分内容与芯片无关——行业每做一个新形态，
都从"重新搭一遍软件基座"开始。于是交付物从"某一块板的镜像"改成**一份可安装的底座**，老固件整树退役并留下
可回溯标签（`v0-pre-legacy`）。起点是 Rockchip RK3566 桌面陪伴机器人（约 0.5L），终点是被裁到不同预算的
各种具身形态。开源是逻辑必然：底座的收益只有被别人复用才成立——所以架构、契约、决策记录、验收矩阵
连**门禁脚本本身**一起进仓，别人既能照着搬板，也能逐条检查我们的宣称有没有证据。

## 一、核心方案：跨芯片快部署凭什么成立

### 1.1 两层一切、三档承载、两轴定档

底座切成**机制核**（与 OS 无关、`core + alloc` 可达、契约级冻结）与**主承载层**（有 OS 才叠加）。
早期按"有没有操作系统"画线，跑 FreeRTOS 的 ESP32 无处可归——它有 OS，却没有 Linux 那样的主承载层。
判据先改判为**七位平台供给的齐备度**，又发现这根轴分不开 host 与 rtos（两位都"七位齐"），于是定为一横一纵**两轴**：

| 承载档 | 轴一 七位供给 | 轴二 主承载层形态 | 现役实例 | 交付形态 |
|---|---|---|---|---|
| **host 全承载** | 齐 | 有进程监督 + 富文件系统 | RK3566 / 树莓派 | `rrd` 守护 + HAL 后端 + 契约 + 装机档 + deb 包 + 六模块 |
| **rtos 轻承载** | 齐 | 无进程监督 / 无富文件系统 | ESP32、**ESP32-S3** | 机制核切片 + 一个能力面后端 + 一条字节流实现 + 一份描述符 |
| **bare 无承载** | 仅时基 + 事件循环 | 无 OS | 尚无（真板批触发） | 机制核 + 本地守护输出行 + 平台看门狗喂拍 |

七位供给＝**时基、内存、事件循环、传输、时序预算、平台看门狗、能源域**。一位供给就是一条结论所依赖的前提——
**结论引用的能力必须在前提里被供给过**，否则那句结论是断头话；能源域补成第七位，正因为欠压复位循环（§2.3）
不是软件 bug，而是缺一个被建模的物理前提。运行期由 `rrd` 管注册、心跳、看门狗判死、自愈重启、依赖仲裁、
启动序与降级传播；六模块各自独立进程（sense / interact / act / connect / power / brain，**全 Rust**，
6/6 共用 `rr3mod` 那份同构启动序列）；OS 侧**双轨**（Buildroot 全镜像保底、deb 快路优先）；意图以结构化
`actions[]` 上总线，执行侧经**归属门 + 开放门**两道白名单，越权拒执行、折日志、不断链。

### 1.2 四处窄缝：把"可移植"钉成接口而不是形容词

跨平台能否落地，取决于平台之间**必须相接的缝隙有多窄**。全部跨 OS 语义收敛成四处，逐条有代码形状与门禁执法。

**缝一 · 能力面去平台形状。**12 个硬件 trait（`Rr3PwmServo`、`Rr3GpioOut`、`Rr3AudioSource/Sink`、`Rr3Power`、
`Rr3Link`、`Rr3Display`、`Rr3Sensor`、`Rr3DigitalIn`、`Rr3Rail`、`Rr3Actuator`、`Rr3Store`）全部**同步签名**：
去 `async`、去 `Send + Sync`，值类型去 `String`/`Vec` 改定长缓冲（`Rr3SsidText` 32B、`Rr3ErrText` 128B）。
增长律：**新执行器只能新增 trait，禁止给既有 trait 加方法**，否则一块板的改动牵连所有板；它由 `⑨-w 依赖面禁令`
机器执法（"单元与板侧只许依赖能力面 crate"，放行的 `use` 面白名单钉成**条目数只降不升**）。

**缝二 · 总线只需要一条字节流。**整条通信栈对平台的要求收敛成两个方法，RPC 连接面在其上 blanket 实现；
宿主走 Unix 域套接字、板档走 UART、第三块板可以是 SPI，**契约与上层一行不改**（`Rr3ByteStream`，
`rr3_read_into` ＋ `rr3_write_all_bytes`，签名见 `contracts/` 与 `rr-ipc`）。

**缝三 · 注入面是数据不是代码。**原子件把"要哪个能力句柄、取自描述符哪个键"（`handles`）与"暴露哪些参数槽、
类型与非法值收敛方向"（`ops`）写成装配清单，装载门与运行期双重校验；缺格、句柄缺、句柄值错、后端未实装、
参数非法五种情况各有行为定义。

**缝四 · 资源与语义缝（ADR-0021 定形）。**引脚角色词表（`contracts/roles.toml`）＋ 装机档 `[[pin]]` 绑定 ＋
能源域 `[[supplies.domain]]` 与件级 `demands` ＋ 平台事实表（`contracts/platform/*.toml`，四份在册）。
八枚物理键（`pwm_chip`、`i2c_bus`、`spi_device`…）**只允许由 `[[pin]]` 派生**，在 `[hardware]` 直给即拒 boot——
"某个信号接哪个硬件"不许有两个来源（`⑨-n` 执法）。一处**消除不掉的不对称**明写在契约里：`esp-idf-hal`
的构造签名要具名引脚类型，所以引脚号必然同时出现在数据与"角色→具名构造表"两处——S3 就是按这条交出那 36 行表的。
此外控制与安全原语（限速门、低电边沿、饱和检测、行程钳位）剥成零依赖 `#![no_std]` 的 `rr-mech`，
因为板档固件必须直接吃判定核（桥断时安全核也要成立）——这是"机制核与承载层真的可组合"的**最简可证面**。

### 1.3 坐标系冻结与八段描述符

换板要稳定，前提是**问问题的方式不变**。能力面冻结成契约：**23 张能力格**（正常 20 / 占位 3，占位必须写填实
触发条件）、**42 条主题契约**（含 2 条 `retired`；前缀归属、kind、稳定等级全在册，越权发布运行期拒绝并计数）、
**128 字节定长消息头**（AiryIPC 开源线格式，跨 x86_64、aarch64 + qemu、xtensa 编译期常量断言、arm64 容器
四路逐字节对拍）。纪律是"契约只增不改"，并为被证伪的承诺开了 **retired 号位下线**出口（号位保留、义务解除）——
没这个出口，"只增不改"会制度性逼出空壳件。主线三步由此定型：**立格 → 造件 → 成面**。

平台差异不写进代码缺省（缺省一律 fail-closed，不回落任何一块具体板的引脚），全部落到八段描述符
`[os] [platform] [supplies] [slots].present [bindings] [enabled_slots] [hardware] [pins]`，且芯片档与底板走线
强制分两段：**换底板只改 `[hardware]`，换芯片只改 `[platform]`/`[supplies]`/`[[pin]]`**。描述符也不是"交上来看看"——
装载期跑**十条校验、31 个判定位**，逐位有判据实体与反例用例，每条必填"留空怎么算"（一律**红**）与"后果三态"
（拒 boot / 降级+点名 / 仅点名）。"十条全过"这句不可核，所以引用必须写到"第 ⑦-c1 位"这一级：
**判据的分母与形状都要能被机器数**。

### 1.4 于是"换一块板"的完整动作

① 写**一个能力面后端**（只实现本平台需要的那几个 trait，没有新硬件就一个都不写）；② 写**一条字节流实现**；
③ 交**一份八段描述符**；④ 填**一行点验矩阵**（① 字节契约 ② 机制核编译面无 std 逃逸 ③ 供给自证 ④ 描述符装载
⑤ 安全核生效 ⑥ 生命周期 ⑦ 时序达标——③④ 证描述符没撒谎，①②⑤⑥⑦ 是行为证据）；
⑤ 产品码、对外主题、能力格表**零改动**（功能守恒红线）。迁移成本不给笼统数字，给三段判断：
**覆盖内近零**、**覆盖外有界**（新执行器＝新增一个 trait，不牵连既有板）、**未定档有主**（裸机档语义已定形、
尚无板兑现，敞口挂台账并带归属批次）。

## 二、板上证据

- **host 全承载 · 树莓派 aarch64 / Debian 13**（与目标 RK3566 **完全不同**）：deb 装入 → 开机自启 →
  **六模块全 `running`、`denied_publish = 0`**；整机重启后全栈自愈、启动计数跨重启累积；配网凭据持久化；
  硬件探测五面真值接线，缺格显式降级不许恒真。
- **rtos 轻承载 · 经典 ESP32**：字节契约在 xtensa **编译期**与宿主逐字节对拍；UART 128B 头完整收发，半帧与
  坏 magic 双拒不进死锁；`rr-core::runtime` 跑在 FreeRTOS（心跳 195–204 ms，安全核逐拍与宿主 **bit-for-bit**
  一致）；UART↔UDS 桥 16 项 PASS / 0 FAIL，含真拔 USB 断链自愈；微型形态行**七列点验收口**，安全核 200 拍
  直方图 min 198 / avg 200 / max 299 ms；实测 LX6 无 64 位原子 ⇒ 计数降 `AtomicU32`。
- **外设与语音**：SSD1306 真出字与表情面；舵机过桥 round-trip **90/45/135/90 逐度一致**（证据对象＝设定值
  回显一致，不是位置反馈——开环舵机无位置反馈，故 ADR-0021 把"回读可信度"写进契约类型）；双麦 I2S 经 UART
  上行、宿主落 wav；UART 组帧 680 ms → **11.7 ms**；TTS 下行 PCM 分帧有**跨语言 golden 对拍**，播放面参数
  数据化、占位波形退役，真云三腿冒烟通过，板麦增益 ×8 与 VAD 阈值实测重标定；密钥经手机面板录入 → 仓外
  `0600` 文件 → 运行期现读，值全程零回显。
- **第三个宿主 · macOS**（手写 CoreAudio AudioQueue，零外部依赖）：真麦克风全链路首通——同一能力面由
  **完全不同**的后端兑现，"后端可替换"是被跑过而不是被声称。

### 2.1 第二块 MCU：ESP32-S3 N16R8 的实测改动清单

`espflash` 烧录成功（App **1,139,760 / 16,384,000 B = 6.96%**），启动实录
`chip=esp32s3 flash=16MB psram=8MB-octal`、boot 堆 `free=8,667,992 B`；**五端口装配面全过**
（UART2 921600 @ GPIO17/18、LEDC pan/tilt 4/5、ADC1 GPIO1、I2S0 16 kHz/32 bit @ 6/15/7、I2C0 8/9），
全程**无 panic、无复位**。未接线的预期失败（I2C 扫描空、OLED init 终败、双麦 rms=0、轨压 542 mV 判 severe）
按"未接线"如实登记，**不当作通过，也不藏着**。支撑上板的就是 §1.4 那几步的实际形状（`dc7a40c`，14 文件 / +634 −70）：

| 改的东西 | 性质 | 行数 |
|---|---|---|
| `contracts/platform/esp32s3.toml` | 芯片事实表（控制器词表、能力集、冲突矩阵、构造表） | 75 |
| `profiles/esp32s3-mini.toml` | 八段装机描述符（喂拍者等与 esp32-mini 同源） | 110 |
| `src/board/pins_s3.rs` / `pins_classic.rs` | 消除不掉的那件码：角色 → 具名引脚构造 | 36 / 32 |
| 该板对拍入口 + 构建档三件 | 可复跑 CI 检查；目标三元组与 16MB/PSRAM 布局 | 107 + 35 |
| 契约四表、六模块、机制核 | **未改** | **0** |

那份引脚表恰好说明"换板"为什么不是一句空话：S3 的 16MB Flash 与 Octal PSRAM **占掉 GPIO26–37**，经典 ESP32
用了很久的 26/27/32/33/34 在 S3 上全部不可用，再叠加 strapping（0/3/45/46）、原生 USB（19/20）、UART0 控制台
（43/44）与 ADC2 对 Wi-Fi 的冲突避让，才落到"17/18、8/9、4/5、6/15/7、ADC1_CH0 GPIO1"这一组号。这类知识过去
只活在工程师脑子里；在这里它是**一份带避让理由、可 diff、可核对的表**。

### 2.2 软硬一体的失败，多数在电气与总线

CP2102 的 DTR/RTS 翻转会复位板子并污染首帧（据此补齐开口净化与 UART 超时读）；SG90 堵转约 **700 mA/只**
触发板载 Brownout 复位循环，据此定案"舵机保持电流与 SSD1306 电荷泵抢同一条 5V 轨"，落成供电分时仲裁、
分轴行程限幅、5V 轨 ADC 双阈值迟滞欠压判定与重度拒动。这些不是算法问题，是**建模缺失**问题。

## 三、方法学：让宣称自己会腐烂

底座最难的不是写出来，是**三年后还有没有人知道哪句是真的**。我们把检查做成了门禁与台账。

- **本地门禁 20 步 + CI 9 个 job**（`grep -c '^step ' tools/ci/check.sh`）；门禁也判文档——空 md、断链、
  README 漏进导航都会红（步 ⑤）。
- **欠账用"基线文件钉数、只降不升"**：角色覆盖差集钉在 **21**（`gate-a-baseline.txt`），面板未申报项钉在 **0**、
  分母下限 **79**（`gate-d-baseline.txt`）。新增一项未申报字段当场红，改善则必须下调基线否则红——比"设个高目标
  然后长期豁免"诚实，因为欠账成了可下降的数值。
- **SKIP ≠ PASS**，失败分两本账："缺码 + 工单号"与"无载体 + 触发条件"。**可达终点表**把它摊到明面：
  三形态 × 十项 = **30 格**，逐格写"今天能做到哪一步、证据编号、缺什么"，回答行业文档最常回避的那句——
  "我拿这块板，今天到底能跑什么"。
- **未决对象唯一登记处** `docs/process/decisions.md`：每个悬着的决定写满六列（对象名／在问什么／缺哪一类／
  **不裁会怎样**／落点／取证基线号），只有"裁定·评审·载体"三类才占用人的裁定预算。
- **十一轮公开证伪审查**（全案 §18–§25）：每轮换一把尺子重查同一套设计，**打在自家判据上的那几条单独成节、
  不软化**——上一轮刚用它抓出两处我们自己的过度宣称并当场收回。附带一条纪律：**会随基线漂移的实测计数
  不再抄进文档**，只写"谁产出 + 基线号 + 当时值"。

## 四、抽象是**收**出来的，不是堆出来的

底座的价值在于"同一份东西被用第二次"，所以每次抽象都要回答：它有没有真实的第二个消费者？三件收敛动作都是
**先跑两遍、再抽一层**：

| 收敛件 | 抽掉的重复 | 依据 |
|---|---|---|
| `rr-bus-api` | 五单元直依 std 承载 crate（换 OS 要改 5 份 Cargo 清单） | 能力面先例已验证，禁令 `⑨-w` 执法 |
| `rr-periph-proto`（ADR-0024） | 板-宿主帧协议两端各抄一份（task 位形、主题串、信封、应答门序） | 靠人记同步 ⇒ 迟早漂 |
| `rr3mod` | 六模块同构启动序列各写一遍（今天 6/6 依赖它） | 只编排不重写，**不给既有语义立第二份实现** |

反面账也记：**"过度抽象"同样入册**（教训类 L-32）——845 行共享内存传输在 `rr-ipc` 之外零消费者、两个 transport
trait 零多态调用点，就是这么被记成欠账并在整理窗裁决摘除的。抽象不够会被功能卡住（会红），抽象过头只会安静地
占着维护面，所以两类账必须并列。

## 五、应用场景与当前边界

**形态就是装配单**：桌面陪伴 / 教育科研（host 档按需启用 20 个正常格）；微型具身终端与形态族群（只留
舵机 + 拾音 + VAD 三格，BOM 下探 MCU 级，认知留宿主侧）；行业语音交互终端（接待 / 示教 / 适老 / 无障碍——
拾音 + 表情播放 + 认知，裁掉执行面，认知层可换本地引擎摆脱云依赖，配网、面板、自愈、日志环是现成运维面）；
边缘巡检与行业专用硬件、RISC-V 新 SoC 基线（任意格子集按 §1.4 五步接入；低电禁动这类安全语义在机制层而非
